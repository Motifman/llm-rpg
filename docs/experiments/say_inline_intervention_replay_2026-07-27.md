# 行動しながらの発話 (say_inline) の説明文を変えると、専用ターンの発話が減る

2026-07-27 に記録済み prompt の再送で測った介入実験の結果。200 tick の run を
回す前に「その手が使えるなら使うか」だけを切り出して確かめた。

## なぜこれを測ったか

v4 の run 003 / 004 / 005 の分析で次が分かっていた。

- `speak` は 3 run 通算 601 回中 600 回成功する = 事実上唯一失敗しない行動
- 004 の `speak` は 106 回。いっぽう `say_inline` (行動しながらの一言) は
  speak 以外の行動 217 件中 **3 件** しか使われていない
- `say_inline` を既に持つツールでも、直後に `speak` 専用ターンを使う率が
  17〜72% ある = **使えるだけでは行動が変わっていない**
- 停滞の表出 (「同じことばかり繰り返している焦りが拭えない。」) は 004 の
  prompt の 43% / 005 の 64% に届いていて、それでも繰り返していた =
  **「気づかせる」系の介入は効かないことが実測済み**

そこで「上限を上げ、説明文を書き換え、`wait` / `explore` にも足したら選択が
変わるか」を、run を回さずに測った。

## 方法

`scripts/replay_prompt_intervention.py`。`prompt_dataset` の
`reconstruct_request()` で記録済み call を完全復元し、**toolset だけ**差し替えて
再送する。

- 対象: `var/runs/v4coop_memo_keep_004` で phase=one_step かつ `speak` を
  選んだ call の先頭 50 件
- アーム A (対照): 記録された toolset をそのまま再送
- アーム B (介入): toolset を差し替えて再送
- 各 3 サンプル、計 300 呼び出し、エラー 0

**アーム A は検証器である。** capture の `unset_parameters` に temperature が
入る (= 未指定) ので選択は揺らぐ。A で元と同じ tool が選ばれる率がこの実験の
信頼性の上限になる。A を測らずに B だけ回すと、差が介入なのか揺らぎなのか
区別できない。

### 介入の内容

| 変更 | 対象 |
|---|---|
| `say_inline` の上限 80 → 200 字 | 既存 8 ツール |
| `say_inline` の説明文を書き換え | 既存 8 ツール |
| `say_inline` を新設 | `wait` / `explore` |
| `speak` の説明に「専用ターンを使う価値がある場合」を追記 | `speak` |

`say_inline` は任意引数のまま (必須にすると「黙って動く」選択を潰す)。
`speak` は消さない (`shout` / `whisper` / target 指定 / 長話は代替できない)。

## 結果

| | A (対照) | B (介入) |
|---|---|---|
| `speak` を選んだ率 | **60.0%** | **33.3%** |
| speak 以外の行動に発話を添えた率 | 1.7% | **15.0%** |
| 世界を変える行動 | 18 (12%) | **39 (26%)** |
| 移動 / 探索 / 世界操作 | 8 / 7 / 3 | 14 / 8 / **17** |
| 発話の総数 (speak + say_inline) | 91 | 65 |
| 呼び出し失敗 | 0 | 0 |

**call 単位の対応比較 (n=50): B で `speak` が減ったのが 27 件、変わらず 18 件、
増えたのが 5 件。** 27 対 5 なので A の再現率 60% という雑音の床を超えている
(符号検定で p ≈ 0.0002。1 call 3 サンプルのクラスタを最悪に見積もっても
z ≈ 2.8)。

## 上限の引き上げは主因ではなかった

B で実際に使われた `say_inline` は **15 件中 12 件が 80 字以内** (中央値 45 字、
最大 98 字)。

**効いたのは説明文の書き換えで、80 → 200 字の緩和はほぼ寄与していない。**
「実際の `speak` 本文は中央値 104 字で 80 字上限には 71% が入らない」という
事前分析は、`speak` として書いた長さから測ったもので、`say_inline` として
書くときに同じ長さを書くとは限らなかった。短く書けるのに `speak` を選んで
いた。

ただし 98 字の 2 件は、**一番価値の高い「段取りの合意」がちょうど 80 字を
超える帯にある**ことを示している。

```
(98字) ノアさん、連絡手段の話が出ましたが、ここは二手に分かれる前に「戻る場所と
       時間の目安」だけ決めておきませんか。例えば「日が昇る頃に一度この浜に
       戻る」とか。
(98字) リオさん、この流木の山はまだ何本か取れそうです。...あとは山頂への道筋が
       まだ分かっていません——何か心当たりはありますか？
```

上限は主因ではないが、この層を可能にしている。**次に検証する人を誤らせない
ため、上限緩和を主因として説明してはいけない。**

## 一番大きい変化: 手分けの宣言が行動と同時になった

B の `say_inline` の中身はほぼすべて手分けの宣言だった。

```
俺は拠点の方を見てくる。枯れ葉が落ちてないか確かめる。残りは森か川方面に分かれて調べたらどうだ。
カイさん、枯れ葉と山頂ルートの下見をお願いします。私は拠点の様子を見てきます。
じゃあ俺は森方面探ってみるわ！枯れ葉あったら拾ってくるし、山頂への道の入口も探してみるね。
森方面で枯れ葉を探す。エイダ、ノア——見つけたら戻る。
干潟はカニが巣食っててまともに探れなかった。貝は取れたが、枯れ葉は見つからずじまいだ。
```

載っている先は `travel_to` 8 件 / `interact` 3 件 / `wait` 2 件 / `use_item`
1 件 / `explore` 1 件。

**これは「宣言が行動の代わりになる」病理を構造的に潰す。** 005 の P4 は
「拠点に戻る」と 3 tick 言い続けて一度も動かなかったが、
`travel_to(say_inline="拠点の方を見てくる")` では宣言が移動に乗っているので、
言った時点で動いている。空宣言ができない。

`wait` に 2 件載ったのも設計意図どおり。「その場に留まって喋る」が表現でき、
かつ行動枠の集計には idle として正しく現れる。

## 限界

- **発話の総数が 91 → 65 で 29% 減った。** 会話が移動したのではなく減っている。
  シナリオは「口に出して共有しない限り仲間には存在しないのと同じ」と明示して
  いるので、これは損失になりえる。B の非 speak 行動 100 件のうち発話を伴った
  のは 15 件で、85 件は黙って動いている。失われた会話が有用だったかは本実験
  では分からない
- **1 ターンの反実仮想なので、発話が同席者を起こして更に発話を呼ぶ増幅の動態は
  出ない。** 増幅率 (004 で 1.94) も `speak` → `speak` (57.7%) も複数ターンの
  相互作用から生じる
- **対象は「実際に喋ることを選んだ call」に絞っている。** 会話に傾きやすい文脈
  だけを見ているので、33.3% が run 全体の `speak` 比率になるわけではない
- prompt 自体が旧体制下で生成されている。`【行動前の状況評価】` などは
  「`say_inline` は付随発話用」という世界で書かれた内省

## 再現方法

```bash
# まず A アームだけで再現率を測る (低コスト)
uv run python scripts/replay_prompt_intervention.py var/runs/v4coop_memo_keep_004 \
    --arm A --limit 30 --samples 3 --out var/replay/a_only.jsonl

# 再現率が使える水準なら A/B 両方
uv run python scripts/replay_prompt_intervention.py var/runs/v4coop_memo_keep_004 \
    --arm both --limit 50 --samples 3 --out var/replay/ab.jsonl
```

300 呼び出しで約 $0.3。200 tick の run 1 本 ($0.28〜0.49) と同程度のコストで、
ツール定義の効果だけを切り出せる。
