## D2229-4. 誰がどの登場人物を動かすかは、遊びの進行の配役 (`Cast`) が持つ

**何を**: Being を新しい世界に入れる遊びの進行 (`play_session`、#2229) を作り、誰がどの登場人物を動かすかの対応表を、遊びの進行のドメインの集約 `Cast` として作り直した。古い `PlayerBeings` は使わない。

### 1. `Cast` が持つもの

| | 決まり |
|---|---|
| ID | 世界 (`WorldId`)。1 つの世界に配役は 1 つ |
| 配役 | 登場人物 (`PersonId`)・Being (`BeingId`)・Being の名前の組 (`CastMember`)。登場人物・Being・名前のどれも重ならない。紹介は名前で渡すので、名前が重なると誰を紹介したかが分からない |
| 入るときの材料 | 登場人物ごとの取り決め (`EnvironmentEntry`) と案内 (`Orientation`)。`brief` で持つ |
| 紹介 | 世界が返した最初から知っている人 (`PersonId`) を、配役の Being の名前にして `Introduction` にする。配役に無い人なら断り、何も持たない |
| 知らせ | `brief` のたびに `BeingCastInWorldEvent` (世界・登場人物・Being・取り決め・案内) をためる。trace への書き出しは実験 (#2233) がする |

例: 廃坑の山村 v2 で、ゲン (`gen`) が知っている人は世界の問い合わせで `sayo` と返る。`Cast` は `sayo` を動かす Being の名前「サヨ」に変え、ゲンの取り決めの紹介を「サヨ」だけにする。

案内と課す目的を `Cast` が持つのは、Being が案内を持たないため。作業記憶 (`CurrentWorkingMemory`) は、環境から毎ターン案内と課す目的を受け取る。遊びの進行がターンを回すとき (#2232) に、`Cast` から渡す。

**採らなかった案**:

- 古い `PlayerBeings` を使う: 古いパッケージの整数の `PlayerId`・古い `WorldId`・古い `AggregateRoot` を使っており、遊びの進行から import すると古いゲームのパッケージへの依存が入る
- 案内を Being に持たせる: Being の契約が変わる。いまの Being は案内を毎ターン受け取る形で、持つ場面が無い

### 2. Being の snapshot には載せない

`Cast` は `BeingId` を値に持つが、キーは世界で、中身は「この遊びで誰が誰を動かしたか」という遊びの持ち物になる。Being が世界をまたいで持ち越す記憶ではないので、Being の snapshot (`BeingMemorySnapshotService`) には配線しない。遊びを止めて再開するときの保存は、遊びの進行の保存として #2232 以降で決める。

**採らなかった案**:

- Being の snapshot に「どの世界の誰を動かしていたか」を載せる: 別の世界に連れて行った Being が、前の世界の配役を持ち続ける。居場所 (`BeingAttachment`) は Being が持つが、それは環境の識別子と表示の名前だけ (D1928-2)

### 3. 遊びの進行は、世界と Being を入口だけで呼ぶ

| 層 | import してよいもの |
|---|---|
| どの層も | 遊びの進行の domain、`eventing`、Being の契約と `BeingId`、世界の ID の値 (`game_world.domain.value_object`) |
| application | さらに、遊びの進行の application、Being の application、世界の application (入口) |
| infrastructure | さらに、遊びの進行の infrastructure、シナリオの読み込み (`game_world.infrastructure.scenario`) |

`tests/architecture/test_play_session_package_import_boundary.py` が層ごとに見張る。シナリオのファイルを読むのは infrastructure の仕事なので、application は `LoadedScenario` も `WorldDesign` も知らない。遊びを始める `StartPlaySession` は、infrastructure が組んだ `OpenWorldCommand` と役 (`Role`) の並びを受け取る。

### 4. 登場人物の名前を、そのまま Being の ID にする

シナリオから役を作るとき (`roles_from_scenario`)、`BeingId` を登場人物の名前と同じにする (`gen` → `BeingId("gen")`)。同じ登場人物を次の run で同じ Being に当てられるようにするため。どの Being をどの登場人物に当てるかを実験の条件で選ぶ場面が出たら、実験 (#2233) が役を組み直す。
