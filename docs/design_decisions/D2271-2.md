## D2271-2. 書き起こしを Being の中で閉じ、裏で書いた分は行動を選ぶ前に入れ、環境を離れるときだけ待つ

**何を**: 新しい世界で、短期記憶の範囲が埋まったときのいきさつとエピソードの書き起こしを動かすための、Being の側の部品を作る (#2271)。遊びの進行への配線は次の PR で行う。調整役とユーザーと決めた。

### 古い run との違い

| | 古い run | 新しい Being |
|---|---|---|
| 書き起こしを始める | 短期記憶の範囲が埋まったイベントで、裏のスレッドで書く | 同じ (`WriteBackstoryHandler` と `WriteEpisodesHandler` をそのまま使う) |
| 書いた分を記憶に入れる | エージェントのターンの入口で、書き終わった分だけ入れる | 同じ。`ChooseAction` の最初で `take_in_finished` を呼ぶ |
| 書きかけを待つ | 待たない。run の終わりに受付を止めて期限まで待つ | 行動を選ぶときは待たない。環境を離れるときだけ、上限の時間まで待つ (`finish`) |
| 環境を離れるときの書き起こし | 裏の書き起こしを待たずに残りを書き、run の終わりに裏の結果を入れる | 裏の書き起こしを待って入れてから、残りを書く |
| 人格の文と環境の名前 | ゲームの側がプレイヤーを走査して引く | Being が自分の人柄と居場所 (`BeingAttachment`) から引く。人格の文は【ペルソナ】と同じ |
| ターンの終わり | 環境が記憶のターン数を渡す | Being が自分の記憶の時計から読む |
| 書けなかったこと | trace に残す | trace (#2233) ができるまで、理由ごとの数を `failures()` で返す |

### 決めたこと

- **行動を選ぶ入口では待たない**。書き起こしが届くまで、出来事は短期記憶から外れない (`end_turn` は範囲が埋まっても出来事を外さない)。待たなくても、エージェントが見られるものは欠けない。1 人ずつ回す進行で待つと、全員のターンが止まる
- **待つのは環境を離れるときだけ**。裏で書いた範囲が記憶に入ってから残りを書かないと、裏の範囲と残りの境目がずれる。上限の時間を過ぎたら待つのをやめ、残りは書き、待ちきれなかったことを返して数える
- **待ちきれなかった書き起こしも捨てない**。上限の時間を過ぎて書き終わったいきさつとエピソードは、組み立てを止める (`shutdown`) ときに記憶に入れる。書いたものを捨てると、その範囲のエピソードは二度と書かれない
- **環境を離れるのは、今は run の終わりに 1 回だけ**。離れたあとの短期記憶と居場所 (`Being.detach`) の決まりはまだ無いので、`LeaveEnvironment` はどちらも変えない。2 回目以降の決まりは、記憶のドメインの Issue で決める
- **人格の文と環境の名前は、Being が自分から引く** (`CircumstancesOfBeings`)。古い世界の人柄は名前と一人称だけで、人格の文は world_character から作っているため、古い世界は今の関数のまま渡す。置き換えると古い run の書き起こしのプロンプトが変わる
- **`EndBeingTurn` は Being の記憶の時計を読む**。環境は記憶のターン数を知らない。古い世界は同じ時計の値を渡していたので、振る舞いは変わらない
- **待つ口は、本人の分だけを待つ** (`AsyncEventExecutor.wait_for`)。結果を入れるのは呼んだスレッドで、記憶を書き換えるのは Being のスレッドだけにする (D1824-15)

### このままでは直らないこと

- 裏で書けなかった範囲のエピソードは、書き直されない。いきさつは遅れのイベントで書き直されるが、エピソードは同じ範囲を 2 回書かないため遅れを受けない (D1824-11)。snapshot を足すときに、書けなかった範囲を覚えるかを決める
