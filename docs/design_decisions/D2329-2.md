## D2329-2. 思い出す件数の上限と重複、目次の切り詰めをドメインの値に置き、思い出す・目次を直すをユースケースに分ける

**何を**: `ChooseAction` が抱えていた思い出す・目次を直すの処理を、ユースケース `RecallEpisodes` / `ReviseEpisodeIndex` (コマンドつき) に分けた (#2329)。調整役と決めた。本人に返す文と短期記憶に残る行は変えない。

| | 前 | 今 |
|---|---|---|
| 一度に思い出せる件数の上限 | application (`ChooseAction` と古い経路の executor) が `len(set(handles))` で数えていた | 値オブジェクト `EpisodeRecallHandles.within(handles, limit=)`。超えたら `EpisodeRecallLimitExceededException` (`BEING.EPISODE_RECALL_LIMIT_EXCEEDED`、上限を持つ) |
| 同じ呼び名の重複 | ドメインの自由関数 `recall_episodes` の中で外していた | `EpisodeRecallHandles` が書かれた順に 1 度だけ持つ。`recall_episodes` はこの値を受ける |
| 目次の文の切り詰め | application の `read_index_revision` が 40 字で切っていた | ファクトリ `EpisodeIndex.fitted(summary=, recall_when=)` が切り、切った項目と切る前の長さを `FittedEpisodeIndex.truncated` に残す。ツールの引数の名前 (`about`) への写しは application がする |
| 目次を直した結果 | 文字列 (`"revised"` など) を比べていた | Enum `EpisodeIndexRevisionResult` (`REVISED`・`REJECTED`・`FAILED`) と `IndexRevisionRejectReason` (`MALFORMED`・`UNKNOWN_HANDLE`)。値は前の文字列のまま |

- 重複を外してから上限と比べる (D1623-2 の「同じ呼び名を重ねて渡したときは 1 件と数える」)。上限を超えたら一部だけ思い出さずに、どれも思い出さない
- 古い経路の `BeingEpisodeRecallToolExecutor` も `EpisodeRecallHandles` を使う。trace (`episode_recall` の `reject_reason: too_many`) は変わらない
- ユースケースの結果の型は `EpisodeRecallAnswer`・`EpisodeIndexRevisionAnswer` とした。`EpisodeIndexRevised` はドメインイベントの名前で使われているため

**関連**: Issue #2329、D1623、D1623-2、D2261、D2329。
