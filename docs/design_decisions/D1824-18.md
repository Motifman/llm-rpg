## D1824-18. いきさつは、非同期のハンドラが書き、ユースケースが短期記憶に入れる

**何を**: 短期記憶のいきさつを書く処理を、CLAUDE.md の「コマンド・ユースケース・ドメインイベント・ハンドラ」に沿って組み直す。

| 種類 | 名前 | 置き場所 | すること |
|---|---|---|---|
| 非同期のハンドラ | `WriteBackstoryHandler` | `being/application/handlers/` | 範囲が埋まった (`ShortTermMemoryRangeFilledEvent`) と、いきさつが遅れている (`ShortTermMemoryBackstoryOverdueEvent`) を受ける |
| コマンドとユースケース | `WriteBackstoryCommand` / `WriteBackstory` | `being/application/write_backstory.py` | 材料からいきさつを書く (LLM を呼ぶ)。記憶には触らない |
| コマンドとユースケース | `AddBackstoryToShortTermMemoryCommand` / `AddBackstoryToShortTermMemory` | `being/application/add_backstory_to_short_term_memory.py` | いきさつを短期記憶に入れて保存する |
| 同期のハンドラ | `RecordShortTermMemoryTraceHandler` | `application/being/handlers/` | 上限で古いターンを外した (`ShortTermMemoryOldestTurnsDroppedEvent`) と、いきさつが入った (`ShortTermMemoryBackstoryAddedEvent`) を trace に残す |

`WriteBackstoryHandler` の 3 つの段 (design_decisions D1824-15):

| 段 | 動くスレッド | すること |
|---|---|---|
| `prepare` | ターンを進めるスレッド | イベントから材料 (まとめる出来事、いちばん新しいいきさつ、範囲の終わり、ターン) を取り出し、本人の名前と人格の文を引いて `WriteBackstoryCommand` を作る |
| `handle` | 裏のスレッド | `WriteBackstory` を呼び、書いたいきさつを `AddBackstoryToShortTermMemoryCommand` にして返す |
| `apply` | その Being のターンの始め | `AddBackstoryToShortTermMemory` を呼ぶ |

- 本人の名前と人格の文は、Being の `Persona` に移すまで (#1469)、ゲームの側がプレイヤーを走査して引く関数をハンドラに渡す。Being のパッケージはゲームを import できないため。保存先を走査するので `prepare` で呼ぶ
- 引けないとき (どのプレイヤーにも結びつかない Being) は、`prepare_failed` として `async_event_delivery_failed` に残る
- いきさつが入ったことの trace は、今までどおり `being_backstory_written` の種類で残す。trace の種類の名前は保存済みの trace と合わせるため変えない。外した出来事の数 (`dropped_count`) を足した
- `RecordShortTermMemoryTraceHandler` は、2 つのイベントを trace の記録に訳すために、イベントの型で分ける。ドメインの規則ではなく、外への出し方の違いなので、application の側に置いた
- 消したもの:
  - 前のハンドラ `BeingBackstoryWriting` と、名前と性格を先に引いて取っておく `note_person`
  - trace のハンドラ `ShortTermMemoryEventTraces`
  - `AsyncDelivery` と、配送器の `asynchronous=` 引数 (使う箇所が無くなった)
- `AsyncEventExecutor.submit` は残した。本番では呼ぶ箇所が無いが、実行の仕組み (宛先ごとの順序、受付の上限、終了) の試験が使っている

**なぜ**: いきさつを書く処理は、名前と性格を引く、書く、記憶に入れる、trace に残す、を 1 つのクラスと 2 つの登録に分けて持っていた。CLAUDE.md の決まりに沿って、ハンドラはイベントからコマンドを作ってユースケースを呼ぶだけにし、記憶を変えるのはユースケースと集約に置く。trace に残すことは、ドメインイベント (いきさつが入った) を受ける別のハンドラにする。いきさつを書く処理が trace のことを知らずに済む。

**まだしないこと**: `end_turn` はまだ誰も呼ばないので、run ではいきさつは書かれない。エピソードを書くハンドラ (`WriteEpisodesHandler`) は次の PR。
