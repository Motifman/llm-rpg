## D2029. ステージ 4 の設計を、実装役の論点から見直す

**何を**: ステージ 4 (#2023〜#2026) の実装役 4 人から、設計の文書では決まらない点・食い違う点が 40 件ほど出た。4 本を止め、原因ごとに束ねて設計を直した。経緯の質問と回答は #2029 のコメントにある。D2022 で決めたことのうち、偶然の機会 (`ChanceOccasion`、`ConditionPath` / `EffectPath` を位置に使う形) と、`WorldFacts` を質問ごとのメソッドで並べる形は、ここで置き換える。

| 論点 | 決めたこと |
|---|---|
| 偶然を引く位置 (A1) | 「同じきっかけ・tick・位置なら同じ値」という決まりは持たない。求めていたのはテストが flaky にならないことだけ。偶然は `RandomSource` から順に引き、本番はふつうの乱数、テストは決めた値を順に返す。`ChanceOccasion` と、偶然のための位置は外す |
| 世界を読む窓口 (A2) | `WorldFacts` は集約ごとに、問い合わせだけを持つ型 (`...Reading`) を返す入口にする。ロジックを持たない。条件は集約に直接たずね、2 つの集約を組み合わせる処理は使う条件の中に書く。質問ごとにメソッドを並べる形は、集約の問い合わせを写し忘れるたびに足りなくなり、組み合わせの処理が窓口に溜まって神クラスに向かう |
| 理由の文の人の呼び方 (A3) | プレースホルダーに `PersonId` を当てただけの `TextAboutPeople` を足す。見る人ごとの呼び方 (`PersonRef`) は、見る人が分かる場所で当てる。同じ理由や出来事を、行った人と見ていた人が別の呼び方で見るため |
| 作者のいない文 (B1) | ドメインに決まった文を持たない。作者の条件は根に `failure_text` を必ず書く。共通の決まりと集約の断りは、シナリオの断りの文の表 (`RefusalTexts`) に書き、既定の表はデータとして取り込む |
| 伏せた所属 (B2) | 行う人が知りうること (`EVERYONE`、自分の `SELF_ONLY`、`members_know_each_other` の仲間) だけで一覧と理由を決める。知りえない所属に頼る前提は一覧で「できる」と出し、試したときに理由を言わずに断る。compose は `DesignWarning` で作者に知らせる |
| 行為ごとの性質 (C) | 行為の型自身が `exertion`・`can_start_while_busy`・`copresence_requirements`・`actor_requirement`・`is_allowed_in` を答える。組み込みの行為の値は action.md の表 |
| 何をするかの書かれていない効果と条件 (D) | effect.md と condition.md の各行のとおり。倒れた理由はきっかけが `fall_cause_for` で答える。新しい品物は `WorldAggregates.bring_item_into_world` で作り、ID は uuid |
| 中身の無い型 (E) | 操作の宣言に `arguments` を足す。宣言の型は既定値を持たず、「書かなければ」は読み込む側が埋める |
| 分け方 (F) | 複数の PR が待つ型は土台に入れ、土台 (約束 / 集約と規則) を先に入れてから中身の 4 本を並べる |

**文書を通して確かめて足したこと**: 作る型ごとに何を受け取り何を読むかを文書の上でたどり、次を足した。

- `WorldFacts.nouns()`: 共通の前提が、区画の中から届く物を確かめるのに、物と区画の宣言が要る
- きっかけの `argument(name)`: `ArgumentEqualsCondition` と `WriteTextEffect` が引数を読む
- きっかけの `acting_person()`: 伏せた所属を判断するとき、行う人がいるきっかけかを例外に頼らずに知る。`fall_cause_for` もこれを使う
- 暗がりの誰かを選べるかは、明るさ (ステージ 5) が要るので、共通の前提ではなく、行為を行うユースケース (ステージ 7) が確かめる
- 人の居場所を問う条件と効果は、去った人として動いていれば `DepartedPerson`、それ以外は `PersonBody` を見る

**関連**: Issue #2029、#1978、D2022。
