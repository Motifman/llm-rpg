# ショップのスポットによる場所判定（#1862）

## テストリスト

- [x] 同じスポットでは座標・物理マップなしで購入できる。
- [x] 別スポット・未配置・プレイヤー未取得では場所の例外になる。
- [x] 座標の有無は場所判定に影響しない。
- [x] 開設・施設の重複拒否・出品・全部購入・部分購入・在庫不足・資金不足の既存規則を維持する。
- [x] smoke_stub と2シナリオ×3シード×40tickの前後で観測種別別件数・行動件数が一致する。

## 確認範囲

ショップは本番の実験経路に未接続であり、本番の質感の改善は主張しない。購入の場所条件だけを既存スポットに合わせる。施設割当の location_area_id と保存形式は維持する。

## 参照解析と設計の選択

`rg` とPythonの構文木で `ShopCommandService` の構築と読み込みを確認した。構築は専用試験だけで、サービスの再公開は維持する。ショップのコードと専用試験から `PhysicalMapRepository`・`PhysicalMapAggregate`・`LocationArea`・`Tile`・`PointArea`・物理マップの保存先の参照を外す。モジュール本体は他範囲で使うので削除しない。

目的の選択は、購入をスポットの一致で許す案を採用する（検討時点: 実装前）。座標への依存が消える一方、同じスポット内の店舗間で位置を区別しなくなる。タイルの領域判定を残す案は細かい位置を区別できるが、削除予定の世界を要求する。場所IDの設計を変える案は統一できるが、DBまで波及するため今回の対象外とする。コード上は既存の判定メソッドと状態の保存先を使い、新しいモデルや注入は作らない。

## 検証

変更前の試験は6件失敗・22件成功。座標や物理マップがないため購入が拒否されることを確認した。変更後はショップのアプリケーション・ドメインと施設割当の関連107件が成功した。全部購入を座標なし・任意の座標の両方で確かめ、場所の拒否は別スポット・未配置・状態未取得をそれぞれ確認した。

比較型の実験は `smoke_stub`、既定の `survival_island_v3_coop`、2tick、スタブで実行。解決済み設定を確認し、観測・行動は前後とも0件、全trace種別別件数が一致した。この短い実験だけでは同等性を判断せず、廃坑の山村と避難訓練を各シード0〜2・40tickで確認した。通常の `make fuzz-scenario` と同じ実行関数の一時的な記録収集を使い、観測種別別件数・行動件数・全trace種別別件数が全6条件で一致、検出事項0件。行動件数は山村142/139/145、避難訓練301/199/279、観測件数は山村92/127/84、避難訓練531/497/659。座標の判定変更は専用試験で確かめており、この比較から未接続のショップの体験まで同等とは主張しない。

作業ツリーに `.env` を置かず、一時 `sitecustomize` で `dotenv.load_dotenv` を無効化して実行した。比較対象は変更前のソースと変更後のソース。実LLMは呼ばない。変更したPythonファイルのruffと、mypy（1,502ファイル）が成功。独立レビューは CRITICAL/HIGH/MEDIUM/LOW 全て0件。

## 質感の所見

本番の人物が見る観測は変わっていない。休眠中のショップでは、スポットに居る購入者がタイルの座標を持たないために拒否される条件を取り除いた。同じスポット内の細かな店舗位置は区別しなくなる。売り手の所有権、支払い、品物と在庫の動きは従来どおり。ショップをシナリオへ接続した世界での体験は今回未確認であり、今後の接続時に見る。
