# モンスター集約試験の所有範囲

- 値オブジェクトの算術・値域はその所有試験で扱い、集約では公開入口の生存判定、入力の受渡し、状態の代入、通知生成を検査する。同名だけで層の重複と決めない
- 拒否条件や無操作の試験では、既定値に含まれる別の無効条件が対象ガードの欠落を隠さないか確認する。隠す場合は条件を独立させた入力を加え、元の既定入力も残す
- 容量・順序・対象と座標の組を守るときは、製品定数や対象の計算関数に追従する期待値を使わない。固定値には公開仕様や履歴の根拠を残す
- 引数として渡した値を使う契約では、素の値と異なる入力を使う。HPとMPの取り違えを確かめる場合は、期待増分も異なる値にする
- 状態を変える前提操作と検査対象を区別する。死亡後の要求を検査するときは、死亡処理完了後・要求直前を比較起点にする。無関係な全状態の原子性を推測して追加しない
- `get_events()` の検査は集約内の未配信通知列の検査である。配送や観測への到達は、実際の配送経路を通す所有試験に委ねる
- 表へ統合するときは元の入力・例外型・確認式を先に保持先へ移す。移管元を残した段階が成功してから旧宣言を除去する
- 短い正常系・専用例外・既定値の試験も、独立した公開契約を守るなら残す。削除件数を目標にしない
- 試験を持つクラスから別の試験クラスを継承しない。準備だけを共有し、既存試験を二重収集させない

栄養・資源21宣言の具体的な判断と履歴は `docs/test_audits/monster_aggregate_nutrition_resources.md` を参照する。行動・追跡と状態効果の先行監査文書も、各契約の保持先を記録している。
