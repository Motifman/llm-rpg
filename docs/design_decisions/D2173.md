## D2173. 二人で合わせる操作の帳簿と、揃う・時間切れの規則

**何を**: 二人で合わせる操作 (`JointActionDeclaration`) の、誰がどの部分をいつ行ったかを覚える帳簿を `ScenarioProgress` に作り、揃った・時間切れの規則とドメインイベントを足した (#2173、親 #1978)。D2027 で「使うユースケースの Issue で作る」と先送りしたものを、ユースケース (#2149) の中で決めないよう、ドメインを先に作る。配線 (行為の共通の流れから書く、`SettleWorldConditions` から発火する、知らせを刺激に変える) は #2175 で行う。

例はすべて「梃子」: 部分が (左の梃子, 押す) と (右の梃子, 押す)、窓が 2 tick、`distinct_people` あり。

| 決めたこと | 例 |
|---|---|
| 最初の一押しの tick を起点に、起点 〜 起点 + 窓 のあいだに全部の部分が埋まれば揃った。窓を過ぎたら時間切れ。どちらでも落ち着かせると帳簿を空に戻し、次の一押しから数え直す | ハルが tick 5 に左、ナツが tick 7 に右 → tick 7 に揃う。ナツが tick 8 に右 → tick 8 には時間切れが先に起き、ナツの一押しは新しい試みの 1 つ目になる |
| 部分ごとに、最後に行った人を覚える。`distinct_people` なら、覚えている人が全員違うときだけ揃う | ハルが左、続けてハルが右 → 揃わない。そこへナツが右 → 右がナツに替わって揃う。ナツが左でも、左がナツに替わって揃う |
| 押し直しても窓は延ばさない | ハルが tick 5 と tick 7 に左 → 起点は tick 5 のままで、tick 8 に時間切れ |
| 帳簿は `ScenarioProgress` に置く。部分を行ったことを書く口 (`note_joint_action_part_done`) は試みと宣言を受け取り、どの宣言のどの部分に当たるかを帳簿が決める。外から部分を渡す口は持たない | 1 つの一押しが 2 つの宣言の部分に当たれば、両方に書く |
| 1 回の落ち着かせで、同じ操作は揃いか時間切れのどちらか 1 回まで | 落ち着かせると帳簿が空になるので、同じ tick にもう一度問うと `UNDECIDED` を返す |

**実装で決めたこと**:

- 試みがどの物体のどの操作かは `ActionAttempt.operates(obj, interaction)` に聞く。物体の操作 (`ObjectInteractionAttempt`) だけが自分の物体と操作に真を返す。帳簿が試みの型を見分けないため
- 問い合わせ `joint_action_settlement(joint, now)` は `JointActionSettlement` (`COMPLETED` / `TIMED_OUT` / `UNDECIDED`) を返し、当てる効果は `effect_in(joint)` が選ぶ。配線が揃いか時間切れかで分岐しないため
- 全部の部分が埋まっていれば、窓を過ぎた tick に問われても揃いを返す。部分は窓の中でしか書けないので、埋まっていれば窓の中で揃っている
- 揃いか時間切れが落ち着いていないうちに次の部分を書こうとすると `JointActionUnsettledException`。時間を進めたあとの落ち着かせが同じ tick の行為より先に走るので、起きれば配線の誤り。黙って混ぜると効果を当てないまま次の試みになる
- 揃っても時間切れでもないのに落ち着かせると `JointActionNotSettlingException`
- 揃った・時間切れのイベント (`JointActionCompletedEvent` / `JointActionTimedOutEvent`) は、出来事と同じく知らせの相手 (`audience`) と断った理由 (`refusal`) を持ち、断られたら相手を空にする。trace で誰がどの部分を行ったかが分かるよう、部分を行った人 (`parts_done`) も載せる
- 保存の形の版を 1 から 2 に上げた (persistence.md の決まりどおり、古い形からの変換は作らない)

**採らなかった案**:

- 最初に行った人を覚える: 1 人目が両方の部分を押すと、窓が過ぎるまで誰が押しても揃わなくなる
- 1 人で 2 つ目の部分を行う行為そのものを断る: 梃子の操作自体が動かなくなり、ほかの案と性質が違う
- `LatestActions` を見て揃いを決める: (人, 操作) → 最後の tick しか持たず、左右の梃子の「押す」を区別できない
