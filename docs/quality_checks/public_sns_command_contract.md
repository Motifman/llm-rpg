# 公開SNSの投稿と通知の確定契約

## ねらい

公開された対象に返信し、その直接の親の返信数と本文付き通知までを一つの操作として保存する。
操作を失敗させたときに返信だけ残ること、確定前に相手へ本文が届くことを防ぐ。
新しい入口は `PublicSnsCommandService.publish` で、隔離中の旧 `PostCommandService` と
`ReplyCommandService` は呼び出さない。

## 契約

- 投稿・返信は常に公開。対象の不在、削除、非公開、祖先の破損、双方向ブロック、別の保存領域は同じ取得不能応答にする
- 親と作者は保存済みの不変IDで検査する。閲覧可能な最大の深さへ、読めない子を作らない
- メンションは重複し得る表示名から推測せず、本文の `@user_name` を一意なアカウント名として解決する。返信先と同じ宛先は一件にまとめ、本人への通知を除く
- 両保存方式で、投稿・直接の親の返信数・通知・採番を同じ `CommandScope` で確定する。インメモリは排他と全状態復元の対象へ即時適用し、SQLは同一接続へ書き込む
- 確定前は通知本文を外部へ渡さない。通知は本文を切り詰めず保存し、確定後に現在の公開条件を再検査する
- 配送失敗は `CommandPostCommitException` と確定済み結果を返し、非冪等な投稿のやり直しを促さない。保存済み通知は `retry_pending_notifications` で再送できる
- 再送は少なくとも一回になる可能性がある。受信側は通知の不変IDで重複適用を防ぎ、成功後の配送状態だけを別の確定境界で更新する
- 受信イベントは発生時の人・対象・実行要求の識別情報を保持する。旧フォロー・いいね型もこの情報があるものだけ取り込む。整数IDしかない旧イベントを現在の人や本文へ結び直さない
- 初期の自動通知は、実行層で `schedules_turn=False` にする。表示の総予算と重複抑止は実行層の責務とし、本文のあふれは永続受信箱で回復できる

## 試験

`tests/application/social/public_sns/test_public_sns_command_service.py` の共通試験をインメモリとSQLiteに適用する。
投稿・返信・孫返信、親更新、本文と不変ID、非公開・祖先・双方向ブロック、同期処理失敗、確定失敗、
確定後配送失敗と再起動相当の再送、発生時出典、イベント再投入、既存集約からのフォロー・いいね、
解除への非通知、同じ整数IDへの置換、別保存領域、表示名重複、閉じた確定境界、本文検証を含む。

## 質感の確認

相手の通知から返信先の不変IDと返信全文を受け取れるため、通知が届くたびに同じスレッドを開き直す必要を減らせる。
一方、届く時点で公開されていない祖先があるときは、その本文も存在理由も知らせない。
配送先の一時停止で投稿を繰り返させず、保存した受信箱と発生時の出典から復旧する。
実LLMを使う実験は行っておらず、この段階の確認は保存・配送境界の決定的な試験に限定する。


## 一部の配送先が停止した場合の確認

一人への配送が失敗しても、同じ投稿を読める別の相手への通知は届く。
停止が長引いて未配送通知が100件を超えても、一度の再送件数を増やさずに後続へ進み、
復旧した相手へは保存済み通知から戻って届ける。成功した宛先へ同じ通知を重ねないことと、
投稿自体は確定済みであることを、両保存方式の共通試験で確認した。
