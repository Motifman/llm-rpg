# 箱・扉の相互作用試験の所有範囲

> 過去の試験監査（2026-10-25追記、Issue #1862）。削除済みのタイルマップ・当たり判定に関する実装や試験の記述を含む。
> 本文の呼出元・保持先・件数は監査当時の記録で、現在の保証ではない。現存する領域もあるため一括して退役とは扱わない。[世界の現在の構成](../game/world_architecture.md)を参照。

## なぜ

物理地図の箱・扉に属する4ファイル55宣言を、試験本体、製品所有者、呼出元、履歴、関連試験まで読み直した。
箱の空初期化と正しい向きでの相互作用成功には、同じ責務の準備が別の宣言に重複していた。

箱は開状態の省略と明示False、相互作用は対象データありと省略という入力差がある。
単に片方を削ると元入力が失われるため、同じファイルの保持先へ2つの入力を先に移してから重複宣言を除いた。
新しい製品不具合の修理や、既存試験が見逃した退行の補強ではない。検出力と元入力を保ったまま準備を一か所へまとめる。

## 統合した入力と保持先

### 箱の空初期化

`TestCreation.test_creation_empty_item_ids_default`を同クラスの`test_default_creation`へ統合した。

- `ChestComponent()`を空の引数辞書で再現する
- `ChestComponent(is_open=False)`をFalseを明示する引数辞書で再現する
- 両行で品目一覧が空であることを検査する
- 元の省略入力が検査した閉状態と型名も保持する

現実装が省略と明示Falseを別分岐で処理する、という主張ではない。元から存在した2つの呼出入力を保つ。

### 正しい向きでの相互作用

`TestDirection.test_passes_when_facing_correct_direction`を`TestSuccessCases.test_adjacent_facing_target_succeeds`へ統合した。

- `InteractableComponent("talk", {"name": "Bob"})`と`InteractableComponent("talk")`を別表行にする
- 省略したデータ引数を明示した空辞書へ置き換えない
- actor1=(0,0,0)・南向き、NPC2=(0,1,0)、現在tick10を保持する
- 両行とも検証が例外なく終わることを確認する

検証関数の成功は例外なく戻ること自体が期待結果である。assert文がないという外形を削除理由にはしない。

## 変えずに保持した責務

箱・扉の構築、既定値、公開getter、操作種別、所要時間、辞書出力は残した。
開閉、施錠拒否、解錠後操作、品目追加、重複拒否、最終一品の除去、複数品からの選択除去、不在品の除去も、入口や入力が異なる契約として残した。
直接の製品呼出が少ない公開open/closeなどを、その事実だけで廃止しない。

政策は距離・向き・busy・箱/操作能力の条件を所有する。同座標、斜め隣接、期限経過、componentなし、componentはあるが操作能力なしを保持した。
集約はID解決後に政策へ届く接続、実効果、通知蓄積、busyを所有する。アプリケーションは自動で向き直ること、保存、インベントリ連携を所有する。

[6f76228](https://github.com/Motifman/llm-rpg/commit/6f7622870e259650400296b630f60c8e4fbdc038)では政策抽出と同時にstore/takeのbusy検証漏れが修理された。
政策単体の条件検査は、呼出元が政策を実際に通すことの代わりにならない。
[c1b3476](https://github.com/Motifman/llm-rpg/commit/c1b34769a7a79185d12e460fdabe34c667609189)で導入された検証済み箱の返値は、実store/takeと関連試験が使っている。
政策単体に返値の断言がないだけでは修正対象にしなかった。

## mockを使う効果試験の限界

箱のapply試験は実際の開閉効果と余分な通知ゼロ、扉のapply試験は指定対象への遮蔽解除要求と通知1件を保持する。
施錠中のapply試験は、この公開効果入口自身の拒否と通知抑止を保持する。集約側は例外伝播後に共通成功通知やbusyを作らないことを別途検査する。

扉のmockはset_blockingでis_blockingを更新せず、通知の型・識別子・値を検査していない。その内容を保証する試験だとは説明しない。
実WorldObjectの遮蔽解除は既存の集約試験がすでに検査している。通知値の未検査だけを理由に新たな補強や型専用の変異を追加しなかった。

get_object未呼出は、単独では独立した公開契約と確認できなかった。これを全副作用なしや扉状態不変の証明、一般的な設計規則には格上げしない。
元の有効な契約を含む試験全体は保持し、今回はその断言だけの整理も行わない。

## 基準・保存確認

遠隔main `ba942f5a9cad4b6d362c9e2ce59566cc8ce3396f`に対応する固定作業木で、Python3.10.22 / pytest8.4.1を使用した。
実行ごとに対象作業木のsrcを確認し、秘密環境変数の除去、通信遮断、offline、専有する新規JUnit出力を適用した。
独立した第二読が全55宣言、保持先、履歴、基準ハッシュを確認してから編集した。

- 未編集の所有55件・関連43件: 全成功
- 元宣言を残した保持先先行移管: 57件成功
- 重複2宣言を除いた所有範囲: 53宣言・55実行、全成功
- 箱の既定品目へ余分なIDを混入する変異: 元2入力・新2表行の双方が空一覧の断言で失敗
- 正しい向きを誤って拒否する変異: 元2入力・新2表行の双方が意図した向き例外で失敗
- 各変異後に製品を元のバイト列へ復元。全3製品所有ファイルの元SHA-256と一致
- 完全復元後の所有55件・関連43件: 一意な98件が全成功
- 変更試験2ファイルのRuff0.16.8、`git diff --check`: 成功

変異は元入力の検出力保存を確かめる対照であり、旧試験全体が見逃していた退行を新たに検出した結果ではない。
最初のRuff実行は指定先に実行物がなく起動できなかったため、既存のRuff0.16.8を使い直して成功を確認した。
全リポジトリの試験・型検査・遠隔CIは、この局所検証には含まれない。
