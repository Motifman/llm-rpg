## D1982. game_world の音の値で、文書から決まらなかったこと

**何を**: 音の届き方の値 (`SoundLevel`、`SoundLoss`、`SoundLink`、`SoundNetwork.spread`、`SoundReach`、`Loudness`、`HearingQuality`、`HearingValues`) を `game_world/domain/sound/` に、`SpotId` を `game_world/domain/value_object/` に作った。設計の文書 (`docs/environment_model/design/`) から決まらなかったものは調整役と次のように決め、文書も合わせて直した。

| 何を | 決めたこと | なぜ |
|---|---|---|
| `SpotId` の置き場所 | `value_object/` | 設計図、世界の状態、条件でも使う識別子で、音のものではない |
| `SpotId` の中身 | シナリオが宣言した場所の名前 (空でない str) | 名前から連番の数を振る `ScenarioIdMapper` を新しい世界で持たず、trace でも読めるようにする |
| `SoundLevel` の範囲 | 0 以上。`weakened_by` は 0 で止まる | `HitPoints.damaged_by` と同じ形。負の大きさに意味が無い |
| `quietest_audible` | `faint_from − attentive_allowance` (0 で止まる) | `spread` の `stop_below` に渡すので、耳を澄ました人を含めないと、その人に届く音が途中で切られる |
| 耳を澄ましたときの境目 | はっきり・くぐもる・かすかの 3 つをすべて `attentive_allowance` だけ下げる | 「15 だけ小さい音まで聞こえる」を、届いた大きさに 15 足して境目と比べるのと同じ意味と読む |
| `HearingValues` の不変条件 | `loudness` が 4 段階すべてを持ち、`clear_from ≥ muffled_from ≥ faint_from` でなければ作れない | 設定の食い違いを、作るとき (シナリオの読み込み) に止める |
| 元の大きさが下限を下回るとき | 音の鳴った場所も `SoundReach` に入れない | 「聞こえる下限を下回ったら広げない」を、鳴った場所にも同じく当てる |
| `SoundLink` の向き | 持たない。どちらの端で鳴った音も反対の端へ届く | 文書の型に向きの欄が無い。片側だけ通れる通路 (`two_way` が偽) の音を `SoundLink` にどう写すかは、`SoundNetwork.through` と一緒に決める |

**関連**: Issue #1982、#1978、D1979。
