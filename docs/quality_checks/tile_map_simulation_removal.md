# 旧タイルのシミュレーション削除の確認

Issue #1862 の変更範囲4。新しい行動や観測は追加しない。
スポットのグラフでのモンスター行動、空腹、温度、標的選択、
状態異常、天候、時刻の処理を残し、本番で構築されない旧時間進行だけを消す。

## 検証する条件

- [x] 削除前に AST で製品コードと試験の import を調べ、型参照と再公開も確認する。
- [x] 旧シミュレーションの共有補助は専用試験1本だけの利用と確かめる。
- [x] 削除後、削除したモジュール名が src/tests に残らない。
- [x] 残す移動・追跡、モンスター、スポット、本番構築、構造検査を含む関連試験が通る。
- [x] smoke_stub の前後で全記録種別の件数が一致する。
- [x] 山村と避難訓練を各シード0〜2・40tickで実行し、全記録種別・観測種別ごとの件数と行動件数が一致する。
- [x] 独立レビューで巻き添えの削除がないことを点検する。

比較用のスタブ実験は、作業ツリーに .env がない状態で、
検証専用の sitecustomize から dotenv.load_dotenv を無効にして実行する。
実 LLM は呼ばない。数値の一致だけでは長期の質感までは保証できないため、
長時間の実 LLM 実験は今回の確認範囲に含めない。

## 質感の所見

本番のモンスターや環境の処理は差分に含まれず、エージェントに届く
観測文と手番を起こす規則も変えない。削除したのは別の物理マップで
進む未接続の処理であり、世界内で知覚できる変化は意図していない。
残した本番処理の関連試験と低コストの記録比較で、その維持を点検する。

## 実行結果

関連試験は2,272件成功し、移した試験を含む2ファイル37件も成功した（重複なしで計2,309件）。変更したPythonファイルのruff検査と、
mypyの1,448ファイルの型検査も成功した。
削除した30製品ファイルのモジュール名は、src/testsの文字列検索で0件だった。
ASTでの削除前の候補外参照は、製品コードが再公開1ファイル、
試験が削除した旧試験・補助24ファイルだけだった。
ただしその旧試験には残す追跡継続7件と当たり判定の重複排除1件があり、
独立レビューの指摘を受け、それぞれの専用試験へ移して保証を残した。

smoke_stubは既定の無人島シナリオ・2tick・stubで前後とも成功し、
全記録種別の件数が一致した。観測と行動は0件なので、
これだけでは効果の比較に使わず、以下の40tickの比較も行った。

| シナリオ | シード | 行動件数（前後共通） | 観測件数（前後共通） |
| --- | --- | ---: | ---: |
| mine_village_v1 | 0 | 142 | 92 |
| mine_village_v1 | 1 | 139 | 127 |
| mine_village_v1 | 2 | 145 | 84 |
| station_drill | 0 | 301 | 531 |
| station_drill | 1 | 199 | 497 |
| station_drill | 2 | 279 | 659 |

全6試行で例外・検出事項0件。全記録種別・観測種別ごとの件数が前後で一致した。
通常のfuzzコマンドに加えて、同じrun_random_agentsの
NullTraceRecorder.recordを検証専用スクリプトで収集して比べた。
山村ではモンスター出現・遭遇・攻撃と時刻変化の観測も一致している。
この条件では知覚できる変化は見つからなかった。

独立レビューは初回 CRITICAL 0 / HIGH 0 / MEDIUM 2 / LOW 0。
上記8件の移動後は全て0件となり、試験本体のASTも移動前と一致した。
