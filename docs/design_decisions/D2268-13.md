## D2268-13. 自分で書く値は、何を書くかを【現在選べる対象引数】で案内する

**何を**: 操作が自分で書く値 (金庫のダイヤルの番号など) を求めるとき、【現在選べる対象引数】にその値の行を足し、何を書くかを案内する (#2268 の 5 本目、ユーザーが決めた案 A)。

```
- interact.target: "金庫"
- interact.how ("金庫"): "番号を合わせて金庫を開ける"
- interact.details.code ("番号を合わせて金庫を開ける"): 金庫の番号を書く
```

| | 新しい世界 | 古い run との違いと理由 |
|---|---|---|
| 案内の置き場所 | 【現在選べる対象引数】の、候補の行と同じ形の 1 行。どの操作の下の値かを `("…")` で添える | 違う。古い run は操作の案内に「持ち物を奪う (奪う品の名前を item に書く) → "pickpocket"」と書いていた。新しい世界は操作の案内を出さないので、候補のある引数を探すのと同じ節に置く (ユーザーが決めた) |
| 何を書くか | シナリオの引数の宣言に書く (`arguments: { code: { text: 金庫の番号 } }`)。`text` とだけは書けず、読み込みで断る | 古い run は操作の表示名に書き込んでいた。表示名に混ぜると、候補として書き写す文字に案内が混ざる |
| 話す中身 (`speak.content`) | 案内を出さない | 同じ。ツールの引数の説明「中身」で、自分で書くことが分かる |
| 品物の引数 | これまでどおり候補の行に出す | 同じ |

- 案内の言葉が無いとき、自分で書く値は【現在選べる対象引数】に 1 行も出ず、ツールの説明も details を「操作が求める引数。」としか書いていなかった。LLM はその操作に書く値が要ることを知る手段が無かった
- 契約の自由に書く値 (`FreeText`) に、何を書くかの欄 (`writes`) を足した。案内の要らない値 (話す中身) は持たない。「を書く」の言い回しは、表を組む Being が持つ
- 組み込みの引数 (話す中身など) は世界のコードで宣言するので、何を書くかの欄を持たせていない
