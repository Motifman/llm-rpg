## D2268-5. 入るときの案内を、古い run と同じ【世界の前提】1 つにする

**何を**: 古い run のシステムプロンプトの【世界の前提】を、新しい世界の入るときの案内 (`BriefEnteringPerson` の orientation) で再現する (#2268 の 3 本目)。D2268 の 2 節で決めた題名と締め切りを、ここで作る。

古い run (mine_v1_002、ゲン):
```
【世界の前提】
- 舞台のタイトル: 廃坑の山村
- 概要: 冬が近い山あいの廃村。…聞いている。

坑道の中は光が無いと何も見えない。…かもしれない。

【この場所の造り】
  北の竪坑口 (明るい) → …
- 行動の制限: この局面で取りうる自発的な行動（…）の総量には限りがあり、…
```

| | 決まり | 古い run との違いと理由 |
|---|---|---|
| 区画 | 案内は見出し「世界の前提」の説明 1 つ。それまでの【この世界について】【この世界の前提】【この場所の造り】の 3 つをまとめる | 同じ |
| 題名 | `- 舞台のタイトル: {題名}`。題名はシナリオの導入の `title` (必須) | 同じ。古い run は metadata の題名 |
| 概要 | `- 概要: {導入の文}`。段落の空行はそのまま | 同じ |
| 前提 | 導入の `premises` を書いた世界だけ、概要のあとに行のまま並べる。書かなければ何も出さない | 山村 v2 は書かない (ユーザーが決めた)。古い run に前提の行は無く、同じ文にするため。欄は、作者が全員に同じ前提を書く場所として残す |
| 地図 | 地図を見せる世界だけ、空行のあとに `【この場所の造り】` の行と地図 (D2268-2) を続ける | 同じ。見出しは区画の見出しではなく本文の 1 行として書く。古い run も【世界の前提】の中に入れていた |
| 行動の制限 | 結末の条件 (`ending.ends_when`) が世界の時刻を読む世界だけ、最後に `- 行動の制限: …` を出す。文は古い run と同じ | 古い run は手書きの旗 (`metadata.limits_actions`) で出していた。山村 v2 は全員の結末が決まったら終わり、時間では終わらないので出ない。手本 (mine_v1_002) は旗で出していたので、ここは違う |

- 締め切りの有無は、条件の要件 (`Requirements.reads_world_tick`) で決める。何 tick 目に達したか (`TickAtLeastCondition`) と、段階に入ってから何 tick 経ったか (`TicksInWorldStageAtLeastCondition`) が真にする。時刻帯 (朝になったら) は、行動の総量の締め切りではないので数えない。結末の宣言が `has_deadline` で答える。見るのは結末の条件の木の中の時刻の条件だけで、時刻で立つ旗を結末が待つ形 (できごとが 40 tick 目に旗を立て、結末はその旗を見る) は締め切りとして数えない。そういう世界を作るときは、結末の条件に時刻の条件を直接書く
- 言い回し (見出し、題名・概要の行、地図の見出しの行、行動の制限の文) は共通の部品 `ja_default.yaml` の `briefing_headings` に置く。題名と概要の行は、埋める値をちょうど書いているかを読み込みで確かめる
- 知っていることは、D2267 で Being の【ペルソナ】へ移った。案内には入らない
