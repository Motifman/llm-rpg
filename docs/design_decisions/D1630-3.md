## D1630-3. 毎ターンのプロンプトを作業記憶から組み、ゲームの側の並べる処理を消す

**何を**: #1630 (作業記憶) の移し方の 3 本目。プロンプトは 1 文字も変えていない。

- `DefaultPromptBuilder.build` は、環境の材料 (案内、場面、課された目的、締めの一文、繰り返しの警告) を集め、`CurrentWorkingMemory` で作業記憶を組み、その文をシステムプロンプトとメッセージにする。区画の中身と並びは作業記憶が決める
- 出すツールが決まって候補表を差し込むときは (`inject_dynamic_argument_candidate_table`)、場面を差し替えた作業記憶 (`WorkingMemory.with_scene`) から文を組み直す
- 消したもの
  - `context_format_strategy.py` (`SectionBasedContextFormatStrategy`、`_emit_*`) と `IContextFormatStrategy`
  - システムプロンプトを組む口 (`ISystemPromptBuilder`、`SystemPromptPlayerInfoDto`、`WorldSystemPromptBuilder`、`WorldProfileRepositoryAdapter`)
  - 配線されていなかった口 (`inventory_text_provider`、`persona_block_provider`)
  - 区画の本文を作る provider (知っている人、目次、メモ、直近の出来事、いきさつ) と、それを返していた `WorldRuntime` のメソッド (`being_memo_text`、`being_recent_events_text`、`being_backstory_text`、`episode_index_text`)。作業記憶が Being の保存先から直接集める
  - 2 本目の、今の組み立てと作業記憶の組み立てを並べて比べる試験と `WorldRuntime.working_memory_for`。今の組み立てが無くなったので、比べる相手を切り替える前の main で書いた資料にした (下)
- `WorldRuntime.build_system_prompt` (プレイヤーごとのシステムプロンプト) は残した。作業記憶と同じ区画の組み方 (`WorkingMemory.system_sections`) で作るので、1 ターンのプロンプトのシステムプロンプトと源が同じになる。シナリオに居ないプレイヤーに返す共通のシステムプロンプトだけは、`build_world_system_prompt_for` で組む

**決めたこと**:

- reason_first の行動の段の足し書き (【行動前の状況評価】、候補表、行動の段の指示) は、作業記憶に取り込まない。作業記憶の外にある、行動の段だけの付け足しとして、ゲームの側が評価の段の文の後ろに足す
  - 行動の段は、評価の段の文をそのまま再利用してキャッシュに載せる作り。作業記憶の区画として組み直す利点が小さい
  - 評価の文 (`inner_thought`) は、phase B が行動の段で選んだ行動の引数に注入し、行動の心の声として短期記憶に写している。次のターンからは【直近の出来事】に出るので、新しい置き場所は要らない (#1630 のコメント)
  - 候補表は、行動の段で出すツールで選び直すので、場面の候補表とは位置も中身も別
- 目次を出したときの trace (`episode_index_shown`) は、`CurrentWorkingMemory.episodes_in_index` で引いたエピソードで残す。目次の文と trace が同じ選び方を使う。作業記憶の値には trace の材料を持たせない
- 区画ごとの文字数 (`prompt_section_breakdown`) は、作業記憶の区画の本文 (見出しの行を除く) から数える。キーの名前は変えていないので、trace を読む側 (trace.html、分析のスキル) はそのまま読める
  - 2026-11-01 から、`recent_events_chars` は前置きの一文と改行の分だけ増える。前の trace と比べるときは差し引く
  - 常に 0 だった `inventory_chars` は無くなった
  - 出ていない区画は 0
  - 出来事の本文が空白だけのときは「（なし）」、現在地の文が空のときは「（情報なし）」も数える (前は 0)。今の run ではどちらも起きない

**残したこと**: 案内が無いプレイヤーのプロンプトを組もうとしたときは、`PlayerProfileNotFoundForPromptException` を投げる。前はプロフィールが無いときに投げていた例外で、名前は変えていない。どちらも「そのプレイヤーのプロンプトを組めない」ことを伝える。

**一字一句同じであることの確かめ**:

- 比べる資料 `tests/fixtures/prompts/` は、切り替える前の main で `tests/support/prompt_baseline.py` を走らせて書いた
  - 廃坑の山村と station_drill の 3 つの場面: 最初のターンの全員、同じ待機を繰り返した直後、記憶 (いきさつ・目次・メモ・知っている人) と知らせに中身があるターン
  - `data/scenarios` の全シナリオの最初のターンの全員を、締めの一文の 2 通り (tool_choice が required と auto) と候補表を差し込まない評価の段の文で、sha256 にしたもの (`every_scenario_sha256.json`)
  - 1 本目で書いた資料は、切り替える前の main で書き直しても同じだった
- 不変条件 2 は、出来事が増えるターンと、知っている人が増えるターンで見張る。いきさつが届くターンは、直近の出来事の古い分も外れるので途中が変わるのが正しく、見張りの対象外
