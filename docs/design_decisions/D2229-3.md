## D2229-3. 観測の人の穴は Being が受け取るときに埋め、名前は遊びを始めるときに世界へ付ける

**何を**: 世界の観測を Being の短期記憶に届ける受け口 (`HandObservationToBeing`) を、遊びの進行 (#2229) に足した。そのとき見つかった 2 つの抜けの扱いを決めた。

### 1. 人の穴は、Being が観測を受け取るときに、そのときの呼び名で埋める

新しい世界の観測の出口 (`ObservationExit`) は、本文を人の穴の形 (`TextWithPeople`) で渡す。人が 1 人も出てこない「扉が壊れた」も同じ形になる。いまの短期記憶は、人の穴の形の本文を断る。

| | 決まり |
|---|---|
| 埋める時 | Being が観測を受け取るとき (`PerceiveObservation`) |
| 埋める名前 | そのときの呼び名 (`text_naming_people`、#2252)。名前が見えれば名前、見えなければ見た目 |
| あとで名前を知ったとき | 過去の記憶は書き換えない。そのとき知覚したとおりに残す |
| 埋める振る舞いの置き場所 | 契約の `Observation.with_people_named(name)`。本文が文字列ならそのまま返す。受け取る側は本文の型を見分けずに頼むだけにする |

例: 見知らぬ男が扉を壊したのを見て、あとでそれがゲンだと知っても、記憶は「背の高い男が扉を壊した」のまま残る。

**採らなかった案**:

- 短期記憶に人の穴の形のまま入れ、思い出すときに埋める: あとで名前を知ると過去の記憶の見え方が変わり、そのとき知覚したとおりにならない
- 受け取る側 (`PerceiveObservation`) で本文の型を見分けて埋める: application に型の分岐が出る

### 2. Being の名前は、遊びを始めるときに世界の名簿へ付ける

世界の人の名簿 (`PeopleRegister`) は、名前を付けていない人が出てくる観測を作ろうとすると `PersonNotNamedException` で断る。名前を付ける操作 (`PeopleRegister.name`) はドメインにあったが、世界の application に入口が無く、遊びの進行から呼べなかった。

| | 決まり |
|---|---|
| 入口 | 世界の application に `NamePerson` (`NamePersonCommand(person, name)`) を足した |
| 呼ぶ時 | `StartPlaySession` が、世界を開いたあと、Being を入れる前に、全員に 1 回ずつ |
| 付ける名前 | 配役の Being の名前 (人柄の `name`)。Being は自分の名前で入り、世界は名前を遊びの進行から受け取る (D1928-3) |

いまの `PeopleRegister.name` は、同じ人に 2 回名前を付けたとき次のようにふるまう。

| 2 回目 | ふるまい |
|---|---|
| 同じ名前 | 何もしない。イベントも出さない |
| 違う名前 | `PersonAlreadyNamedException` で断り、最初の名前のまま |

名簿は世界ごとにあるので、同じ Being が別の世界から入り直すときは、その世界の名簿に初めて名前を付けることになり、断られない。同じ世界に同じ名前で付け直すことも断られない。`StartPlaySession` は 1 つの世界を開くときに 1 回だけ呼ぶので、この形で足りる。

途中で入れ替わる Being に、同じ登場人物で別の名前を付けたくなったら (#1548 の組み分けの入れ替えを、1 つの世界の中でするとき)、名前を付け直す決まりを、そのときに決める。

**採らなかった案**:

- 世界を開くとき (`OpenWorld`) に名前も受け取る: 世界を開く処理が、遊びの進行の配役を知ることになる
- 名前を付けずに、観測の出口が名前の無い人を見た目で出す: 名前を名乗った相手も見た目でしか呼べなくなる
