## D1469-2. いきさつとエピソードの書き手は、名前と一人称を Being の人柄から引く

**何を**:

- いきさつ (`WriteBackstoryCommand`)、範囲が埋まったときのエピソード (`WriteEpisodesCommand`)、離れるときのエピソード (`WriteEpisodesOnLeavingCommand`) のコマンドは、名前の文字列 (`self_name`) の代わりに Being の人柄 (`persona: Persona`) を持つ。人格の文は `persona_text` に分けた
- 人柄は Being の保存先から引く (`WorldRuntime.being_persona`)。ゲームの側の関数から名前を引く経路は消した
- 書き手への文は、名前の次の行に一人称を書く (`あなたの一人称 = 俺`)。一人称が決まっていなければ (`None`)、一人称について何も書かない。行を作る処理は `being/infrastructure/self_lines.py`
- `persona` の無い古い snapshot は、`identity_name` と `identity_first_person` を読み捨てる。復元するときは、起動時にシナリオから入れた人柄で埋める。読み捨てた値は `snapshot_load` の `removed_legacy_identities` に `{being_id, name, first_person}` で残す

**人格の文はまだゲームの側から渡す**: `persona_text` は、ゲームの側の `persona_prompt` から作る文 (`_build_persona_resolver`)。`Persona` の性格などはまだ空なので、ここを `Persona` に切り替えると、書き手から人格の説明が消える。`persona_prompt` を分けるとき (#1339 / #1548) に `Persona` から作る。

**古い snapshot を読み捨てる理由**: #1925 より前の snapshot の名前と一人称は、どれも人柄を渡す呼び出し元が無かったころの仮の値 (`agent_N`、「わたし」) である。書いてあるとおりに読むと、そこから再開した Being は仮の名前のまま続き、書き手にも仮の名前と一人称が渡る。

- 人柄を埋める先の Being が保存先に無い (シナリオから用意していない) ときは、`BeingSnapshotIncompleteException` で断る。実験の再開では起動時に全員の Being を用意するので、run の中では起きない。`scripts/being_snapshot_cli.py` で古い snapshot を空の DB に読み込むときは断られる
- SQLite に残る古い行は、人柄の無い snapshot として読める (`find_snapshot_by_id`) が、Being にはしない。`find_by_id` も、その行を含む `find_all_attached_to` も `BeingSnapshotIncompleteException` で断る。古い行を飛ばして warning にすると、所属の検索から Being が黙って消えるので、断る方を選んだ。SQLite の Being の保存先を使うのは `scripts/being_snapshot_cli.py` だけ
- 古い snapshot の `BeingSnapshot` は、人柄を `None` にし、読み捨てる値を `legacy_identity_name` / `legacy_identity_first_person` に持つ。書き出す前に人柄で埋める。人柄の無い snapshot は decode も書き出しもしない
