# 公開SNSを安全に読み直せる範囲

## 今回の入口

`PublicSnsReadService` は、既存の仮想画面とは別の読取り入口である。
投稿一覧、選択した投稿または返信、通知一覧を取得する。既存の `PostQueryService`、
`ReplyQueryService`、`NotificationQueryService` の取得経路は使わない。
そのため #1456 / #1457 / #1458 / #1462 の既存画面に関する修正を置き換えるものではない。

対象の名前は `sns:<保存領域UUID>:<種別>:<作成時UUID>` である。ページの世代や
作者の表示名に依存せず、別の画面を見たあとでも同じ対象を指す。保存領域と本文を
一緒に戻せば以前の対象を指し、本文を戻さない新世界では古い名前を拒む。
複製した世界で新たに作った内容は別の作成時UUIDを持つ。

## 公開条件

- 作者本人にも `public` 以外を出さない
- 選択した返信から根投稿まで、削除・公開範囲・作者の存在・双方向ブロックを検査する
- 作者と親は整数に加えて作成時識別子を保存し、整数再利用時に別人物・別スレッドへ結び直さない
- 途中の親が欠ける、循環する、64件以内に根へ到達しない場合は全体を表示しない
- 存在しない、別の保存領域、読めない、古い仮想画面参照は同じ対象不可視エラーになる
- 通知は受信者と発信者の作成時識別子を検査し、対象を不変名で引き直す
- 通知に保存された本文・作者名は再利用しない。返信とメンションの本文は現在読める対象から得る
- フォローといいねの通知に本文は付けない。旧整数だけの通知はこの入口では出さない

SQLiteの旧データは移行時に存在する作者・親へ一度だけ結合する。メモリ上の旧データで
この束縛を持たないものは新入口から隠し、読取り時に現在の整数から補完しない。

過去に正当に受け取った記憶を削除する処理ではない。新たに取得・配送する内容を
現在の権限で検査する。保持画面は取得時点を示す保存済みの表示として扱い、新しい取得や操作ではこの入口の現在の権限検査を通す。

## 取得量と順序

一覧は最大20件。各回で整数の作成順番号を降順に最大101候補だけ取り、100件以内を検査する。
境界となる番号より古い候補を次に取るため、途中の追加や削除で既読を重複させない。
本文模型はスカラー値だけを取り、各投稿の全いいねや全返信一覧を復元しない。
人物も名前と不変識別子だけを読み、ブロックの有無は対象の組だけを照会する。
フォロー先や購読先の全一覧を認可のために復元しない。

100件すべてが読めない場合にも、まだ候補があれば継続位置を返す。空の結果を
「この先も公開投稿がない」と偽らない。継続位置は保存領域・閲覧者・一覧の種類・
選択対象に結び付け、別の一覧へ転用しない。継続位置は認可の代わりにはならず、
取得するたびに権限を調べ直す。

選択した本文は短縮しない。返信を選べば、根から親までの文脈と、直下の返信一覧も返す。
表示側は全文と不変IDを区別し、選択した本文を優先して画面全体の文字数予算へ収める。
投稿の本文自体には既存ドメインの280文字制限がある。

## 質感の点検

実モデルを呼ばず、同じ表示名を使う人物や、画面移動後の参照、返信の途中だけが非公開に
なった場面を契約試験で確かめる。長い本文を一覧の先頭200文字だけに固定せず、
読みに行った対象の末尾まで得られる。別の枝へ移ったあとでも以前に読んだ名前から
同じ対象へ戻れ、読めなくなった対象を別の投稿に置き換えない。

これはエージェントが実際に読み返して返信するかの測定ではない。実行時の共通道具と
画面保持への配線は後段で検査し、有料モデルによる評価は行わない。
