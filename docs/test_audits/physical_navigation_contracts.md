## なぜ直したか

### 除外IDを渡さなくても通る試験

`test_excludes_object_from_passability_check` は中央の物体100を除外していた。しかし探索するのはその隣接セルで、中央の物体は候補を塞いでいない。除外引数を捨てても試験が通った。

元の地図・中央座標・除外100・非None断言を残した上で、8隣接の道路へ遮断物体200〜207を追加した。同じ地形と配置で、次を比べる。

- 除外なしなら通行先はない
- 北にある物体200だけを除外すると、明示した北座標 `(2, 1, 0)` を返す
- 候補外の中央100を除外しても通行先はない

別の空きセルへ逃げる余地はなく、期待座標も本体の方向表から生成しない。この検査は公開の除外引数を実地図へ伝える契約であり、アプリが現在隣接物体を除外しているという主張ではない。

### 地図角の試験が中心座標でも通る

元の名前はNone返却を示していたが、実際には道路の角から非Noneを要求していた。元入力と非None断言を残し、成功を表す名前へ変更して、最初の有効な隣接座標 `(1, 0, 0)` も要求する。

角 `(0, 0, 0)` では北と北東は負のyになって拒否され、その次の東が通行可能である。名前だけでなく、例外処理後に中心へ留まる誤りを検知する。

### 消去後の照会で予期しない故障も受理する

`test_transition_player_updates_everything` の旧地図照会を、任意の例外から `ObjectNotFoundException` に限定した。新地図の着地座標、プレイヤー状態、非空だった経路と目的地の解除は全て残す。

この例外は利用側との契約でもある。`GatewayTriggeredEventHandler` は同例外だけをゲートウェイ対象不在へ変換し、`ArrivalPolicy` は同例外だけを目標消失へ変換する。`KeyError` を消去成功の証拠として飲み込むべきではない。

## 統合した重複と保持先

`test_returns_north_first_when_all_passable` と `test_finds_passable_adjacent_when_object_at_center` は、同じ5×5道路、中央の物体100、座標 `(2, 2, 0)`、通常歩行、除外100で同じ入口を呼んでいた。

後者へ前者の `x == 2`、`y == 1` を先に移し、両宣言が残る状態で7件全成功を確認してから、重複宣言だけを除いた。保持先には元の非None・非中心・距離1・実地図で通行可能の断言も残る。返却座標は `SetDestinationService` が経路の目標へ使うため、北優先は観測可能な選択である。

除外なし、水泳能力、壁による全周遮断、地図角は別入力なので統合しない。

## 残した試験層

- 到着判定: 未設定、別スポット、領域のID・現在座標欠落、領域/物体の地図欠落、点領域の内外、矩形内部、同一セル、隣接、斜め拒否、目標消失、未知の目標種類を保持する。アプリの経路解除と保存を確認する試験だけでは、これら全入力を代替できない
- スポット間経路: 実地図と実A*を使う同スポット、直接出口、複数段、接続なし、未知領域型を保持する。接続供給器の辞書は入力を与えており、経路を捏造していない
- 地図間移送: 2実地図と状態の整合を保持する。アプリの通知経由、保存、取引の巻戻しとは別の効果を確認する
- 経路政策: 模擬した戦略結果に対し、本体が行う始点/終点拒否、空経路の例外と抑制、部分経路の許可と拒否、単純化の有無、同一点短絡、公開の既定引数を保持する。実A*の探索試験はこの政策を代替しない
- 遷移条件値: 公開構築と基底型、既定/明示受取先、0と負数、天候の直接/ヘルパー構築、空集合、不変性を保持する。評価器の条件充足やSQLiteの保存試験だけでは、値の全契約を代替しない。短い構築試験というだけで削らない

今後も、実地図で入力を区別してから隣接・除外・不在を断言する。同一準備の統合は元の入力と独立断言を先に保持先へ移して行う。模擬値の利用だけを理由に、経路政策と実探索の所有者を混ぜない。
