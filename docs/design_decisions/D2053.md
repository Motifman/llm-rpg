## D2053. 宣言を照らし合わせてまとめる WorldDesign.compose

**何を**: シナリオから作った宣言をまとめ、宣言どうしを照らし合わせて書き間違いを読み込みで止める `WorldDesign.compose` と、動いている世界が宣言を引く口を作った (#2053、#1978 のステージ 6)。文書から決まらなかったことは、ユーザーと次のように決めた。

| 何を | 決めたこと | 採らなかった案 |
|---|---|---|
| compose が照らし合わせる材料の取り出し方 | `Requirements` に欄を足す (`reads_world_stage`、`reads_day_phases`、`reads_weather`、`raises_flags`、`closes_group_decisions`、`may_hide_membership`)。根の文は `Condition.explains_failure()` が答える | 別の型と別のメソッド (`footprint()`) をすべての条件と効果に足す。意味は分かれるが、60 前後の型に 2 つ目のメソッドが要る |
| `route` の道の選び方 | `route(start, destination, passable)`。通れる通路だけをたどり、かかる tick の合計、通路の数、宣言の並びの順で 1 つに決める | 宣言だけでたどる。閉じた近道を選び、扉の前で止まる |
| `InitialWorld` の中身 | 宣言どうしを組み合わせないと作れないものだけ (人ごとの `StartingPerson`、最初に立っている旗、最初の段階、天候の最初)。物の状態などは集約が宣言から作る | 全集約の材料を並べる。集約のファクトリと重なる |
| 最初の体力と荷の上限 | どの宣言にも無いので、この Issue では足さず、別の Issue で決める | — |
| `WorldIntroduction` の欄 | `text` と `objective`。形式の案 (#2054) とそろえる | — |
| `RefusalTexts.world_state` | 起きうる `RefusalCode` をドメインで列挙できないので compose では確かめない。表に無い理由で断られたときの扱いはステージ 7 で入れる | — |

調整役と決めたこと: compose が受け取る `refusal_texts`、`built_in_action_perceptions`、`weather`、`day_night` を同じ名前の口で引けるようにする (文書の書き漏らし)。`initial_stage` は `InitialWorld` に入る。

**実装で決めたこと**:

- 置いた場所ごとの主語と読める引数は `RulePlacement` が持ち、`requirements()` と照らし合わせる。通路の通り方の条件と、見つかる物は、行為の中に置いた条件として `Actor` を使える
- 根に `failure_text` を求めるのは、宣言が直接持つ条件 (操作の前提、区画の入る条件、通路の通り方、見つかる物、出来事、反応、終わり)。`PeopleSelection` や `ConditionalEffect` の中の条件は根ではない
- 行う人に知りえない所属を見る警告は、断られる前提 (操作の前提、区画の入る条件、通路の通り方) だけに出す。行う人のいない出来事などでは伏せないため
- 旗の警告は「立てるが誰も見ない」旗だけ。立ても見もしない旗は警告しない
- 宣言 1 つだけで決まる「猶予 0 で介抱がある」も、文書どおり compose で `DesignFlaw` にする (`WorldRules.design_flaws`)
- 出発地と目的地が同じなら `NoRoute`。`Route` は通路を 1 本以上持つため
- 組み込みの行為の知覚の文の知らせの相手も照らし合わせる。拾う・渡すなどには相手がいることがあるので、`Actor` と `Target` を使える場所として扱う
- 段階・昼夜・天候が宣言されているかは、`DeclaredWorldTime.of` が `NoWorldStages`・`NoDayNight`・`NoWeather` を見分けて決める。宣言の型に「宣言されているか」を答えさせると、宣言の側が常に真を返すだけのメソッドになるため
- 出来事・反応・見つかる物・二人で合わせる操作の ID の重複は確かめない。文書に決まりが無いため。要るとわかったら Issue にする
