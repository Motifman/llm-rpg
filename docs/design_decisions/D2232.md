## D2232. ターンを回す決まりを巡り (TurnRounds) に置き、誰が動けるかは世界に問う

**何を**: D2225 の決まりを、遊びの進行のドメインの集約 `TurnRounds` と、世界に誰が動けるかを問う入口 `CheckReadinessToAct` で作った (#2232、親 #2212)。

### 1. 誰が動けるかは世界が答え、ターンを回すかは遊びの進行が決める

世界は、人ごとに 3 つのどれかで答える (`ReadinessToAct`)。

| 世界の答え | 根拠 | 遊びの進行が回すか |
|---|---|---|
| `FreeToAct` | 生きていて、結末が決まっておらず、行為の最中でない | 回す。ただし「待つ」を選んで待っている人には回さない |
| `InTheMiddleOfAction` | 生きていて結末が決まっていないが、行為の最中 (移動中など、`is_busy`) | 前の巡りで呼びかけを受けたときだけ回す |
| `UnableToAct` | 気を失っている・死んだ・結末が決まって世界から外れた | 回さない |

- 根拠は、世界が行為を受け付けるかの判定 (`_acting_occupant`) の生者の側と同じにした。ずれると、ターンを回したのに行為が全部断られる人が出る
- 世界には死者が動ける設定 (`departed_persons_act`) があるが、死者にはターンを回さない (D2225)。幽霊を動かすときに改めて決める

例: ハルが北の坑道へ移動中なら `InTheMiddleOfAction`、サヨが気を失っていれば `UnableToAct`。

### 2. 「話しかけられた」は wants_wake の立った観測で代える

D2225 は、行っているあいだの人には「話しかけられたときにだけ」回すと決めた。しかし、世界の観測の出口 (`ObservationExit`) は `addressed_to_self` を `UNKNOWN` で渡していて、話しかけられたかを見分けられない。

代わりに、`wants_wake` の立った観測を呼びかけ (`TurnRounds.hear_call`) として数える。`wants_wake` は、その人が関わっている (話しかけられた、自分に向けて何かされた) か、目立つ知らせ (`Notable`) のときに立つ。

- 待っている人も、同じ呼びかけで起こす
- 呼びかけは次の巡りでターンを回すためのもので、その巡りでターンにならなかった人 (気を失っていた人) の呼びかけは捨てる。持ち越すと、気がついてから移動を始めた人に、古い呼びかけでターンが回る
- ターンを終えたら呼びかけを消す。行為の確定のあとで消すので、自分の行為が呼んだ観測でもう一度ターンが回ることはない

### 3. 「待つ」を選んだ人は、決めた巡りの数のあいだ飛ばす

巡り r で待つを選んだ人は、巡り r+1 から r+N を飛ばし、r+N+1 でまたターンが回る。N は `TurnRounds` が受け取る値 (`wake_waiting_after`) で、遊びの進行のドメインは値を決めない。値は実験の条件として profile で渡す。

例: N = 3 のとき、巡り 1 で待つを選んだゲンは、巡り 2〜4 は飛ばされ、巡り 5 でターンが戻る。途中で呼びかけを受ければ、次の巡りで戻る。

### 4. 1 巡りの中の順番と、巡りを閉じる条件

- ターンを終えた順を `TurnFinishedEvent.order` (1 から) に残す。LLM の返事が返った順に終えるので、記録 (#2233) はこれで同じ tick の中の順番を書き出せる
- その巡りにターンのある人が全員終えるまで、巡りを閉じない (`RoundStillHasTurnsException`)。閉じたら時間を 1 進める
- 誰にもターンが無い巡りは、開いてすぐ閉じる。全員が移動中でも時間は進む
- 巡りを開いた (`RoundOpenedEvent`、ターンのある人の一覧つき)・閉じた (`RoundClosedEvent`) をイベントで残し、時間を進めた時点を記録に渡す
- 決めた巡りの数 (`round_limit`、run の `MAX_WORLD_TICKS`) を閉じ終えたら、上限に届いたと答える

### 5. 進め方を差し替えられる形

D2225 で、決まった実時間ごとに進める案を今後の選択肢に残した。巡りで進める決まりは `TurnRounds` に閉じ込め、誰が動けるかの問い合わせ (`CheckReadinessToAct`) と、ターンを頼む先は巡りを知らない形にする。実時間で進めるときは、`TurnRounds` の代わりの集約を足して、同じ問い合わせと頼む先を使う。

**採らなかった案**:

- 遊びの進行が世界の人の状態 (`PersonVitals`、`PersonOutcomes`) を直接読んで決める: 世界の判定と別に同じ規則を書くことになり、ずれる
- 世界がターンを回す人を決める: 「待つ」・呼びかけ・巡りは遊びの進行の決まり (D2226 の地図)
- 待っている人の起こしを tick (世界の時刻) で数える: 遊びの進行は自分の巡りを数えていて、1 巡りで 1 tick 進むので同じになる。世界の時刻に頼ると、時刻の読み方が変わるたびに直すことになる
