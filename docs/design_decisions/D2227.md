## D2227. シナリオの人柄は欄ごとに確かめて地図で返し、立場と目的は必須にする

**何を**: D2222 の決まりに沿って、登場人物の `being:` を人柄の型 (`Persona`) の欄ごとに読み、`known_facts` と `objective` を `LoadedScenario.briefings` (`CharacterBriefing`) に返すようにした (#2227、親 #2212)。そのとき決まっていなかった 3 つを決めた。

### 1. 読み込む側は `Persona` を作らず、欄ごとに確かめた地図を返す

game_world は eventing と `being.contract` のほかを import できない (`tests/architecture/test_game_world_package_import_boundary.py`)。`Persona` は `being/domain` にあるので、シナリオの読み込み (`game_world/infrastructure/scenario`) からは作れない。

| | 決まり |
|---|---|
| 読み込む側がすること | `being:` の鍵を `Persona` の欄の名前 7 つ (`PERSONA_FIELDS`) に絞る。知らない鍵 (古い `persona`、`objective` など) は `DesignFlaw`。`name` などは文、`traits`・`values`・`fears` は文の一覧であることと、空白だけでないことを確かめる |
| 返す形 | `LoadedScenario.beings: Mapping[PersonId, Mapping[str, object]]`。一覧は tuple にする。書かなかった欄は地図に入れない |
| `Persona` を作る場所 | Being を用意する側 (8-3)。人柄は Being が自分で持つもので (D1928-3)、世界が渡すものではない |
| 欄の名前のずれ | `PERSONA_FIELDS` と `Persona` の欄が一致することを、境界の外の `tests/architecture/test_scenario_being_fields_match_persona.py` が見張る |

**採らなかった案**:

- `being.contract` に人柄の材料の型を足す: Being の契約が変わる。いま契約で人柄を受け渡す場面が無い
- game_world の境界の例外に `being.domain.persona` を足す: 世界が Being の中身を知ることになり、境界が崩れる

### 2. `known_facts` と `objective` は必須にする

書き忘れたら `DesignFlaw`。`defaults:` に既定を置かない。

**採らなかった案**:

- 任意にし、書かなければ「無い」を表す型 (`NoKnownFacts` など) を返す: 目的の無い人や知っている事柄の無い人を表すシナリオがまだ無い。要るシナリオが出たときに、「無い」の書き方を決める

### 3. 人柄の欄のうち必須なのは `name` だけ

`being:` そのものは必須 (書かないと Being が入れない)。`being:` の中は `Persona` の型と同じく、`name` のほかは書かなくてよい。

**採らなかった案**:

- `first_person` と `speech` も必須にする: `Persona` は決まっていない値を `None` にする型で、仮の値で埋めない (#1469)。読み込む側だけ厳しくすると、型とずれる

### 4. ほかの登場人物や、この世界の場所に触れる文は人柄に書かない

`background` などの人柄の欄には、ほかの登場人物 (「家族のサヨと」) や、この世界の場所 (「この鉱山で」「父の職場だった事務所」) に触れる文を書かず、`known_facts` に書く。人柄は世界をまたいで持ち越すので、別の世界や別の組み分けに入ったとき、いない人や無い場所を自分の生い立ちとして持ってしまうため。組み分けの中での間柄 (調査隊の隊長と隊員) も同じく `known_facts` に書く。

廃坑の山村 v2 では、ゲンの `background` を「元鉱夫。」、サヨを「物覚えのよい娘。」、ハルを「山の測量を請け負ってきた測量士。」にし、残りを `known_facts` に移した。ミオの調査隊の隊員という立場も `known_facts` に移し、`background` は書かない。D2222 のゲンの例も合わせて直した。

**採らなかった案**:

- D2222 の例のまま、生い立ちに家族や働いていた場所を書いてよいとする: ゲンを別の世界へ連れて行くと、そこにいないサヨと村に戻ってきたことを人柄として持ち続ける
