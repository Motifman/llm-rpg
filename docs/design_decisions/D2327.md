## D2327. 行為の結末と終わった世界の断りを、世界を変える取引の中で決める

**何を**: 本人に返す行為の結末 (文と要約) と、終わった世界の変更の拒否を、世界を変える (または断りを記録する) 取引の中で決めるようにした (#2327)。

例: ゲンがカンテラの油を足そうとして断られる。断りを記録する取引の中で、要約「ゲンはカンテラに油を足そうとした」が `ActionOutcomeForActor` として決まる。返事を書くまでにミオが最後の油を使い切っても、要約は変わらない。世界が終わったあとにゲンが籠に乗ろうとすると、行為を確定させる取引の頭で `WorldEnding.admit_change` が断り、返事は「世界はもう終わった。」と籠に乗り込む要約を持つ。断られた試みは記録されず、出来事も発火しない。

| | 決まり |
|---|---|
| 成功の結末 | 効果の前の世界から `ActionAttempt.fixed_before_effect` が `ActionFixedBeforeEffect(situation, present, outcome)` を作る |
| 断りの結末 | `ActionRefusal.outcome_for_actor` が断りを記録する取引の中で作る。品物を全部引けなければ要約は `UnsummarizedAction` |
| 出来事の宛先 | `HappeningNotice.reach_before_the_effect` が宛先とその場にいた人を `NoticeReach` で返す |
| 終わった世界の拒否 | 行為の確定 (`CarryOutAction`)、時間の経過 (`PassWorldTime`)、落ち着かせ (`SettleWorldConditions`) の取引の頭で `WorldEnding.admit_change` を呼ぶ。行為の断りは既存の `except WorldRefusal` に流れる |
| 終わった世界の断りを記録しない | `ActionRefusal.leaves_a_record` が WORLD_ALREADY_ENDED のときだけ偽を返し、`LatestActions.note_failed_attempt` が受け取った断りに問う |
| 終わった世界の落ち着かせ | `SettleWorldConditions` は `WorldAlreadyEndedException` を受けて何もせずに返る |

**採らなかった案**:

- 世界が終わったかを別の取引で先に問う (`AcceptAction`): 問うてから実行するまでのあいだに世界が終わると、終わった世界が変わる
- 記録しない規則を application で `ending` に問うて分岐する: application に「問うて分岐」が入る
- `WorldEnding` が記録の呼び出しを受け取る (`unless_ended(work)`): 集約が呼び出しを受け取る形になる
- 落ち着かせを、世界を変える集約がそれぞれ `WorldEnding` を見て止める: 集約どうしが結びつく

**関連**: Issue #2327、D2218、D2216。
