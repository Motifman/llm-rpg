# モンスター攻撃の試験

- 拒否理由だけで不発を証明せず、被害と攻撃時刻の更新、実集約の通知が増えないことも、その契約の主試験で確かめる
- 複数の拒否条件が同時に成立する入力では、狙った例外型を検査する。詠唱停止と再使用待ちを「どちらかの例外」で済ませない
- 再使用待ちは既存の技能アプリ試験が所有する。別階層へ追加するときは、その階層だけの失敗要因を明らかにする
- グラフの配置保持は、そのグラフを受け取る実際の入口で検査する。呼出先に渡していない別のグラフを断言しない
- 致命攻撃後の配置は `tests/application/world_graph/test_spot_player_attack_presence.py` が所有する。保存や後続イベント配送の保証とは分ける
- 技能拒否時の入力集約の原子性と正式保存の原子性を混同しない。設計上未確定の巻き戻しを試験整理へ持ち込まない
