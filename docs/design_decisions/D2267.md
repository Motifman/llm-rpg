## D2267. Being が出す区画を、古い run のプロンプトどおりに再現する

**何を**: #2271 (古い run のプロンプトを新しい世界で再現する) のうち、Being が文にする区画を、古い run (`var/runs/mine_v1_002`) のとおりに出す (#2267)。調整役とユーザーと決めた。

### 現在地の行は Being が書く

古い run の【現在地と周囲】は `現在地: 南の坑道 (初めて訪れた)` の行で始まる。初めて訪れたかは Being の記憶から決まるので、現在地の行は Being が書く。

- 世界は、場面の専用の欄 `Scene.here: Here(place, heading, text)` で渡す。`place` は場所の名前で、訪れた記録の鍵になる。`text` は現在地の行より下の本文 (説明・雰囲気・時刻・接続先・物・人) で、人の穴を持てる
- Being は【現在地と周囲】を、場面のほかの説明より先に、`現在地: {place}` の行と世界の本文で組む。古い run の【現在地と周囲】→【現在選べる対象引数】の並びに合わせるため
- 何も見えないとき (気を失っている、移動中など) は `here` を持たない。Being は【現在地と周囲】を出さない
- `here` の見出しは、場面のほかの説明や知らせの見出しと重ならない

**採らなかった案**:

- 世界が現在地の行まで本文に書き、Being がその行を探して (初めて訪れた) を書き足す: 世界の文の形に頼ることになる
- 世界が訪れた記録を持ち、(初めて訪れた) を世界の文に書く: #2271 で、訪れた記録は Being の記憶として持つと決めた
- 着いたことの観測から現在地を知る: 最初のターンや、snapshot から再開したあとは、着いた観測が届かない

### 訪れた記録を Being の記憶として持ち、着いた場所に (初めて訪れた) を付ける

**何を**: Being のドメインに、訪れた場所の記録 (`VisitedPlaces`。Being ごとに 1 つ) を置く。場所の名前は環境の中でだけ通じるので、環境の名前と組 (`VisitedPlace`) にする。

- 作業記憶は、場面の現在地 (`Scene.here.place`) を、今いる環境の名前で記録と照らし、まだ訪れていなければ現在地の行に `(初めて訪れた)` を付ける
- `ChooseAction` は、1 手を使ったら、その場所を訪れたと記録する。出していないツールの名前を呼んで失敗した 1 手と、思い出すツールの 1 手も含める。ツールを呼ばなかったターンは数えない。だから印は、着いたあと最初に 1 手を使うまで付き、使う前に組み直したプロンプトにも付く。古い run の #1596 と同じ決まりで、古い run も、失敗も含めて実行した手番の数で判定していた
- 手本の run (`mine_v1_002`、2026-10-10) では、同じ場所で 2 ターン続けて印が付いている。#1596 (2026-10-11 に直した) より前の run だからで、直したあとの決まりに合わせた (#2271 は、いまの古い run のコードを一次情報とする)
- Being の snapshot に `being_visited_places` として配線した。足す前の snapshot は、どこも訪れていないとして読む (`ADDED_PAYLOAD_KEYS`)
- 古い run の組み立て (`world_runtime`、実験の snapshot のセッション、スクリプト) にも保存先を通した。Being の snapshot を古い run と共有しているため。古い run の場面は現在地の欄を持たないので、記録は増えず、プロンプトは変わらない

**採らなかった案**:

- 古い run の出会いの記録 (`IEncounterMemory`) を使う: 古い run のプレイヤーの番号で引く記録で、Being の記憶ではない
- 記録を知り合いの保存先 (`AcquaintanceRepository`) に混ぜる: 人と場所は別の記録で、問い方も違う

### 候補表を、古い run の【現在選べる対象引数】の形で出す

**何を**: Being が場面に置く候補表を、古い run (`dynamic_argument_candidates.py`) と同じ形にした。

```
【現在選べる対象引数】
- interact.target: "南の坑道の水門", "カンテラ"
- interact.how ("南の坑道の水門"): "水門を開ける"
- travel_to.destination: "北の坑道", "南の横坑の奥", "道具置き場"
※ 一覧にあることは操作の成功を保証しない。現在の状態や前提条件によって失敗する場合がある。
```

- 引数の名前は、世界が渡す見取り図の名前をそのまま使う。Being は引数の名前を書かない (#2268 で古い run の名前に戻る)
- 候補の下で選ぶ値には、どの候補の下かを括弧に添える。見取り図に無い値は `details.名前`
- 自由に書く値、候補の無い行動、いまはできない行動は出さない。どの行動にも候補が無ければ表ごと出さない
- いまはできない理由は、世界の【現在地と周囲】が物の行の下に出す (ユーザーと決めた)。#2240 の最初の決まり (理由つきで場面に出す) を、出す場所を世界に移す形で変えた
- 同じ名前の品物は 1 回だけ出す。見分けのつかない人には古い run と同じ「 #1」「 #2」を添え、番号は表に出る候補の人だけで数える

**採らなかった案**: 候補表の末尾に「いまはできない」の行を残す。古い run に無い行が増え、理由の文は世界の言葉なので、出すなら世界の【現在地と周囲】がよい

### 【ペルソナ】を、人柄とこの世界で知っていることで組む

**何を**: 古い run の【ペルソナ】は、人柄の文と、この世界で知っていること (金庫の番号など) と、話し方の行を並べていた。Being がこの区画を組む。ユーザーと決めた。

```
【ペルソナ】
あなたはゲン、元鉱夫。口数は少ないが、坑道の空気には敏い。
大事にしていること: 身内を無事に家へ帰すこと。
苦手なこと: 坑道のガス。

この鉱山で働いていた。家族のサヨと村に戻ってきた。
働いていた頃に、事務所の金庫の番号は 1907 だと覚えた。…

話し方: ぶっきらぼうな常体。一人称は「俺」。
```

- 人柄の文は、人柄の欄 (`Persona`) から組む。「あなたは{名前}、{生い立ち}。{性格}。」、大事にしていること、苦手なこと、の順。決まっていない欄の行は出さない
- 知っていることは、入るときの取り決め (`EnvironmentEntry.known_facts`) で受け取り、居場所 (`BeingAttachment.known_facts`) に持つ。環境を離れれば一緒に消えるので、別の世界へ持ち越さない (D2222 の分け方はそのまま)。Being の snapshot (`BeingSnapshot.attachment_known_facts`) で読み書きし、足す前の snapshot は知っていること無しとして読む
- 世界の案内からは【あなたが知っていること】を外した。D2222 で「取り決めは変えない」と決めていたのを覆した。理由は、知っていることを【ペルソナ】の中に置くには、Being がそれを案内の説明の 1 つとしてではなく、自分の知っていることとして受け取る必要があったため。毎ターン渡し直す案内に置くと、Being の記憶を Being の外 (遊びの進行の配役) が持ち続けることになる
- 置く位置は、世界の案内のあと、現在の目的の前。古い run (いまのコード) と同じで、人ごとに違う区画を全員に同じ案内の後ろに置くので、案内がプレフィックスのキャッシュに載る
- 古い run は自分で【ペルソナ】を案内に入れているので、Being が足すのは新しい流れ (`ChooseAction`) だけにした。古い run のプロンプトは変わらない
- 世界の導入の段落 (古い run の【ペルソナ】の冒頭にあった「冬が近い山あいの廃村に来ている。…」) は【ペルソナ】に入れない。v1 の `persona_prompt` に人ごとに書いてあったためで、新しい世界では【世界の前提】(#2268) だけに出す (ユーザーと決めた)

**採らなかった案**: 案内 (`Orientation`) に知っていることの専用の欄を足し、毎ターン渡し続ける。取り決めは変えずに済むが、Being の知っていることを Being の外が持ち続ける

### 一言の上限と無いツール名の文を、いまの古い run のコードに合わせる

**何を**: #2267 の本文は、手本の run (古い版) の【独白と一言の書き方】を指していた。いまの古い run のコードに合わせ、Being と世界で次のように分けた。

- 無いツール名の文は、古い run と同じ「未対応のツールです: pickup。もしかして 'pickup_item' ですか? 現在使える tool: […]」にした (使えるツールは名前の順)。文を作る関数 (`format_unsupported_tool_message`) を `being/application/closest_tool_name.py` に移し、古い run と Being の両方から使う
- 一言の 200 字の上限は、古い run ではツールの引数のスキーマの `maxLength` だった。見取り図に長さの上限の欄 (`ArgumentOutline.max_length`) を足し、Being はあればスキーマに `maxLength` を付ける。値は世界 (#2268) が入れる。Being が引数の名前を見て付け分けると、ゲームの引数を知ることになるため
- 一言の引数の説明文は、見取り図の `label` として世界が渡す。一言の書き方の段落は、いまの古い run のコードでは世界の【この世界の決まり】(`world_rules`。一言を持つツールがある世界でだけ出す) にあるので、世界 (#2268) が出す
