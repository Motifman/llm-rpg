## D2251. 候補に当たらない名前を、Being が世界に返す前に Jev で選び直す

**何を**: LLM が書いた名前が、Being が渡した候補に当たらないとき、Being が Jev (型付きの判断) に候補から選び直させ、選び直した名前で `AgentMove` を返す (#2251)。古い run の `action_name_rescue.py` (#1321) と `target_label_rescue.py` の決まりを引き継ぐ。

### 1. 引き継いだ決まり

| 決まり | 新しい置き場所 |
|---|---|
| 表記の崩れ (引用符、`→` の右、丸括弧の中、`:` の後ろ) を直して候補に当たれば、Jev に問わない | `name_forms` と `ActionTools.with_names_matched` |
| 候補が空なら問わない (伏せた操作を確率で漏らさない。design_decisions #46) | `ActionTools.with_names_matched` |
| 選択肢に「該当なし」(`__no_match__`) を必ず入れる | `RechooseName` |
| 選んだ候補の確率と確信がどちらも下限に届いたときだけ置き換える。確信の無い答えは確率だけで見る | `RechooseName` |
| 判断を得られなかったときは置き換えず、得られなかった理由 (`error_code`) を残す | `NameRechoice.unavailable_reason` |
| 採らなかった選び直しも残す | `ActionChosen.name_rechoices` |

`name_rechoices` に残るのは、Jev に問うたものだけ。問わなかったもの (名前が当たった、候補が空、名前が空や空白だけ、文字列でない、引数が無い、`RechooseName` をつないでいない) は残さない。どれも名前を変えずに世界に渡り、当たらなければ世界が場面に合わないと断る。その断りは行為の結果として残るので、問わなかったことを別に残す必要が無い。

候補から選ぶ値は、`move_from` が行為に使うのと同じ場所で照合する。上の段に書いた名前が details の中の名前に勝ち、details を取らない行動では details の中を見ない。行為に渡らない名前を Jev に問うても、結果が捨てられるため。

### 2. 古い run との違い

| | 古い run | 新しい Being | 理由 |
|---|---|---|---|
| 何を選び直すか | 行動名・対象の名前・相手の持ち物の名前を、それぞれ別の部品で選び直す | Being が渡した `PickOne` の候補すべてを、1 つの部品で選び直す。どの引数かで分けない | Being は引数の意味 (行動か対象か) を知らず、候補の並びだけを持つ。`PickOne` で渡したものは何でも同じ決まりで救えるので、#2247 で品物の候補を渡せば、コードを足さずに品物も選び直される |
| 相手の持ち物 | 相手の見えていない持ち物の名前も選び直していた (#1641) | 見えている候補だけを選び直す | 見えていない持ち物を選び直すには、世界が Jev を呼ぶか、Being が見えていないものを推し量ることになる。前者は世界から判断を外す #2251 の方針と食い違い、後者は Being のドメインとして不自然 |
| 問いの文 | 行動名と対象の名前で別の文 | 「書かれた名前 written_name は、{引数の見出し}としていま選べる候補のどれを指しているか」の 1 つ。入れ子の候補 (金庫の操作など) では、親の名前を state の `under` に入れる | Being は行動名と対象を区別しないため。引数の見出し (「相手」「操作」) が、何の名前かを Jev に伝える |
| 正規化 | 先頭の内部 ID (`S2: 禁書扉`) を外す形も試す | 外さない | 新しい世界はエージェントに内部 ID を見せないので、書き写されることが無い |
| 置き場所 | 世界が行為に戻すときに選び直す | Being が世界に返す前に選び直す | 世界の中で LLM を呼ぶと、確定が判断で揺れ、テストで振る舞いを固定しにくい (Issue #2251 でユーザーと決めた) |

### 3. Jev とのつなぎ方

- Being は `NameChoiceJudging` (問いを受けて答えを返す) だけを知る。Jev のクライアントはゲームの `ITypedJudgmentPort` にあり、Being から import できないので、`infrastructure/llm/typed_judgment_name_choosing.py` が写し替える。`ActionChoosingCompletion` と同じ形
- テストは `ScriptedNameChoosing` (Being の infrastructure) か、ゲームの `ScriptedJudgmentPort` を使い、実の Jev を呼ばない
- `ChooseAction` に `RechooseName` をつながなければ、表記の崩れだけを直し、Jev には問わない
