## D1928. 「プレイヤー → Being」の対応表をゲームの側に置き、世界の snapshot に入れる

**何を**: #1928 の 1 本目。Being の居場所を環境の言葉で持つ前に、誰がどのプレイヤーを動かしているかをゲームの側に移す。

- ゲームの側に、世界ごとの対応表 `PlayerBeings` (`domain/world/aggregate/player_beings.py`) を置いた。ID は世界の番号
  - 1 人のプレイヤーを動かす Being は 1 つ。別の Being がもう動かしているプレイヤーを動かさせようとすると、`PlayerAlreadyDrivenException` で断る
  - 1 つの Being が動かすプレイヤーは 1 人。ほかのプレイヤーを動かしている Being に動かさせると、そこを離れてから動かす (`Being.move_to` と同じ考え方)
- 「このプレイヤーを動かす Being はどれか」(`BeingAttachmentResolver`) と、起動時に Being を用意する処理 (`BeingProvisioningService`) は、対応表を引く。Being の保存先を番号で探す `find_all_attached_to` は呼ばなくなった (消すのは 2 本目)
  - `BeingProvisioningService` の `world_id` の指定はやめた。用意する世界は対応表の世界だけ
- 対応表を世界の snapshot (`world.json`) の `player_beings` の欄に入れる。再開したときに、世界と対応表を同じ時点でそろえる
- 再開したときに対応表をどこから読んだかを、`snapshot_load` の `player_beings_source` に残す

**古い snapshot の読み方**:

- Being の snapshot を読むとき、snapshot に残る番号 (`attachment_world_id` / `attachment_player_id`) で、対応表にも書く (`PlayerBeings.drive`)。世界の snapshot に対応表があれば、あとでそれに置き換わる
  - 起動時に Being を用意していないプレイヤー (今のシナリオにいないプレイヤー) は、対応表に載せずに飛ばし、warning を残す
- 対応表の欄が無い古い `world.json` と、`world.json` が無い古い snapshot は、Being の snapshot の番号で書いた対応表のまま続ける (`player_beings_source="being_snapshots"`)。番号も無ければ、起動時に用意した対応表のまま (`"startup"`)
- 読めない形は、起動前に止める
  - 2 つの Being の snapshot が同じプレイヤーを指す: `PlayerAlreadyDrivenException`
  - 世界の snapshot の対応表が、同じプレイヤーか同じ Being を 2 回載せている: `PlayerBeingsValidationException`
  - Being の snapshot を読んだのに、世界の snapshot の対応表に snapshot の無い Being が載っている: `WorldStateSnapshotCoverageError`。起動時に全員の Being を用意するので、保存先にあるかを見るだけでは、snapshot の欠けたプレイヤーを記憶の無い Being が黙って動かす。世界の snapshot だけを読んだときは確かめない
  - 世界の snapshot の対応表が、Being の snapshot の番号と食い違う: `WorldStateSnapshotCoverageError`
- 世界の snapshot の `schema_version` は上げていない。上げると、対応表の欄の無い今までの `world.json` を厳格な読み込みが全部断るため。欄が無いときの読み方で古い形を読む

**なぜ**:

- 誰がどのプレイヤーを動かしているかは、ゲームが知っていればよい。Being はゲームのプレイヤーの番号を知らなくてよい (#1928)
- Being の居場所を環境の言葉 (環境の識別子と表示の名前) に替えると、Being の保存先からプレイヤーの番号で探せなくなる。先に対応表へ移しておけば、居場所の形を替える 2 本目で挙動が変わらない
- 対応表を世界の snapshot に入れるのは、世界の状態と同じ時点でそろえるため。これはつなぎの置き方で、#1339 で環境を集約にし直すときに、「今自分の中に誰が入っているか」を環境の集約が持つ形に移す

**まだしないこと**:

- Being の `BeingAttachment` と snapshot の形は変えていない (2 本目)
- `EnvironmentEntry.self_name` は残っている (3 本目)

**関連**: Issue #1928、#1469、#1339、design_decisions D1469-4。

---

**その後 (design_decisions D1928-2)**: Being の居場所を環境の識別子と表示の名前に替え、`find_all_attached_to` を消した。今の形の Being の snapshot には世界とプレイヤーの番号が無いので、対応表の欄の無い古い世界の snapshot と今の形の Being の snapshot の組では、起動時に用意した対応表のまま続ける (`"startup"`)。番号の欄の古い Being の snapshot からは、今までどおり作り直す。再開した Being は、この run の環境に入れる。

**その後 (design_decisions D1928-3)**: `EnvironmentEntry.self_name` を消した。
