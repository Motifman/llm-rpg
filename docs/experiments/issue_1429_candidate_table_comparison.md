# Issue #1429: 動的引数候補表と Jev の比較

## 結論

この比較では、行動指示直前の候補表は Jev の意味救済を置き換えられなかった。
操作名では Jev の正答率 89.5% に対して候補表は 76.3%、対象名では 98.2% に
対して 65.5% だった。特に対象名では、候補表を見た主モデルが「該当なし」と
すべき入力を、一覧にある別の対象へ置き換える誤選択が多かった。

ただし、これは過去 run 全件の比較ではない。既存デモから再抽出できた操作名
99件・対象名70件のうち、失敗時点の完全な主モデル入力が保存されていた操作名
38件・対象名55件を比較母集団にした。主モデルも元 run ごとのモデルではなく、
全件を `openrouter/openai/gpt-4.1-mini` に固定した。したがって「小型モデル一般」
への外挿ではなく、この93件・このモデルでの反証として扱う。

## 比較方法

- 同じ入力事例、候補集合、独立正解ラベルを両方式へ使用した。
- 正解ラベルは実験結果を見る前に固定した。翻訳・短縮・同義表現、候補名を含む
  表示行、候補外を明示規則にし、各事例に根拠を保存した。
- Jev は既存実装と同じ `typesafe/jev-1.13`、閾値 0.7 を使用した。
- 候補表方式は保存済みの system prompt、user prompt、tool schema を復元し、行動指示
  の直前へ表を追加して、主モデルを実際に再実行した。元出力の文字列変換ではない。
- 操作名と対象名は混ぜずに集計した。試行回数は各事例1回、temperature は0。
- 候補は既存失敗文に記録された runtime 候補を使った。この候補は
  `tool_runtime_context` と同じ実行時の真実源から作られた表示であり、別の候補探索は
  実装していない。ただし、保存済みデータから全ツールの候補表は復元できないため、
  失敗したツールと引数の候補だけを再掲した。提案方式に有利な最小比較である。

適合率は「候補を選んだうち、独立正解と一致した割合」、再現率は「候補内に正解が
ある事例のうち、正解を選べた割合」と定義した。正答率では正しい「該当なし」も正解に
含めた。

## 誤りの質

Jev の操作名での誤救済は1件だった。「配線の結束を締め直す」に段階別候補が3つ
ある事例で `tighten_wiring` を選んだ。独立ラベルは、どの段階か特定できないため
「該当なし」とした。対象名の誤救済は0件だった。

候補表方式は、対象名で存在しないものを一覧中の近い対象へ置き換える傾向が出た。
例は「大型カニ」から「貝の岩棚」、「発電機」から「資材棚」、「古い手記」から
「岩肌の刻み跡」である。候補表は名前を正確に写す助けにはなるが、意図した対象が
候補内に無いときに、一覧から何かを選ぶ圧力にもなった。

## 判断

この結果だけなら、Jev を外して候補表だけに置き換える仮説は支持されない。
候補表を本番へ追加する前に、少なくとも明示的な「該当なし」選択と、候補外の意図なら
別のツールを選ぶよう促す文面が必要である。ただしそれを加えると比較対象は単なる短い
候補表ではなく、別の行動選択方針になる。現行 Jev は残し、候補表を試すなら Jev と
併用した第4条件で、通常 run の成立操作数まで測るのが次の妥当な段階である。
