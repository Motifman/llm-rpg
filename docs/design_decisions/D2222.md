## D2222. ステージ 8 の入口で、人柄と立場を分け、目的は本人のものだけにし、時刻を何日目と時:分で見せる

**何を**: ステージ 8 でゲームの世界を Being とエージェントにつなぐ前に、シナリオに書いた人柄・導入・目的を Being のどこへ渡すかと、観測の時刻をどう見せるかを決めた (#2222、親 #2212)。実装はステージ 8 の Issue で行う。

### 1. 人柄と、この世界での立場を分けて書く

廃坑の山村 v2 の `being.persona` には、性質の違う 3 つのものが 1 つの文に混ざっていた。

| 中身 (ゲンの例) | 誰のものか | 書く場所 |
|---|---|---|
| 名前「ゲン」、一人称「俺」、ぶっきらぼうな常体、口数は少ないが坑道の空気に敏い、元鉱夫 | 人柄。Being が世界をまたいで持つ | `being:` に、人柄の型 (`Persona`) の欄ごとに書く (`name`、`first_person`、`speech`、`traits`、`values`、`fears`、`background`) |
| 金庫の番号は 1907、カナリアが鳴きやむのはガスの前兆 | この世界での立場 | 登場人物の直下の `known_facts` に書く |
| 冬が近い廃村で、峠道は雪で閉ざされた…… (4 人とも同じ文) | 世界の導入 | `introduction.text` だけに書く。人ごとには書かない |

ゲンを別の世界へ連れて行っても、金庫の番号を人柄として持ち越さない。回ごとに組み分けを入れ替える #1548 にもつなげられる。

本人の目的も人柄ではないので、`being.objective` から登場人物の直下の `objective` に移す。

```yaml
characters:
  gen:
    appearance: ...
    knows_at_start: [sayo]
    known_facts: |-
      働いていた頃に、事務所の金庫の番号は 1907 だと覚えた。昇降機を動かす起動鍵も、その金庫にしまわれていた。
      坑道では、カナリアが鳴きやむのはガスの前兆だと教わった。
    objective: サヨと二人そろって、坑道の奥の昇降機で外へ出る。
    being:
      name: ゲン
      first_person: 俺
      speech: ぶっきらぼうな常体
      traits: [口数は少ないが、坑道の空気には敏い]
      background: この鉱山で働いていた元鉱夫。家族のサヨと村に戻ってきた。
```

| | 決まり |
|---|---|
| 立場の欄の名前 | `known_facts`。`knows_at_start` は最初から知っている人、`known_facts` は知っている事柄で、名前から見分けられるようにする |
| 立場と目的の置き場所 | `characters.<名前>` の直下。`being:` には入れない |
| 読み込む側 | `known_facts` と `objective` は `being:` と同じく世界の宣言 (`CharacterDeclaration`) に入れない。人ごとに入るときに渡す文 `CharacterBriefing` にして、`LoadedScenario.briefings` に返す。世界の規則はこの文を読まない |
| `being:` の鍵 | `Persona` の欄の名前と同じにする。`persona:` の 1 つの文は使わない |

**採らなかった案**:

- いまのまま 1 つの文で書き、人柄の型に自由に書ける文の欄を足す: ゲンは次の世界でも金庫の番号を自分の人柄として持ち続ける
- 人柄はシナリオに書かず、Being の保存だけが持つ: 最初の Being をどう作るかが別に要る
- 立場と目的を `CharacterDeclaration` の欄にし、`WorldDesign` から引く: 世界の規則が読まない文を世界の宣言に持たせることになり、宣言が太る
- 入るときに渡す文を `characters.<名前>.entry: { known_facts, objective }` の節にまとめる: 欄が 2 つしかなく、節を挟むと書く手間が増えるだけになる

### 2. 導入と目的を渡す先

| シナリオの欄 | 渡す先 |
|---|---|
| `introduction.text` | 案内 (`Orientation`) |
| `introduction.premises` (全員に同じ箇条。もとの `introduction.objective`) | 案内 (`Orientation`)。中身は目的ではなく世界の前提 (「昇降機は一度しか動かない」) なので、欄の名前を `objective` から `premises` に変える。型の欄も `WorldIntroduction.premises` にする |
| この世界での立場 (`known_facts`) | 案内 (`Orientation`)。環境が、導入とは見出しの違う `Description` (見出し「あなたが知っていること」) にして入れる。取り決め (`EnvironmentEntry`) は変えない |
| 登場人物の目的 (`objective`) | 課された目的 (`EnvironmentEntry.imposed_goal`) |

- `introduction.text` と `premises` の見出しは、ステージ 8 の実装で決める。`Orientation` は見出しの重複を許さないので、3 つは違う見出しにする
- v2 のいまの `introduction.objective` の 1 つ目の箇条「最終目標は、坑道の奥の昇降機で外へ出ること」は前提ではなく目的で、各人の `objective` がすでに含んでいる。v2 を書き直すとき `premises` から外す。残すと目的を 2 回読むことになる

**採らなかった案**:

- 全員の箇条と本人の目的を、どちらも目的に並べる: 同じことを 2 回読み、どちらが目的か迷いうる
- 本人の目的があれば全員の箇条を出さない (古い run と同じ): 「昇降機は一度しか動かない」がどこにも出なくなる
- 立場を取り決め (`EnvironmentEntry`) の新しい欄で渡し、Being が自分の見出しで出す: Being の契約が変わる。いま Being が、知っていることを世界の前提と分けて扱う場面が無い

### 3. 観測の時刻は、何日目と時:分で見せる

いまの仮の札 `tick 13` を、何日目と時:分に変える。時:分は、昼夜の宣言 (`DayNightDeclaration`) の 1 日の tick 数から割り出す (1 日 = 24 時間)。シナリオに新しい欄は要らない。

| | 決まり |
|---|---|
| 何日目 | 世界が始まった日を 1 日目とし、日付は 00:00 で変わる。`(starts_at + now) // ticks_per_day + 1` |
| 時:分 | `time_of_day_at(now)` の 1 日の中の位置を 24 時間に割り当てる。1 tick は `24 時間 / ticks_per_day`。割り切れないときは、0 時からの分を `tick_of_day * 1440 // ticks_per_day` で切り捨てる |
| 割り出す場所 | 昼夜の宣言が `DayNightDeclaration.day_and_clock_time_at(now) -> DayAndClockTime` で返す。`DayAndClockTime` は何日目・時・分を持つ値。文にするのは観測の出口。`NoDayNight.day_and_clock_time_at` は、ほかのメソッドと同じく `NotDeclaredInThisWorldException` を投げる |
| 昼夜の無い世界 | ステージ 8 では扱わない。run の入口で `is_declared()` を確かめて止め、知らせる。表示は、要るシナリオが出たときに決める |

例:

- 廃坑の山村 v2 は 1 日 48 tick、`starts_at` は 0 なので、1 tick は 30 分になる。61 tick にゲンが金庫を開けると、61 = 48 + 13 で、記憶の行は `[2 日目 06:30] ゲンが金庫を開けた` になる
- 1 日 48 tick、`starts_at` が 36 (18:00) の世界では、0 tick は `1 日目 18:00`。13 tick は 36 + 13 = 49 = 48 + 1 なので、`2 日目 00:30` になる

**採らなかった案**:

- 何日目と時間帯の名前 (`[2 日目の朝]`): 時間帯ごとに表示の名前の欄を足す必要があり、朝のうちの前後が分からない
- `tick 13` のまま: エージェントには何時かが分からない
