# 目的層 (goal layer) の設計 — 能動的推論を「構造だけ」借りる

> 2026-07-09。unified_full_001 の分析
> ([unified_memory_full_run_analysis_2026-07-08.md](./unified_memory_full_run_analysis_2026-07-08.md))
> で見つかった「効用勾配の不在」(同 §3.4) と R6 改訂の続き。要求は
> R6 の一般化: **シナリオが無くても — ただ世界があってそこで生活する
> だけでも — エージェントが自分の目的を持ち、それに向かって行動する**こと。
> 能動的推論 (active inference) / 期待自由エネルギー (expected free energy)
> を参考にするが、そのまま真に受けない (借りるものと借りないものを
> 冒頭で固定する)。ステータス: 2026-07-12 レビューでほぼ合意
> (§2.1 / §4 の詳細化はレビュー Q&A を反映)。PR 分解は
> [unified_memory_phase2_implementation_plan.md](./unified_memory_phase2_implementation_plan.md)
> (G1〜G4 = P5〜P8)。

## 1. 能動的推論から借りるもの・借りないもの

能動的推論は「生物は自由エネルギー (予測の外れやすさ) を最小化するように
知覚し行動する」という枠組みで、行動選択は期待自由エネルギーの最小化 =
**実利的価値** (選好に合う観測を得る) と**認識的価値** (不確実性を減らす)
の合成として定式化される。

### 借りる (構造)

1. **選好は予測である**: 目標は報酬関数ではなく「自分はこういう観測を
   見るはずだ / 見たい」という**選好の事前分布**として表現される。
   「望む」と「予測する」を同じ器に入れる — これにより目的の非達成が
   予測誤差として、既存の evidence 漏斗にそのまま流れる
2. **認識的価値**: 不確実性の削減それ自体が行動の動機になる。
   行動は仮説検証 (実験) である
3. **階層とタイムスケール**: 速い層は行動を、遅い層は文脈 (目的) を
   予測し、上位が下位に文脈を与える。既存の 3 段のはしごの時間軸拡張
   (R6-b) と同型
4. **恒常性が選好の原型**: 生理信号 (空腹) が最も原始的な選好的予測で
   あり、実際に unified_full_001 で行動を支配した実測がある (同 §4.4)

### 借りない (文字通りにしない)

1. **自由エネルギー / 期待自由エネルギーの数値計算**: LLM に効用や情報
   利得を数値で計算させるのは偽精度。トレードオフの判断は文脈内の
   意味判断に任せる
2. **選好の数値ベクトル**: ペルソナの価値観 (自然文) がその役割を既に
   果たしている。数値化しない
3. **探索ボーナス項のハードコード**: 好奇心の強さはペルソナの一部として
   自然文で表現する。全員一律の探索係数は作らない
4. **「すべての行動は推論である」の教義**: 実装の指針にならない
   形而上学は置いていく

## 2. 中核: 目的 = 取り下げない選好的予測

unified_full_001 §4.4 の実測が出発点になる:

> 空腹は【身体の状態】として毎ターン観測され、悪化が感じられる。
> 目的はテキストとして与えられるだけで、前進も後退も感覚信号を持たない。
> 感じられる駆動が、テキストでしかない駆動に構造的に勝つ。

**空腹は世界が勝手に誤差を作ってくれる。目的は、自分で立てた予測だけが
誤差を作れる。だから「目的を持つ」とは、取り下げない予測を自分に課す
ことである。**

これを既存部品に写すと:

- 目的 = 選好的な pending prediction (「N 日以内に山頂で狼煙を上げて
  いるはずだ / いたい」)。器は U10 のまま
- 目的の非達成 = U10b の清算がそのまま誤差化する。専用の停滞検出器は
  要らない (R6 初版のルール検出を棄却した判断と整合)
- 目的の階層: 行動予測 (1 ターン、`expected_result`) → 方針予測
  (N ターン、R6-b) → **目的 (数日〜、本メモ)** → 価値観 (不変、ペルソナ)。
  すべて同じ PredictionOutcome の時間スケール違い

### 2.1 「取り下げない」の意味 — 誤差の消し方は 2 通りある

予測誤差が出たとき、消す方法は 2 つある。**予測の側を直す** (「チェスト
に道具があるはず」→ なかった → 信念「空のこともある」に更新。世界に
合わせる) か、**世界の側を直す** (行動して現実を予測に近づける) か。
この向きの違いが belief と goal の違いのすべてである:

- belief: 外れたら予測を修正して終わり
- goal: 「自分は救助されているはずだ / いたい」— 外れても取り下げない。
  代わりに狼煙を上げる。**現実を予測に合わせるのが行動であり、
  それを選び続けることが「望む」の実装**

この形にする実装上の利得は 3 つ:

1. **目的と信念が同じデータ構造に乗る**: どちらも予測なので、pending
   prediction の器・清算 (U10b)・evidence 漏斗を共有できる。違いは
   更新ポリシーだけ — belief は無意識 (固着パス) が改訂してよい、
   goal は意識 (G2) しか改訂できない
2. **目的が「感じられる」ようになる**: 現状の目的は静的テキストで、
   目的にまつわるイベントが system 内に一度も発生しない (実測:
   unified_full_001 の belief 23 件に山頂ルート関連ゼロ — 目的は
   evidence の流れに一度も現れなかった)。予測の形なら清算のたびに
   「まだ達成されていない」という誤差イベントが発生し続け、空腹と
   同じ種類の鼓動のある信号になる
3. **諦めが一級の出来事になる**: 取り下げは G2 の意識的決断としてだけ
   起き、abandoned は journal に残り、諦めの瞬間の大きな誤差が
   「この島で救助を待つのは現実的でない」型の belief の素材になる。
   **諦めた夢を覚えていて、そこから学ぶ** (設計原則 #4)

## 3. 目的はどこから来るか (シナリオなしで)

3 つの生成源。いずれも既存の素材で表現できる。

| 生成源 | 能動的推論での対応物 | 例 |
|---|---|---|
| ペルソナの価値観 + 生理 | 選好の事前分布・恒常性 | 「まずは生き延びる」+ 空腹上昇 → 目的「食料の確保」 |
| belief (世界モデル) | 目的の**免許** — 信じている可能性だけが目的になれる | 「山頂で狼煙を上げれば救助される」という belief が「山頂へ行く」を目的として成立させる |
| 社会・自己像 | 遅い事前 (L5 / 約束) | 「私は医師だ」(L5 self_image) → 「怪我人を診る」。約束 (U10) の目的への昇格 |

シナリオとの互換: 【現在の目的】をシナリオ静的テキストから goal store の
描画に置き換え、**シナリオは初期値の注入に退化する**。勝利条件のある
ゲームは初期目的を locked (改訂不可) にすれば従来どおり、open world は
unlocked で自己生成に任せる。1 つの機構で両方をカバーする。

## 4. 機構 — 意識と無意識の分担

記憶の設計で確立した分担 (行動 = 意識、記憶処理 = 無意識、
[prediction_error_unified_memory_design.md](./prediction_error_unified_memory_design.md) §4)
を目的にも適用する。**不安は下 (無意識) から滲み、決断は意識がする**。

| 処理 | 担当 | 実装 |
|---|---|---|
| 目的の生成・改訂 | **意識** (エージェント自身) | 常時使える同乗フィールド `goal_update` (下記 G2。2026-07-12 改訂) |
| 目的の監査 (停滞・矛盾・達成の検出) | **無意識** (固着パス reflect = R6-a) | 検出結果は内省観測「ふと振り返ると…」として意識に上げる。**書き換えはしない** |
| 目的の非達成の誤差化 | ルール (U10b 清算) | 期限・cue による清算 → evidence 漏斗へ |
| 選好の原型 | ペルソナ価値観 + 生理 (既存) | 変更なし |

### 作業項目 (G 系)

- **G1 — goal store**: per-Being の journal 方式 (belief journal と同型:
  改訂は supersede、履歴は消えない)。【現在の目的】を store から描画。
  シナリオは初期値 + locked flag。snapshot 追従 (checklist #27)。
  **目的の履歴が自伝になる** — 「あの頃は生き延びることしか考えて
  いなかった」を後から想起できる。自己の継続性 (設計原則 #4) に直結
- **G2 — 意識的な更新入口 (2026-07-12 改訂)**: 専用ツール (`set_goal`)
  案は棄却 — 1 ターン 1 ツールの制約下で目的変更に丸 1 ターン消費させると
  能動想起と同じ「使われない機能」になる。既存の主観フィールド
  (`inner_thought` 等) と同じ**行動ツールへの同乗フィールド**
  `goal_update` (optional, nullable) を、**run 全体で常時露出**する。

  > 初版の「更新トリガのターンだけ schema に許可する」は撤回した。
  > 理由 1: 設計判断 #1 (tool list は tick 間 byte 不変。プレフィックス
  > キャッシュ) に反する。理由 2: schema 不変のままサーバ側で書き込みを
  > ターン限定すると「schema は誘うのに黙って捨てる」というエージェント
  > が知覚できないルール = 静かな失敗になる。理由 3: 守るべき不変条件は
  > 変更の頻度ではなく**高度** (目的が次の 1 手 = intent に退化しない
  > こと)。目標が状況で変わること自体は不自然ではない

  高度の防衛は schema 説明文で行う (`intention` との対比が鍵):
  「数日スケールの方針を捨てて立て直すときにだけ書く。次の 1 手の意図は
  intention に書くこと。目的を変えることは、これまでの自分の方針を
  捨てることでもある。続けるなら書かない」。頻度は機構で強制しない —
  説明文の摩擦 + journal での churn 観測 + 実測で退化が出たら
  min-interval cap を定数 1 個 (発動時も観測で返し silent にしない)。
  書けば store が supersede で更新、書かなければ現状維持。locked は
  拒否 + 観測で本人に返す。旧トリガ (salience=high / 清算 / 生理閾値 /
  無為) と【目的の見直し】section は v1 から削除し、「気づき」の役割は
  G3 の内省観測へ、「目的なし」の需要信号は【現在の目的】の
  「(まだ定まっていない)」描画へ移管する
- **G3 — 監査の接続**: R6-a の reflect の監査対象を「シナリオ目的」から
  goal store へ。停滞・矛盾 (目的と行動が乖離)・達成の 3 種を検出し
  内省観測化。**停滞 ≠ 即改訂** — 粘るか諦めるかは意識 (G2) の判断で、
  その傾向自体がペルソナ表現 (固執的な者 / 見切りの早い者)
- **G4 — 目的の予測化**: 目的を選好的 pending prediction として保持し
  U10b で清算 (= R6-b の目的への拡張)。達成は大きな CONFIRMATION、
  非達成は大きな誤差として belief (「この島で救助を待つのは現実的で
  ない」等) の素材になる
- **G5 (将来) — 認識的価値**: ヘッジつき belief (「〜かもしれない」) は
  可視化された不確実性であり、「確かめに行く」= 行動の仮説検証化の
  素材になる。unified_full_001 で誰も大樫の樹 (地形開示の仕掛け) に
  登らなかったのは、「自分は地形を知らない」という不確実性が感じられる
  形で提示されていないから。まずは【関連する学び】に conf/sup を
  文面で滲ませる (「まだ 1 度しか確かめていないが…」) 程度の軽い
  実装から。探索係数のハードコードはしない

## 5. 質感シナリオ (open world での目的の一生)

シナリオなしの世界に置かれた慎重なペルソナのエージェントで:

1. 生理と価値観から最初の目的が立つ (「安全な寝床と食料を確保する」)
2. 満たされる → G4 の達成清算 → 無為トリガ (G2) → ペルソナの好奇心から
   次の目的 (「この土地の全容を知りたい」)
3. ヘッジ belief を確かめる行動 (G5) の途中で他者と出会い、約束 (U10) が
   生まれ、対人の目的に昇格する (「明日、川で待ち合わせる」)
4. 目的が競合したとき (安全 vs 好奇心) の選択はペルソナが決める
5. 数百 tick 後、goal journal を振り返ると生活の章立てになっている

このループのどこにもシナリオ固有の知識・報酬関数・数値効用は現れない。

## 6. リスクと逃げ道

- **目的の揺れ (毎回書き換わる) / intent への退化**: G2 の schema
  説明文の摩擦 (`intention` との層の対比) + journal (履歴が残るので
  churn 自体が観測・分析できる) + 実測で退化が出てから min-interval cap
  (定数 1 個、発動時も観測で返す)。固執と柔軟のバランスはペルソナに
  委ね、全員一律の閾値を先回りで作らない
- **壮大化・空虚化** (open world で「世界を救う」等の浮いた目的):
  belief による免許 (§3) が抑制になる — 信じている可能性の範囲でしか
  目的は立たない。初期の目的は生理と出会いが供給するので素材不足には
  ならない
- **シナリオ互換の破れ**: locked 初期目的で従来挙動を保証。flag OFF なら
  現行の静的テキストのまま (default OFF の原則どおり)
- **監査 (無意識) が意識を乗っ取る**: reflect は観測を注入するだけで
  goal store に書かない、を不変条件にする (テストで固定)

## 7. 実装順とテスト

**実装上の好材料 (コード確認済み)**: 【現在の目的】は
`objective_text_provider: Callable[[PlayerId], str]`
(`prompt_builder.py:351, 507, 951`) として既に注入可能な口になっている。
G1 の差し替えは wiring 層で完結し、**prompt_builder は無変更**。
シナリオの目的は「provider が毎ターン返す固定文字列」から「run 開始時に
goal store へ 1 回 seed される locked 初期値」に変わり、locked なら
描画結果は現状と同一 — 既存シナリオの挙動不変を質感テストで固定できる。

**G4 の清算の引き金 (2026-07-12 確定)**: 本人の自己申告。`goal_outcome`
(achieved | abandoned) を goal_update と同じ同乗フィールドで常時露出し、
宣言された遷移だけをルールが evidence に転記する。reflect (無意識) は
「達成したようだ」の内省観測で促すだけで store には書かない — 検討した
「reflect verdict からのルール直結」は不変条件違反 + 周期起因の誤ラベル
(達成直後の更新が abandoned 扱いになる) のため棄却。詳細は実装計画の P8。

G1 → G2 → G3 (R6-a と同 PR でも可) → G4 (U10b 依存) → G5 (将来)。
G1/G2 で「シナリオ目的の store 化 + 見直しターン」が動けば、v2/v3 系
シナリオは locked のまま何も変わらない (質感シナリオ pytest で保証)。
open world の検証は、シナリオイベントなしの `persistent_world_demo` 系
での短 run + goal journal の目視から始める。L2 replay の対象は G2 の
見直しプロンプト (トリガ素材を再投入し、目的の改訂が自然か・揺れないか)。
