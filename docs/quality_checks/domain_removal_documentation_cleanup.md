# ゲームのドメイン整理後の構成案内

Issue #1893の文書担当。#1902〜#1905を取り込んだmainの構成と保存互換を説明する。コードや過去の設計判断の本文は変更しない。

## 更新する説明

- 本番の追跡はスポットのCHASEを使い、旧`domain/pursuit`を使わない。
- スポット移動の`PlayerSpotNavigationState`と、旧タイルの`PlayerNavigationState`の退役を区別する。
- スキルの装備・消費と、除去した当たり判定の形・速度・追加効果を区別する。現行の状態異常は残す。
- 天候は`SpotGraphWeatherChangedEvent`から実行環境が通知し、旧`SpotWeatherChangedEvent`の観測経路は持たない。
- 世界の旧追跡キーとBeingの廃止宣言は別の入口で読み捨て、記憶本文の削除キー表へ混ぜない。
- SQLiteの過去の列を保持することと、旧値をドメインへ復元することを分けて説明する。

CLAUDE.mdの領域一覧は既に短縮され、構成案内を参照する形になっている。旧一覧は再導入せず、保存キー廃止時の案内だけを補う。モンスターの座標・物体IDの削除は別の実装PRが担当し、共有の`Coordinate`型まで削除したと読める説明にはしない。

## 検証

基準は`5fa0abd4ec541c906ae1ca7a3ec690b97ed7e183`。マージ前の統合HEADとmainのソースが一致することを確認した。

- 先行4PRの合流後の関連試験2,516件、mypyの1,242ファイルが成功。
- 合流の独立レビューは全重大度で指摘0件。独立側の観測試験92件も成功。
- 合流後のsmoke_stubと山村・避難訓練各3シード40tickが成功。削除前の基準と全記録種別・観測種別・行動件数が一致（1,990観測・1,205行動）。実LLM・`.env`読込なし。
- 文書変更後にローカルリンク39件の参照先が存在することと、空白検査を確認。
- 独立監査で、世界snapshotの登録にモンスター個体やグラフ上のモンスター位置が含まれないことと、実行環境の初期構築後に復元する順序を確認した。SQLiteの個体保存と世界snapshot再開を区別し、個体の復元を保証しない既存の制限を構成案内へ明記した。

これらの実行確認は先行PRの統合時に行ったもので、文書だけの変更による再実験は行わない。本PRの最新HEADのCI結果と、モンスターの座標整理を含む最終照合の結果はPR本文へ記録する。

## 質感と限界

実行時の変更はないため、観測や行動の質感の改善を主張しない。旧実装を現役と読み違えず、現在の発火・配信・保存の入口をたどれるようにする。履歴と明示された旧計画・監査・設計判断は保存する。#1893の分類2・3の改名や、Being記憶・イベント基盤・シナリオの再設計は扱わない。
