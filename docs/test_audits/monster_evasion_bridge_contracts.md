# モンスター回避の計算入力とHP保持の試験契約

## 目的と範囲

モンスター集約の監査で残っていた元24、`test_application_style_damage_flow_evaded` の1宣言を、共通計算と直接回避の既存試験へ統合する。判定はC1。先行107契約を重ねて数えない。

回避率0.03・乱数0.0の計算入力と、無傷HP100の保持・回避通知の5確認を先に移し、元宣言を残した成功と同じ故障による旧新対照を確認してから元24だけを除去した。製品の動作は変えない。

基準は [#1732](https://github.com/Motifman/llm-rpg/pull/1732) の固定先端 `a6865234d94edb5cd4e6e7141772a702692756e8`、基準ブランチは `codex/test-audit-player-combat-bridge-20261014`。この変更はその先端に対する限定差分で、#1732のマージは前提にしない。

[#1733](https://github.com/Motifman/llm-rpg/pull/1733) の固定先端 `f9882c20800b6b1faa76cbca8cac3da788a37ddc` は兄弟であり、#1732の祖先ではない。別作業木でその固定Monster試験、#1732の固定計算表、今回の限定差分を併用して確認した。#1733の無関係な差分は主変更へ取り込んでいない。

## 計算の全入力を保つ

能力値の順序は `max_hp, max_mp, attack, defense, speed, critical_rate, evasion_rate`。既存2行と追加行は次のとおり。

| 行 | 攻撃側 | 防御側 | 乱数条件 |
|---|---|---|---|
| 元の計算行 | `(100,50,50,20,10,0.0,0.0)` | `(100,50,20,30,10,0.0,1.0)` | 試験本文では固定しない |
| 先行Playerの移管行 | `(100,50,40,10,10,0.0,0.0)` | `(100,50,20,15,10,0.05,1.0)` | 試験本文では固定しない |
| 元Monster24の移管行 | `(100,30,50,5,12,0.0,0.0)` | `(100,50,20,15,10,0.05,0.03)` | この行だけ `random.random` を0.0に固定 |

全行で倍率と設定の引数は省略し、既定値を使う。`damage.is_evaded is True` と `damage.value == 0` の既存確認も保持する。既存2行に追加行の乱数固定を一律適用しない。

既存2行だけでは、回避率が1.0の場合にしか回避しない誤実装を検出できない。同じ故障を入れると、旧Monster24はHP58となって失敗し、新しいMonster計算行は回避旗の確認で失敗した。既存計算2行は通過したため、追加行が保持する差を区別できる。

元24は回避時の `damage.value` を使用せず、0を直接確認していない。損傷0は計算保持先の既存確認であり、「元24がその値の故障を検出していた」とは主張しない。

## 集約の全入力と確認を保つ

共通準備は不変更。MonsterId1、WorldObjectId1001、TemplateId1、SpotId1、SkillLoadoutId1／所有者1001／容量10・10を使う。テンプレートはSlime、Race.BEAST、ENEMY、報酬exp100/gold50/loot1、復活間隔100・自動復活あり。

| 行 | 出現座標・時刻 | 回避前の損傷 | 確認する実HP・通知HP |
|---|---|---|---|
| 元25の負傷行 | `(2,3,0)`、tick0 | 20、tick1 | 80 |
| 元24の無傷行 | `(1,1,0)`、tick0 | 適用しない | 100 |

両行とも出現と必要な損傷の後で通知を消し、`record_evasion()` を1回呼ぶ。無傷行は損傷0を適用する行ではなく、損傷適用そのものを行わない行である。期待座標は入力オブジェクトから生成せず、表内の独立した固定辞書を使う。

元25の負傷行には次の8確認があった。全てを同じ負傷条件で残した。

1. 通知件数1
2. `MonsterEvadedEvent` 型
3. `aggregate_id == monster.monster_id`
4. `aggregate_type == "MonsterAggregate"`
5. 座標 `{"x": 2, "y": 3, "z": 0}`
6. 通知の `current_hp == 80`
7. `event_id` が存在
8. `occurred_at` が存在

元24の5確認は、新しい無傷行へ全て移した。

| 元24の確認 | 保持先での確認 |
|---|---|
| 実HP100 | 回避後に `monster.hp.value == expected_hp`、無傷行の期待値100 |
| 通知件数1 | 共通の `len(events) == 1` |
| 回避通知型 | 共通の `isinstance(event, MonsterEvadedEvent)` |
| 座標(1,1,0) | 無傷行の固定辞書と通知座標を比較 |
| 通知HP100 | 無傷行の固定期待値100と `event.current_hp` を比較 |

実HP保持の確認は負傷行にも追加した。元25はもともと通知のHPだけを検査し、回避後の実HPを確認していなかった。正しい通知を作った後に実HPだけを1減らす故障では、旧直接API試験は通り、旧元24と新直接APIの両行が実HP確認で失敗した。

## 所有者と保持判断

- 数値と回避旗の所有者は `CombatLogicService.calculate_damage`。防御側の回避率を乱数と比較し、成立時に `Damage.evaded()` を早期返却する。入力の `BaseStats` は凍結値で、集約のHPへ触れない
- 状態と通知の所有者は `MonsterAggregate.record_evasion()`。計算結果の `Damage` や数値を受け取らず、生存状態と座標を確認し、現在の座標・HPで回避通知を追加する
- 元24の `monster.template.base_stats` は保存された凍結能力値を返す。全7値を計算所有者へ保存し、無傷集約の状態・通知を直接操作側へ保存すれば、この合成だけに残る可変状態や値の受渡しはない
- 元23成功側は計算値を `apply_damage` へ渡して実HP58と通知損傷42を検査するため、今回の回避側と一括処分しない。本文をそのまま残した

履歴は [`1cf0e10`](https://github.com/Motifman/llm-rpg/commit/1cf0e10b10ab80a45380695c6798dde5542c5bf5)。集約内の `take_damage` から計算を分離し、`apply_damage` と `record_evasion` へ整理した際に、元の回避入力が計算＋試験内分岐へ移された。手書きのifであることだけを削除理由にせず、入力と確認の全てに主担当を置いた。

本番の呼出元は `HitBoxDamageHandler`。`CombatEventHandlerRegistry` が `HitBoxHitRecordedEvent` へ登録し、実効能力・HitBox倍率で計算した後に回避か損傷かを分岐する。元24はこのハンドラを呼ばない。既存の関連7件も回避経路を通す入力ではないため、今回の試験を本番回避の分岐・保存・配送の証明とは呼ばない。この未検査は元24の削除によって新たに生じるものではない。
