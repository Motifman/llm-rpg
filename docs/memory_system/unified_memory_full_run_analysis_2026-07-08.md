- **S7 (学びの成長)**: ○。「浜辺では目立った発見はない」が 1 件のまま

さらに設計に書いていない良い性質が 2 つ確認できた:

discard ゲートの判断理由も設計意図どおり読める:

「泉での釣竿使用の予測が当たったという確認だが、具体的な学びとして
一般化できず廃棄」。

### 3.2 弱点 1: ヘッジ凍結 — supersede / revise = 0

23 件の belief の多くが「〜かもしれない」「〜ことがある」で終わる
(p3 は 7 件中 5 件)。**これは LLM の弱気ではなく sup1 / conf0.5 時点の
正しい較正**である。問題は機構側にある:

- strengthen は `support_evidence_ids` を積み confidence を上げるだけで、
  **文面は最弱証拠時点の表現のまま凍結される**
- 「干潟への移動中に大型カニに襲われる危険がある」は sup4 / conf0.8 まで
  育ったのに、文面を証拠に見合う強さへ改訂する動きが一度もない
- 予測 (`expected_result`) を動かすのはプロンプトに載る**文面**であって
  confidence の数値ではない。conf が育っても文面がヘッジのままなら、
  学びの行動への効果は sup1 の頃と変わらない

原因は固着プロンプトが revise を「間違いの訂正」としてしか提示して
いないこと。「証拠が増えたときの言い切りへの強化」も revise の正当な
用途だと教えていない。修正は R3 (プロンプト 1 段落)。

### 3.3 弱点 2: CONFIRMATION は動いたが関連性を見ない

発火条件 (in-context belief 非空 + expected_result あり) は belief と行動の
関連を確認しないため、「travel_to で隠し入江に戻れた」のような自明な的中が
無関係な belief の支持に化けうる。ただし全否定はしない — 両面の実例がある:

- **正当な信用割り当ての例**: conf1.0 / sup10 の「浜辺では目立った発見は
  ない」。この belief を文脈に持って浜を探索し「実際に何もない」が反復して
  支持が積まれた。しかもこの belief は沿岸の罠から抜ける方向を指す
  唯一の強い信号だった
- **自衛の実例**: 固着 LLM が無意味な confirmation を discard で弾いている
  (上記の泉の釣竿の例)

よって機構の削除ではなく**関連性ゲートの追加** (R4) が正解。あわせて
confirmation の confidence 寄与を誤差より軽くする重み付けを入れる。

### 3.4 弱点 3 (最重要): 世界の法則は学ぶが、目的の前進を学ばない

p3 の最強 belief「難破船の浜の探索は岩礁海岸への道の手がかりとなる
(conf0.9, sup5)」は、**忠実に学習された有害な信念**である。

- 岩礁海岸は行き止まり (BARRIER 封鎖)。この belief は最高の確信度で
  p3 を袋小路のクラスタに縛った
- sup5 まで育った理由: 浜を探索すると岩礁海岸への言及 (手がかりらしき
  もの) は**実際に見つかり続けた**。「探索すれば言及が見つかる」という
  予測は当たり続けた — 局所的な世界法則としては真
- 一方、目的 (山頂で狼煙) に対して 115 tick 停滞していることを誤差として
  検出する機構はどこにもない。23 件の belief に山頂ルートへの前向きな
  命題は 1 件もない (最接近は p3 の弱い否定形「岩礁海岸では山頂への
  手がかりは見つからないかもしれない」conf0.5)

これは統一原理の破綻ではなく境界の発見である。**予測誤差は世界の
ダイナミクスの学習信号であって、効用の勾配を含まない**。原理
(記憶 = 世界モデルの圧縮学習) は正しく動き、エージェントは行き止まりに
ついての優れた世界モデルを構築した。欠けているのは記憶ではなく
**戦略層** — 「この方針は目的を前進させるはず」という暗黙の予測と、
その破れの検出。最小の実装案は R6。

### 3.7 能動想起の再解釈 — 「壊れた機能」ではなく「需要駆動の機能」(2026-07-09 追記)

使用 1 回を「ほぼ死んだ機能」と書いたが、レビューを受けて読み直す。
使われない原因は能力不足ではなく**需要の不在**である:

1. **ギャップの体験が発生しない**: 受動想起は毎プロンプト自動で走り、
   【関連する記憶】が常に埋まる。能動想起の需要は「思い出せない」という
   欠落の自覚から生まれるが、その欠落をエージェントはほぼ体験しない
2. **機会費用の構造**: 1 ターン 1 ツールの制約下で、想起は移動・探索・
   発話と同じ枠を奪い合う。期待値が見えない想起は、目前に直接価値の
   ある行動がある限り常に後回しになる
3. **需要の発生条件がシナリオに無い**: 能動想起が要るのは「過去について
   問われた」「受動想起が空なのに過去を語る必要がある」とき。survival
   シナリオには尋問的な対話がほぼなく、需要 ≈ 0

人間も能動想起は需要駆動である (問われて思い出す、喉まで出かかって
探しにいく)。日常の想起の大半は cue 駆動の自動想起で回っており、
**「無くても回っている」のは受動想起が十分に働いている健全な状態**と
読むのが正しい。

対応方針 (優先度は据え置きだが「放置」から「測り方を変える」へ):

- **使用を促さない**: プロンプトで能動想起を push するのは偽の使用を作る
  だけで、質感を壊す
- **測定を需要正規化する**: run あたりの使用回数ではなく「需要イベント
  (過去への質問・受動想起が空のまま過去に言及する局面) あたりの使用率」
  を指標にする。分母が 0 に近い run で分子を数えても意味がない
- **需要の多いシナリオで再評価**: 情報非対称・尋問型 (`recall_probe_v*` /
  禁書庫系) が本来の検証場。協力シナリオ v3 (R9) では「相手が知っている
  はずのことを聞く」需要が構造的に生まれる
- **発見性は afterglow 経路に寄せる**: `memory_recall_by_handle` (見出し
  index → 引き戻し) は「そこに何かある」が見えるぶん、白紙から問いを
  立てる generic な能動想起より人間の想起にも近い。能動想起の主経路は
  こちらと考える

## 4. (B) 物語的分析

### 4.1 学びの分布がペルソナを写す (設計外の創発)

予測誤差学習は「予測する気がある対象」についてしか学ばない。結果として
**ペルソナが学習カリキュラムを決める**:

| 人物 | belief の内訳 | 対応するペルソナ |
|---|---|---|
| p3 リオ (寡黙・独走) | 7/7 が地形・手続き。人物 belief 0 | 人に予測を立てないので人について学ばない |
| p4 カイ (ムードメーカー) | 5 件中 4 件が社会的 (リオ関連 3 + 「他の人が調べた場所」) | 人に予測を立てる (約束 6 件) ので人について学ぶ |
| p1 エイダ (医師・情報整理役) | 手続きと環境の慎重な一般化 | 観察的な気質どおり |
| p2 ノア (リーダー) | 危険と安全 (カニの道・安全な合流地点・開かない箱) | 集団の安全を予測する立場どおり |

これは仕様に書いていない性質が機構の合成から出てきたもので、
設計原則 #3 (質感は機能の総和ではない) の実例として記録に値する。
人間も「何を学ぶか」は何を学んできたか・どんな状態かに依存する —
予測誤差駆動システムの結果として、現時点で最も面白い創発。

**反証可能な追試 (提案)**: 同一シナリオでペルソナだけを入れ替える
(リオに社交家、カイに寡黙を与える) run を回し、belief 分布の軸
(社会 / 地形) が人物についていくかペルソナについていくかを見る。
ペルソナについていけば「ペルソナがカリキュラムを決める」は因果として
確定する。1 run で足り、既存の trace 集計で測れる。

**裏面のリスク (盲点の自己強化)**: 人に予測を立てない者は人について
学ばず、学ばないから対人の belief を持たず、持たないから予測も
立てない — 寡黙さが自己強化するループになりうる。短期 run では
人間らしさだが、長走 (数千 tick) では人物の固定化・カリカチュア化と
して現れる可能性がある。長走実験の観測項目に「belief 分布の軸の
経時変化」を足しておく。

### 4.2 カイ→リオ: 片思い的な弧と両価的な人物理解

カイはリオ宛の約束を 6 件作り (t32 山頂ルート、t99 河口で釣り、t110 川の
上流…)、t99 に「リオがナイフを持っている前提で行動したが、先に彼と話す
べきだった」と自省し、t107 に取り残されて salience=high の傷を負い、
「リオは話をちゃんと聞いていないことがある (conf0.8)」に至る。それでいて
「リオは釣り場の情報を提供してくれる (conf0.5)」も併存する —
**失望しても関係を単色に塗り潰さない**。リオ側にカイの belief が皆無という
非対称も含め、人間の関係の質感になっている。U10b が入れば、この 6 件の
約束の破れが人物 belief の反証として形式的にも清算される (R5 の検証素材)。

### 4.3 カニ危機は結束イベントとして機能した

t18〜25、ノア 4 連続被弾 →「加勢するよ！」→「一旦引いて隠し入江に
逃げるのも手かもな」→ 退避。ここから「隠し入江は安全な合流地点だ」
(p2, conf0.5) が生まれた。**共有された危機から場所への愛着が生まれた** —
感情的に構造化された記憶の実例。

### 4.4 有能な戦術、不在の戦略

狼煙の材料は t25 に揃った (速い)。残り 115 tick はルート探しの漂流と
飢餓。リーダーのノアの belief はカニと箱についてであり、島の地形に
ついてではない。誰もマクロ計画を保持していない。皮肉の頂点は結末にある:
**t140、p3 は山頂の 2 ホップ手前の山麓に立っていたが、目的は食料だった**。
ミッションではなく空腹が正解ルート (河口→上流→泉→山麓) を歩かせた —
効用勾配を持たないエージェントを、生理的な勾配だけが正しい方向へ押した。

感情の弧: 希望 (t1 所持品共有と役割分担) → 危機と結束 (カニ) →
漂流 (方針喪失) → 飢餓 → 静かな TIMEOUT。主題文は t137 p3
「探索すれば何か手がかりが得られると思ったが、何も見つからなかった。
空腹で倒れるとは思わなかった」— 世界モデルは学ばれた、ただし遅すぎた。

**なぜ生理的勾配が勝ったのか (2026-07-09 追記)**: 「生存を第一目標と
するエージェントが救助 (長期目的) に向かうのは非自明」というレビューの
指摘はそのとおりで、しかも構造的に説明できる。空腹は【身体の状態】
として**毎ターン観測され、悪化が感じられる**。目的は【現在の目的】の
テキストとして与えられるだけで、前進も後退も感覚信号を持たない。
予測誤差も空腹については発生する (t137「空腹で倒れるとは思わなかった」)
が、目的の停滞については発生しない。つまり**感じられる駆動が、
テキストでしかない駆動に構造的に勝つ**。人間も同じで、内受容感覚を
持つ欲求 (空腹・痛み) は自動で行動を動かすが、長期目標は内的
シミュレーションで勾配を自作しなければ動かない。これが R6 (改訂) の
設計根拠になる — 目的に「感じられる信号」を与えるのが戦略層の実体。

## 5. (C) シナリオ難度 — 「クリアされない」の帰属

### 5.1 140 tick ではクリアは物理的に不可能 (実験設定の問題)

`rescue_at_ticks=[192, 288, 336]` — 最初の救助機会は tick 192 (Day 4)。
run は 140 tick で終わる。**この構成ではどんな行動主体でも救助は不可能**。
TIMEOUT はエージェントの失敗の証拠ではなく、観測期間と成功判定の
ミスマッチである。140 tick で誠実に測れる中間進捗は: 材料確保 t25 (達成)、
山頂到達 (未達)、狼煙点火 (未達)。

### 5.2 では伸ばせばクリアされたか — 半々 (シナリオ JSON の一次確認)

`data/scenarios/survival_island_v2.json` を直接確認した結果:

1. **spawn 周辺の情報勾配がゼロ**: 沿岸クラスタ (難破船の浜・拠点・干潟・
   岩礁海岸・隠し入江) のスポット記述に内陸 (河口 / 山 / 上流 / 高地) への
   言及が**一切ない**。内陸への手がかりは内陸に入ってから初めて現れる。
   最初の脱出は純粋なランダム探索頼みで、しかも沿岸には「探索すると
   何かの言及は見つかる」というノイズ (p3 の conf0.9 belief を育てた餌) が
   撒かれている。**環境自体が誤った事前分布を教えていた**
2. **設計された解決手段が未発見**: 「大樫の樹 — 樹上からなら島の地形が
   よく見えるはず」という地形開示の仕掛けがあるが誰も使わなかった
   (崖の見張り台も同様)。想定解は「登って地図を得る」で、難度の本体は
   ルート長 (7〜8 ホップ + 山麓の分岐 + 蔓ロープ前提) ではなく
   **見晴らし台の発見性**
3. エージェント側の欠陥も実在する: (a) 3.4 の戦略層不在、(b) 知識の
   非共有 — カニの教訓を 3 人が別々に学び直し、memo に書かれたルート
   知識が口頭で伝播しない

**結論**: 短期の「クリアされない」は実験設定の問題。長期でも危ういのは、
シナリオの情報設計 (沿岸に内陸ヒントなし + 見晴らし台の発見性) と
エージェントの構造欠落 (目的勾配・知識共有) の**合算**であり、
どちらか一方に帰属させる読みは誤り。シナリオ側の作り直しは R9
(協力検証用 v3) として設計する。

## 6. 改善提案 (ROI 順) と実装スケッチ

> 2026-07-12 追記: 本節の R 系と goal 層 / HEARSAY を PR に分解した
> 実装計画は
> [unified_memory_phase2_implementation_plan.md](./unified_memory_phase2_implementation_plan.md)。
> なお前提 1 (U10b 未マージ) はその後解消済み (main にマージ済み)。

### R1. 実験設定の修正 (コードほぼゼロ・最優先)

これを直さない限り、今後のどの run も「クリアできるか」に答えられない。

- 変種 `data/scenarios/survival_island_v2_short.json` を作る:
  `rescue_at_ticks=[96, 144]`, `stranded_at_tick=192` に前倒し
  (または run を 220+ tick に伸ばす。コストは 1.6 倍)
- 中間指標を trace 集計に足す (`/trace-analysis` 側): 山頂到達 tick /
  狼煙点火 flag / 最深到達スポット (spawn からのホップ数) /
  新規スポット初訪問の時系列 (探索前線の速度) / 目的停滞 tick 数
- 大樫の樹・崖の見張り台の使用有無も指標化 (想定解の発見性の直接測定)

### R2. U5 配線バグ修正 (進行中) + 構造対策

setter 注入された transcriber が executor 再生成で失われる形は、
memory_full_002 の link_service 配線漏れ (「stack に作ったが prompt builder
に渡し忘れる」) と同型の**再発**である。個別修正に加えて:

- 修正は ctor 注入 (build 時に確定) に寄せ、setter 注入をやめる
- 起動時整合チェック (EXPECTED_PAYLOAD_KEYS と同じ fail-fast 思想):
  MEMO_DISTILL flag ON なのに transcriber 未配線なら起動時に例外
- 修正後 run で S6 を再検証 (memo 42 件相当の素材が evidence に流れるか)

### R3. revise-on-strengthen — ヘッジ凍結の解除 (プロンプト 1 段落)

固着プロンプトに追加する指示の案:

```
- strengthen を選ぶとき、その belief の文面が積み上がった証拠より弱い
  言い方 (「〜かもしれない」「〜ことがある」) のままなら、代わりに
  revise を選び、証拠に見合う強さに言い直してよい
  (例: 支持3件なら「〜ことが多い」、支持5件+反証0なら言い切り)。
  revise は同じ命題の強化であり、新しい主張を混ぜない。
```

- ルール側の変更なし (revise → supersede の機構は実装済み・未使用)
- 検証は L2 replay: 本 run の strengthen 14 件の素材を再投入し、
  何件が revise に転じるか・文面が命題として自然かを目視
- 質感の受け入れ基準: sup>=3 の belief の文面からヘッジが消えること。
  逆に sup1 の belief がヘッジ付きで生まれるのは**正しい較正**として維持

### R4. CONFIRMATION 関連性ゲート (ルールのみ・小粒)

- 転記条件に追加: そのターンの行動 context (tool / spot / 対象 player) と
  belief の cue_signature / tags の**軸一致が 1 つ以上ある belief のみ**
  支持を積む。一致 0 なら転記しない
- confidence 再計算で confirmation の重みを prediction_error 由来の
  反証より軽くする (まず 1/2)
- 期待効果: 自明な移動成功による sup 水増しの遮断。conf1.0/sup10 型の
  正当な成長 (浜辺 belief) は cue が一致するので残る — これが
  ゲートの妥当性テストケースになる

### R5. U10b 清算 (設計済み・検証素材あり)

- 本 run が検証データを既に用意した: カイのリオ宛約束 6 件 + t107 の
  破れ。清算が入れば「果たされなかった約束」が `player:リオ` belief への
  反証 (PENDING_RESOLUTION evidence) として流れ、S3 型の訂正ループが
  人物 belief で回る
- 実装は計画どおり (chunk 補完への同乗フィールドで果たされたか判定)。
  期限失効は「静かに消える」を維持 (忘れられた約束は人間でも消える)

### R6 (2026-07-09 全面改訂). 戦略層 — ルール検出をやめ、方針を「予測」として扱う

**初版 (ルールベース STRUCTURED_STAGNATION) はレビューで棄却**。
「新規スポット未訪問 N tick = 停滞」の類のルール代理変数はシナリオ依存で、
例外が増殖する (待ち合わせ中の正当な停滞・既知スポットでの資源集め・
会話中心シナリオ・看病や見張り…)。「前進」の一般的定義はフレーム問題
そのもので、ルールでは書けない。これは salience 設計で「ダメージ = 重要」
のハードコードを退けたのと同じ判断であり、既定の分担原則
(**意味判断は LLM が書き込み時に一度だけ、ルールは溜めて・数えて・
発火させるだけ**) に立ち返る。

置き換えは 2 段。どちらも新規 LLM 呼び出しゼロで、判定を意味判断に移す。

**R6-a「振り返り」— 固着パスに前進評価を相乗り (小粒)**

- 固着 coordinator の既存 batch prompt に decision 種別 `reflect` を追加:
  「この期間の evidence 群と現在の目的を読み、目的への前進があったかを
  判断せよ。停滞と判断したら 1 文で宣言せよ」
- 停滞宣言は 2 つに変換される:
  (i) `goal:` 軸の belief 候補 (「岩礁海岸方面の探索では山頂への前進が
  ない」— 本 run の有害 belief conf0.9 への直接の対抗馬になる)、
  (ii) 次ターンへの**内省観測**の注入 (「ふと振り返ると、この数日、
  山頂には一歩も近づいていない気がする」)
- 待ち合わせ・資源集め・看病が停滞かどうかは、無意識コンテキスト
  (belief・目的・約束) を持つ LLM が文脈で区別する。ルールが担うのは
  発火周期 (既存の固着周期に相乗り) だけ
- §4.4 追記との接続: 空腹が行動を動かすのは毎ターン**感じられる**から。
  内省観測は、テキストでしかなかった目的に**内受容感覚に相当する信号**を
  与える最小の器である

**R6-b「方針の予測化」— self-directed pending prediction (中粒・U10 の一般化)**

- 方針とは「このやり方で N tick 内に X が得られるはず」という
  **自分自身に向けた解決の遅い予測**である。U10 の pending prediction は
  対人の約束のために作ったが、器はそのまま使える: chunk 補完の
  pending prediction 抽出の対象に「自分の方針への見込み」を含める
  (解決 cue = tick 範囲)
- U10b の清算がそのまま方針の検証になる: 期限が来たら「X は得られたか」
  を判定 → 方針レベルの prediction_error / confirmation として同じ
  evidence 漏斗に流れる
- 新しい機構はゼロ。行動予測 (1 ターン) と方針予測 (N ターン) が
  **時間スケール違いの同じ PredictionOutcome** になる — 3 段のはしごが
  時間軸方向に伸びる、という原理的に綺麗な一般化
- 順序: R6-a を先に (プロンプト 1 decision + 観測注入のみ)、R6-b は
  U10b (R5) が入ってから。R6-a の停滞宣言の質を L2 replay
  (本 run の evidence 28 batch 分を再投入) で確認してから run に載せる
- **さらなる一般化 (2026-07-09)**: 「シナリオが無くても目的を持って
  行動する」への拡張は
  [goal_layer_design_active_inference.md](./goal_layer_design_active_inference.md)
  に切り出した — 目的 = 取り下げない選好的予測、生成・改訂は意識
  (エージェント自身)、監査は無意識 (R6-a)、清算はルール (U10b) の分担。
  シナリオの目的は goal store の locked 初期値に退化し、後方互換を保つ

### R7. belief の社会的伝播 — HEARSAY (大粒・次期の本命候補)

- 動機は 2 つ: カニの教訓の三重学習 (非効率)、ルート知識の死蔵
  (p4「この岩礁海岸は山頂に繋がってなさそうだ」という発話が誰の belief
  にもならない)
- スケッチ: 聞き手側の chunk 補完に「相手の主張から得た知識候補」を
  同乗フィールドで抽出させ (U10 の約束抽出と同型)、`HEARSAY`
  source_kind の evidence として固着パスに流す。**信頼は話者への
  人物 belief (`player:` 軸) に依存させる** — 「リオは話を聞かない」と
  思っている相手からの伝聞は弱く重み付く。統一設計の部品 4 との合成で、
  伝聞・信頼・人物モデルが 1 つの機構に乗る
- 副産物: 「Bの現在を人づてに聞いて嘆く」「前は違うこと言ってなかった?」
  (統一設計 §6 シナリオ 2・5) の土台がここで敷かれる
- **設計確定 (2026-07-12)**: 詳細は
  [belief_hearsay_design.md](./belief_hearsay_design.md) に切り出した。
  レビューで対象を世界だけでなく**人物についての主張 (噂話) にも
  広げる**ことを含めて合意 — 人物モデルは `player:` 軸 belief なので
  機構の追加なしで乗る。話者 (source_speaker) と対象 (cue) の分離が
  唯一の注意点

### R8. U6 (STRUCTURED_FAILURE) の優先度引き下げ

3.5 のとおり prediction_error 経路が S5 を代替できると実証された。
残作業があっても R1〜R7 の後でよい。

### R9 (2026-07-09 追加). 協力検証シナリオ v3 — 記憶システムの検証場としての設計

survival_island_v2 は「個人の生存 + ついでに協力」の難度設計で、
協力しなくても 140 tick 生き延びられてしまう (実測)。検証目的
(集団の協調が記憶システムの上で創発するか) に合わせ、
**「一人では非効率すぎ、協調すれば余裕を持って解ける」**を難度の定義
とする `survival_island_v3_coop.json` を設計する
(**v2 は残したまま新ファイルで作る** — 過去 run との比較可能性を保つ)。

協力を強制ではなく誘導する 4 原則:

1. **情報の分散 (禁書庫パターンの移植)**: ルート知識を人ごとに別の場所で
   発見できる断片にする — 大樫の樹の眺望 (登った者だけが地形を知る)、
   洞窟の壁画、墜落機の地図片。**知識は移動せず、発話だけが運ぶ**ので、
   協力 = 知識共有となり、HEARSAY (R7) の検証場がシナリオ側に整う。
   v2 の欠陥だった「沿岸に内陸ヒントゼロ」もこれで直す (手がかりを
   撒き直す。ただし正解を書くのではなく「川は高いところから来ている」
   程度の勾配に留める)
2. **相互依存の作業 (約束の検証場)**: 狼煙の材料 3 種を 1 人の所持枠では
   運びきれない量にする / 蔓のロープ作りは 2 人作業にする。
   「Day4 の朝に山頂で合流」型の約束が構造的に必要になり、
   U10b (R5) の清算・R6-b の方針予測がシナリオ側から需要される。
   注意: 「2 人同時でないと絶対に不可能」のゲートはデッドロックを生む
   ので最小限にし、基本は「一人だと極端に非効率」で誘導する
3. **時間圧の再調整**: 救助機会を horizon 内に置く (R1)。飢餓は
   「食料知識を共有すれば余裕、単独往復だと破綻」の水準に —
   ベリーの茂み・釣り場の場所知識が共有価値を持つように配置する。
   v2 では飢餓が集団を分散させた。v3 では共有が飢餓を解くようにする
4. **協調の測定可能性**: trace で機械的に数えられる協調指標を先に決める —
   発話による知識移転回数 (HEARSAY evidence 数)、約束の履行率
   (U10b)、同一スポットの重複探索回数 (減るほど協調)、材料の分担運搬、
   合流イベント数。「協力しているように見える」ではなく数字で比べる

難度の受け入れ基準: 理想的に協調する 4 人なら 150〜200 tick で
クリア可能 / 4 人がバラバラに動くと stranded、を設計段階で手作業
シミュレーション (ホップ数と所持枠の計算) で確認してから run に使う。

### 依存関係 (2026-07-09 改訂)

R1 / R2 / R3 / R4 は互いに独立 (即時並行可)。R5 は既定路線。
R6-a は独立 (固着プロンプトのみ)、R6-b は R5 の後。R7 と R9 は対に
なっている (R9 が R7 の検証場) — R9 のシナリオ設計は R7 実装と並行で
先に進められる。次の検証 run は R1〜R4 + U5 修正 + R6-a を積んだ状態で
`survival_island_v2_short` を回し、①クリア可否 ②ヘッジ解除 ③S6 復活
④CONFIRMATION の sup 分布変化 ⑤stagnation reflect の質、を一度に見る。
その次が R7 + R9 (v3_coop) の協調 run。

## 7. 統一設計へのフィードバック (原理の検証結果)

- **原理 (記憶 = 世界モデルの圧縮学習、予測誤差 = 制御信号) は実走に
  耐えた**。学びの発生・成長・棄却・訂正・一撃学習・人物モデル・
  ペルソナ相対の学習分布まで、設計の語彙で説明できない現象は出ていない
- **原理の境界が 1 つ見つかった**: 予測誤差は世界のダイナミクスの学習
  信号であって、効用の勾配を含まない (3.4)。世界モデルが良くなることと
  目的が前進することは別物。ただしレビューを経た読み直しでは、この
  境界は原理の**外**ではなく**適用範囲の拡張**で越えられる — 方針も
  「解決の遅い予測」として同じ PredictionOutcome に乗る (R6-b)。
  欠けていたのは新しい原理ではなく、目的に「感じられる信号」
  (内受容感覚に相当するもの) を与える配線だった (§4.4 追記)。統一設計の
  非スコープに「戦略層」を明記し、R6-a/b を最初の一歩として接続する
- **学習のカリキュラムはペルソナが決める (4.1)**: 設計外の創発として
  最重要。反証可能な追試 (ペルソナ入替 run) と、長走での盲点の
  自己強化 (人物の固定化) の観測を宿題に積んだ
- **能動想起は需要駆動 (3.7)**: 「使われない = 壊れている」ではなく
  「受動想起が十分な環境では需要が発生しない」。測定は需要正規化に
  変え、検証は情報非対称シナリオで行う
- **未検証のまま残っているもの**: U7 の A/B (無意識コンテキストの効果
  分離、L2 replay 待ち)、U10b (未マージ)、S6 (バグ修正待ち)、
  想起の信用割り当ての長期効果 (1 run では boost の副作用は「なし」
  だが、belief が増えた状態での再測定が要る)、ペルソナ入替追試 (4.1)、
  R6-a の停滞宣言の質 (L2 replay)
