## D1824-20. 範囲が埋まったことと、切り詰めた項目を trace に残し、0 件だった書き起こしを見えるようにする

**何を**: 短期記憶の範囲が埋まったときのエピソードの書き起こし (design_decisions D1824-19) で、trace に残らなかったものを見えるようにする。

| 見たいこと | どう見えるか |
|---|---|
| 書いたエピソードが 0 件だった範囲 | 範囲が埋まったこと (`ShortTermMemoryRangeFilledEvent`) を受けるハンドラ `RecordRangeFilledTraceHandler` が、`being_short_term_memory_range_filled` (being_id / turn / until_turn / experience_count) を残す。書いたエピソードの `being_episode_written` と、Being と、ターン (`turn` = `written_turn`) で突き合わせる |
| 切り詰めた項目と元の長さ | `Episode.write` に `truncated` を渡し、`EpisodeWrittenEvent` に載せる。`being_episode_written` の `truncated` ({鍵: 切り詰める前の長さ}) に残る。今の書き起こしの経路でも残る |

- 切り詰めた項目は、エピソードの集約には持たせない。書いたときの事実なので、イベントにだけ載せる
- `being_episode_written` は、ほかの書き起こし (`episode_writing`。環境を離れるとき。この判断の時点では今の短期記憶を畳むときも) でも出る。同じ Being・同じターンで重なることがあるので、重なったら `episode_writing` の件数を引いて見る。畳むときの書き起こしは、`end_turn` を配線する PR で消す。環境を離れるときの書き起こしは残るので、この注意も残る
- 上限 (1 回に 3 件) を超えて捨てた件数は、まだ残らない。エピソードごとのイベントには載せられず、範囲ごとの書き起こしの結果を残す場所が無いため

**なぜ**: `end_turn` を配線すると、範囲が埋まったときの書き起こしが run で動き始める。その前に、0 件だった範囲と切り詰めを run で見えるようにすると #1824 で決めた (design_decisions D1824-19 の「trace に残らないもの」)。範囲が埋まったことは、いきさつとエピソードの両方のきっかけなので、それ自体を残しておけば、書き起こしが届かなかった範囲 (失敗、終了時の間に合わなさ) も突き合わせで見える。

**関連**: Issue #1824、design_decisions D1824-17、D1824-19。
