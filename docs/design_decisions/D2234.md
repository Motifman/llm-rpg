## D2234. run の入口で新しい世界を選び、profile の鍵は古い profile と同じ名前を使う

**何を**: `make experiment` で、新しい世界 (`game_world`) を回せるようにした (#2234、親 #2212)。調整役と決めた。

| | 決まり | 例 |
|---|---|---|
| 世界の選び方 | profile に `"world": "game_world"` を書く。書かなければ古い世界のまま。知らない名前は断る | `smoke_stub_game_world` は `"world": "game_world"`、シナリオは `mine_village_v2.yaml` |
| 組み立ての置き場所 | `src/ai_rpg_world/experiment/infrastructure/` (`GameWorldPlay`)。遊びの進行・世界・Being の部品を組み、`StartPlaySession` → `PlayRounds` (`BeingsTakingTurnsAtOnce`) → `EndPlaySession` → 書き起こしの `shutdown` の順に呼ぶ | |
| profile の鍵 | 古い profile と同じ意味のものは同じ名前を使う (`BEING_EPISODE_INDEX_LIMIT`、`BEING_EPISODE_RECALL_MAX_HANDLES`、`MEMO_TOOLS_ENABLED`、`SCENARIO_RANDOM_SEED`、`ASYNC_EVENT_*`)。新しく足したのは `PLAY_WAKE_WAITING_AFTER_ROUNDS` (待つ人を起こすまでの巡りの数、既定 3、D2232) と `BEING_EPISODE_INDEX_ENABLED` (目次と、思い出す・目次を直すツールを出すか) | 書き起こしを待つ上限は `ASYNC_EVENT_SHUTDOWN_TIMEOUT_SECONDS` |
| 読まない鍵 | 断る。古い世界の鍵 (`LLM_IDLE_TIMEOUT_TICKS` など) を書いた profile で回すと、効いていない設定で回したことに気づかない | |
| 巡りの上限 | `max_world_ticks` (`MAX_WORLD_TICKS`) を巡りの上限にする。1 巡りで 1 tick 進む (D2225) | |
| 入口で止めるもの | 昼夜を宣言しない世界 (`WorldDesign.day_night_declaration()` が `NotDeclaredInThisWorldException`、D2222)、設計の欠けのあるシナリオ、snapshot の保存と読み込み、gist の公開、1 未満の巡りの上限。どれも出力の場所を作る前に止める | |
| 新しい世界で動いた印 | `experiment.config.resolved.json` の `world` と `scenario_sha256`、trace の `run_start` の `world` | |
| run の結果 | `run_end` に止まった理由 (`WORLD_ENDED` / `ROUND_LIMIT_REACHED` / `CHOOSING_KEPT_FAILING` と理由の並び)、最後の tick、終えたターンの数、捨てた選択の数、書き起こしの失敗の数 (`failures()`) を残す。選び続けて失敗して止まった run は、終了コード 1 にする | |
| LLM | いまはスタブ (`LLM_CLIENT=stub`) だけ。スタブ (`MurmuringActionChoosing`) は毎ターンふつうの声で一言つぶやく。LiteLLM 版は being の外 (experiment か infrastructure/llm) に置く (being は ai_rpg_world のほかのパッケージを import できない) | |

- trace.jsonl にはまだ `run_start` と `run_end` しか書かない。遊びの途中で例外が出たときも、`outcome: ERROR` の `run_end` を残してから例外を上に出す。中身の書き出しは #2233。古い世界の viewer は新しい世界の trace を読めないので、trace.html などは作らない
- snapshot は対象外にした。新しい世界の保存と再開は別の Issue で扱う
- 締めの一文「利用可能なツールから、次に取るべき 1 つの行動だけを選んでください。」は、置き場所を決めるまで experiment のコードに置く (古い run では世界の側 `world_runtime.py` に固定で書かれていた)

### fuzz-scenario (D1557) を新しい世界で回す

```bash
make fuzz-scenario SCENARIO=data/scenarios/mine_village_v2.yaml FUZZ_PROFILE=data/experiment_profiles/smoke_stub_game_world.json
```

| | 決まり | 古い世界の fuzz との違い |
|---|---|---|
| 世界の選び方 | `--profile` に新しい世界の profile (`"world": "game_world"`) を渡す | |
| でたらめなスタブ | `RandomActionChoosing`。新しい世界の【現在選べる対象引数】(`- ツール.引数 ("親"):` の下の「いまできる」) を読み、候補のある引数はそこから、親の候補を選んだあとの引数は親の下の行から選ぶ。必須の引数の「いまできる」が空のツールと、行動ごと選べないツールは選ばない | 古いスタブは古い表の形しか読めず、新しい世界ではどの引数にも決まった文を書いていた |
| 頼み方 | 1 人ずつ (`BeingsTakingTurnsOneByOne`)。同じシードで同じ行動の並びを再現するため。並べて呼ぶと、返事の順にスレッドの都合が入る | |
| 見つけるもの | 例外 (`exception`)、選べなかったターンとして飲まれた例外 (`swallowed_exception`、`ChoiceFailed` の理由)、プロンプトとツールの説明文への内部番号とシナリオの ID の漏れ (`leak`)、読めない候補表の行 (`unreadable_candidates`)、ERROR 以上のログ (`logged_error`)、書き起こしの失敗 | 古い世界だけの検査 (`stranger_name`、`unrecorded_action`、シナリオごとの `extra_checks`) はまだ無い |
| シナリオの ID | 世界の設計の名詞 (人・旗・場所・通り道・物・区画) と、YAML の `item_specs`・`happenings`・`reactions`・`person_interactions`・`groupings` の鍵のうち、下線を含む英字の名前 | 古い世界は JSON の `id` から集めていた |

**採らなかった案**:

- 古い世界の設定の読み手 (`ResolvedLlmRuntimeConfig`) で新しい世界の鍵も読む: 古い世界だけの鍵が新しい世界で効いているように見える
- シナリオの拡張子 (`.yaml`) で世界を見分ける: 実験の条件が profile の外 (ファイル名) に出る
