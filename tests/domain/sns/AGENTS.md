# SNS試験の保持境界

- 数値IDの構築、公開factory、変換、型別等価性、集合キーは値型の試験で守る。本番の直接呼出し0件だけで公開APIを削らない
- 不変性を変更する試験は通常の属性再代入の拒否と元値の維持を観測する。構築成功やfrozenフラグの確認だけにしない
- 同値のhash一致を守り、異値のhash不等値を要求しない。異種IDの同じ整数は、hash値ではなく非等価性で区別する
- 比較契約の「!= None」を「is not None」に変えない。前者だけが等価性の実装を通る
- 宣言統合では元入力、例外型、診断、返却ID型、valueのint型確認を保持先へ先に移す。数値等価性だけでは1.0と1を区別できない
- 数値IDとUUIDの保存同一性、画面参照寿命、配送・公開範囲は別の所有者。互いの試験で代替したと扱わない
- 新しい行の期待値は独立した値で書く。試験対象の解析・変換を期待値生成にも使わない
