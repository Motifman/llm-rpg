# 採集サービス試験の所有範囲

この節は採集関連の試験に適用する。

- 開始条件の距離・向き・ビジー・採集可能型は、実物を動かす `test_harvest_session_domain_service.py` で検査する。同じ入力を政策単体へ重複追加しない
- 入力の移管では状態も残す。未開始の採集可能資源は、型検証を通って `HarvestNotStartedException` へ到達することを守り、先に開始して代用しない
- 同時採集は同じIDの再試行と別IDの行為者を区別する。距離・向き・ビジーの別条件で先に拒否されない準備を使う
- 完了時刻の `is_busy=False` だけでは期限切れと解除を区別できない。公開DTO・保存へ残る `busy_until` の解除も実際の完了後に検査する
- 集約のID解決・通知蓄積・移動連携、コンポーネントの構築・回復・出力形式、報酬サービスの任意引数・生成数量・空抽選は独立契約として残す。小さい値やモック使用だけを削除理由にしない
- 期待値は入力と契約から固定し、対象メソッドの返値から作らない。専用の製品公開口や内部呼出の監視を増やさない
