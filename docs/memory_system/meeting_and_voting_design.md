# 会議と投票 — フェーズで世界のモードを切り替える

## 1. なぜ要るか

対人行為 (`interpersonal_interaction_design.md` PR 1-8) と陣営の勝敗
(`SURVIVING_PLAYERS_WITH_STATE_AT_MOST`) が揃い、Among Us の骨格で残るのは
**会議と投票**だけになった。

いま欠けているのは「疑いを持ち寄って、話し合い、多数決で 1 人を追放する」
という**社会的な決着の手段**である。これが無いと、襲う側は一方的に減らす
だけになり、襲われる側には抵抗する手が無い。観測と記憶で「誰が怪しいか」を
組み立てられても、**それを行使する場所が無い**。

## 2. 決めたこと

### 2.1 フェーズは専用の値オブジェクトと per-world store で持つ

`world_flag` に `phase:meeting` のようなフラグを立てる案は採らない。フラグは
排他を保証しないので、`phase:meeting` と `phase:free` が同時に立った状態を
型が止められない。「会議が終わったのにフラグを消し忘れて永久に会議」が
静かに起きる。

day_night に相乗りする案も採らない。「夜」と「会議中」は直交する概念で、
掛け合わせたくなった瞬間に破綻する。

```
GamePhase (enum)   : FREE_ROAM | MEETING
GamePhaseState (VO): phase / started_at_tick / last_activity_tick / trigger
GamePhaseStore     : per-world。現在のフェーズと遷移履歴を持つ
```

**per-Being ではなく per-world**であることに注意する。フェーズは世界全体の
モードで、プレイヤーごとに違うことは無い。

### 2.2 招集は緊急ボタンと死体発見の 2 つ

本家に合わせる。

| トリガー | 誰が引けるか | 制約 |
|---|---|---|
| 緊急ボタン | 生存している誰でも | 個人 1 回 + 世界共通クールダウン (§6.3) |
| 死体発見 (`report_body`) | 死体と同じ spot に居る生存者 | 同じ死体は 1 度だけ |

定期招集 (N tick ごとに自動) は**採らない**。「招集する判断」がプレイの
一部であり、世界の都合で起こすとその判断が消える。ただし初回の実 run で
「会議が一度も起きなかった」となると観測が取れないので、**シナリオ設定で
定期招集を足せる余地だけ残す** (既定は無効)。

### 2.3 投票は単純多数決・同点は追放なし・棄権あり

本家と同じ。同点や過半数不足で**誰も追放されない**ことも結果であり、
「誰も確信を持てなかった」という情報になる。

強制投票 (棄権を認めない) は採らない。「情報が足りないので保留」は正当な
判断で、それを潰すのは `agent_design_principles.md` の「取れる手段の質」に
反する。

決選投票も最初は作らない。2 回目の会議として自然に表現できる。

**投票は全員に見える。** 誰が誰に入れたかを観測として配る。投票行動そのものが
次の会議の材料になるので、秘匿すると社会的推論の材料が一段減る。

### 2.4 会議中は発話で起こし合い、沈黙で終わる

`PlayerSpokeEvent` の formatter は `schedules_turn=True` を返す (確認済み)。
つまり誰かが喋れば同じ場所の全員が起きる。話者本人には観測を返さない
(Issue #188 の自己三人称ループ対策) ので、自分の声で自分が起きることもない。

これに**沈黙上限**を足す。N tick 誰も喋らなければ会議を終える。

- 発話駆動だけだと、全員が黙った瞬間に会議が止まって二度と進まない
- 毎 tick 全員を強制的に起こすと、話すことが無くてもトークンを使う

沈黙上限は per-agent idle timer (`note_player_activity` 以降 N tick で
heartbeat) と同じ発想で、既存の考え方の延長にある。

### 2.5 フェーズごとに toolset を選び、共通 tool を先頭に置く

`design_decisions.md` #1 (prefix cache 不変) は**コストの判断であって正しさの
判断ではない**。文面が禁じているのは「毎 tick 変わる動的注入」で、フェーズ
境界でだけ変わるなら、遷移 1 回につき 1 ターンが cold になるだけである。
フェーズは tick でも実時間でも長いので、次のターンが来る頃にはキャッシュの
TTL が先に切れている可能性も高い。

reason-first の二段ターンに前例がある。あちらは正しさのために step2 から
`assess_situation` を外し、**末尾に置いて先頭の共通ブロックを守る**という
技法を確立した。同じ形をフェーズにも使う。

```
tools = [共通 tool (発話 / 記憶 / 観察)] + [フェーズ固有 tool]
                ^ ここは常に同じ            ^ ここだけ入れ替わる
```

会議中に移動や interact を**前提条件で弾く**のではなく、**そもそも tool を
出さない**。全 interaction に「会議中は不可」を書いて回るのは、宣言の重複が
シナリオ全体に散らばるうえ、LLM から見ても「選べるのに必ず失敗する手」が
並ぶことになる。

## 3. フェーズの状態機械

```
        緊急ボタン / 死体発見
FREE_ROAM ──────────────────► MEETING
    ▲                            │
    │   追放 or 追放なし          │  全員が投票した
    └────────────────────────────┘  or 沈黙上限
                                    or 会議の tick 上限
```

状態は 2 つだけにする。本家は「議論時間 → 投票時間」と分かれているが、
実際には**議論中いつでも投票できる**ので、投票を MEETING 中に使える tool に
すれば 1 状態で足りる。状態を増やさないぶん、遷移の抜けと snapshot の
追従漏れが減る。

会議の終了条件を 3 つ持つのは、どれか 1 つでも欠けると止まるため。

| 終了条件 | 無いとどうなるか |
|---|---|
| 全員が投票した | 議論が尽きても終わらない |
| 沈黙上限 | 全員が黙ると永久に会議 |
| tick 上限 | 喋り続けるだけで投票しなければ永久に会議 |

## 4. 実装順

| PR | 内容 | 動くもの |
|---|---|---|
| 1 | `GamePhase` / `GamePhaseState` / `GamePhaseStore` + **snapshot 追従** | なし (状態が持てるだけ) |
| 2 | フェーズ遷移の event と観測。trace に遷移が残る | 「会議が始まった」が見える |
| 3 | フェーズ別 toolset (共通先頭 + フェーズ固有末尾) | 会議中に移動できなくなる |
| 4 | 緊急ボタン + `report_body` による招集 | 会議が始まる |
| 5 | `PlayerOutcomeEnum.EJECTED` + 生存判定の更新 (§6.2) | 追放を死と区別できる |
| 6 | `vote` tool + 集計 + 追放 + 投票結果の配信 (§6.4) | **会議が決着する** |
| 7 | 沈黙上限と tick 上限による終了 | 会議が必ず終わる |
| 8 | 質感確認シナリオへの組み込み | 通しで遊べる |

**PR 1 に snapshot 追従を含める理由**: per-world store を足す PR で
`BeingMemorySnapshotService` (per-Being) ではなく world snapshot 側の配線を
同時に済ませる。`design_decisions.md` #27 が per-Being store について定めた
のと同じ理由で、「あとで足す」と長走実験の再開で連続性が静かに壊れる。

**PR 5 を PR 6 の前に置く理由**: `EJECTED` を足すと、陣営の勝敗条件の生存
判定 (`DEAD` 以外は生存) を同時に直す必要がある (§6.2)。追放処理を書く前に
outcome の語彙を確定させておかないと、「追放したのに生存として数えられ、
陣営の全滅が永久に成立しない」を踏む。

**PR 6 を最後の山にしない**: 追放が動かないと会議は「話して終わり」になる。
PR 4 と 6 は近接して入れる。

## 5. 実装時のチェックリスト

### H-1. 死んだプレイヤーを投票の母数に入れない

追放と全滅の判定に直結する。DEAD が確定した相手を母数に残すと、生存者 2 人
死者 2 人のときに「過半数 = 3 票」となり、**誰も追放できなくなる**。しかも
これは「同点だったので追放なし」と区別が付かない。

母数は「**行動可能な生存者**」に固定する。具体的には次をすべて外す。

- `DEAD` / `EJECTED` が確定した相手 (§6.2)
- 倒れている (`is_down`) 相手 (§6.1)。会議に参加できないので、票を投じる
  機会が無いまま母数だけ増やすことになる

### H-2. 会議招集時に進行中の移動を止める

`ObservationOutput.breaks_movement` が既にある。フェーズ遷移の観測でこれを
立てないと、会議が始まっても歩き続けるプレイヤーが出る。

### H-3. 招集時に全員を同じ場所へ集めるか決める

本家はテレポートする。`TELEPORT_ENTITY` effect が既にあるので実現できる。

集めない場合、発話の伝播 (hop-based) の都合で遠くの人に議論が届かず、
「会議に参加できない人」が構造的に生まれる。**集める方に倒すのが本家に
近く、実装も既存 effect で足りる。**

### H-4. フェーズ遷移の観測が `schedules_turn=True` を持つ

これが False だと、会議が始まっても誰も起きず、沈黙上限で即終了する。
MEMORY に残した「行動密度の親原因は `schedules_turn`」を一度踏んでいる。

### H-5. 投票 tool を MEETING 以外で呼べないようにする

toolset から外すだけでは、悪性クライアントや provider の変換崩れで届く
可能性がある。reason-first が `action_phase` で `assess_situation` を
fail-fast で弾いているのと同じ保険を置く。

## 6. 決着した論点 (旧「未解決」)

### 6.1 倒れているプレイヤーは会議に参加しない

`is_down` の player は観測の宛先から構造的に外れる (Issue #621 Phase 4:
ターンが回らず観測を消化できない) ので、**放っておいても参加できない**。
これを追認する。本家の幽霊が発言できないのと同じ形になる。

ただし「放っておいてもそうなる」を理由にすると silent 規則に飲まれるので、
**投票の母数から明示的に外し、そのことをテストで固定する**。母数に残ると
過半数の計算が狂い、「誰も追放できない」が「同点で追放なし」と区別できなく
なる (H-1)。

### 6.2 追放は `EJECTED` を足す

`PlayerOutcomeEnum` に `EJECTED` を追加する。`DEAD` に混ぜない。

- 分析で「殺されたのか追放されたのか」を区別したい
- 陣営の勝敗条件 (`SURVIVING_PLAYERS_WITH_STATE_AT_MOST`) は現在
  「`DEAD` 以外は生存」で数えている。追放を `DEAD` に混ぜると条件式の意味が
  濁るし、`EJECTED` を足したときに**生存側へ回ってしまう**

`EJECTED` を足す PR では、生存判定を「`DEAD` 以外」から
**「`DEAD` でも `EJECTED` でもない」**へ直す。ここを忘れると、追放された
プレイヤーが生存として数えられ、陣営の全滅が永久に成立しない。

### 6.3 緊急ボタンは「個人 1 回」と「世界共通クールダウン」の 2 段

個人あたりの使用回数は **1 回**。誰が持ち札を切ったかが情報になる (本家と
同じ)。

**個人の使用回数が 1 回なら、個人単位のクールダウンは一度も発動しない。**
連続招集を防ぐには**世界共通のクールダウン**が要る。両者は別の目的なので、
別々に持つ。

| 制限 | 目的 | 既定 |
|---|---|---|
| 個人の使用回数 | 持ち札を切る判断を作る | 1 回 |
| 世界共通クールダウン | 会議直後の再招集を防ぐ | 会議終了から 20 tick |

死体発見による招集はクールダウンの対象外にする (死体は世界の事実であって、
招集の濫用ではない)。既定値は実 run で調整する。

### 6.4 投票結果は、追放の有無にかかわらず必ず配る

同点や過半数不足のとき、世界には**何も起きない**。誰も移動せず state も
変わらないので、**ドメインイベントが自然には発生しない**。イベントは普通
「状態が変わったこと」を表すので、この経路は実装から漏れる。

漏れると、各エージェントには「投票した」「気付いたら自由時間に戻っていた」
しか残らず、次の 3 つが区別できなくなる。

- 集計結果 (誰に何票入ったか)
- 会議が終わったのか、まだ続いているのか
- 誰も追放されなかったのか、**誰かが追放されたが自分は見ていなかった**のか

**特別扱いしない。** 追放の有無にかかわらず「投票が終わった」観測を必ず配り、
集計結果を載せる。「誰も追放されなかった」は結果の 1 つの値になるだけで、
非イベントを別途作り込む必要が消える。

```
投票が終わった。カイト 2 票、リン 1 票、棄権 1 票。
過半数に届かず、誰も追放されなかった。
```

これは #831 (倒れている間の出来事を目覚めに渡す) と同じ形である。**届かない
情報は無かったことになる**ので、届く経路を先に作る。

## 7. 残る未解決

- 世界共通クールダウンの既定値 (20 tick) が長すぎ / 短すぎないか。実 run で
  会議の頻度を見てから調整する
- 会議の tick 上限と沈黙上限の既定値も同様
