## D1824-21. Being のターンの終わりを配線し、今の短期記憶を畳むときの書き起こしをやめる

**何を**: エージェントの 1 手を処理し終えたときに、Being の短期記憶のターンを終わらせる (`EndBeingTurn`)。同時に、今の短期記憶 (`SummarizingShortTermMemory`) を畳むときのエピソードの書き起こしをやめる。

| 置き場所 | すること |
|---|---|
| `being/application/end_being_turn.py` | `EndBeingTurnCommand` / `EndBeingTurn`。短期記憶を取り出し、`end_turn` を呼んで保存する |
| `WorldRuntime.end_being_turn` | Being を引き、Being の記憶のターン数で `EndBeingTurn` を呼ぶ。Being に結びつかないプレイヤーなら何もしない |
| `world_llm_turn/phase_b.py` の `run_phase_b` | 1 手を処理し終えたあとに `end_being_turn` を呼ぶ。Being の記憶のターン数は、同じ関数の始めで 1 進めている (`advance_memory_turn`) |

ターンの終わりで、短期記憶は次のことを見て、起きたことを配送器に渡す (design_decisions D1824-17)。

- 範囲が埋まった: いきさつ (design_decisions D1824-18) とエピソード (design_decisions D1824-19) を別のスレッドで書く
- いきさつが遅れている: いきさつだけを書き直す
- 上限に届いた: 古いターンを外す

消したものと残したもの:

| | 中身 |
|---|---|
| 消した | 今の短期記憶を畳むときのエピソードの書き起こし (`WorldRuntime._write_compacted_episodes`、`TRIGGER_COMPACTION`、trace `episode_writing` の `trigger: compaction`) |
| 残した | 環境を離れるときの書き起こし (`write_episodes_on_leaving`、`trigger: leaving`) |
| 残した | 今の短期記憶そのもの (畳むこと、【ここまでのいきさつ】の要約)。プロンプトに出す【直近の出来事】と【ここまでのいきさつ】は、まだ今の短期記憶の文 (切り替えは #1630) |
| 残した | 【直近の出来事】の影 (`RecentEventsShadow`) と、畳んだことを影に知らせる処理 |

**なぜ**:

- 切り替えの設定は作らない。ユーザーの方針は「二重の経路は管理の手間が増えるだけなので、うまく動いたら今の経路を消す」(#1824)。うまく動かなければ PR を戻す
- 畳むときの書き起こしと、範囲が埋まったときの書き起こしを両方動かすと、同じ出来事のエピソードが二重に記憶に入る
- ターンの終わりを `run_phase_b` の最後に置くのは、Being の記憶のターン数を進めるのが同じ関数の始めで、1 手の結果 (観測) がこの間に短期記憶に写るため

**ターンの終わりが失敗したとき**: `end_being_turn` の例外 (保存先の失敗など) は捉えず、手番の単位の失敗として `world_tick_unit_failed` に残す。run の報告と fuzz に数えられるので、静かな失敗にはならない。そのとき、同じ手番の後始末 (今の短期記憶のターンを閉じるなど) は飛ぶ。インメモリの保存先では起きる経路が無い。保存先を SQLite に替えるときに見直す。配送器の同期のハンドラの失敗は、配送器が捉えて知らせ先に渡すので、手番は止まらない。

**いきさつ**: 書いたいきさつは、Being の短期記憶に入るだけで、プロンプトにはまだ出ない。プロンプトの【ここまでのいきさつ】は、今の短期記憶の要約のまま (#1630 で切り替える)。

**確かめ方**: 実 LLM の run は、この PR が CI で緑になってから、ユーザーの許可を取って本命の profile で比べる。手元では、スタブの run と fuzz で次を確かめた。

- `episode_writing` の `trigger: compaction` が出ない
- `being_short_term_memory_range_filled` と、同じ Being・同じターンの `being_episode_written` が出る
- 範囲が埋まったあとで保存して再開しても、【直近の出来事】の影が食い違いを出さない

**関連**: Issue #1824、#1630、design_decisions D1626、D1824-17、D1824-18、D1824-19、D1824-20。

**その後 (design_decisions D1824-22)**: 【直近の出来事】の影と、畳んだことを影に知らせる処理は、プロンプトを Being の短期記憶から作るように切り替えたときに消した。
