## D1469-1. Being 集約を being/ に移し、名前と一人称を人柄 (Persona) に育てる

**何を**: #1469 の移し替えの 1 本目。

- `Being` 集約を `domain/being/aggregate/` から `being/domain/being.py` に移した
- `BeingIdentity` (名前と一人称) を、値オブジェクト `Persona` (`being/domain/persona.py`) にした。中身は名前・一人称・口調・性格・大事にしていること・怖いもの・生い立ち
- `Being` から、記憶の種類の宣言 (`declared_memory_kinds`、`declares`、`with_declared_memory_kinds`) と `MemoryKind` を消した
- import の境界の試験の一時的な例外を、`domain/being` 全体から、まだ移していない 3 つのモジュール (`BeingId`、`BeingAttachment`、例外) に絞った

**人柄の値の出どころ**:

| 項目 | 出どころ |
|---|---|
| 名前 | シナリオの `players[].name`。起動時にプレイヤーごとの Being を用意するときに渡す |
| 一人称、口調、性格、大事にしていること、怖いもの、生い立ち | まだ無い。決めずに空のままにする |

- シナリオには一人称を書く場所が無い。人柄は `persona_prompt` の 1 つの文に、世界の状況や役割と混ざって書かれている。これを分けて構造のある人格にするのは #1339 / #1548 で行う。そのときに一人称などもシナリオから入れる
- 決まっていない値を仮の値で埋めない。前は一人称を全員「わたし」にしていた。run `mine_v1_011_switched` では、4 人とも snapshot の一人称が「わたし」だったが、エピソードの本文では「俺」と「私」で揺れていた。仮の値が本当の人柄に見えるので、`None` にした
- 起動時以外で Being を新しく作るとき (プレイヤーの名前を渡さないとき) は、名前だけを `agent_{player_id}` にする。起動時に全員の Being を用意するので、run の中では通らない
- Web のキャラクター作成 (`CharacterPromptInput`) には一人称や性格があるが、まだ Persona には入れない

**snapshot**:

- 人柄は `persona` のキーに、項目ごとに書く。消した `identity_name`、`identity_first_person`、`declared_memory_kinds` は書かない
- `persona` の無い古い snapshot の `identity_name` と `identity_first_person` は読み捨てる。人柄は起動時にシナリオから入れたものを使う (design_decisions D1469-2)
- 古い snapshot の `declared_memory_kinds` は、どの文字列も読み捨てる。種類ごとの件数を `snapshot_load` の `removed_declared_memory_kinds` に Being ごとに残す。`semantic` を消したとき (design_decisions D1893-5) と同じ欄で、記憶本文の `removed_memory_keys` には混ぜない
  - 宣言そのものを消したので、未知の値も拒まない。前は `semantic` 以外の未知の値を壊れた宣言として拒んでいた
- ファイルと SQLite で同じ dict の形を使う。読み書きの関数 (`snapshot_to_dict`、`dict_to_snapshot`) を 1 か所 (`domain/being/service/being_snapshot_dict.py`) にまとめ、ファイルの gateway と SQLite のリポジトリの両方がそれを使う。前は同じ変換が 2 か所にあった。形が崩れた dict は `BeingSnapshotIncompleteException` で拒む

**なぜ**:

- 名前は Being のもので、世界が変わっても同じ名前で入る。記憶もこの名前の人物に結び付く (#1469 の 2026-10-31 のコメント)
- `Persona` はプロンプトの文を持たない。文にするのは application の側に置く
- 記憶の種類の宣言は、宣言を見て記憶を読み込む予定で足したが、`declares()` を呼ぶところは無かった。記憶の読み書きは `BeingMemorySnapshotService` の `EXPECTED_PAYLOAD_KEYS` が決めている。`with_declared_memory_kinds` は新しい `Being` を作って返すので、集約の決まり (状態を変える操作は自分を書き換える) にも合わない

**まだしないこと**:

- いきさつとエピソードを書くハンドラは、まだゲームの側の関数から名前と人格の文を引く (`persona_of`、`circumstances_of`)。`BeingRepository` から `Persona` を引くように変えるのは別の PR (その後、D1469-2 で変えた)
- `BeingId`、`BeingAttachment`、例外、`BeingSnapshot`、codec、リポジトリのインタフェースは `domain/being` に残した。`BeingAttachment` はゲームの `WorldId` と `PlayerId` を持つので、移すには所属の表し方を決める必要がある
- `Role` (世界ごとの割り当て) はまだ作らない

**関連**: Issue #1469、#1339、#1548、design_decisions D1824-6、D1893-5。

---

**その後 (design_decisions D1469-2)**: 古い snapshot の名前と一人称を書いてあるとおりに読む例外はやめた。どれも人柄を渡す呼び出し元が無かったころの仮の値 (`agent_N`、「わたし」) なので、読み捨てて `snapshot_load` の `removed_legacy_identities` に残し、人柄は起動時にシナリオから入れたものを使う。いきさつとエピソードの書き手は、名前と一人称を Being の人柄から引くようになった。
