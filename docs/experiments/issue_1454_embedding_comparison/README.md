# 状況の想起で信念を絞る手法を、2 字組と埋め込み (Qwen3 / Ruri v3) で比べる (#1454)

> `scripts/situation_recall_probe.py` と、それが呼んでいた状況の項目から引く想起は、#1631 の #1656 で消した。この記録の再現手順は、いまのコードでは動かない。
>
> 埋め込みの絞り込みと任意の依存 `embedding-local` も、#1631 の段 10 で消した。

状況の 6 つの項目をつないだ 1 本の文で信念を引くとき (design_decisions D1414-8)、絞り込みの手法を次で並べた。
#1498 で形態素解析にしても戻らなかった「体が危ない場面で体に関わる信念が載らない」件が、長い文に強い埋め込みで戻るかを見る。
あわせて、載った信念が場面に合っているかを、場面ごとに読んで当否を付けた。

| 名前 (`*_NARROWER` に書く値) | 中身 |
|---|---|
| `char_bigram_bm25` (既定) | 区切りの中の文字の 2 字組の BM25 |
| `qwen3_embedding_8b_openrouter` | OpenRouter の `qwen/qwen3-embedding-8b` (4096 次元)。問い合わせ文にだけ英語の指示文を付ける。この run では provider は DeepInfra だった |
| `ruri_v3_30m` / `_70m` / `_130m` / `_310m` | 手元の Ruri v3 (cl-nagoya、Apache-2.0)。「検索クエリ: 」「検索文書: 」を付ける |

どの埋め込みも、cosine 類似度の上位 3 件を載せる。比べた版は sentence-transformers 6.1.0、transformers 5.15.1、torch 2.14.1 (Mac、Apple シリコン)。

## 素材と母集団

- **40 場面**: `var/runs/v4coop_reasonfirst_003` (4 人)。人ごとに連続 10 回のプロンプトを 1 窓。#1498 と同じ選び方で、2 字組の数字は #1498 の `results.json` と一致した
- 手法ごとに 40 回の想起、120 枠。「前の想起 (cue)」は、その run で実際に頭に載った 3 件 (trace の `semantic_passive_recall`)
- **当否**: 40 場面で、比べた手法のどれかが載せた信念を場面ごとに重ねずに並べた 365 行 (前の想起、2 字組、Qwen3、Ruri v3 の 30m と 310m)。
  Claude が、どの手法が載せたかを伏せて付けた。人の当否はまだ無い (下の「人が当否を付ける」)

## 結果

### 載った信念が場面に合っているか (Claude の当否、`labels_claude.json`)

「この信念は、この場面で次に何をするかを決める材料になるか」で 3 つに分けた。

- Y: 判断の材料になる。場面の課題・相手・場所・体の具合に関わり、場面と食い違わない
- ?: 関わりはあるが判断にほとんど効かない、または決められない
- N: 関わらない、または場面と食い違う (もう古い、済んだこと、別の場所の話など)

| 手法 (各 120 枠) | Y | ? | N | 体の危険の語がある 32 場面の 96 枠の Y | Y が 1 件も無い場面 (40 中) |
|---|---|---|---|---|---|
| 前の想起 (cue) | 13 | 56 | 51 | 11 | 27 |
| 2 字組 | 14 | 38 | 68 | 10 | 30 |
| **Qwen3 (API)** | **19** | 51 | **50** | **14** | **25** |
| Ruri v3 30m | 12 | 28 | 80 | 8 | 29 |
| Ruri v3 310m | 14 | 22 | 84 | 10 | 29 |

場面ごとの Y の数で比べると、Qwen3 が 2 字組より多い場面は 11、少ない場面は 6。前の想起より多い場面は 8、少ない場面は 3。

当否を付けた 4 つのサブエージェントは人ごとに分けたので、人によって厳しさが違う (Y はエイダ 4/98 行、ノア 16/95 行)。手法の比べは同じ付け手の中で行っているので、
比べには効かない。

### #1498 と同じ集計 (`results.json` の `summary`)

| 見たもの | 前の想起 | 2 字組 | Qwen3 | Ruri 30m | Ruri 70m | Ruri 130m | Ruri 310m |
|---|---|---|---|---|---|---|---|
| 体の危険の語がある 32 場面の 96 枠で、体に関わる信念が載った件数 | 26 | 16 | **32** | 11 | 2 | 2 | 4 |
| 続けての想起で同じ 3 件が並んだ割合 (36 組) | 16/36 | **2/36** | 11/36 | 10/36 | 15/36 | 18/36 | 15/36 |
| 続けての想起の重なり具合 (Jaccard の平均) | 0.66 | **0.29** | 0.57 | 0.58 | 0.68 | 0.69 | 0.66 |
| 他人の名前が出て、その名前を含む信念が候補にある 110 組で、名前を含む信念が載った組 | 37 | 42 | 65 | 64 | 63 | 63 | **68** |
| 場所の名前が出て、その名前を含む信念が候補にある 42 組で、名前を含む信念が載った組 | 18 | **25** | 10 | 12 | 13 | 14 | 19 |

体に関わる信念の語と体の危険の語は #1498 と同じ。語で数えているので、載った信念が場面に合うかは上の当否で見る。

手法どうしで上位 3 件が重なる数 (40 場面、1 場面あたりの平均): 2 字組 × Qwen3 0.72、2 字組 × Ruri 0.9〜1.0、Qwen3 × Ruri 1.4〜1.65、Ruri どうし 2.0〜2.35。
前の想起とはどの手法も 0.2〜0.45 で、ほとんど重ならない。

### 1 回の想起にかかる時間と費用

| 手法 | 人ごとの最初の想起 (信念のベクトルをまとめて作る) | 2 回目から (中央値) | 2 回目から (90 パーセンタイル) | 2 回目から (最大) | 手法を組む時間 |
|---|---|---|---|---|---|
| 2 字組 | 1.6 ms | 0.6 ms | 0.8 ms | 1.0 ms | 0 |
| Qwen3 (API) | 14,078 ms | 820 ms | 7,710 ms | 19,129 ms | 3 秒 |
| Ruri v3 30m | 112 ms | 28 ms | 67 ms | 85 ms | 12 秒 (初回はモデルの読み込みを含む) |
| Ruri v3 70m | 45 ms | 17 ms | 37 ms | 41 ms | 4 秒 |
| Ruri v3 130m | 68 ms | 21 ms | 29 ms | 33 ms | 4 秒 |
| Ruri v3 310m | 139 ms | 44 ms | 59 ms | 72 ms | 5 秒 |

- Qwen3 の時間は、ほぼ全部が API の往復と provider の待ち時間。手元で 30 件のベクトルを比べる時間は 0.06 ms (1 万件でも 10 ms)
- Qwen3 の 1 回目の試算では、20 秒の時間切れが 2 回 (ノアの体の危険の語がある 2 場面) あり、2 字組へ縮退した。縮退は trace と結果の `fallback` に残る。
  数字は、縮退が 0 回だった 2 回目の試算のもの。1 回目は体に関わる信念が 30/96、同じ 3 件の割合が 10/36 だった
- Qwen3 の費用は 1 回の試算 (40 場面、50 回の呼び出し) で 15,075 トークン、$0.00017。疎通の確かめ (32 トークン) と 2 回の試算を合わせて $0.00032。
  課金は 100 万トークンあたり $0.01 の見込みどおりだった
- Ruri v3 のモデルの大きさ (Hugging Face のキャッシュ): 30m 148 MB、70m 286 MB、130m 512 MB、310m 1.2 GB

### 依存の大きさ (任意の依存 `embedding-local`)

`uv sync --extra embedding-local` で入る。torch 528 MB、scipy 75 MB、transformers 50 MB、scikit-learn 32 MB、ほか数 MB。ふだんの依存と CI には入れていない。
numpy (21 MB) は行列積に使うので、ふだんの依存に足した。

## 実例

### 体の信念が載る場面 (リオ、プロンプト 102、観測拠点跡)

#1498 で、どの手法でも「空腹が危険域に達したら…」が 3 件に入らなかった場面。

| 2 字組 | Qwen3 | Ruri 310m |
|---|---|---|
| カイは火起こし道具一式を持っている (Y) | カイは火起こし道具一式を持っている (Y) | カイは火起こし道具一式を持っている (Y) |
| ノアは川沿いルートを推した (Y) | 救助には狼煙台への山頂到達が必要だ (Y) | カイが手記から川沿いルート安全と読んだ (Y) |
| カイが手記から川沿いルート安全と読んだ (Y) | 空腹が危険域に達したら即座に食料を口にする (?) | 隠し入江への移動は仲間の合意を得て進める (Y) |

Qwen3 は体の信念を載せたが、リオ本人の空腹はすでに 29 まで戻っていて、当否は ? になった。語で数える集計では体の信念が増えても、場面に合うとは限らない。

### 同じ 3 件が続く (エイダ、10 場面)

Ruri 310m は「ノアとリオは干潟に向かっている。」「ノアとリオは干潟に行くようだ。」を 10 場面すべてに載せた。Qwen3 も 9 場面と 8 場面に載せた。
問い合わせ文は、場所と 3〜4 人の名前の行から始まる。埋め込みは文全体を 1 本のベクトルにするので、名前が並んだ部分に引かれ、
人の動きを述べた信念が、場面が変わっても上に来続ける。2 字組では語が点を分け合うので、こうはならない。

## 分かったこと

1. **どの手法でも、載った信念のうち場面に合うものは 1〜2 割**。120 枠のうち Y は 12〜19。40 場面のうち 25〜30 場面で、Y が 1 件も無い。
   手法を替えるより、問い合わせ文の組み方と、信念そのもの (もう古い、済んだことを述べた信念が多い) のほうが効いている
2. **Qwen3 は、場面に合う信念と体の信念の両方で、2 字組と前の想起をやや上回る**。Y 19 (2 字組 14、前の想起 13)、N 50 (2 字組 68)。体に関わる信念は 32/96 で、
   前の想起の 26 も上回った。ただし差は数件で、1 人の付け手の当否による
3. **埋め込みは同じ 3 件を続けて載せやすい**。2 字組 2/36 に対し、Qwen3 11/36、Ruri 10〜18/36。6 つの項目をつないだ文を 1 本のベクトルにすると、
   名前の並びのような毎回同じ部分に引かれる。#1414 の背景にあった「いくつもの観点を 1 本につなぐと平均に寄る」が、埋め込みでは強く出る
4. **Ruri v3 は、どの大きさでも体の信念と場面に合う信念が 2 字組より少ない**。大きさを替えても選ぶ 3 件は似ている (Ruri どうしで 3 件中 2 件以上重なる)。
   人の名前は当たるが、場所の名前は 2 字組より当たらない
5. **Qwen3 は 1 回の想起に 0.8 秒 (中央値)、悪いときは 20 秒の時間切れまでかかる**。想起はターンごとにプロンプトを組む前に走るので、ターンの時間にそのまま足される

## 提案 (決めるのはユーザー)

- **状況の想起の既定は 2 字組のまま変えない**ことを提案する。Qwen3 の上積みは 120 枠で Y が 5 件で、同じ 3 件の繰り返しが増え、1 ターンに 1 秒前後
  (悪いときは 20 秒) が足される。人の当否で Qwen3 の上積みが確かめられたら、想起を先に走らせて待ち時間を隠す形とあわせて決め直す
- **Ruri v3 は既定の候補から外す**ことを提案する。この比べではどの大きさも 2 字組を上回らず、依存が 600 MB を超える。手元で動くことが要るとき
  (通信できない環境) の代わりとして残す
- 埋め込みの弱さ (同じ 3 件が続く) は、問い合わせ文をつないで 1 本にしていることから来ている。ただ、2 字組も埋め込みも「状況の文に似た記憶」を
  探していて、「状況で役に立つ記憶」には届かない。エピソードの側 (Issue #1454 の次の PR) では、似ているかではなく「使える時」で引く。
  書くときに、エージェントの必要で作った抽象的なタグを決まった語彙で付け、状況にも同じ語彙でタグを付けて突き合わせ、この比べと同じ集計で確かめる
  ([Issue #1454 のコメント](https://github.com/Motifman/llm-rpg/issues/1454#issuecomment-5978392194) に語彙の案)

## 引ける上限 (10 場面の全候補)

場面に合う信念が少ない原因が、引き方か候補かを分けるため、候補の信念の全部に当否を付けた。
結果は [Issue #1454 のコメント](https://github.com/Motifman/llm-rpg/issues/1454#issuecomment-5978462025) にも書いた。当否と集計は [ceiling_labels_claude.json](ceiling_labels_claude.json)。

- **母集団**: 上の 40 場面を人の順に並べ、4 つおきに選んだ 10 場面 (エイダ 3、ノア 2、リオ 3、カイ 2)。その時点で持っていた信念の全部を候補とし、
  (場面, 信念) の 306 組。各場面で上位 3 件を載せるので 30 枠
- **当否**: Claude のサブエージェント 2 体が、どの手法が載せたかを伏せて、上と同じ基準で付けた。人は確かめていない。上で付け済みの 92 組を付け直したところ、
  一致は 66 組 (72%)。食い違いの多くは ? と N の間だが、上で Y だった 9 件のうち今回も Y だったのは 6 件で、Y の判断も揺れる

| | 30 枠で拾えた Y |
|---|---|
| 上限 (候補の Y を完璧に 3 枠へ載せた場合) | 17 |
| 前の想起 (cue) | 4 |
| 2 字組 | 3 |
| Qwen3 (API) | 6 |
| Ruri v3 30m | 2 |
| Ruri v3 310m | 3 |

- 306 組のうち Y は 20 件 (7%)。1 場面あたり平均 2 件で、Y が 1 件も無い場面が 1 つあった。手法の数件の差は、付け直しの揺れの範囲に収まりうる
- **候補の乏しさと引き方の弱さの両方が原因**。完璧に引いても半分近くの枠は埋まらず、各手法は上限の 4 割に届かない (いちばん多い Qwen3 でも 17 のうち 6)
- **ピンチを抜ける信念がほとんど無い**。Y になったのは、システムの制約、人の持ち物や能力、世界の決まりが中心で、「空腹のとき、どこで何を食べればよいか」の
  ような、ピンチを抜けた経験から学んだ信念は候補にほとんど無い。「試して効いた抜け方」が信念として残る流れが回っていないためで、Issue #1491
  (予期を、経験から立てた仮説を確かめる流れとして回す) と同じ根の問題として、そちらの材料になる

## 人が当否を付ける

[review.html](review.html) をローカルで開く。場面ごとに、状況の 6 つの項目と、手法のどれかが載せた信念が並ぶ。行ごとに Claude の当否があり、
「そのまま」か Y / ? / N を押す。どの手法が載せたかは既定で隠している (「どの手法が載せたかを見る」で出る)。押した当否はブラウザに残り、
「当否を書き出す」で `labels_human.json` を保存できる。保存したら、ここに置いて次で数える。

```bash
uv run python scripts/situation_recall_review.py tally \
    --items docs/experiments/issue_1454_embedding_comparison/review_items.json \
    --labels docs/experiments/issue_1454_embedding_comparison/labels_claude.json \
    --labels docs/experiments/issue_1454_embedding_comparison/labels_human.json
```

## 再現

`var/runs` はリポジトリの外 (worktree から見て `../../../var/runs`) を指す前提で、パスは手元に合わせる。Qwen3 は実際に API を呼ぶ (1 回 $0.0002 ほど)。
キーは環境変数 `OPENROUTER_API_KEY` から読む。無ければ `OPENAI_API_KEY` を、OpenRouter のキー (`sk-or-` で始まる) のときだけ使う。Ruri v3 は初回にモデルを Hugging Face から取ってくる。

```bash
uv sync --extra dev --extra embedding-local
uv run python scripts/situation_recall_probe.py \
    --run-dir <var/runs への絶対パス>/v4coop_reasonfirst_003 \
    --narrowers char_bigram_bm25,qwen3_embedding_8b_openrouter,ruri_v3_30m,ruri_v3_70m,ruri_v3_130m,ruri_v3_310m \
    --out docs/experiments/issue_1454_embedding_comparison/results.json
uv run python scripts/situation_recall_review.py items \
    --results docs/experiments/issue_1454_embedding_comparison/results.json \
    --methods old,char_bigram_bm25,qwen3_embedding_8b_openrouter,ruri_v3_30m,ruri_v3_310m \
    --out docs/experiments/issue_1454_embedding_comparison/review_items.json
uv run python scripts/situation_recall_review.py html \
    --items docs/experiments/issue_1454_embedding_comparison/review_items.json \
    --labels docs/experiments/issue_1454_embedding_comparison/labels_claude.json \
    --out docs/experiments/issue_1454_embedding_comparison/review.html
```

API の結果は呼ぶたびに少し変わり、時間切れで縮退することもある。`results.json` の `summary.fallbacks` が 0 でない試算は、その手法の数字として読まない。
`items` は、表に入れる手法が縮退した場面を含む結果を受け付けない。
`items` をやり直すと行の番号が変わり当否とずれるので、既存の `review_items.json` は `--overwrite` を付けない限り上書きしない。
