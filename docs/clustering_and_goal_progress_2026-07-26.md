# 固まると目標に向かわなくなる (v4 第 2 回 / 第 3 回 run の対照)

2026-07-26 に v4coop_reasonfirst_002 と 003 を同じ定義で比較して得た知見。
「なぜ誰も山頂へ行かなかったか」への答えの中核。

## 何が分かったか

**002 は分散して動き、2 人が山頂に到達した。003 は固まって喋り、一度も向かわなかった。**

| 指標 | 003 (山頂到達 0) | 002 (2 人が山頂到達) |
|---|---|---|
| 空間分散 (平均何箇所に分かれていたか) | **1.57** | **3.15** |
| 会話 (speak / listen) | **40.7%** | 30.9% |
| 移動 (travel_to) | **6.3%** | 13.6% |
| 探索 (explore) | 7.8% | **15.0%** |
| 世界を変える行動の合計 (移動 + 探索 + 世界操作) | **40.5%** | **49.8%** |
| `speak` の直後がまた `speak` | **49.0%** | 37.0% |
| 総行動数 | 639 | 301 |

002 は 2 人が死亡している (最初の死亡は tick 119)。死体の位置が carry-forward で
分散を膨らませている疑いがあったので、**死亡前だけで再計算した**。002 の死亡前
(tick 1-118) の平均は 3.03 で、全期間の 3.15 とほぼ変わらない (= 死亡の寄与は小さい)。

```
tick 1-100  002: mean 2.88  (1 箇所=8, 2 箇所=19, 3 箇所=50, 4 箇所=23)
tick 1-100  003: mean 1.16  (1 箇所=84, 2 箇所=16)
```

**003 の最初の 100 tick は、84 tick で 4 人全員が同じ場所にいた。** 死亡の影響ではない。

## なぜそうなったか

003 で入れた改善は、いずれも **「一緒にいることの価値」を上げるもの** だった。

- 食料経済の緩和 (腐敗までの時間を延ばす / 腐敗食でも空腹は一部回復)
- 同席者の観測で相手のターンを起こす (#803)
- `give_item` の affordance を同席者行に出す (#805)
- シナリオ宣言の初期所持品を実際に配る (#830)

結果として **全員生存 (0 死) と協調成立 (`give_item` 0 → 13)** という成果が出た。
同時に **固まる圧力** も上がっていた。

固まると次の連鎖が起きる。

1. 喋る相手が常にいる。そして **`speak` は唯一失敗しない行動**である
   (003 の `interact` は 135 回中 77 回失敗 = 57%)。失敗しない行動が 1 つだけ
   あると、期待値でそこへ寄る
2. 合意をいつでも取り直せる。だから取り直す (`speak` → `speak` が 49%)
3. 誰も遠くへ行かない (移動 6.3%)
4. そして 003 の拠点 `隠し入江` は `is_outdoor` 未宣言で **屋内扱い**だった。
   屋内では `distant_view` が全面抑止される

```
隠し入江 (屋内扱い) にいた prompt 421 件 → 「山影」が見えた: 0 件
難破船の浜 (屋外)   にいた prompt  56 件 → 「山影」が見えた: 56 件 (全部)
```

**目標である山が、拠点にいる間 一度も見えていなかった。**

つまり 003 は「山が見えない場所に全員で固まって、失敗しない行動を反復した」run
だった。エージェントの推論が弱かったのではなく、**世界の側が目標を隠し、固まる
ことに報酬を与えていた**。

## ここから引き出す方針

### 分散はコードで誘導しない。阻害要因を外す

「山頂へ行け」と促す実装は入れない。002 が示すとおり、条件が揃えば分散する。
今わかっている阻害要因は 3 つ。

1. **拠点から目標が見えない** — `隠し入江` の `is_outdoor` 宣言漏れ。1 行で直る
2. **離れると相手が見えない** — `distant_view` は地形専用で、人が乗っていない。
   分散のコストを下げるには「遠くの仲間が粗く見える」が要る
3. **失敗しない行動が 1 つだけある** — `interact` の失敗率 57% を下げると
   `speak` への逃避が減る (#847 の広い try / `INVALID_TARGET_LABEL` 32 件)

### 協調の改善は「固まる圧力」を同時に上げる

これは 003 で実際に起きた。協調を促す変更を入れるときは、**分散のコストも
同時に下げる**か、少なくとも空間分散を観測する。片方だけ入れると、協調は
成立するが目標に向かわなくなる。

### 「宣言しないと黙って無効」の 6 例目

`SpotNode.is_outdoor: bool = False` / loader も `spot_raw.get("is_outdoor", False)`。
19 スポットが `true` を宣言し、1 つが漏れた。エラーにならず、症状は
「なぜか遠景が出ない」としてしか現れない。2026-07-26 に同型を 5 件
(`initial_items` #830 / `initial_state` #840 / `sync_action_groups` #850 /
記憶ツール露出フラグ 3 件 #851 / 終了条件の `target_flag` #843) 潰した直後に
6 例目が出た。個別に直すだけでなく検出の仕組みを増やす必要がある (#845 / #852 / #859)。

## 測り方 (次の run 以降)

`.claude/skills/trace-analysis/extract_metrics.py` に 3 指標を追加した。

- `action_budget`: 会話 / 記帳 / 想起 / 移動 / 探索 / 世界操作 の内訳と
  「世界を変える行動」の割合
- `speak_chains`: `speak` の直後に何をしたか、`speak` → `speak` 率、
  player ごとの最長連続 `speak`
- `spatial_dispersion`: tick ごとに何箇所に分かれていたかの分布と平均。
  死体の位置も carry-forward で残って分散を膨らませるため、最初の
  復帰不能 outcome (DEAD / EJECTED) より前だけで再計算した値も併せて返す

**この 3 つが無いと「改善したか」を言えない。** 003 までは目視と個別クエリで
やっていたため、002 との差が最後まで見えていなかった。

### 分類外のツールが見えるようにしてある

`action_budget` はどのカテゴリにも属さないツールを `unclassified` として
実名と件数で残す。総数から黙って消えない。ツールを足したときに割合の分母が
静かにずれるのを防ぐのが主目的で、会議ツールの分類網羅テストが書いた時点で
`prepare_action` の未分類を捕まえたのと同じ役割。

導入した時点で 002 の `inner_thought` 2 件が引っかかった。これは分類漏れでは
なく **LLM が引数名をツール名として呼んだ幻覚**だった。`inner_thought` は
`tool_catalog/inner_thought.py` にある全ツール共通の引数スキーマ断片で、
ツールとしては登録されていない。

2 件とも `UNSUPPORTED_TOOL` で失敗し、`未対応のツールです: inner_thought。
現在使える tool: [...]` と実名一覧を返していた。つまり失敗経路は正しく
働いていて、対処は不要。003 では 0 件 (reason-first 二段化で inner_thought が
引数として明示されるようになったため)。

**`unclassified` は分類漏れの検出だけでなく、存在しないツール名の呼び出しの
検出にもなる。** 件数が増えたら幻覚が増えたと読める。
