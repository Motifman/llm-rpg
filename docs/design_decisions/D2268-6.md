## D2268-6. 着いたことを本人には自分の行動の行で返し、出発の要約に出発した場所を書く

**何を**: 古い run の【直近の出来事】にあった、移動の 2 つの行を再現する (#2268 の 4 本目の前半)。

古い run (mine_v1_002、ゲン):
```
- [Day 1 深夜 1:00] [行動] 「南の横坑口」から「南の横坑の奥」へ向かって出発した → [結果] 「南の横坑の奥」へ移動中。到着までは他の行動はできない。
  呼び出し: travel_to(destination_label="南の横坑の奥", say_inline=発言)
- [Day 1 深夜 2:00] [行動] 「南の横坑の奥」に着いた → [結果] 「南の横坑の奥」に到着した。ここから次の行動を選べる。
  呼び出し: travel_to()
```

| | 決まり |
|---|---|
| 着いた本人 | 到着の目撃と足音 (`built_in_action_perceptions.arrival`) を本人に届けない (`withheld_from`)。代わりに、本人にだけ届く刺激 `OwnActionCompletion` で、着いた要約と結果の文を届ける。Being へは契約の経路 `OwnActionCompleted` (要約・ツールの名前 `travel_to`) で渡り、Being が古い run と同じ行に書く (#2275) |
| 本人以外 | これまでどおり、見えた人に「{actor}が{origin}からやって来た。」、聞こえた人に足音が届く |
| teleport | 来た場所が無いので、目撃も本人への結果も作らない (これまでと同じ) |
| 文面 | `ja_default.yaml` の `action_texts.arrival` (`「{destination}」に着いた` / `「{destination}」に到着した。ここから次の行動を選べる。`) |
| 出発の要約 | `action_texts.travel.summary` を古い run と同じ `「{origin}」から「{destination}」へ向かって出発した` にする。出発した場所は、行動を行う直前の行為者の状況 (`ActorSituation.at_spot`) から書く。要約と結果の文の口 (`summary_in` / `done_text_in`) は、品物の種類の表の代わりに行為者の状況を受け取る |

- 自分の行動の続きの刺激は「1 人に 1 つ」の数に入れない。同じときに届く見聞きした知らせを押しのけないため。順位は体の観測と同じにして、同じときの知らせより先に並べる
- 観測の経路は、知覚 (`Perceived.route`) が知覚の質から決める。あとから届く結果の経路は要約とツールの名前を持つので、application 層の表ではなく知覚の側で作る
- これまで暗い場所に着いた本人に「誰かがどこからかやって来た。」が届いていた。自分を見分けられずに受け取っていたもので、本人に届けないことで消える
- 断られた移動 (疲れすぎて動けない、など) の要約も、同じ文で「「{origin}」から「{destination}」へ向かって出発した」になる。断られた行は Being が `[失敗]` として書くので読み違えは小さいが、文は出発したと読める。これは移動の要約の文が 1 つしか無い作りからくる、この PR より前からの挙動で、直すかは別に決める
- 古い run が持ち物の出入り (「〜を入手しました。」「〜を捨てました。」) も本人に出していた件は、次の PR で扱う。持ち物のイベントに起きた時刻と品物の種類を持たせる変更が要るため
