## D2268-16. 去っていく人を、通ってゆく通路の名前つきで知らせる

**何を**: 古い run の、去っていく人の目撃の文を再現する (#2268 に足した項目。調整役が決めた)。D2268-15 の着いた人の文と対になる。

古い run (`764beb875` の `_spot_graph_movement_handler.py:165-170`):
```
{actor}が〈{connection_name}〉を抜けて「{to_spot_name}」へ去っていった。
```

| | 新しい世界 | 古い run との違いと理由 |
|---|---|---|
| 見えた人への文 | `{actor}が〈{passage}〉を抜けて「{destination}」へ去っていった。` | 同じ |
| 暗くて見分けられないとき | `{actor}がどこかへ去っていった。` のまま | 着いたときの文 (D2268-15) と同じく、暗がりの文は変えない |
| 同じ行き先へ通路が何本もあるとき | 宣言の順で最初の通路の名前を書く | 同じ。古い run も、通れるかを問わず最初に見つかった接続の名前を書いていた |

- 行き先の候補は、場面に出た通路の向こうの端 (隣の場所) だけなので、通路は出発した場所と行き先をつなぐものになる。どの通路かは、行う直前の居場所から引く (`DeclaredNouns.first_passage_between`)
- 行為の目撃の文を組むところ (`ActionAttempt.witnessed_in`) は、品物の種類の控えだけでなく、行う直前の様子 (`ActorSituation`: 居場所・体・品物の種類) を受け取るようにした。行う直前の居場所は、移り始めると引けなくなるため。行為の結果の文 (`done_text_in`) と同じ形
- 移動を始めたときに決まる経路 (`TravelStartedEvent.route`) を使えば、実際に通る通路を書ける。ただ、目撃の文は行為の記録 (`PersonActedEvent`) から作るので、経路を記録に足すより、古い run と同じ決め方にした

**関連**: Issue #2268、#2271、D2268-15。
