## D1893-3. スキル定義の当たり判定を削除し、SQLiteの旧必須列だけ保存層で満たす

Issue #1893 の決定に従い、SkillSpecの `hit_pattern` と `hit_effects`、形・速度・命中パターン・追加効果の値と専用例外を削除する。#1862で保持した理由は保存・復元の依存だったが、現在のスポットの世界に当たり判定の読者はいない。スキルの装備・デッキ・進行・消費と、別の現役概念であるStatusEffectは残す。

SQLiteの `game_skill_specs.pattern_type` はNOT NULLでdefaultを持たない。過去migration・列・子表は変更せず、writerが空文字を保存する。空文字は保存互換の値であり、ドメインの型や仮の当たり判定を作らない。readerは旧列と旧子表を読み込まず、旧DBの現役フィールドだけを復元する。定義の置換・削除ではその定義に属する旧子行も消すため、子表名を使うDELETEだけは残す。単に読み込む操作では保存済みの旧行を書き換えない。

実装前に、新migrationで列を消す案と、仮の命中パターンを残す案を比較した。列を消すとschemaを整理できるが、データ移行と巻き戻しの検討が増え、今回の型削除と別の目的になる。仮の命中パターンは旧コードへ戻しやすいが、使われない値を現役のスキルに要求し続ける。今回の案は旧表が残る欠点を受け入れ、型削除と保存互換を切り離す。旧コードは空の命中パターンを復元できないため、この変更後に書いたDBの旧版への巻き戻しは保証しない。列を物理削除する必要が生じた時点で、別PRの新migrationに置き換える。

Being/world snapshotには今回の対象の保存キーがない。キーの削除・読み替え・fail-fastの変更は行わない。変更前の実際のsnapshotを使った再開試験で、既存の再開を確認する。
