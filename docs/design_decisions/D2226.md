## D2226. 古い application/llm の仕事を 4 つの境界に分け、行動の選択肢を契約の型で渡す

**何を**: 古い `application/llm` が 1 か所で受け持っていた仕事を、Being・ゲームの世界・遊びの進行・実験の 4 つに置き直した。そのうえで、世界が Being に渡す行動の選択肢の形を決めた (#2226、親 #2212)。ユーザーと決めた。選択肢の材料になる一覧から、引数を取る操作と話すことが抜けていたので、値のまだ無い行動の確かめ方も決めた (#2230)。

### 1. 仕事の地図

1 回の行動の流れ (事務所にいるゲンが金庫を開ける):

1. 遊びの進行が「このターンはゲン」と決める
2. ゲームの世界が、ゲンに見えている場面と、行動の選択肢を作る
3. Being (ゲン) が作業記憶を組み、LLM で考えて、選んだ行動 (`AgentMove`) を返す
4. ゲームの世界が、選んだ行動を行為の試みに変えて確定させ、観測を Being に届ける
5. 遊びの進行が、全員の行動が済んだら時間を進め、世界が終わったら止める

| 境界 | 置き場所 | 受け持つこと |
|---|---|---|
| Being | `src/ai_rpg_world/being/` | 作業記憶を組む、LLM で考えて行動を選ぶ、メモ・心の声・思い出す、行動の選択肢を LLM のツール (JSON Schema) に変える、出力が切れたときの呼び直し、無いツール名の救済 |
| ゲームの世界 | `src/ai_rpg_world/game_world/` | 場面と行動の選択肢を作る、選んだ行動を名前から行為の試みに変えて確定させる |
| 遊びの進行 | `src/ai_rpg_world/play_session/` | 誰にターンを回すか、時間を進める、止める (世界の終わり、決めた tick、LLM の呼び出しが続けて失敗したとき、同じ行動の繰り返し) |
| 実験 | `src/ai_rpg_world/experiment/` | 実験の条件 (profile、run id、シナリオ、モデル)、記録 (trace、計測、プロンプトの保存、report.md) |

- LLM を呼んで考えるのは Being。遊びの進行は「ゲン、あなたのターン」と頼むだけにする。スタブで動く Being も同じ入口で差し替えられる
- 遊びの進行は、記録のことを知らない。実験は、進行・世界・Being から出来事を受け取って書くだけにする。実験ではなく世界を動かし続けるとき (MMO) は、遊びの進行だけを使う
- 遊びの進行と実験は、Being と同じくトップレベルのパッケージにし、中を domain / application / infrastructure に分ける。ターンを回す決まり (#2225) は遊びの進行のドメインに置く
- `play_session` は「1 回の遊び」を受け持つ。ゲームの世界の作業単位 `WorldSession` と区別するため `play_` を付けた

**採らなかった案**:

- 遊びの進行と実験を 1 つにまとめる (`AgentRuntime`): ターンを回す決まりと trace の書き方が同じ場所に並び、古い `world_runtime` に近い形に戻りやすい。LLM を使うのは Being なので、名前もエージェントを動かしているように読めて合わない
- 進行役を `game_master` と呼ぶ: TRPG の進行役は判定 (世界の決まり) もするので、世界と役割が重なって読める
- 遊びの進行を `application/` の下に置く: ドメインの決まり (ターンを回す決まり) の置き場所が無い
- 遊びの進行が、Being の作業記憶を使って LLM を呼ぶ (古い run と同じ): 考える仕事が Being の外に出て、ターンの仕事とプロンプトの仕事が混ざる
- 世界が LLM のツールの JSON を直接作って渡す: 世界が LLM の書式を知ることになり、ツールの形を変えるたびに世界のコードを直すことになる

### 2. 行動の選択肢の型

世界の「いまできる行為の一覧」(`AvailableActions`) はゲームの型 (場所の宣言、品物の ID) でできていて、Being は import できない。`being/contract` に、世界と Being のどちらも読める行動の選択肢の型を足す。世界は LLM のツールの書式を知らずに済み、Being はゲームの型を知らずに済む。

例の場面: 事務所にいるゲン。番号を合わせて金庫を開ける、サヨに話す、井戸・鍛冶場・南の横坑口へ行くことができる。ランプを手に持つことは、両手がふさがっているのでいまはできない。

| | 決まり | ゲンの場合 |
|---|---|---|
| 単位 | 行動の種類ごとに 1 つの選択肢にし、相手は候補の一覧から選ぶ。**この仕様は変えない** (ユーザー) | 「行く」(候補: 井戸・鍛冶場・南の横坑口)、「話す」(候補: サヨ)、「操作する」(金庫 / 番号を合わせて開ける / 番号を 1 つ入れる)。LLM のツールの顔ぶれはターンが変わっても変わらず、候補は場面の文に出す (design_decisions #1)。古い run の `travel_to(destination_label)` と同じ形 |
| いまはできない行動 | 理由を付けて渡す。ツールは呼べない。Being は候補表に出さず、理由は世界の【現在地と周囲】が出す (D2267 で変えた) | 「ランプを手に持つ — いまはできない: 両手がふさがっている」 |
| 値の種類 | 自由に書く文字と、候補から選ぶものの 2 種類 | 金庫の番号と話す中身は文字。渡す品物と行き先は候補から選ぶ |

選択肢を LLM のツールに変えるのは Being の仕事 (#2240)。世界は契約の型まで作る (#2230)。

契約の型 (`being/contract/action_choice.py`):

| 型 | 受け持つこと |
|---|---|
| `ActionChoice` | 行動の種類 1 つ。`name` はツールの名前になるので 64 文字までの ASCII の識別子。選べるものが無いターンも同じ顔ぶれで渡す |
| `PickOne` / `Candidate` | 候補から選ぶ値。候補の下に、その候補を選んだときに続けて決める値を持てる (金庫 → 番号を合わせて開ける → 番号)。値の名前は道筋に沿って重ならない (Being が引数を平らに並べても、入れ子にしても衝突しない)。別々の候補の下で同じ名前を使うのはよい。候補の下の空の `PickOne` は行き止まりなので拒む |
| `FreeText` | 自由に書く文字 |
| `UnavailableAction` | いまはできない行動。選んだはずの候補の道筋 (`picked`) と理由。道筋が空なら行動ごと選べない。候補にも並ぶ道筋と、同じものの重複は拒む |
| `ActionChoices` | 1 ターン分の並び。同じ名前の選択肢を拒む |
| `ArgumentOutline` | 引数の見取り図の 1 つ (名前と見出し、必須か)。`ActionChoice.outline` に並ぶ (下の「引数の見取り図」) |

**採らなかった案**:

- 行動と相手の組ごとに 1 つの選択肢: 場所を移るたびにツールの顔ぶれが変わってキャッシュが効かず、選択肢の多い場面でツールが数十個並ぶ
- できる行動だけを渡す: 何をすればできるようになるかが分からない
- 値を文字だけにする: 品物も名前の文字で入れることになり、候補に無い名前の扱いが増える

#### 引数の見取り図 (#2240)

Being が選択肢をツールにするとき、ターンごとの値からは引数を組めない。候補の無いターンには入れ子の `how` が現れず、ツールの定義がそのターンだけ変わる (design_decisions #1)。道筋の `how` と操作の宣言の引数 `code` は、どちらも候補の下の値として届くので見分けられない。そこで `ActionChoice` に、候補によらず行動の種類ごとに変わらない見取り図を持たせる。

| 欄 | 決まり | ゲンの場合 |
|---|---|---|
| `outline` | ツールの上の段に置く引数の名前と見出し。`required` の引数は、いちばん上の値として毎ターン同じ順に必ず渡り、ツールの必須の引数になる。`say_inline` (行動しながらの一言) は、古い run で付けていた 9 つ (travel_to、explore、interact、wait、use_item、drop_item、give_item、pickup_item、tend_to_player) に載る | `interact` は `target`・`how`・`say_inline`。`speak` は `reach`・`to`・`content` |
| `takes_details` | 見取り図に無い名前の値 (操作の宣言にある引数) を、候補の下に持てるか。Being はこの値を `details` (object) で受ける | `interact` だけが真。金庫の番号 `code` は `details.code` |

見取り図は世界の `ActionChoiceKind` が持つ。Being は見取り図をそのままツールの引数にし、候補は場面の候補表に出す (表の形は D2267 で古い run の【現在選べる対象引数】に合わせた)。人の候補は、呼び方が重なったときだけ「 #1」「 #2」を添えて出す。選んだ行動を世界に返すときは、`details` を外して平らに並べ、人の候補は `{"person": <handle>}` にする (#2240 の後半で入れる)。

**採らなかった案**: Being が古い run の顔ぶれを表で持つ (`interact` → `target`・`how`・`details`)。契約は変えずに済むが、Being がゲームの行動の種類を知ることになる。

### 3. 一覧の抜け

`ActionCandidates._without_words` は引数を取る操作を一覧から外していて、ゲンの「番号を合わせて金庫を開ける」(`open_safe`、引数 `code`) が出なかった。話すことも出なかった。次の形で直した (#2230)。

| | 決まり | ゲンの場合 |
|---|---|---|
| 値のまだ無い試み | 引数を後で選ぶ操作は `ArgumentsNotChosen`、中身を後で書く発話は `SpeechContentNotChosen` で表す。この試みは世界を変えられず、確定させようとするとドメイン例外を投げる | 「金庫 / 番号を合わせて開ける」が、番号の無い試みとして一覧に出る |
| 前提の確かめ方 | 値の無い試みは、条件を「成り立つ・成り立たない・値が無いので分からない」の 3 つで確かめる。`all_of` (`for_everyone`) はどれかが成り立たなければ成り立たない。`any_of` (`for_someone`) はどれかが成り立てば成り立つ。`not` は分からないものを分からないまま返す。最後に分からないものは「できる」にする | 金庫の前提は `not flag safe_opened` と `code == 1907`。閉じているあいだは「できる」、開いたあとは前半が成り立たないので「いまはできない: 金庫の扉はもう開いている。中は空だ。」 |
| 話すこと | ふつうの声、叫ぶ、見分けのつく起きている人へのささやきを、中身の無い発話として並べる。行っているあいだ (`Busy`) もできる | サヨへのささやきが出る。暗がりで見分けのつかない人には出ない |

**採らなかった案**:

- 値の無い試みは、共通の決まり (`Busy`・居合わせ・疲れ・段階) だけで分け、宣言の前提を確かめない (暗がりの相手と同じ扱い): 金庫が開いたあとも「番号を合わせて開ける」が「できる」に出る
- 仮の値 (空の番号など) を入れて前提を確かめる: 値しだいの条件が必ず成り立たず、まだ選んでいない行動が「いまはできない」に出る

### 4. 行動の種類のまとめ方と、古い run のツールとの対応

行動の種類は、古い run のツールに合わせてまとめる (ユーザー)。選択肢の名前 (`ActionChoice.name`) は LLM のツールの名前になるので、古い run と同じ名前を使う。

| 選択肢 (`name` / 見出し) | 新しい世界の行為 (`ActionKind`) | 古い run のツール | 値 |
|---|---|---|---|
| `travel_to` / 行く | `TRAVEL` | `travel_to` | 行き先 (候補) |
| `set_sub_location` / 区画に出入りする | `ENTER_SECTION`、`LEAVE_SECTION` | `set_sub_location` | 作者が書いた出入りの文 (候補。「籠に乗り込む」「籠から降りる」) |
| `explore` / 探す | `SEARCH` | `explore` | なし |
| `interact` / 操作する | `INTERACT_WITH_OBJECT`、`INTERACT_WITH_CARRIED_ITEM`、`INTERACT_WITH_PERSON` | `interact` | 相手 (候補。物・持ち物・人が並ぶ) → 操作 (候補) → 宣言された引数 (文字か、持ち物の候補) |
| `wait` / 待つ | `WAIT` | `wait` | なし |
| `listen` / 耳を澄ます | `LISTEN` | `listen` | なし |
| `speak` / 話す | `SPEAK` | `speak` | 届け方 (候補。ふつうの声・叫ぶ・人へのささやき) と中身 (文字) |
| `use_item` / 使う | `USE_ITEM` | `use_item` | 持ち物 (候補) |
| `drop_item` / 置く | `DROP` | `drop_item` | 持ち物 (候補) |
| `pickup_item` / 拾う | `PICK_UP` | `pickup_item` | 落ちている品物 (候補) |
| `give_item` / 渡す | `HAND_OVER` | `give_item` | 相手 (候補) → 持ち物 (候補) |
| `tend_to_player` / 介抱する | `TEND` | `tend_to_player` | 倒れている人 (候補) |
| `vote` / 投票する | `CAST_BALLOT` | `vote` | 決めごと (候補) → 選び先 (候補) |
| `hold_item` / 手に持つ (新しく足す) | `HOLD` | なし | 荷物の中の持ち物 (候補) |
| `put_away_item` / しまう (新しく足す) | `PUT_AWAY` | なし | 手に持っている持ち物 (候補) |

古い run にあって新しい世界に無いツール: `attack` (新しい世界には `ActionKind.ATTACK_MONSTER` の値だけがあり、行為の試みが無い)、`report_body`、`buy_item`・`sell_item`、`market_*`、`trade_*`。取引は店 1 つにまとめる決まり (D2224、#2237) で、別に作る。

**採らなかった案**:

- `ActionKind` ごとに 1 つ (物・持ち物・人の操作、区画に入る・出るを別々にする): ツールが 18 個に増え、相手が物か人かでツールを使い分けることを LLM に求める。古い run の顔ぶれとも合わず、比べにくい
- 区画に入る・出るを、区画の名前を候補にした 2 つのツールにする: 作者が書いた出入りの文 (「籠に乗り込む」) を使えず、どちら向きかを名前から読み取らせることになる。この形はユーザーに確かめている途中で、変わったら区画の出入りの組み立てだけを直す

### 5. 候補の名前が重なったとき

| 重なるもの | 決まり | 例 |
|---|---|---|
| 同じ名前の品物 | 1 つの候補にまとめ、数 (`Candidate.count`) を添える。選ばれたら古いものから使う | ゲンの「ランプの油 ×3」 |
| 人 | 世界は人の名前を文字にせず、観測の本文と同じ `PersonInText` (人の印・見た目・見えている名前) で渡す (D1928)。呼び方は Being が決め、呼び方が重なったときだけ番号を添える (#2240) | 見分けのつかない 2 人は「誰か #1」「誰か #2」 |
| 同じ場所の同じ名前の物 | シナリオの読み込みで止める (`DesignFlaw`) | 事務所に「机」が 2 つ |
| 同じ名前の場所 | 行き先を名前で選ぶので、シナリオの読み込みで止める | 「井戸」が 2 つ |
| 同じ相手の下の、同じ表示名の操作 | 物ごと・品物の種類ごと・人への操作の中で重なれば、シナリオの読み込みで止める | 金庫に「開ける」が 2 つ |
| 操作の引数の名前 | LLM のツールの引数の名前になり、操作の道筋 (`target` → `how`) にも並ぶので、64 文字までの ASCII の識別子で、`target`・`how` と重ならないことを、シナリオの読み込みで確かめる | `code` はよい。`番号` と `target` は止める |

契約の型は、1 つの候補の並びに同じ文字の候補や同じ人の印が 2 回並ぶと拒む (`ContractViolation`)。重なりを解くのは、渡す側の世界と、呼び方を決める Being の仕事にする。契約が拒む形は、毎ターン落ちるより原因を追いやすいので、世界の側ではシナリオの読み込みで先に止める。

**採らなかった案**:

- 品物に番号を添えて別々の候補にする (「ランプの油 #1」「ランプの油 #2」): どれを選んでも同じなのに、LLM が番号を選び分けることになる
- 人の番号を世界が付ける: 世界が人の呼び方を決めることになり、Being が呼び名を持つ決まり (D1928) と合わない
- 同じ場所の同じ名前の物を番号で呼び分ける: 作者の書き分け忘れを、エージェントに見分けさせることになる
