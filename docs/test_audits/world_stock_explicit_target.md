# 備蓄条件が明示した対象物を読む修正

関連: [Issue #1687](https://github.com/Motifman/llm-rpg/issues/1687)

## 起きていたこと

`OBJECT_STOCK_AT_LEAST` は、条件に書かれた `target_object_id` を無視して
操作元の物体の備蓄を読んでいた。操作元0個・対象3個・必要数2個なら
誤って拒否し、反対に操作元3個・対象0個なら消費を許可していた。

条件パーサーは `target_object` を正式に許可し、名前をIDへ変換する。
不足理由の表示も明示対象を読む。宣言を受け付けることと実行の意味が
食い違っていたため、既存の対象解決に備蓄条件をそろえる。

## 修正

`SpotInteractionService._evaluate_condition` は先頭で対象を
`condition_object` に解決済みである。備蓄条件だけがこの結果を使って
いなかったので、対象の存在確認とstate参照の2行を変更した。

- 明示対象があれば、その物体の備蓄を読む
- 同じ室内の明示対象が無ければ、操作元へ戻さず拒否する
- 操作元を持たない `execute_declared_interaction` でも明示対象を読める
- 対象省略と自分自身の明示は従来のまま

対象解決の新しい実装、追加API、パーサーの変更はない。
同じ `condition_object` を使う `OBJECT_STATE` と
`OBJECT_STATE_INT_AT_LEAST` の扱いに合わせた。

## 回帰試験の所有者

`tests/domain/world_graph/test_object_stock_condition_target.py` の1つの表が、
実際の条件評価と消費までを次の6ケースで確かめる。

|ケース|期待|修正前|
|---|---|---|
|操作元0・明示対象3|対象だけ2個減り1個残る|誤拒否して失敗|
|操作元3・明示対象0|拒否し両物体の状態不変|拒否されず失敗|
|操作元のない宣言済み操作・対象3|対象を消費できる|誤拒否して失敗|
|明示対象が室内に無い・操作元3|拒否し状態不変|操作元へ作用して失敗|
|自分自身を明示・3個|操作元だけ2個減る|成功|
|対象省略・操作元3個|操作元だけ2個減る|成功|

現在手番は0に固定する。再生が不足を埋めてしまう対照ではなく、対象の
取り違えだけを判別する。評価器・効果サービスを模倣せず、返された状態を
直接確認する。拒否時は失敗条件そのものと、全物体の状態不変を確認する。

## 検証の固定点と結果

修正前後の対照はmain `78ee4d7e0181a2439dd3ecbf15b516e64a6f8434` 上で実施した。
資格情報を除去し通信を遮断する共通実行器を使い、対象作業木のsrcを
読み込むことを毎回確認した。Python3.10.22 / pytest8.4.1。

- 既存関連8ファイル106件: 成功
- 新しい回帰表: 修正前4件失敗・互換2件成功 → 修正後6件成功
- 新しい回帰表を加えた関連9ファイル112件: 成功
- 実条件パーサーで辞書の対象名をID化してから実行する外部2対照: 成功
- 修正2行を元へ戻す対照: 回帰表の同じ4件、パーサー外部2件が再び失敗
- 対照実行後、修正済み製品を元のバイト列へ復元
- 復元後の最終反復: 関連112件とパーサー外部2件が再び成功
- 変更した製品・試験のRuff、製品1ファイルのmypy、`git diff --check`: 成功

型検査の初回は共有ツールの検索パス不足で起動に失敗した。既存のmypyを
正しい検索パスで実行し直して成功を確認した。全リポジトリの試験・型検査は
実行していない。

公開前にmain `b27faa5156714ab27888df43bfc5f50a1d18410d` を取り込み、
関連112件・パーサー外部2件が再び成功した。2つのmain間でworld_graphの
製品・試験、条件パーサー、関連読込試験、手番受渡し試験、依存固定ファイルは
同一だった。修正した製品と新規回帰試験も取込み前後でバイト単位の一致を確認した。

関連試験は備蓄計算・消費、物体操作、失敗条件の受渡し、数量、記録手番、
runtimeの手番受渡し、道具操作の読込である。再生・端数の試験を扱う
PR #1684とは別の修正で、その試験ファイルは変更しない。

出たシナリオは未確認。この不具合のシナリオ全体を `ScenarioLoader` から
読み込む試験や、道具操作のアプリケーション公開入口からの実行は行って
いない。宣言済み操作について今回確かめたのは同室内のドメイン入口まで。
