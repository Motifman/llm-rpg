## 対象と判断

`test_player_status_aggregate.py::TestPlayerStatusAggregate::TestStatusEffects`
の元3宣言を全件確認した。保持R2・検査補強F1とし、宣言数と実行件数は3のまま。
同じファイルの他65宣言や、成長値・自由state・注意レベルの完了をこの変更には含めない。
製品、共有準備、共通計算、アプリ試験、CI設定は変更しない。

| 試験 | 判断 | 所有する契約 |
| --- | --- | --- |
| `test_effective_stats_with_multiplicative_buffs_via_domain_service` | R | 同種の有効効果2個をPlayerに追加し、両方を公開一覧経由で計算へ渡す |
| `test_effective_stats_filters_expired_effects_via_domain_service` | F | 失効効果を計算から除外し、清掃後に有効な効果だけを保持する |

## 件数が正しくても残す効果を誤る

元Fは攻撃20へ、UP2.0・期限5とUP1.5・期限20をこの順で追加する。
tick10で計算した攻撃30を確認し、清掃後は一覧の件数1だけを見ていた。
元の計算30は清掃前の値なので、清掃が誤った1個を残しても検出できない。

元の2入力、追加順、tick10、攻撃30、件数1を全て残した。
有効側の元入力を `active_effect` に束縛し、清掃後の公開一覧が `[active_effect]` と
等しいことを追加する。期待値は製品の計算から作らない。
`StatusEffect` と `WorldTick` は不変の値オブジェクトで、比較は値の等価性である。
内部listの同一性や、複数効果の保持順序を新しい仕様として固定しない。

単純な期限条件の全面反転は、既存のPlayer向けtick試験や戦闘ハンドラ試験でも検出する。
今回の独自差は混在入力の選別である。有効件数Nだけを正しく数えて元一覧の先頭N個を残す
誤実装では、単独失効から空になる関連試験も元Fも通るが、失効効果を残してしまう。
追加した値比較はこの取り違えを直接検出する。

## Playerの実際の利用境界

`SpotInteractionApplicationService` と `SpotAttackOrchestrator` は公開追加APIを使い、
現在tick＋継続tickから期限を設定する。`SkillCommandService` は公開一覧を計算へ渡す。
`HitBoxDamageHandler` は現在tickを取得し、攻撃側・防御側の清掃後に能力を計算する。

`StatusEffectsTickStageService` は継続HP変化を扱う。
current == expiryでは最後のHP変化を適用し、その後の清掃で期限到達済み効果を除く。
current > expiryではHP変化を適用しない。この順序は `TestExpiry` の既存2件へ残し、
今回のtick10・期限5/20の入力へ等号境界を混ぜない。

計算分離の導入コミット `72309b9862746ae89a37f14d262bdca2165ce0c5` は、
集約の公開能力・一覧をアプリ側が純粋計算へ渡す責務を明示した。
継続効果の導入 `f1b1b470cfab621a9ba08115d77597074ad55c78` は、最終tickのHP変化と
その後の清掃を区別している。Playerの追加は新list、Monsterの追加はappendだが、
今回その内部実装差を試験へ固定しない。

## 旧版・候補の検出力

製品に一時的な誤変更を入れ、毎回旧版と候補の全ファイル68件＋関連9件を直列実行した。

| 誤変更 | 旧版77件 | 候補77件 |
| --- | --- | --- |
| 清掃で有効件数Nを数え、先頭N個を残す | 全成功 | Fの追加した残存効果比較だけ失敗 |
| 追加時に同種効果を上書き | 同種保持のRだけ24≠36で失敗 | 同じRだけ失敗 |
| 追加時にATTACK_DOWNを破棄 | 強弱併存のRだけ30≠15で失敗 | 同じRだけ失敗 |

関連9件は全対照で成功した。全6実行で準備・後始末の失敗は0。
これらは検出力を確かめる意図的な誤変更で、現行製品の不具合報告ではない。
