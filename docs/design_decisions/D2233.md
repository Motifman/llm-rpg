## D2233. 新しい世界で起きたことを、受け取って書くだけの trace に残す

**何を**: 新しい世界 (`game_world`) の run で、遊びの進行・世界・Being に起きたことを `trace.jsonl` に書き出す (#2233、親 #2212)。調整役と決めた。

### 書き方の決まり

| | 決まり |
|---|---|
| 誰が書くか | experiment (`src/ai_rpg_world/experiment/`)。遊びの進行・世界・Being は記録のことを知らない (D2226) |
| 取り方 | ドメインの事実がドメインイベントとして出ているものは、そのイベントを受け取って書く。ドメインの事実でないもの (LLM とのやりとり) と、世界に断られて巻き戻された行為は、組み立てるときに差し込んだ口で受け取る |
| kind | `game_world.` を頭に付け、古い世界の kind と混ぜない |
| payload | 名前つきの値だけにする。人は `{"person_id": "gen", "name": "ゲン"}` で書く (古い世界の `player_id` の整数は使わない) |
| 行の tick | 書いたときの世界の tick。時間を進めた出来事 (`WorldTickAdvancedEvent`) は進めたあとの tick で書くので、その `before` / `after` と合わせて読む |
| 書けなかったとき | 例外を上に出さず、書けなかった数を `run_end` の `trace_failures` に残す。記録は見るためのもので、書けなくても遊びは変えない。巡りのイベントは、Being に観測を渡したあとで書く |

### 1 本目: 遊びの進行

| kind | 元 | payload |
|---|---|---|
| `game_world.round_opened` | `RoundOpenedEvent` | `round`、ターンのある人 (`due`)、飛ばした人と理由 (`skipped`、`TurnSkipReason` の値) |
| `game_world.turn_finished` | `TurnFinishedEvent` | `round`、`person`、終えた順 (`order`)、`outcome` (`acted` / `waited` / `choice_failed`) と `reason` |
| `game_world.round_closed` | `RoundClosedEvent` | `round`。閉じたら時間を 1 進める (D2232) |
| `game_world.observation_passed_on` | `ObservationPassedOnEvent` | `person`、名前を埋めた本文、`route`、`subject_is_self`、`wants_wake`、`addressed_to_self` (分からなければ `unknown`)、時刻の札。考えているあいだに預かった観測は、ターンを終えたあとに出る (D2232 の 10 節) |
| `game_world.choice_discarded` | `WorldEnded.discarded` / `ChoosingKeptFailing.discarded` | `person`、考え始めていたか、落ちた理由、選んだツールと引数 |

- 誰がなぜ起こされたかは、`observation_passed_on` の `wants_wake` と `addressed_to_self` を、次の巡りの `round_opened` と突き合わせて読む
- 同じ tick の中の順番は `turn_finished` の `order` からしか分からない

### 2 本目: 世界の側

| kind | 元 | payload |
|---|---|---|
| `game_world.perception_delivered` | `DeliverPerception` に渡す知らせの届いた記録 (`PerceptionDeliveryReport`) | 原因 (`cause` の型と `fields`)、刺激ごとの感覚・本文・場所・向けた相手、`perceived_by`・`kept_for`・`missed_by` と理由 (`NotPerceivedReason` の値)。本文は人の穴 (`{actor}`) を埋めない文面のまま。だれのことかは `cause` と、同じ tick の `observation_passed_on` で読む |
| `game_world.world_event` | 世界が確定させた出来事の配り口 (`CommittedEventsDistributor.register_receiver`) | 出来事の型の名前 (`event_type`) と、欄の値をまとめた `fields`。欄の名前が記録の引数とぶつからないようにまとめる。人は名前つき、人を鍵にした対応表は鍵を人の id で、値が 1 つの値オブジェクトは中の値だけ、数を値にした列挙は名前で書く。5 段より深い入れ子は型の名前だけを書く (シナリオの宣言を出来事ごとに丸ごと写して trace が膨らむのを防ぐ)。通し番号と時刻のスタンプは書かない |

- どちらも登録するだけで、game_world の中は変えていない
- 知らせの届いた記録は、受け取ったらすぐ書いて手放す。run のあいだためると、長い run でメモリが増え続ける
- 世界の出来事を書く口は、知らせを配る口より先に登録する。後にすると、出来事より先に、それが届いた記録が並ぶ
- `ALREADY_PERCEIVED` には、より多くを伝える刺激に差し替えられた場合と、後ろの刺激を試さなかった場合がある (D2268-20)。差し替えかどうかは、同じ行の別の刺激の `perceived_by` に同じ人がいるかで読む
- 世界に断られた行為は巻き戻されて出来事が残らないので、3 本目で Being に結果を渡す口から書く

### 3 本目: Being の側 (前半)

包むか受け取るかは、ドメインの事実がドメインイベントとして出ているかで分けた (調整役と決めた)。Being の集約が出すイベントは、メモ帳 (`MemoBook`)・エピソード (`Episode`)・短期記憶 (`ShortTermMemory`) の範囲が埋まった・いきさつを足した・古いターンを外した、の 3 つの集約にある。試みを残した・結果を受けた・観測を受けたときのイベントは無い。

| 書き出すもの | 包む / 受け取る | 理由 |
|---|---|---|
| 場面・行動の選択肢・LLM とのやりとり・選んだ行動・目次の直し (`game_world.choice`) | 包む (`TracedChooseAction`) | LLM とのやりとりはドメインの事実ではなく、イベントにならない |
| 行為の結果と断られた理由 (`game_world.action_result`) | 包む (`TracedReceiveActionResult`) | 世界に断られた行為は巻き戻されて出来事が残らず、Being も結果を受けたイベントを出さない |
| メモを書いた・エピソードを書いた・目次を直した・短期記憶の範囲が埋まった | 受け取る (後半で足す) | Being の集約がイベントを出している |
| 書き起こしの呼び出しの費用と時間 | 受け取る (後半で足す) | `LiteLLMClient` の `aux_call_sink` |

| kind | payload |
|---|---|
| `game_world.choice` | `person`、`llm_call_id`、プロンプトの `prompt_sha256` と文字数、考えた時間 (`thinking_ms`)、場面 (`scene`)、行動の選択肢の名前、【現在選べる対象引数】の本文、LLM の返事 (呼び直しも含めて全部)、結果 (`action_chosen` / `recalling` / `revising_index` / `not_chosen`) と選んだ行動、目次の直し、名前の選び直しの数 |
| `game_world.action_result` | `person`、結果の道筋 (`route`: `call_id`、成功したか、行動の要約)、本文 |

- 包む口は継承せず、遊びの進行の Protocol (`ChoosingAction`、`ReceivingActionResult`) にした。`BeingTurnSteps` は受け取ったものを使うだけで、遊びの進行は記録のことを知らない
- プロンプトの全文は trace に載せず、古い世界と同じく `prompt_dataset/` (`PromptDatasetCaptureSink`) に書く。trace の `llm_call_id` で `calls.jsonl` の 1 件を引ける。古い保存の形は人を整数で持つので、配役の並び順を番号にした
- fuzz の行動の記録は、`game_world.choice` の行から誰が動いたかを取る。前は全員が「P0」と出ていた
- 記録を組む途中で落ちても (人の引き当て、プロンプトの全文の書き出しなど)、選んだ行動は選べなかったターンにしない。選んだ行動はもう記憶に書いてあり、行為の結果も世界で確定しているため。書けなかった数は `trace_failures` に残る
- `prompt_dataset/` の行には、世界の tick と、人ごとのターンの番号を入れる。古いプロンプトの viewer は tick で並べるため
- 呼び出しが落ちたターンと、世界が終わって捨てた選択は、`game_world.choice` の行もプロンプトの全文も残さない。理由は `turn_finished` の `reason` と `choice_discarded` に残る

### 3 本目: Being の側 (後半)

| kind | 元 | payload |
|---|---|---|
| `game_world.being_event` | Being の集約のイベント (メモ帳・エピソード・短期記憶の保存先が渡すもの) | 型の名前、誰の記憶か (`person`)、欄の値 (`fields`)。短期記憶の出来事といきさつ (`experiences`・`backstories`) は本文ごと並ぶので件数だけにする |
| `game_world.aux_llm_call` | `LiteLLMClient` の補助の呼び出しの受け口 (`aux_call_sink`) | 部品 (`episode_writing` / `short_term_summary`)、モデル、時間、成功したか、トークンと費用 |

- 短期記憶のイベントは、裏の書き起こし (`MemoryWritingOnThreads`) に渡したあとで書く。書けなくても書き起こしは動く
- 書き起こしは裏のスレッドで LLM を呼ぶので、`aux_llm_call` の行には tick を入れない。裏のスレッドからは世界の保存先に触れない
- LLM のクライアントは組み立てのときに受け口を受け取るので、書く先は遊びを始めるときに渡す (`AuxCallsForwarded`)
- 行動を選ぶ呼び出しのトークンと費用は、まだ書かない。`LiteLLMClient.choose_action` が計測を捨てているため
