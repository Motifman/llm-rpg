## D1630-2. 作業記憶 (WorkingMemory) を組み、今のプロンプトと一字一句同じ文にする

**何を**: #1630 (作業記憶) の移し方の 2 本目。ターンの組み立てはまだ切り替えていない (3 本目)。プロンプトは変わらない。

- `being/domain/working_memory.py` に作業記憶を置いた
  - `Steadiness`: 区画の書き換わりにくさ。`FIXED` < `ON_ENTRY` < `GROWING` < `OCCASIONAL` < `EVERY_TURN`
  - `Section`: 見出し (無ければ `None`)、本文の行、書き換わりにくさ
  - `Closing`: 区画の外に置く締めの一文と、同じ手を続けたときに環境が添える一文 (繰り返しの警告)
  - `MemoryTexts`: Being の記憶の持ち主がそれぞれ作った区画の本文
  - `WorkingMemory`: システムプロンプトの区画、メッセージの区画、知らせ、締めを持つ値。作るときに、システムプロンプトとメッセージのそれぞれで書き換わりにくい順に並んでいるかを確かめ、崩れていれば `WorkingMemoryOrderException` を投げる。`WorkingMemory.compose` が、環境の材料と記憶の本文から今の並びを作る
- `being/application/current_working_memory.py` の `CurrentWorkingMemory` は、Being の保存先 (短期記憶、知り合い、エピソード、メモ帳) から区画の本文を集め、`WorkingMemory.compose` に渡す問い合わせ。状態を変えない
- `being/application/working_memory_text.py` が、作業記憶をシステムプロンプトとメッセージの文にする
- ゲームの側の `WorldRuntime.working_memory_for(player_id, prompt)` が、組んだ 1 ターンのプロンプトの材料 (案内、場面、課された目的、締めの一文、繰り返しの警告) で作業記憶を組む。今は、今のプロンプトと同じ文になるかを確かめるためだけに使う

**並び**:

| 文 | 区画 | 書き換わりにくさ |
|---|---|---|
| システムプロンプト | 冒頭の一文 | FIXED |
| | 案内の説明文 (人柄、世界の前提、見取り図) | ON_ENTRY |
| | 作法と環境の決まりの文 (見出しの無い 1 区画) | ON_ENTRY |
| メッセージ | 【現在の目的】 | ON_ENTRY |
| | 【知っている人】【ここまでのいきさつ】【直近の出来事】 | GROWING |
| | 【思い出せる出来事】【メモ】 | OCCASIONAL |
| | 場面の説明文 (【現在地と周囲】【現在選べる対象引数】) | EVERY_TURN |
| 区画の後ろ | 繰り返しの警告 → 知らせ (【進行中の異常】【時間の経過】など) → 締めの一文 | 並びの決まりの対象外 |

**決めたこと**:

- 案内 (`Orientation`) は、環境が毎ターン場面と一緒に渡し直す。Being は案内を状態として持たない
- 「ON_ENTRY はシステムプロンプトへ」の分け方は、まだ守れない。【現在の目的】がメッセージの先頭にあるため。作業記憶はシステムプロンプトとメッセージを別々の並びとして持ち、それぞれの中で書き換わりにくい順を守る。【現在の目的】を案内に移すのは 4 本目
- 作法と環境の決まりは、今のゲームの固定文 (`world_conduct_text`) を見出しの無い 1 区画で受け取る。案内より後ろにあるので、FIXED ではなく ON_ENTRY にした。作法を Being の道具の一覧から作り、環境の決まりを案内に分けるのは 4 本目
- いきさつは新しい順に並ぶので、末尾に足すだけではない。それでも GROWING にした。いきさつが届くのは短期記憶の範囲が埋まったときで、そのとき直近の出来事の古い分も外れる。いきさつが変わるときは、直近の出来事もいっしょに変わる
- 繰り返しの警告の位置 (#1630 のコメントに残した問い): 今の文の並びのまま、場面の説明文と知らせの間に置く。そのために、場面 (`Scene`) に知らせの並び (`notices`) を説明文と分けて持たせた。知らせは「今見えている場面に付く、毎ターン置き換わるもの」なので、#1630 で決めた環境が渡す 3 種類 (入るときに決まるもの、出来事、毎ターン置き換わるもの) からも外れない。知らせを締めの一文の直前に置くのは、最新の変化を行動を選ぶ直前に読ませる位置だから。警告を知らせの前後どちらに置くかは、4 本目で文面を変えるときに決め直す
- reason_first: 作業記憶は、普通のターンと reason_first の評価の段で送る文 (同じ文) を組む。行動の段で足す部分 (【行動前の状況評価】、候補表、行動の段の指示) は、ゲームの側が今のまま後ろに足す。行動の段では、場面に候補表を入れない (`inject_dynamic_argument_candidate_table(..., in_scene=False)`)。表は場面ではなく足し書きの中にあるため。足し書きを作業記憶に取り込むかは 3 本目で決める
- #1630 のコメントの型の案にあった `Section.empty_text` は持たせなかった。空のときにどうするかは区画ごとに違い (目的・知っている人・いきさつは見出しごと出さない、直近の出来事は「（なし）」と書く、目次とメモは持ち主が空と分かる文を作る)、それを決めるのは `compose` にした

**見張る試験**:

- 不変条件 1 (書き換わりにくい順): `WorkingMemory` を作るときに確かめる (`tests/being/domain/test_working_memory.py`)
- 不変条件 2 (末尾に足す区画は途中を書き換えない): 出来事が 1 つ増えた前後のターンで、システムプロンプトは同じで、メッセージが直近の出来事までの前のターンの文で始まることを比べる (`tests/being/application/test_current_working_memory.py`)
- 一字一句同じ: 同じ試験の中で、今の組み立てと作業記憶の組み立てを両方動かして比べる (`tests/application/world_runtime/test_working_memory_matches_the_prompt.py`)
  - `data/scenarios` の全シナリオの最初のターンの全員で、締めの一文の 2 通り (tool_choice が required のときと auto のとき) と、候補表を差し込まない評価の段の文
  - 廃坑の山村と station_drill で、繰り返しの警告が出るターン、いきさつ・目次・メモ・知っている人がそろうターン、停電の知らせと直近の出来事があるターン
- 行動の段で場面に候補表を入れないこと: `phase_a` が `in_scene=False` で差し込むことを見る (`test_reason_first_action_phase_keeps_the_candidate_table_out_of_the_scene`)

**まだ見ていないこと**: 不変条件 2 の試験は、出来事が増えるターンだけを見ている。知っている人が増えるターン (名前の順に並ぶので途中に入る) と、いきさつが届くターン (直近の出来事の古い分もいっしょに外れる) は、末尾に足すだけではないので、前のターンの文が先頭に残らない。どちらも今の文でも同じで、1 本目のキャッシュの実測 (#1630 のコメント) の 12 組と 8 組にあたる。

**例外の置き場所**: `WorkingMemoryOrderException` は、ほかの Being の例外と同じ `domain/being/exception/being_exceptions.py` に足した。Being の例外を `being/` に移すのは移し替え (#1469) でまとめて行う。

**trace**: 作業記憶は trace に出していない。今の組み立てが送る文は変わらないので、`prompt_section_breakdown` と prompt dataset はそのまま。目次を出したときの `episode_index_shown` は、今の組み立てが記録している。作業記憶へ切り替えるとき (3 本目) に、記録する場所を移す。
