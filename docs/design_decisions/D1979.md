## D1979. game_world の値の型の範囲と、文書から外した型

**何を**: 設計し直したゲームの世界 (#1978) の置き場所 `src/ai_rpg_world/game_world/` を作り、どの段階も使う値の型を `game_world/domain/value_object/` に置いた。値の範囲のうち、設計の文書 (`docs/environment_model/design/`) から決まらなかったものは次のように決め、文書も合わせて直した。

| 型 | 範囲 | 持たせた操作 |
|---|---|---|
| `Ticks` | 0 以上 | 比べる |
| `WorldTick` | 0 以上 | `+ Ticks`、`ticks_since` (前の時刻からの長さ)、比べる |
| `Count` | 0 以上 | 足す、引く (0 を下回るなら断る)、比べる |
| `Gold` | 0 以上 | 足す、引く (持っている額を超えるなら断る)、比べる |
| `Damage`、`HealAmount` | 1 以上 | なし |
| `HitPoints` | 今の値 0 以上、最大値 1 以上、今の値 ≤ 最大値 | `damaged_by` (0 で止まる)、`healed_by` (最大値で止まる) |
| `Rate` | 0 以上 1 以下の割合 | なし |
| `Multiplier` | 0 より大きい倍率 | なし |
| `Probability` | 0 以上 1 以下 | 足す (1 で止まる) |
| `FatigueAmount`、`HungerAmount` | 0 以上 | 足す、比べる |
| `Capacity` | 1 以上 | なし |
| `HandsNeeded` | 1 か 2 | なし |

文書の直し:

- `StealthRule.duration_rate` を `Multiplier` にした。同じ `Rate` に割合 (`revive_hp_rate` の 0.6) と倍率 (2 倍) の 2 つの意味を持たせないため
- `HungerRule.starvation_damage` を `Damage | NoStarvationDamage` にした。`Damage` は 1 以上なので、飢えても痛手の無い世界 (今のコードの既定) を別の値で書く
- `NeedType` と `NeedAmount` を外した。今のコードの欲求は空腹と疲れの 2 つだけで、それぞれ `HungerAmount` と `FatigueAmount` がある。同じ量を 2 つの型で表さないよう、条件・効果・世界を読む口を空腹と疲れに分けた (`HungerAtLeastCondition` / `FatigueAtLeastCondition`、`SatisfyHungerEffect` / `RestEffect`、`hunger_of` / `fatigue_of`、`satisfy_hunger`、`HungerLevelChangedEvent`)
- `SubtractFromObjectCountEffect` を足した。`Count` は 0 以上なので `AddToObjectCountEffect` では減らせないが、今のシナリオには数を減らす宣言がある

**なぜ操作を絞ったか**: 文書に式として出てくる操作 (`fell_at + grace`、`Item.age` など) だけを持たせた。`Capacity` の満員の判定、`HandsNeeded` の手が足りるかの判定、疲れと空腹を減らす操作、起こすときの体力の計算 (`revive(hp_rate)`) は、使う集約 (`Whereabouts`、`PersonInventory`、`PersonVitals`) を作る段階で足す。先に作ると、使う側の形を値の型が決めてしまう。

**例外**: `game_world` は古い `ai_rpg_world.domain` を import しないので、`domain.common.exception` の基底は使わず、`game_world/domain/exception/game_world_exception.py` に基底 `GameWorldDomainException` を置いた。
