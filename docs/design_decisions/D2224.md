## D2224. 取引を店 1 つにまとめ、持ち主が留守でも売り買いできるようにする

**何を**: 旧コードで 4 つに分かれていた取引 (宣言だけの商人、人どうしの取引の申し出、掲示板、旧ドメインの `domain/shop`) を、店 1 つにまとめる決まりを決めた (#2224、親 #2212)。旧シナリオ 5 本 (market_town v1 / v2 / v3、offering_race v1 / v2) をステージ 8 で移す前に決める。実装は別の Issue で行う。

例の場面: 市場町の広場に、トムが店を出している。トムはパンを 1 つ 10G で 3 つ売り、薬草を 1 つ 6G で 2 つ買い取ると掲げている。レナは薬草を摘んで売り、そのお金でパンを買う。

### 1. お金

| 決まり | 例 |
|---|---|
| お金は人ごとの数で持つ (`PersonInventory` の `Gold` のまま) | |
| 手渡しで、品物と一緒にお金も渡せる。お金だけを渡してもよい。払うかどうかは本人しだいで、払ったふりもできる | ミナがトムにパン代の 10G を渡す (`ItemHandOverAttempt` に `gold` を足す)。見ていた人には「ミナがトムに10Gを渡した。」 |
| 初めの所持金は、登場人物の宣言に書ける。書かなければ 0 | `characters.lena.initial_gold: 20` |

### 2. 店

| 決まり | 例 |
|---|---|
| 店は、いまある場所に出す。地図は変わらない | トムは広場に店を出す。新しい場所は増えない |
| 店を出せる場所は、シナリオ作者が場所の宣言に書く (`SpotDeclaration.allows_shops`)。宣言の無い世界では店を出せない | 市場町なら広場と通りに出せる。坑道の奥には出せない |
| 1 つの場所に出せる店の数に上限は無い。1 人が開ける店は 1 つ | 広場にトムの店とミナの店が並ぶ |
| 持ち主が店を開け閉めする。閉じた店では売り買いできない | |
| 持ち主が留守でも売れる | トムが坑道にいるあいだに、レナがパンを買う。10G はトムの持ち物に入り、トムには「店でパンが1つ売れ、10Gが入った。」と届く |
| 売る品と買い取る品を、同じ形の品目 (`ShopLine`: 何を・いくつ・いくらで・説明) で持ち主が編集する | 「パンを 3 つ、1 つ 10G で売る」「薬草を 2 つ、1 つ 6G で買い取る」 |
| 値段は持ち主が決める | |
| 品物の名前は偽れない。品目の説明の文 (`ShopLineNote`) は持ち主が自由に書ける | 「薬草 — 摘みたて、よく効く」とは書けるが、薬草を「万能薬」として売ることはできない。品目は品物の種類 (`ItemSpecId`) を指し、名前は宣言の名前で出る |
| 並べた品物は、荷から店に移して預ける。持ち主も手元では使えない | トムは並べたパンを食べられない |
| 買い取りに掲げたお金も店に預ける。お金が足りなければ買い取りを掲げられない | 薬草 2 つの買い取りを掲げると、12G を預ける。レナは必ず売れる |
| 1 回の行為でまとめて買える。お金か在庫のどちらかが足りなければ、全部断る | パン 3 つを頼んで残りが 2 つなら、1 つも買えない |
| 店の見た目 (`ShopLook`) は、開くときに持ち主が書き、開いているあいだは書き直せる。1 行 80 文字まで。物と同じ見え方の決まりに従い、暗い場所では見えない | 「焼きたてのパンが並ぶ小さな露店」 |
| 店の見た目の文は自由に書ける。持ち主の呼び名と、店であることは世界が付ける | 場面には「トムの店: 焼きたてのパンが並ぶ小さな露店」と出る。トムを知らない人には「煤けた上着の男の店」。他人の店のふりはできない |
| シナリオ作者が持ち主の店 (MMO でいうモブの店) も作れる。品物と見た目と持ち主の呼び名は作者が書く。在庫とお金は、数か「尽きない」(`UnlimitedSupply`) かを書く | グスタフの露店は「尽きない」と書けば、market_town_v1 がいまのまま回る |

### 3. 形を決めるうえで、自分の判断で足した決まり

Issue の決まりを形にするときに要った決まり。

| 決まり | 理由 |
|---|---|
| 買う・売るの試みは、エージェントが見た単価 (`seen_unit_price`) を持つ。届いたときに単価が変わっていれば断る (`GAME_WORLD.SHOP.PRICE_CHANGED`) | 考えているあいだにトムが 10G を 50G に上げても、レナが知らずに 150G 払わない。届いたときに必ず確かめ直す決まり (action.md の「できること」) を、値段にも当てる |
| 売る (レナが店に薬草を売る) も、買うと同じくまとめて売れ、買い取りの残りか預けたお金が足りなければ全部断る | 買うと売るで決まりを揃え、エージェントが覚える違いを増やさない |
| 自分の店からは買えない・売れない。行為を作るときにドメイン例外で断る (形の誤り) | 預けた品とお金を、品目の編集を通さずに出し入れできてしまう |
| 店の在庫は品物の種類で数える。買い手に渡す品物は、預けた順に古いものから選ぶ。持ち主が品目の数を減らして荷へ戻す品物は、新しいものから選ぶ | エージェントは品物の 1 つずつではなく「パンを 3 つ」で頼む。同じ種類のどれを渡すかを毎回同じに決める |
| 品目は、売りと買い取りのそれぞれで、品物の種類ごとに 1 つまで。同じ種類を売りと買い取りの両方に掲げてよい | 「パンを 10G で売る」が 2 行あると、どちらから買うかが決まらない |
| 品目を編集する行為は、売りか買い取りか・品物の種類・数・単価・説明を渡し、その品目をその値に書き換える。数を増やせば荷から預け、減らせば荷へ戻す。数を 0 にすると品目が消える。戻すとき荷がいっぱいなら断る | 品目の追加・変更・取り下げを 1 つの行為にまとめ、エージェントの覚える行為を増やさない |
| 店の見た目を書き直すのは、開く行為とは別の行為 (`REWRITE_SHOP_LOOK`) にする | 開いている店を「開く」と、何も開かないのに見た目だけが変わり、行為の名前と結果が合わない |
| 店を出せる場所の宣言は、場所の宣言の欄 (`SpotDeclaration.allows_shops`) にする。作者の店は、店を出せる場所でなくても置ける | 店を出せるかは場所が何であるかの一部。作者の店は作者が置き場所を選ぶので、許しを要らない |
| 持ち主の行為は、店を出せる場所が 1 つも無い世界では、ツールの一覧から消す (`ToolExposure`)。作者の店だけの世界では、買う・売るだけを出す。店を出せる場所のある世界で、出せない場所にいるときは、理由つきのできない (`NotNow`) で出す | 店を想定しない世界では、店の行為がプロンプトに出ない。出せる世界では、いまできない行為を消さない (design_decisions #37) |
| 予約 (`PersonInventory.reserve` / `release_reservation` / `is_reserved`、`ItemsReservedEvent` / `ReservationReleasedEvent`) は設計から外す | 「取引に出した品はほかで使えない」を、荷に残したまま印を付ける形ではなく、荷から手放して店に移す形で満たす。荷に残すと、留守の持ち主の荷から品物が買い手へ移り、預けた品が荷の数に数えられる。予約はまだ実装されていない |

### 4. Issue から決めきれず、ユーザーと決めた決まり

| 問い | 決まり | 例 |
|---|---|---|
| 留守の持ち主への「パンが売れた」の届け方 | 世界の知らせとして、売れた確定ですぐ持ち主に届ける。倒れていればためて、目が覚めたときに届ける。世界から外れていれば届けない。買った人の名前は入れない。目立たない (`Background`) ので、持ち主の手番を考え直させない。持ち主がその場で見ていても、買う行為の目撃と重ねて届ける | 坑道のトムに「店でパンが3つ売れ、30Gが入った。」が届く。買い取ったときも同じ形で「店が薬草を2つ買い取り、12Gを払った。」が届く |
| 店を閉じたとき、預けた品とお金はどうなるか。閉じた店の品目は残るか | 閉じても品目と預けた品・お金は店に残る。同じ場所でまた開けばそのまま再開する。引き上げるのは、品目の編集で数を 0 にしたとき。品目の編集と引き取りは閉じた店でもできる。品目か受け取った品が残っているあいだは、別の場所に店を開けない (`SHOP.GOODS_LEFT_ELSEWHERE`)。空なら、別の場所で開くと店ごと移る | トムが閉じた店は、場面に「トムの店 (閉まっている)」と出る |
| 持ち主が死んだ・世界から外れたら | その確定のあと、ハンドラが店を閉じる。預けた品とお金は店に残り、誰も取り出せない。外れた人の店の品は時間が止まる (D2211) | |
| 買い取った品の行き先 | 店にためる (`received`)。持ち主は店の前で引き取る (`COLLECT_FROM_SHOP`)。荷がいっぱいなら引き取りを断る。代金のお金は上限が無いので、持ち主に直接入る。作者の店が買い取った品は世界から消す | レナが売った薬草 2 つは店にたまり、戻ったトムが引き取る |
| 開く・閉じる・品目の編集・見た目の書き直し・引き取りに、持ち主がその場にいる必要があるか | 閉じる・品目の編集・見た目の書き直し・引き取りは、店の場所にいる必要がある (`WithShop`)。品を預けるのは手から店へ移すことなので。開くは、いまいる場所に開く | |

### 5. 品物の置き場所が 3 つになることと、いまのコードとの食い違い

品物の置き場所は、いまの「人の持ち物」と「場所の地面」に「店」が加わって 3 つになる。いまのコード (#2224 の時点の `game_world`) と食い違うところと、それぞれの扱い。

| いまのコード | 食い違い | 扱い |
|---|---|---|
| `where_item_was.py` の `WhereItemWas = CarriedBy \| LyingAt` と `ByWhereItemWas` (`when_carried` / `when_lying`) | 店の品物が時間で消えると (`Item.run_out(now, where)`)、3 つ目の置き場所が要る | `KeptInShop(shop: ShopId)` を足し、`ByWhereItemWas` に `when_kept_in_shop(shop)` を足す。読む側は `ItemRanOutNotice` (`ItemRanOutEvent` を刺激に変える) だけ。`ItemRanOutNotice` は刺激の並び (`tuple`) を返す形にし、`when_kept_in_shop` は空を返す。店の品が傷んだ刺激は `ShopItemsRanOutEvent` からだけ作り、同じことを二重に届けない |
| `ItemsRunningOut` と `PassWorldTime` | 世界にいる人の持ち物と、場所ごとの地面でだけ品物の時間を進めている | 店に預けた品と受け取った品も傷む。`ItemsRunningOut.run_out_kept_in_shop(shop, now)` を足し、`PassWorldTime` が、持ち主が世界から外れていない店 (作者の店は全部) について呼ぶ。在庫はその分減る (`ShopItemsRanOutEvent`)。品目の扱いと、誰に知らせるかは下の 2 行 |
| 店の品物が時間で消えたときの知らせ | いまは持っていた本人の体の刺激か、地面の場所の見える刺激 | 持ち主にだけ、売れた知らせと同じ世界の知らせ (`Background`) で届ける (`ShopTexts.ran_out_notice` が `Lasts.ended_text` を包む)。同じ tick に同じ店で傷んだ分は、品物の種類ごとに 1 つの知らせにまとめる。その場の人には届けない (場面の在庫の数が減って分かる)。ユーザーが決めた |
| 品目の数が 0 になったとき | (新しい決まり) | 売り切れ・傷んで 0 になった品目も残し、場面に「売り切れ」と出す。消えるのは持ち主が数を 0 に編集したときだけ。買い取りの品目も、残りが 0 になっても「買い取り終了」と出して残す。ユーザーが決めた |
| 品物の状態 (ランプの燃料、パンの年齢。#2073 の持つ時間) | 在庫を種類で数えて古い順に渡すと、同じ種類でも中身の違うものを買い手は選べない | 買い手に見えるのは、種類の名前・数・単価・持ち主の説明だけ。中身の値は場面にも一覧にも出さない。いまの場面も、地面の品物の状態の値を持たない (`SpotContents.ground_items` は `ItemInstanceId` だけ)。中身を伝えたい持ち主は説明に書く (「燃料は半分ほど」)。燃料 3 と 10 のランプが同じ値段で並ぶと、買い手は預けた順の古い方を受け取る |
| 作者の条件と効果: `HasItemCondition`、`GoldAtLeastCondition`、`ItemAgeAtLeastCondition`、`ItemValueIsCondition`、`GiveItemEffect` / `TakeItemEffect` / `MoveItemEffect` | 店に預けた品とお金を「持っている」に数えるか | 数えない。`HasItemCondition` と `GoldAtLeastCondition` は `PersonInventory` だけを読む。「トムがパンを持っている」は店に並べたパンを数えない。`TakeItemEffect` と `MoveItemEffect` は持ち物からだけ取り、店の品を取れない。`ItemAgeAtLeastCondition` と `ItemValueIsCondition` はきっかけの品物 (`ThisItem`) を読み、店の行為は品物をきっかけに持たない (`this_item` は `ItemNotInTriggerException`) ので、店の品を指せない。コードは変えない |
| 明るさ: `lighting_conditions.py` の `_light_source_held_at` | 手に持った品物だけが明かりになる | 店に並べた灯したランプは場所を照らさない。荷の中の物と同じ扱いで、コードは変えない |
| 保存: `game_world/infrastructure/persistence/` の `AggregateCodecs` | 店の集約に memento と変換が無い | `ShopMemento` と `shop_codec.py` を足し、`kind` を `shop`、`key` を `ShopId` の文字の形で登録する (persistence.md、#2084)。登録を見張るアーキテクチャのテストが、足し忘れで落ちる。いまの行の形は変わらないので、古い形を直す変換は要らない |
| お金: `PersonInventory.earn` | いまどこからも呼ばれていない | 店 (`ShopTrade`、品目の編集でお金を戻すとき) と、お金の手渡しが初めて呼ぶ |
| 手渡し: `ItemHandOverAttempt`、`HandOverItems`、`ItemsChangingPlace.hand_over(giver, receiver, items)` | お金を渡せない | `ItemHandOverAttempt` と `ItemsChangingPlace.hand_over` に `gold: Gold` を足す。`hand_over` は品物を移したあと、`gold` が 0 でなければ `giver.pay` → `receiver.earn`。型の名前は変えない |
| できることの一覧: `ActionCandidates.hand_overs` | 相手ごと・品物ごとに 1 つの試みを並べている | 品物の候補はそのまま。お金を持っている人には、相手ごとに「お金を渡す」を 1 つ足し、額はエージェントがツールの引数で渡す (`ToolExposure` の渡すツールに額の引数を足す) |
| 知覚: `BuiltInActionPerceptions` と `BuiltInPerceptionRow` | 店の行為の行が無い。いまは世界で行える組み込みの行為の行をすべて求める | 店の 7 つの行為の行を足す。どの行も `has_target` は偽 (店の持ち主は行為の相手ではなく、留守のこともある)。書ける呼び名は、買う・売るが `{item}`・`{count}`・`{gold}`、品目の編集が `{item}`、ほかは無し。店を出せる場所も作者の店も無い世界では、店の行は求めない (`DeclaredNouns.has_shops`)。いまのシナリオは書き直さずに読める |
| 知覚の文: その場にいる人にどう見えるか | (新しい決まり) | 見ていた人には、行為ごとの目撃の文が届く (共通の部品の既定: 「{actor}が店を開いた。」「{actor}が店を閉じた。」「{actor}が店の{item}の札を書き換えた。」「{actor}が店の飾りを直した。」「{actor}が店で{item}を{count}つ買った。」「{actor}が店に{item}を{count}つ売った。」「{actor}が店から品物を引き取った。」)。音は無し。代金の額は目撃の文に書いてよい (その場で払うのが見える) |
| `RefusalTexts.world_state` と共通の部品の `refusal_texts` | 店の `error_code` が無い | action.md の表の 9 つを、共通の部品に足す |
| `WorldRules.action_durations` と共通の部品の `rules.action_durations` | すべての組み込みの行為の長さを求める | 店の 7 つの行為を 1 で足す |
| `SpotDeclaration`、`CharacterDeclaration`、`StartingPerson` の作り方 | 欄が増えると、宣言を作るテストの呼び出しがすべて変わる | 読み込みでは共通の部品の `defaults.spot.allows_shops: false` と `defaults.character.initial_gold: 0` で埋める。テストの宣言の作り方は、実装の PR で 1 か所の作り方の関数に寄せてから欄を足す |
| `WorldAggregates` と `WorldFacts` | 店を引く入口が無い | `shop(shop: ShopId)` と `shops_at(spot: SpotId)` を足す。場面 (`SpotContents`) を集めるところと、`ShopTrade` を呼ぶユースケースが使う |
| `ToolExposure` | 店のツールが無い | 持ち主の行為のツール (開く・閉じる・品目の編集・見た目の書き直し・引き取り) は、店を出せる場所がある世界でだけ出す (`DeclaredNouns.has_shop_sites`)。買う・売るのツールは、店を出せる場所か作者の店がある世界でだけ出す (`DeclaredNouns.has_shops`)。プロンプトの本文に店のツールの名前を書くときも `is_exposed` で確かめる |

### 作らないもの

- 掲示板: 店の売りと買い取りで代える。旧の掲示板のシナリオ (market_town_v3、offering_race) は店で書き直す
- 人どうしの取引の申し出: だまされない売り買いは店が受け持つ。顔を合わせてやりとりするなら、手渡しを 2 回する (先に渡した側が相手を信じる)。信じるか裏切るかを選ぶ場面も観察したい振る舞いなので、そのまま残す
- 店を見る条件と、店を動かす効果 (「トムの店が開いているなら」「夜になったらグスタフの露店を閉じる」): 要るシナリオが出たときに足す

### 採らなかった案

- お金は取引の中でだけ動く (旧コードと同じ): お金だけを渡すことも、施すこともできない
- 店を新しい場所として開く: 通路のつなぎ方や、消したときに中にいた人をどうするかなど、地図を作り替える決まりが要る
- 宣言だけの商人 (旧と同じ): 品物とお金が湧いたり消えたりし、売り切れの場面を作れない
- 作者の店とプレイヤーの店を別の仕組みにする: エージェントが 2 通りの買い方を覚える必要がある
- 持ち主がその場にいるときだけ売れる: 手番の違うエージェントどうしが取引できない
- 持ち主が品物の名前を変えられる: 何を買うかを偽れてしまう
- 在庫が足りないときは、ある分だけ売る: 結果が分かりにくい
- 買い取りのお金を預けない: 掲げてある買い取りに持っていっても、持ち主の事情で断られることがある
- どこにでも店を出せる: 店を想定しないシナリオでも店が開かれうる
- 掲示板・取引の申し出を店とは別に作る: 似た仕組みが 2 つになり、エージェントが覚える行為が増える
- 預けた品を持ち主の荷に残し、予約の印を付ける (いまの `PersonInventory.reserve` の設計): 留守の持ち主の荷から品物が買い手へ移り、預けた品が荷の数に数えられる
- 単価を試みに持たせず、届いたときの単価で売る: 考えているあいだに値段を上げられると、買い手が知らずに払う
- 売れた知らせを店にためて、持ち主が店に戻ったときに届ける: 坑道にいるトムに「パンが売れた」が届かない
- 閉じると品目が消え、預けた品とお金を持ち主の荷へ戻す: 閉じる行為が荷の空きに左右され、「閉じられない」「品が地面に散らばる」場面ができる
- 持ち主が死んだら、預けた品とお金を倒れた体の持ち物に戻す: 体の持ち物へ戻す決まりを別に足すことになる
- 持ち主が死んでも店を開いたまま売り続ける: 死んだ人の持ち物にお金が入り続ける
- 買い取った品を持ち主の荷へ直接入れる: 留守のトムの荷がいっぱいだと売りを断ることになり、「レナは必ず売れる」が崩れる
- 閉じるだけはどこからでもできる: 閉じた店から品を引き上げるにはどのみち店に行く必要があり、その場にいる決まりを行為ごとに分ける理由が無い
- 店の品が傷んだことを、地面の品物と同じくその場の見える刺激にする: 留守の持ち主が気づかない。持ち主の品なので、売れた知らせと揃える
- 店の品が傷んだことを誰にも知らせない: 持ち主が、在庫が減った理由を知る手段が無い
- 在庫が 0 になった品目を消す: 売り切れと「もともと売っていない」の見分けがつかず、持ち主は補充のたびに品目を書き直すことになる
