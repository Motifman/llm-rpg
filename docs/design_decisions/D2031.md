## D2031. 条件・効果・行為・動詞の宣言が使う型と約束をそろえる

**何を**: ステージ 4 の中身 (#2023〜#2026) が互いを待たずに並べて作れるよう、複数の PR が使う型と約束を入れた (#1978)。D2029 で置き換えると決めた `ChanceOccasion`・`EffectPath`・`ConditionPath.child`・`WorldFacts.roll` と質問ごとのメソッドを外し、`WorldFacts` を集約ごとの読む型 (`...Reading`) を返す入口にした。文書から決まらなかったことは、ユーザーと次のように決めた。

| 型・振る舞い | 決めたこと |
|---|---|
| `WorldFacts.rules()` と、`PersonInventoryReading` の `count_of` / `items_to_give_up` | `WorldRules` と持ち物の問い合わせは並行する #2032 が作る。それ以外を先に作り、#2032 のマージ後に同じ PR へ取り込んで足してからマージする |
| `InteractionDeclaration.arguments` の型 | `ArgumentDeclaration(name, kind)`、`TextArgument`、`ItemArgument` を `action/argument_declaration.py` に値の型として置く。行為の型 (#2025) が引数の種類を確かめ、#2026 の `InteractionDeclaration` はこれを import して `arguments` に使う |

**実装で決めたこと**:

- 読む型は `condition/aggregate_readings.py` に並べた。中身は、いまの集約の問い合わせのうち自分の ID 以外のもの。`ItemReading` は、手に持つ品物の種類を確かめる条件が使うので `spec_id` も持つ
- 操作の宣言の欄の約束は `DeclaredInteraction` (`action/`)、集団の決定の規則の約束は `DeclaredGroupDecisionRules` (`effect/`)。どちらも欄を `@property` で書き、宣言の frozen dataclass が import せずに満たす
- 行為でないきっかけ (出来事、反応、二人で合わせる操作、集団の決定、時間の経過) は、`acting_person`・`argument`・`fall_cause_for` を同じ答えにするので、共通の基底 `_NotAnAction` から受け継ぐ
- 倒れた理由の共通の関数は `fall_cause_from(acting_person, victim)` (`action/acting_person.py`)
- `ConditionPath.under` は位置を前に足す。並びは外に出さないので、等しさと区別だけをテストする
- `WorldInMemory` の偶然は、テストが並べた値を順に返す `FractionsInOrder`。引き尽くしたら `LookupError` で止める。`nouns()` は渡した場所・通路・段階の宣言から `DeclaredNouns` を作る
- `ActionAttemptForTests.is_allowed_in` は、段階の `allowed_actions` を直接見る。本物の行為の型 (#2025) がこれを `isinstance` で外から分けずに答えるには、`WorldStageDeclaration` 側に照らすメソッドが要る

**関連**: Issue #2031、#1978、D2022、D2029。
