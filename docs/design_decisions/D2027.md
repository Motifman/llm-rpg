## D2027. 出来事の帳簿・旗・最後の行為の集約と、それに頼る条件・効果

**何を**: ステージ 3 で後回しにした `ScenarioProgress`・`WorldFlags`・`LatestActions` と `SpotSearchProgress` の見つけた記録を作り、旗・出来事・最後の行為を見る条件と、旗を立て下ろしする効果を足した (#1978)。新しい集約は `game_world/domain/world_records/` に置く。文書から決まらなかったことは、ユーザーと次のように決めた。

| 型・振る舞い | 決めたこと |
|---|---|
| 共通の前提が段階の許可を尋ねる形 | `WorldStage` と `WorldStageReading` に `declaration_in(nouns)` を足し、`NoWorldStages` も `declaration_in` で自分自身を返して `allows` / `allows_interaction` でどの行為も許すと答える。前提は段階の有無を `isinstance` で見分けずに `attempt.is_allowed_in(facts.world_stage().declaration_in(facts.nouns()))` と尋ねる |
| 最後に行った行為の鍵 | `ActionAttempt.done_as()` を足す。組み込みの行為は `{kind}`、作者の操作は `{kind, interaction_id}`。`LatestActions.note` は鍵ごとに、行った人と `Anyone` の両方へ時刻を記録する。行為の型を外から見分けずに作者の操作の ID を知るため |
| once でない出来事の `may_fire` | 同じ tick にすでに起きていたら偽 |
| 一度も見ていない反応の `reaction_changed` | 偽。最初に見た真偽は記録するだけで変わり目にしない。最初から閉じている扉の「閉じたら知らせる」反応が tick 0 に知らせないため |
| 一度も起きていない出来事の `TicksSinceHappeningAtLeast` | 偽 |
| `TicksSinceLastActionAtLeast` の起点 | 最後に行った tick と `since` の基準の遅いほう。`SinceStart` は `WorldTick(0)`、`SinceWorldStageEntered` は今の段階に入った tick。段階の無い世界で後者は `NotDeclaredInThisWorldException` |
| 断られた試み | `note_failed_attempt` はイベントを出すだけで `last_done_at` を変えない |
| 二人で合わせる操作の帳簿 | この Issue では作らない。使うユースケースの Issue で `JointActionProgress` と一緒に作る |

**実装で決めたこと**:

- 立っている旗を立てる、同じ人がもう一度見つける、`ONCE_IN_WORLD` の物を別の人が見つける、は断らずイベントも出さない (world_state.md の「状態が変わらない操作」)。別の場所の見つかる物を `mark_found` するとドメイン例外
- `LatestActions.note` は、同じ tick に同じ行為を記録し直しても `PersonActedEvent` を出す。記録の値が変わらなくても、行為が行われたという事実は起きているため
- 誰にとって見つかったかは `Finding.is_found_by` が決める。`SpotSearchProgress` は見つけた人を記録するだけ
- 旗の初めの値は `FlagDeclaration.initially_raised` を問い合わせのときに読み、`WorldFlags` は立て下ろしした旗だけを持つ
- `FlagIsRaised` と `FlagsRaisedAtLeast` は、見ている旗を `requirements().waits_for_flags` に入れる
- まだ起きていない・まだ行っていないことを表す `NeverFired` / `NeverDone` は、`WorldTick` と同じ名前のメソッド (`has_passed`、`later_of`) で答え、条件は型を見分けない
- `ScenarioProgress` は帳簿でイベントを出さないので `AggregateRoot` を継承しない
- `test_world_aggregates_emit_events.py` は、引数の注釈を評価すると `TYPE_CHECKING` の下の型で `NameError` になるため、戻り値の注釈だけを見る形にした。状態を変えずにイベントだけを出す操作 (`LatestActions.note_failed_attempt`) は `_EVENT_ONLY_OPERATIONS` に挙げ、状態が変わらないことを別に確かめる
