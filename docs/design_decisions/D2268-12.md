## D2268-12. 【この世界の決まり】と、行動しながらの一言の説明を古い run に合わせる

**何を**: 古い run の system にあった【この世界の決まり】と、`say_inline` の説明・上限・伏せる言葉を再現する (#2268 の 5 本目のうち、判断の要らない分)。

| | 新しい世界 | 古い run との違いと理由 |
|---|---|---|
| 【この世界の決まり】の置き場所 | 世界の案内 (`Orientation`) の 2 つ目の説明。【世界の前提】のすぐあと | 同じ並び |
| (a) ラベルの行 | 古い run の文のまま | 同じ |
| (b) 操作の選び方の行 | 「- 行動は条件を満たさないと拒否されることがある。操作は【現在選べる対象引数】に並んだものの中から選ぶこと。いまできない操作は、【現在選べる対象引数】の「いまできない:」に理由とともに出る。」 | 違う。古い run の「各オブジェクトに表示された操作の中から選ぶこと」は、新しい世界ではオブジェクトの行に操作を出さないので事実と合わない。操作の並ぶ【現在選べる対象引数】を指す文にした (ユーザーが決めた)。3 文目は、いまできない操作を【現在選べる対象引数】にまとめる決定 (D2268-14) に合わせた |
| (c) `say_inline` の書き方の行 | 古い run の文のまま。どの世界でも出す | 古い run は `say_inline` を持つツールがあるときだけ出した。新しい世界は「待つ」(`wait`) が毎ターン必ず候補に出て `say_inline` を持つので、いつも条件を満たす |
| (d) 勝利条件の行 | 古い run の、勝敗のある世界の文のまま | 古い run は、勝敗の無い世界 (`has_goal=False`) では「この世界に固定された勝敗や達成すべき最終目的はない。…」という中立の文に切り替えていた。新しい世界は、シナリオの人の宣言で目的 (`objective`) を必ず書かせ、入るときに必ず渡すので、勝敗の無い世界をまだ作れない。勝敗の無い世界を作れるようにするときに、この行の切り替えも足す |
| `say_inline` の説明 | 「この行動をしながら発する一言 (任意、200 字以内)。書き方は【この世界の決まり】。」 | 同じ |
| `say_inline` の上限 | ツールの引数の定義に 200 字 (`maxLength`) を書く。世界は長さで断らない | 同じ |
| `say_inline` を【直近の出来事】で伏せる言葉 | 「発言」 | 同じ (古い run の `_FREE_TEXT_ARGUMENT_PLACEHOLDERS`)。話す中身 (`content`) の「本文」は Being の既定のままで同じ |
| 締めの文 | 試験の遊び (`MineVillageSession`) の既定を「利用可能なツールから、次に取るべき 1 つの行動だけを選んでください。」にした | 同じ文。新しい世界の遊びの進行は本番の run にまだ配線されておらず、締めは進行を組む側が渡す。本番に配線するときに置き場所を決める |

- 決まりの行は `ja_default.yaml` の `briefing_headings.rules` / `rule_lines` に置いた。1 行に収まらない行や空の一覧は、読み込みで断る
- `say_inline` の説明は「書き方は【この世界の決まり】」と見出しの名前を書いている。見出しは `ja_default.yaml` で変えられるので、変えるときは説明も合わせる
- 伏せる言葉と上限は、組み込みの引数の宣言 (`OfferedValue`) に置いた。`say_inline` と `content` は組み込みの引数で、シナリオに書く場所が無いため

**関連**: Issue #2268、#2271、D2268-5。
