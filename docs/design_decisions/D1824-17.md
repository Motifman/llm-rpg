## D1824-17. 短期記憶のターンの終わりは、起きた事実をドメインイベントとしてためる

**何を**: 短期記憶の集約 (`ShortTermMemory`) を、CLAUDE.md の「コマンド・ユースケース・ドメインイベント・ハンドラ」に合わせて作り直す。決まり (範囲の大きさ、待つ長さ、上限で外すこと。design_decisions D1824-11) は変えない。

| 操作 | すること | ためるイベント |
|---|---|---|
| `end_turn(turn)`: 範囲が `RECENT_TURNS` (20) に届き、いきさつを待っていない | 古い `FOLD_TURNS` (10) ターン分のいきさつを待ち始める (`AwaitedBackstory`)。出来事は外さない | `ShortTermMemoryRangeFilledEvent` (まとめる範囲の出来事と、今のいきさつ) |
| `end_turn(turn)`: 待ち始めてから `BACKSTORY_OVERDUE_TURNS` (10) 経っても届かない | 待ち始めたターンを今のターンに進める。範囲は変えない | `ShortTermMemoryBackstoryOverdueEvent` (同じ範囲の出来事と、今のいきさつ) |
| `end_turn(turn)`: 範囲が `FORCED_FOLD_TURNS` (40) に届いた | いきさつを待たずに古い 10 ターン分を外す | `ShortTermMemoryOldestTurnsDroppedEvent` (外した出来事) |
| `add_backstory`: 今のいきさつより後の範囲まで | いきさつを入れ、まとめた範囲までの出来事を外す。待っていた範囲まで届いたら待つのをやめる | `ShortTermMemoryBackstoryAddedEvent` (入れたいきさつと、外した出来事。上限で先に外していれば空) |
| `add_backstory`: 今のいきさつと同じか前の範囲まで | 入れずに断る | 無し。ドメイン例外 `ShortTermMemoryStaleBackstoryException` を投げる |

- 待っているいきさつ `AwaitedBackstory(until_turn, since_turn)` の `since_turn` は、今の待ちを始めたターン (範囲が埋まったとき、または遅れを知らせたとき)。遅れを知らせるたびに今のターンに進める
  - `end_turn` を呼ばないターンがあっても、次に呼んだときに遅れを知らせる
  - 10 ターンなら、範囲が埋まって上限 (40) に届くまでに知らせは 1 回なので、「待ち始めたターン」という意味のずれも小さい
- snapshot の短期記憶の欄は、`request` (`until_turn`、`requested_turn`) から `awaited_backstory` (`until_turn`、`since_turn`) に変えた
  - 保存するときは新しい名前だけを書く
  - `awaited_backstory` が無く `request` がある payload は、`request` を読む (`requested_turn` を `since_turn` にする)
  - 本番の snapshot の `request` には null しか入っていない (誰も `fold` を呼んでいなかった)
- 範囲が埋まったときと遅れたときのイベントは、どちらも、いきさつの材料 (まとめる範囲の出来事と、今のいきさつ) を持つ
  - 共通の欄は、外に出さない基底クラス (`_RangeToSummarize`) にまとめた
  - ハンドラは 2 つのイベントの型それぞれに登録する
- 今のいきさつを書く処理 (`BeingBackstoryWriting`) と、trace に残す処理 (`ShortTermMemoryEventTraces`) は、新しいイベントに最小限だけ合わせた。続く PR で、ハンドラ (`WriteBackstoryHandler`、trace に残すハンドラ) に置き換える (design_decisions D1824-18)
  - 古い範囲のいきさつは、`apply` の中で短期記憶が断り、非同期の配送が `application_failed` として `async_event_delivery_failed` に残す。反映の失敗でターンは止まらない (design_decisions D1824-15)
  - 断ったときの trace `being_backstory_discarded` は、もう出ない
  - 断ったことと、書けなかった失敗は、どちらも `async_event_delivery_failed` に残る。見分けるのは例外の型 (`error_type` が `ShortTermMemoryStaleBackstoryException` なら断った)。断るのは、遅れて届いた 1 つ目と書き直した 2 つ目がそろったときの、決めたとおりの振る舞い
- 外した出来事 (`dropped`) は、材料の出来事と同じく `recent()` と同じ順にする

**なぜ**:

- ドメインイベントの名前は、頼みごと (「いきさつを頼んだ」「頼み直した」) ではなく、集約の中で起きた事実にする (CLAUDE.md)。頼みごとはコマンドになる
- 古い範囲のいきさつを例外で断るのは、断ることがユースケースの失敗だから。CLAUDE.md の「コマンドを断るときは、集約がドメイン例外を投げる。そのときドメインイベントは出さない」のとおり
- 「出来事を外した」を 2 つのイベントに分けたのは、上限に届いて外したときと、いきさつが入って外したときで起きたことが違うから
- 遅れを知らせるまでの長さは 10 のまま。#1824 の設計のコメントに一度「3 ターン」と書いたのは誤りで、3 にすると上限までにいきさつを書き直す LLM の呼び出しが最大 6 回になる (費用の変更になる)

**まだしないこと**: `end_turn` はまだ誰も呼ばない。run の振る舞いは変わらない。ターンを進める処理から呼ぶ (`EndBeingTurn`) のは、続く PR で決める。

**関連**: Issue #1824、design_decisions D1824-9、D1824-11、D1824-12、D1824-15、D1837。
