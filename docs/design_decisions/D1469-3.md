## D1469-3. シナリオのプレイヤーに一人称の欄を足し、Being の人柄に入れる

**何を**:

- シナリオの `players[]` に `first_person` (任意) を足した。空でない文字列で書き、前後の空白は落とす。空白だけや文字列でない値は、読み込みで止める
- 起動時に Being を用意するとき、`Persona.first_person` に入れる。書いていなければ `None` のままで、仮の一人称は入れない
- `mine_village_v1` の 4 人に一人称を書いた

| プレイヤー | 一人称 | 根拠 |
|---|---|---|
| ハル | 私 | 調査隊の隊長で「慎重で、確かめてから動く」、話し方は「落ち着いた常体」。見た目は「年かさの人」で、性別は書かれていない。性別を決めずに済み、落ち着いた年長者に合う「私」にした |
| ミオ | 私 | 若い隊員で、話し方は「気さくな常体」。見た目は「若い人」で、性別は書かれていない。「僕」「あたし」は性別を決めてしまうので、「私」にした |
| ゲン | 俺 | 「初老の男」の元鉱夫で、「口数は少ない」、話し方は「ぶっきらぼうな常体」。常体でぶっきらぼうな男の話し方に合う「俺」にした。「わし」は年寄りらしさを強く出しすぎるので選ばなかった |
| サヨ | 私 | ゲンの娘の「若い娘」で、話し方は「はきはきした敬体」。敬体に合う「私」にした |

**なぜ**: 一人称が決まっていないと、いきさつとエピソードの書き手は本文の一人称を毎回選び直す。run `mine_v1_011_switched` では、エピソードの本文の一人称が「俺」と「私」で揺れていた。書き手は、一人称が決まっていれば名前の次の行で伝える (design_decisions D1469-2)。

**欄の名前**: `persona_prompt` の分割とキーの改名 (#1339 / #1548) は、ここではしない。一人称は人柄の 1 項目で、`Persona.first_person` と同じ名前にした。人柄を構造のある形に分けるときは、この欄もその形に移す。

**まだしないこと**:

- 行動を決める LLM のプロンプトには、一人称を足していない。人格の文 (`persona_prompt`) にも一人称は書かれていないので、話すときの一人称はまだ LLM が選ぶ。人格の文を `Persona` から作るとき (#1339 / #1548) に入れる
  - `persona_prompt` を書かないプレイヤーの行動用の人格の文は、固定で「一人称: 私」を出す (`world_llm_prompt.py` の `_fallback_persona_block` と、`first_person` の無いキャラクター)。そのシナリオに `first_person` を書くと、書き手と行動を決める LLM で一人称が食い違う。`mine_village_v1` は全員が `persona_prompt` を持つので当たらない
- ほかのシナリオには一人称を書いていない

**関連**: Issue #1469、design_decisions D1469-1、D1469-2。
