## D2268-10. 身体の状態に、前に渡した場面からの増減を「、前回 ±N」で添える

**何を**: 古い run の「身体の状態:」の HP・空腹・疲労の行にあった「、前回 +N」を再現する (#2268 の 4 本目の 3 本目、D2268-9 の続き)。

古い run (`764beb875` の `agent_need.py:112` の `AgentNeed.describe` と、`hp.py` の `Hp.describe`。どちらも `f"{base}、前回 {sign}{delta}"` で、値のかっこの外に添える。mine_v1_002 の 36 件もすべてこの形):
```
  HP: 消耗（48/100）、前回 -12
  空腹: 危険（68/100）、前回 +3
```

| | 決まり | 古い run との違いと理由 |
|---|---|---|
| 添える行 | HP・空腹・疲労の 3 つ | 同じ |
| 書き方 | 値のかっこの外に `、前回 +N` / `、前回 -N` を添える。増減が 0 のときは何も添えない | 同じ。初めはかっこの中に添えていた。古い run のコードの docstring の例 (`player_status_aggregate.py` の「疲労: 高い（68/100、前回 -2）」) を写したためで、実際に出していた形 (上のコード) に直した |
| 何からの増減か | その人に前に渡した場面の値から | 下の「覚えるとき」の違いのぶんだけ違う |
| 覚えるとき | 場面を作って Being に渡す直前 (`BeingsTakingTurnsOneByOne`)。LLM の呼び出しが落ちても、場面は渡したので覚え直す | 違う。古い run は行動を終えたあとに覚えていたので、自分の行動で変わった分 (食べて空腹が減った、など) は次の増減に入らなかった。新しい世界は前に見せた場面の値を覚えるので、「前回」が指すのは、エージェントが前に読んだ値そのものになる。例: 場面で空腹 40 を見て、食べて 10 になり、次の場面で 12 なら、古い run は「前回 +2」、新しい世界は「前回 -28」 (ユーザーが決めた) |
| 初めての場面 | 何も添えない | 同じ |
| 覚える場所 | 世界の身体の状態 (`PersonVitals`) に、最後に見せた HP・空腹・疲労 (`ShownBody`) を持つ。まだ見せていない人は `NothingShownYet` | 同じ (古い run も身体の状態の集約に持っていた)。ユーザーが決めた |

- 見せた値を覚えるのは状態の変化なので、世界の集約の決まり (#2008、状態を変えたら必ずイベントを出す) に従い、`PersonBodyShownEvent` を出す。誰にも知覚させないので、知覚に出さない一覧 (`NOT_PERCEIVED_EVENT_KINDS`) に入れた
- 外から呼ぶユースケースは `MarkBodyAsShown`。遊びの進行が世界に入る口の一覧 (`test_play_session_package_import_boundary.py`) に足した
- 身体の状態の保存の形の版を 2 に上げた (`PersonVitalsCodec`、`last_shown` の欄)。版 1 の行は読み込みで断り、変換は作らない。保存の形の版を上げた #2181 と同じ扱いで、調整役と決めた
- 新しい世界の状態は SQLite の世界の保存先だけに残り、別の snapshot ファイルは無い。保存の形に入れれば、止めて再開しても「前回」は途切れない

**関連**: Issue #2268、#2271、D2268-9。
