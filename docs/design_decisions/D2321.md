## D2321. 新しい世界の LLM の入出力を、呼び出しごとに prompt_dataset に全文で残す

**何を**: 新しい世界 (`game_world`) の run で、LLM の呼び出し 1 回ごとに、送ったメッセージ・ツールの定義・返事・費用と時間を、古い世界と同じ `OUT/prompt_dataset/` (`PromptDatasetCaptureSink`) に残す (#2321、親 #2212)。分析は、この入出力と run の終わりの状態 (#2322) を元にコーディングエージェントが行う。分析用の trace (#2233) は、不便が分かってから決め直す。調整役とユーザーが決めた。

| | 決まり |
|---|---|
| 残す呼び出し | 行動を選ぶ呼び出し (`choose_action`)、エピソードの書き起こし (`episode_writing`)、いきさつの書き起こし (`backstory_writing`)。行の `phase` に書く |
| 1 行に持つもの | 誰の呼び出しか (`being_id`、`character_name`、`provenance.person_id`)、tick (`world_tick`)、人と呼び出しの種類ごとの通し番号 (`turn_index`)、`llm_call_id`、送ったメッセージとツール (古い世界と同じく system prompt とツールは別ファイルに分け、`reconstruct_request` で戻せる)、返事、エラー |
| LiteLLM のとき | `LiteLLMClient` の 3 つの呼び出し (`choose_action`、`complete_episode_writing_json`、`complete_short_term_summary_json`) に、省略できる `prompt_capture_context` を足した。渡されたときだけ、呼び出しのあとに生の返事 (本文・ツール呼び出し・usage・finish_reason) ごと書く。古い世界は渡さないので、振る舞いは変わらない |
| スタブのとき | 送ったメッセージ・ツールと、スタブの返事 (ツールの名前と引数) を書く。生の返事は無い |
| 落ちた呼び出し | エラーを書く。行は呼んだその場で書くので、世界が終わって捨てた選択も返事まで残る。呼ぶ前に取り消した選択は LLM を呼んでいないので行が無い |
| 書けなかったとき | run を止めず、書けなかった数を `run_end` の `llm_calls_not_recorded` と report.md に出す。書けた数は `llm_calls_recorded` |

### 誰の呼び出しかの渡し方

Being の公開入口 (`ActionChoosingCompletion` など) に記録の都合を入れないため、experiment が呼び出しの直前に名札 (`LlmCallLabel`: 人・名前・tick・呼び出しの種類) を contextvars に置き、LLM を呼ぶ側 (`CapturedActionChoosing`、`CapturedEpisodeWriting`) がそれを読んで文脈を作る。

| 呼び出し | 名札を付ける所 | 名札を読むスレッド |
|---|---|---|
| 行動を選ぶ | 場面を組む本線 (`LabeledChooseAction.prompt`) で人と tick を覚え、考える段 (`think`、worker) で LLM を呼ぶあいだだけ付ける | 考える段の worker。`LiteLLMClient` の使い捨てのスレッドは HTTP の呼び出しだけを動かし、行は `invoke` を呼んだ worker が書く |
| 書き起こし | 書き起こしの部品 (`LabeledEpisodeWriter`、`LabeledBackstoryWriter`) が `write` のあいだだけ付ける。人は人柄の名前から引く | 裏の書き起こしのスレッド。tick は裏のスレッドから世界の保存先に触れないので、本線で最後に開いた巡りの tick を使う |

- contextvars はスレッドに引き継がれないが、名札を付けるのも読むのも同じスレッドなので、`copy_context` は要らない
- 2 人が同時に名札を付けてから呼んでも取り違えないことを、考える段と書き起こしの両方でテストする (`TestLabelsOfThinkingOnThreads`、`TestLabelsOfWritingOnThreads`)。名札を全体で 1 つの置き場に置く変異で落ちる
- スタブの経路では、文脈を返事が返ったあとに作る。行を書くのも返ったあとで、返事の順を入れ替えたときの取り違えをテストで見られる

### そのほか

- fuzz の行動の記録の人は、考える段の名札から取る。前は全員が「P0」と出ていた
- trace.jsonl には何も足さない (#2233 は止めている)
