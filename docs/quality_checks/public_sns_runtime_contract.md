# 公開SNSを世界の一手として使う

> 2026-10-31 から、公開 SNS を有効にしたシナリオは起動時に止めている (#1920)。下の通知を【直近の出来事】に収める処理は、今の短期記憶の出来事の上で動くもので、Being の短期記憶から作る【直近の出来事】には当てられない (design_decisions D1824-22)。コードは残してあり、収め直したら戻す。

## 選べる行動と時間

シナリオが `public_sns_enabled: true` を宣言した世界だけに、`sns_read` と
`sns_publish` を出す。読む入口は `inbox`、`posts`、`thread`、`close`、発信する
入口は `new`、`reply` である。旧SNSアプリの入退室・仮想ページ操作は混ぜない。
`disabled_tools` による個別無効化は定義と実行の両方で守る。

一度の起動に一つの道具を使う既存の流れに従う。読んだ直後だけ次の手番を作る
仕組みはない。移動中に成功した読み取り・発信は、他の通常行動と同じく移動を
中断する。通知は `schedules_turn=False`、`breaks_movement=False` で通常の
観測へ入る。未読のある人物を検討する既存の起動判定は変更しない。

## 本文の置き場所

返信・メンションは人物名、不変の人物識別子、不変の返信先、本文を通知する。
この通知だけから返信でき、事前の読み取りを要求しない。いいね・フォローは短い
通知である。投稿成功や読み取り成功の行動結果は短い受領結果にして、本文を
重ねて保存しない。

通知の本文は通常観測に保持するが、描画時には一つの総予算へ収める。
`public_sns_push_budget_chars` はUnicode文字数で既定6000、許容範囲512〜24000。
共通見出し、人物・対象識別子、本文、箇条書きと時刻、未表示件数をこの予算に
含める。返信・メンションを先に、同じ優先度では新しいものを先に選ぶ。
識別子は切り詰めず、残量が足りないときは本文だけを部分表示して省略を示す。
部分表示は表示完了にしない。溢れた本文は永続受信箱から読み直せる。

同じ通知の本文を最初に完全表示した後は、直近履歴では短い通知事実にする。
取得画面にある対象の本文も通知欄に重ねない。予測確認などの補助欄には通知事実
だけを置く。保存した観測・構造化情報を削除する処理ではない。

描画の試作やLLM呼出しの失敗では、未表示状態を消費しない。実際に提示した画面
の世代と通知識別子を、モデルの行動応答を受け取った境界で確定する。通知を
表示したことと、サービス上の既読は別である。自動既読・自動削除は行わない。

## 取得済み画面と失敗

一人に一画面だけを最大12000 Unicode文字で保持する。画面名、公開条件、取得位置、
取得時点、表示件数、続きの位置または終端、本文と不変識別子を載せる。これは
取得時点の写しであり、手番が進むだけでは再取得しない。新しい読み取りに成功
した時に置き換え、`close` で消す。失敗した要求は取得済み画面を消さない。

画面の取得元と最後の閲覧要求は、別の出典として記録する。表示でも「新しく取得」
「以前の内容を保持」「失敗したため以前の画面を保持」を区別する。返信の文脈は
近い祖先3件までと省略件数を表示し、選択本文と返信元の不変IDを残す。
深い祖先の全文が画面予算を塞ぎ、選択対象を永久に読めなくなる形は避ける。

閉じていても、自分のアカウント名と不変ID、未表示件数は共通見出しに残る。
古い通知が直近履歴から抜けても、永続受信箱に残った未表示を見失わない。

## 出典と保存・再開

`ExecutionProvenance` は実行開始時に一度発行する要求識別子、当人の手番、実際に
受け取ったproviderの道具呼出し識別子を持つ。provider識別子が無いスタブでは
空のままにする。`llm_call_id` は既存のdataset記録が発行したものだけを使い、
存在しないdataset行に見える値は作らない。通知の出典は発生時に固定し、再配送時
の別の手番を借りない。行動記録・trace・取得画面・通知を同じ出典で辿れる。

世界のsnapshotにはSNSの内容、人物と関係、不変識別子の名前空間、採番位置、通知、
取得画面、最後の要求、表示状態、実行手番を一緒に保存する。表示状態の形式検査を
先に済ませ、壊れた画面のためにSNS内容だけを半端に復元しない。SNS有効の再開で
SNS subsystemや`world.json`そのものが無ければ止める。SNSを宣言しない旧世界の
保存形式との互換は保つ。

投稿は確定したが通知配送が失敗した場合、投稿成功と配送未完了を区別する。
未配信通知は次の世界更新の終端と最初のprompt構築前に最大100件ずつ再送する。
配送済み通知IDの台帳は世界snapshotにも保存し、観測追加直後に停止しても
再送で同じ観測を増やさない。この台帳と未表示IDは通知件数に比例して増える。
画面・描画予算とは別の保存上の費用であり、通知の保存期間を短くする機構は
今回追加していない。

## 質感の点検

実モデルを呼ばず、通知を見てその対象へ直接返信する、読み取り失敗後も前の本文を
見て判断する、読み直さず別の行動を選ぶ、閉じる、再開後も同じ相手・同じ投稿へ
戻る、という流れを実WorldRuntimeで確認した。512文字の小さな通知予算でも、
人物と返信先と本文の一部が最終promptに残る。これはエージェントが実際にSNSへ
注意を向ける頻度の測定ではなく、読める情報と行動の導線の確認である。
