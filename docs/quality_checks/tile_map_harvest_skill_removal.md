# タイル用の採取・スキル実行削除の確認

Issue #1862 の変更範囲8の採取・スキルと、範囲6の専用モンスター処理を対象とする。

## 前後で守る振る舞い

| 場面 | 変更前 | 変更後 |
| --- | --- | --- |
| スポットで採取の作用を使う | シナリオの作用が品や観測を生成する | 変更なし |
| モンスターが初期配置・条件付き出現する | スポット側が装備と実体を作り保存する | 変更なし |
| 装備の値を作成・保存・復元する | スキルの仕様・命中の形・速度・効果を保持する | 変更なし |
| 旧タイル用の採取・スキル実行を使う | 未接続の実装と専用契約が残る | 実装と専用契約が存在しない |
| タイルの採取状態や観測を扱う残存処理 | 物理マップ側に残る | 今回は変更なし |

## 参照の確認

削除前に `src` / `tests` / `scripts` のASTでimportを調べ、文字列検索で契約・例外・再公開も確認した。採取アプリケーション、プレイヤー用の2サービス、スキルの3ドメインサービス、モンスター用の出現・スキルサービスと専用ドメインサービスは、本番からの構築・呼び出しが無かった。残る参照は削除対象同士、対応する試験、構造検査の一覧だけだった。相対importの `application/skill/services/__init__.py` の再公開も外した。

本番で残す依存は次のとおり。

- `world_runtime` / `spot_graph_monster_spawn_stage_service` → `SkillLoadoutAggregate` → `SkillDeck` → `SkillSpec` → `SkillHitPattern` → `hit_box_shape` / `hit_box_velocity`。`SkillSpec` → `hit_effect`。
- 装備と仕様の保存先、`sqlite_skill_state_codec`、`skill_sqlite_wiring` は維持する。
- 旧現在状態の `player_supplemental_context_builder` → `awakened_mode_defaults` を維持する。現行ソースに `SkillQueryService` という型は無く、スキル問い合わせは現在状態の構築処理に残る。
- `domain/world` の採取セッション・物理マップの採取状態とイベント、採取観測の変換は維持する。

削除した試験は、削除したサービスを構築して呼ぶものだけ。独立レビューで、採取試験の末尾に混在した `SpotId.create` の不正形式検査を見つけ、`tests/domain/world/value_object/test_spot_id.py` へ移した。装備・進化提案・保存復元・モンスター集約・スポットの採取作用・観測の試験は残す。既存の構造検査は削除した4経路と採取契約の読み込み件数だけを外し、他担当の対象は変更しない。

## 質感への所見と限界

今回の削除は未接続のタイル経路だけで、観測の発火・配信・表示や手番の起き方を変えない。残す採取作用やモンスターの動きが記録を出す条件で比較し、2tickの短い実験だけでは同等性を判断しない。実LLMでの発言や選択の質感は未確認。新しい実験機能や観測を加える変更ではないため、観測点の追加は行わない。
