## D2268-15. 通路を通って着いた人を、通ってきた通路の名前つきで知らせる

**何を**: 古い run の、通路を通って着いた人の目撃の文を再現する (#2268 の 4)。着いたことのイベント (`OccupantEnteredSpotEvent`) に、通ってきた通路を持たせる (D2268 の予定どおり)。

古い run (`764beb875` の `_spot_graph_movement_handler.py:146-150`):
```
サヨが「南の横坑口」から〈横坑〉を通って南の横坑の奥にやってきた。
```

| | 新しい世界 | 古い run との違いと理由 |
|---|---|---|
| 見えた人への文 | `{actor}が「{origin}」から〈{passage}〉を通って{destination}にやってきた。` | 同じ |
| 暗くて見分けられないとき | `{actor}がどこからかやって来た。` のまま | 古い run に暗がりの見え方は無い (D2268-6 のまま) |
| 引き返したとき・やめたとき | 歩いていた通路の向こうの端から、その通路を通って来たように見える | 同じ考え方。来た場所だけを持っていたとき (D2268-6) と同じく、通路も歩いていたものにする |
| 次の通路が閉じていて止まったとき | 歩き切った通路から来たように見える (閉じていた通路ではない) | 閉じていて通らなかった通路の名前を書かないため |
| teleport | 目撃の文を作らない | 同じ (D2268-6 のまま) |
| 去っていく人の文 | D2268-16 で合わせた | |

- 着いたことのイベントの来た場所 (`origin`) を、来た場所と通ってきた通路の組 (`CameThrough`) にした。場所と通路を別々の欄に持つと、teleport なのに通路がある、のような組み合わせが作れてしまうため
- 到着の文で書ける名前に、通路 (`passage`) と着いた場所 (`destination`) を足した。言い回しは `ja_default.yaml` の `built_in_action_perceptions.arrival`

**関連**: Issue #2268、#2271、D2268、D2268-6。
