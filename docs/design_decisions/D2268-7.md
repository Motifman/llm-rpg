## D2268-7. 持ち物の出入りを、本人にだけ品物の名前つきで知らせる

**何を**: 古い run の【直近の出来事】にあった、持ち物の出入りの行を再現する (#2268 の 4 本目の続き)。古い run は品物の名前を引けずに「何かのアイテム」と書いていたので、名前つきにする (ユーザーが決めた)。

古い run (mine_v1_002、4 人とも、カンテラを灯したとき):
```
- [Day 1 深夜 0:30] 何かのアイテムを入手しました。
- [Day 1 深夜 0:30] 何かのアイテムを捨てました。
- [Day 1 深夜 0:30] [行動] 「カンテラ」で油を足して灯す → [結果] カンテラに油を足して火を入れた。…
```

| | 決まり | 古い run との違いと理由 |
|---|---|---|
| 出す場面 | 持ち物が増えたとき (`ItemReceivedEvent`) と減ったとき (`ItemGivenUpEvent`) のすべて。拾う・渡される・効果で得るは増える、置く・渡す・効果で使う・取られるは減る | 同じ。古い run も持ち物の集約の `acquire_item` と `drop_item` の全部で出していた (`764beb875` の `player_formatter.py:572-610`) |
| 文 | `{品物}を入手しました。` / `{品物}を捨てました。`。減るときは理由を問わず「捨てました」(ユーザーが決めた案 1) | 名前つきにした。古い run は名前を引けず「何かのアイテム」だった |
| 届く人 | 本人だけ。世界からの知らせ (`AnnouncementStimulus`) で、見聞きした知らせを押しのけない | 同じ (古い run は `self_only`) |
| 数 | 品物は 1 つずつ別の個体なので、1 つにつき 1 行。「{数}個入手しました」にまとめない | 古い run は積み重なる品物だけ数を持っていた。新しい世界の品物は積み重ならないので、まとめる数が無い |
| 並び | 同じときの出入りは、効果の書かれた順 (カンテラを灯すと、油を捨てたが先、灯を入手したが後) | 古い run は入手が先だった。起きた事実を効果の順に並べるので合わせない |
| 使い切って消えたとき | 燃え尽きた灯のように使い切って消えた品物は「捨てました」を出さず、品物の知らせ (「カンテラの灯が燃え尽きた。」) だけにする。持ち物のイベント (`ItemGivenUpEvent.ran_out`) が使い切りの印を持ち、持ち物の集約の `run_out` で立てる | 古い run の v1 の灯には寿命が無く、手本の無い場面。捨てていないのに「捨てました」と読めるのを避ける (ユーザーが決めた案 A) |
| 世界を開いたとき | 最初の持ち物は知らせない。世界を開く処理は観測の配り手を通らないため | 同じ (古い run にも始まりの行は無い) |

- 持ち物のイベントに、起きた時刻 (`at`) と品物の種類 (`spec`) を持たせた。知覚にするほかのイベントと同じく時刻が要り、使い切った品物はあとで種類を引けないため。受け取り・手放しの操作 (`receive` / `give_up` / `give_up_held` / `give_up_packed`) は時刻を受け取る
- 言い回しは `ja_default.yaml` の `belongings_texts` に置き、品物の名前をちょうど書いているかを読み込みで確かめる
- 行動の結果の行と、持ち物の出入りの行の並び (古い run は出入りが先、新しい世界は行動の行が先) は、Being と遊びの進行の受け持ち
