## D1630-6. 作法を、環境が出している Being の道具の一覧から Being が作る

**何を**: #1630 の 4 本目の後半。作法 (【渡される文面の読み方】【行動のしかた】【心がけ】【メモの書き方】) の文を、ゲームの側 (`world_conduct_text`) から Being の側 (`being/application/conduct_text.py`) に移した。今のシナリオでは、システムプロンプトとユーザー文は一字一句変わらない。前は独白とメモの文を無条件に出していたので、独白の引数を持たない世界では【行動のしかた】が tool call の 1 行だけになり、メモの引数を持たない世界では【メモの書き方】の節が無くなる。

- 環境は、Being 自身のための道具の一覧 (`being/contract` の `OfferedBeingTools`) を渡す。独白の引数、メモの引数、エピソードを思い出す tool、目次を出すか、の 4 つ。名前は環境の引数や tool の名前で、出していない道具は None
- ゲームの側 (`WorldRuntime._being_tools_offered_now`) は、実際に出すツールの一覧から道具を拾う。#1616 と #1940 と同じく、出していないものを作法が指さないため
- `CurrentWorkingMemory.of` は、作法の文ではなく道具の一覧を受け取り、作法の文を作る
- reason_first のための作法の文 (`tool_schema_mode="reason_first"`) は消した。runtime はこの文を使っていなかった。reason_first のターンも、システムプロンプトは通常の作法のまま
- reason_first の `assess_situation` の `inner_thought` の説明の「システムメッセージ冒頭の【ペルソナ】」を「システムメッセージの【ペルソナ】」にした。D1630-4 で作法が冒頭に入ってから、位置がずれていた (D1630-5)。この説明は reason_first のターンで実際に出すので、消さずに直した

**決めたこと**:

- 道具の名前を環境から受け取る。Being が `inner_thought` などの名前を自分で持つと、ゲームの側で名前を変えたときに作法だけが古い名前を指す
- 目次を出すかは、道具の一覧に入れた。目次は Being の区画だが、出すかどうかは今は run の設定で決まり、環境が渡している
- 作法は、まだ見出しの無い 1 つの区画として作業記憶に入れる。節ごとの区画に分けても文は変わらず、分ける理由が今は無い
