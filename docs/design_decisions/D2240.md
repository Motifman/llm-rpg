## D2240. Being が行動と一緒にメモを書き、思い出すツールで 1 手を使う

**何を**: Being が LLM で行動を選ぶとき (#2240)、古い run の Being の道具のうち、メモ帳への書き込みとエピソードを思い出すツールを付けた。どちらも世界の行為ではないので、Being の中で済ませる。調整役と決めた。

- メモの引数 `memo` は、環境が `OfferedBeingTools.memo` を出しているとき、どの行動のツールにも付ける。必須にはしない。毎回書かせると、書くことが無いターンにも何かを書かせてしまう
- メモは、`ChooseAction` が行動を選んだその場でメモ帳に書く。行動が世界に断られても、書いたことは本人がしたことなので残す (古い run と同じ)。世界に渡す `AgentMove` からは外す
- メモは試みより先に書く。試みを残してから書けずに止まると、世界に渡らない試みが結果を待ち続ける。書けなかったら何も変えずに例外を上げる。古い run は書き込みの失敗を握りつぶして行動を通していたが、保存の失敗を静かに捨てない
- 出どころに `episode` を選ばせるのは、呼び名の載る【思い出せる出来事】を出しているとき (`episode_index_shown`) だけ。知らない呼び名を書かせて外すだけになるため (D1616)
- 思い出すツールは、環境が `OfferedBeingTools.episode_recall` を出しているとき、行動のツールの後ろに並べる。選ばれたら世界には何も渡さず、思い出した本文を記憶の道具の結果 (`MemoryOperationOutcome`) として試みに結び付け、`TurnSpentRecalling` を返す。古い run と同じく 1 手を使う (D1623-3)
- 遊びの進行 (#2232) は、`TurnSpentRecalling` を「ターンを終えた。世界には行為が無い」として扱う。待つとは別にし、次の巡りではまたターンが回る
- 一度に思い出せる件数は、環境ではなく Being の設定なので、`ChooseAction` が受け取る

**採らなかった案**:

- 思い出したあと同じターンでもう一度 LLM を呼び、行動まで選ばせる: 古い run の 1 手の使い方とずれ、1 ターンの LLM の呼び出しの回数も変わる
- メモの結果を、世界の結果が届く `ReceiveActionResult` まで持ち越す: 世界の結果が来るまで、Being がメモの結果を持っておく状態が要る

**部品の置き場所**: メモの引数のスキーマ (`being/application/memo_argument.py`)、操作の読み取りと理由の文 (`being/application/memo_arguments.py`)、思い出すツールのスキーマと結果の文 (`being/application/episode_recall_tool.py`) を、古い `application/llm` から移した。`ToolDefinitionDto` を組む部品と、trace を書く部品は古い run の側に残し、移した先を使う。メモと思い出すことの trace は、実験 (#2233) で扱う。

### 書けなかったメモの操作は、自分の 1 手の結果の文の末尾に足す

**何を**: 行動と一緒に書こうとして書けなかったメモの操作は、【直近の出来事】の自分の 1 手の行で、世界が返した結果の文の末尾に、理由の段落として足す。古い run に合わせた。古い run も、行動の結果の文の末尾に同じ段落 (`feedback_text`) を足していた。

```
- [1 日目 00:00] カンテラに火を入れた。

[メモ] 次の操作は書けませんでした。
- 2 件目: m_3f2a7b というメモはありません。
  心の声: まず灯りだ
```

- 自分の 1 手の行は、古い run と同じく結果の文だけを出し、「選んだ行動 →」の前置きは付けない
- 文面は古い run と同じ関数 (`rejection_text`・`rejection_lines`・`feedback_text`) で作る
- 古い run では、メモの結果と行動の結果が同じ 1 回のツールの実行の中でそろっていたので、その場で文に足せた。新しい流れでは、メモは行動を選んだときに書き、世界の結果はあとから `ReceiveActionResult` で届く。そのため、書けなかった理由は試み (`Attempt.memo_rejections`) が持ち、結果が届いたら結果の文の後ろに並べる。世界の結果の文 (`Observation` の本文) は書き換えない
- 理由は Being の snapshot で読み書きする。結果のある試みと、結果を待っている 1 手の両方が持つ。足す前に保存した snapshot の試みは、理由無しとして読む。試みの中の欄なので、snapshot のいちばん上のキーの表 (`ADDED_PAYLOAD_KEYS`) には足さない
- 世界の結果が届かないまま次の 1 手を選んだ試みは、結果の分からない試みとして残り、【直近の出来事】に出ない (D1824-22)。そのとき、書けなかった理由も本人には出ない。古い run は結果と同時に文へ足していたので、この場面は無かった

**古い run と違うところ** (どちらもドメインの都合):

- 書き込み自体に失敗したとき、古い run は「メモ帳に書けませんでした。もう一度書いてください。」を足して行動を通していた。新しい流れでは、上で決めたとおり例外を上げて何も変えないので、この文は出ない。保存の失敗を静かに捨てないため
- 試みが持つのは、整形した理由の文 (「2 件目: m_3f2a7b というメモはありません。」) で、理由の種類 (上限・無い呼び名など) の値ではない。理由のコード (`REJECTED_*`) は application の `memo_arguments.py` にあり、ドメインの型に持たせるには、それをドメインに移す必要がある。古い run の文を変えずに出すことだけが目的なので、文で持たせた。理由の種類で何かを判断したくなったら、理由のコードをドメインの型に移す

**採らなかった案**:

- 自分の 1 手を「選んだ行動 → 結果」の 1 行にする: 古い run の形から外れる
- 書けなかった理由を、メモ帳 (`MemoBook`) に持たせて【メモ】の欄に出す: どの 1 手で書いたメモの結果かが離れる
- 理由を `ReceiveActionResult` まで Being の外 (遊びの進行) に持っておいてもらう: Being の記憶の一部を、Being の外が持つことになる
