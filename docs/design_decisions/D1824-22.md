## D1824-22. プロンプトの【直近の出来事】と【ここまでのいきさつ】を、Being の短期記憶から作る

**何を**: 毎ターンのプロンプトの 2 つの見出しを、Being の短期記憶 (`ShortTermMemory`) から作る文に切り替えた。

| 見出し | 本文を作るもの |
|---|---|
| 【直近の出来事】 | `being/application/recent_events_text.py` の `recent_events_text`。影で作っていた文 (design_decisions D1824-10) |
| 【ここまでのいきさつ】 | `being/application/backstory_text.py` の `backstory_text`。Being の短期記憶のいきさつ (流れと気分) を新しい順に 3 世代まで |

プロンプトを組む処理 (`DefaultPromptBuilder`) は、2 つの本文を `PromptBuilderCoreServices` の `recent_events_text_provider` と `backstory_text_provider` から受け取る。どちらも Being の ID を受ける。ゲームの出来事は、これまでどおり写す処理 (`PlayerShortTermMemoryCopy`) が Being の短期記憶に書く。

**決めたこと** (#1824 でユーザーと決めた):

- 結果の分からない試み (結果の来なかった 1 手) は行にしない。切り替える前のプロンプトに無かった行で、切り替えで変わるものを減らすため
- 【ここまでのいきさつ】は、今の短期記憶の要約を出していたころと同じ書き方にする (`[最新] 流れ`、`  気分: 気分`、`[2 世代前] …`)
- 公開 SNS を有効にしたシナリオ (`public_sns_enabled: true`) は、起動時に `PublicSnsNotSupportedError` で止める
  - 通知を【直近の出来事】に収める処理 (`PublicSnsPromptProjection`) は、今の短期記憶の出来事 (`UnifiedRecentEventEntry`) の観測の構造の情報で並べ替え、予算に収め、見せた通知を既読にする
  - Being の短期記憶の出来事は、その情報を持たない
  - `data/` のシナリオに公開 SNS を有効にしたものは無い。公開 SNS は休ませている領域で、将来つなぐので、収める処理のコードは消さずに残した。収め直すのは #1920
- 影 (`RecentEventsShadow`) と、その trace `recent_events_shadow_mismatch` は消した。比べる相手が無くなった

**変わること**:

- 【直近の出来事】に出るターンの数が変わる。今の短期記憶は 20 ターンで古い 10 ターンを畳んでいたので、10〜20 ターン分だった。Being の短期記憶は 20 ターンで範囲が埋まり、いきさつが届いたときに古い 10 ターンを外すので、20〜30 ターン分になる (design_decisions D1824-11)。そのぶんプロンプトが長くなる
- 【ここまでのいきさつ】は、Being のいきさつが届くまで出ない。今の短期記憶の要約は、プロンプトに出ないまま動き続ける。消すのは次の段 (#1824)

**退けた案**:

- 公開 SNS の通知を縮めずに全部出す: 通知の多い世界でプロンプトが際限なく長くなる
- 収める処理を Being の短期記憶の出来事の上で作り直す: この段の範囲が大きくなる。#1920 で行う

**関連**: Issue #1824、#1920、design_decisions D1824-10、D1824-11、D1824-21。

**その後 (design_decisions D1824-24)**: 今の短期記憶とその要約は消した。プロンプトに出ないまま要約を書いていた LLM の呼び出しも無くなった。
