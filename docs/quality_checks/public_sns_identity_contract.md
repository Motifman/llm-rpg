# SNS の参照対象を取り違えないための保存基盤

## 何を保証するか

投稿・返信・利用者は作成時に UUID4 の `identity_token` を持つ。同じ整数 ID、
本文、表示名を使った別の対象には新しい値を割り当て、保存した対象を開き直す
ときは元の値を使う。表示順、いいね、削除はこの値を変えない。

保存領域には別の `sns_public_namespace` を持つ。新規領域には新しい値を
割り当て、SQLite の複製とインメモリ保存領域の復元では既存の値を維持する。
分岐後に採番が重なっても、新規対象の `identity_token` は別になる。

SQLite の旧行は移行時に一度だけ補完し、対象別の一意索引を張る。欠損した
識別子を読み出し時に再発行しない。通常の保存でも別の集約で整数を再利用
したときには、以前の対象の識別子を引き継がせない。

## 振る舞いの質感と範囲

この段階ではツール・観測・表示は変えない。記憶に残した参照が、別ページや
再開後の同じ番号へ静かに化ける問題を防ぐための基盤である。外向けの参照
形式、アクセス権の確認、検索と通知への接続は後続の変更で扱う。

既存の世界全体の JSON 保存には SNS の本文を復元する経路がない。この変更は
その経路を追加しない。対象を復元しない新世界は新しい保存領域として区別し、
既存対象の継続性は SQLite の再接続・複製または保存領域全体の復元で保証する。

## 試験

`test_sns_public_identity.py` と `test_sns_identity_persistence.py` が、作成・復元、
分岐、採番再利用、削除、旧形式の移行、索引検索、欠損時の停止、移行の
巻き戻しを検査する。実 LLM と有料 API は使用しない。
