# 食料経済の緩和: 腐敗の長期化 + 腐敗食の部分回復

## なぜ

v4coop_reasonfirst_001 (200 tick) で全員が餓死系終了した。trace 分析で分かった空腹が
治らない構造:

- 持続可能な食料 (焼き魚 +70) は火が要るが、火は一度も熾されなかった (救助の狼煙と同じ
  単一チョークポイント)。
- 唯一手軽な **貝は 48 tick (= 1 日) で腐る**。序盤に採った貝が中盤には腐り、食べると
  +35 の空腹回復どころか **10 ダメージの毒**になった (t134/t146 リオ「貝を食べてしまった。
  腐っていた——胃の奥が灼ける。（10 ダメージ）」)。
- 腐った貝を新鮮な貝と交換しようと 5 回以上発話したが give_item は 0 回で、交換は実行され
  ず、自分の腐った貝を食べ続けて瀕死→死亡。

火・共有・移動の実行を促す施策 (#794 系, reason-first, 記憶) は認知の質を上げるが、腐敗が
速すぎると「採っても持たない」ので、そもそも食料ループが成立しない。ここでは**経済側を
緩めて、生存の土俵に乗ってから協調・登頂の失敗を観察できる**ようにする。

## 何を変えるか

### 1. 腐敗までの時間を延長 (`data/scenarios/survival_island_v4_coop.json`)

ticks_per_day=48, 生存 horizon=5 日=240 tick, run=200 tick。生の傷みやすい物は 3 日、木の実は
4 日、調理/保存物は horizon 全域とし、**調理 (cook_fish) が「空腹 +70」と「最長の保存性」の
両取り**になる設計にする。

| item | 現行 | 変更後 | 意図 |
|---|---|---|---|
| 貝 shellfish | 48 (1.0d) | **144 (3.0d)** | 餓死の元凶。生の貝でも 3 日持つ |
| 生の魚 raw_fish | 64 (1.3d) | **144 (3.0d)** | 生魚も 3 日 |
| 野いちご wild_berry | 96 (2.0d) | **192 (4.0d)** | 木の実は比較的持つ |
| 食べられるキノコ safe_mushroom | 144 (3.0d) | **216 (4.5d)** | やや延長 |
| 毒キノコ toxic_mushroom | 144 (3.0d) | **216 (4.5d)** | safe と揃える |
| 焼き魚 cooked_fish | 160 (3.3d) | **240 (5.0d)** | 調理=保存の見返り。horizon 全域 |
| 椰子の実 coconut | 240 (5.0d) | 240 維持 | 既に horizon 全域 |

### 2. 腐敗食は「ダメージ + 部分的な空腹回復」に (`spot_graph_tool_executor.py`)

現状の腐敗食パス (`is_spoiled` 分岐) は **回復効果を完全に捨てて** 10 ダメージだけを与える。
これを、ダメージは残しつつ **空腹回復の一部を適用**する:

- ダメージ: `SPOILED_FOOD_DAMAGE_HP = 10` は維持。
- 空腹回復: その food の `consume_effect` にある `satisfy_need(HUNGER, amount)` の
  **50% を適用** (`SPOILED_FOOD_HUNGER_RETENTION_RATIO = 0.5`, 切り捨て)。貝 35→17,
  生魚 50→25, 焼き魚 70→35。
- HP 回復 (`heal_hp`) は腐敗食では適用しない (腐った物で HP は回復しない)。
- 適用経路: 腐敗分岐で既に取得している `status` に対し、`apply_damage` の後に
  `status.satisfy_need(NeedType.HUNGER, partial)` を呼ぶ (新鮮パスの
  `ConsumableEffectHandler._apply_effect_to_status` と同じ API)。ConsumableUsedEvent は
  出さない (= 全効果適用の経路には乗せない)。
- メッセージ: 「腐っていた——胃の奥が灼ける。（10 ダメージ、それでも少し空腹は和らいだ）」
  のように、ダメージと部分回復の両方を伝える。

### 設計判断

- 「腐敗を完全に無害化しない」: ダメージは残す。腐敗の危険という質感 (design principle: 失敗の
  質感) を保ちつつ、**飢餓のデススパイラルにおける最後の一手としては機能する**ようにする。
- 部分回復は満杯クランプに従う (satisfy_need の既存挙動)。空腹が既に低ければ回復量は頭打ち。

## 検証観点 (次 run)

- 貝の腐敗頻度が下がり、腐敗食を食べる回数が減るか。
- 腐敗食を食べたときにダメージと部分回復の両方が trace に出るか。
- 空腹が単調 100 に張り付かず、食料ループ (採取→摂食) で下がる局面が生まれるか。
- それでも救助 (火・狼煙・山頂集結) が未達なら、失敗要因が経済ではなく協調/実行へ移ったと
  切り分けられる。
