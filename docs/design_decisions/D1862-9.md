## D1862-9. タイル専用の採取・スキル実行を削除し、装備の値は残す

**何を**: Issue #1862 の採取アプリケーション、プレイヤーとモンスターのタイル用スキル実行、物理マップへのモンスター出現を、専用の契約・例外・試験とともに削除する。スキル装備・進化提案・保存先、覚醒の既定値、スポットの採取作用・モンスター出現・観測は残す。

**なぜ**: 旧LLM・シミュレーション・イベント受け手を外した後、実行サービスの利用側は削除対象内とその試験だけになった。使われない実行経路を残すと、スポット側の仕組みと区別しにくい。一方、本番は `SkillLoadoutAggregate` と `SkillDeck` を通じて `SkillSpec` / `SkillHitPattern` に依存し、形・速度・効果の値まで読み込む。スキル全体の削除は本番の起動と装備の保存を壊す。

**どうしないと壊れるか**:

- `SkillSpec` / `SkillHitPattern` と `hit_box_shape` / `hit_box_velocity` / `hit_effect`、装備集約と保存先は削除しない。
- 旧現在状態の問い合わせが使う `awakened_mode_defaults` と、物理マップ側の採取状態・採取セッション・採取イベント・観測の処理は残す。今回その境界を移さない。
- 専用契約・例外の削除は、実行時・型・再公開の参照が削除対象に閉じていることを確認してから行う。共有のworld契約はまとめて整理しない。
- 採取とスキルの未使用実行経路は一緒に外す。残すコードの変更が小さく、共通の本番比較で確認できるため分割しない。装備の振る舞いまで消す案は採らない。
- 同じ条件のスタブ実験で、変更前後の記録種別・観測種別ごとの件数と行動件数を比較する。実LLMの質感はこの比較では保証しない。
