## D2081. 確定の範囲 (CommandScope) と、確定したイベントを配る順

**何を**: `game_world/application/` に、1 つの確定の範囲 `CommandScope` と、確定したイベントのまとまりを受け口 (`CommittedEventsReceiver`) とハンドラ (`EventHandler`) に配る `CommittedEventsDistributor` を置いた (#2081、設計は [persistence.md](../environment_model/design/persistence.md) と [use_cases.md](../environment_model/design/use_cases.md))。

| 何を | 決めたこと | 採らなかった案 |
|---|---|---|
| ハンドラの範囲が出したまとまりを配る時機 | 待たせて、今のまとまりを受けるハンドラを全部動かしてから配る (世代の順)。ハンドラの中の `CommandScope.run` が戻った時点では、その範囲のイベントはまだ誰にも届いていない。いちばん外の `run` が戻るときには、続いて出たまとまりも全部配り終えている | 確定したその場で配る。同じイベントを受けるほかのハンドラより先に、その結果への反応が動くので、登録の順で結果が変わる |
| ハンドラの断り | `GameWorldDomainException` だけを断りとして数え、ほかのハンドラとまとまりを配り続ける | どの例外も断りとして数える。バグが数に紛れて静かに続く |
| ドメイン例外でない例外 | 範囲を巻き戻して呼び出し元に届け、待っていたまとまりは捨てる。バグとして止めるため。確定済みで配っていないイベントは失われ、受け口とハンドラが見た世界はずれる。止まった run は分析に使わない | 待っていたまとまりを残す。次の確定のイベントと混ざって、どの確定の結果か分からなくなる |
| 受け口とハンドラの順 | まとまりごとに、受け口に渡してからハンドラに配る。空のまとまりは配らない | ハンドラが先。反応のまとまりが原因のまとまりより先に受け口へ届くことはないが、受け口が見る前に世界が進む |
| 断りを外から数える形 | `CommandScope.refusals` は `error_code` ごと、`CommittedEventsDistributor.refused_handlers` はハンドラの型の名前と `error_code` の組ごとの件数。trace への配線は、trace に出す Issue で行う | 総数だけ。集約が無いことによる断り (`AggregateNotInWorldException`) のようなバグの兆しと、行為の断りが見分けられない |
