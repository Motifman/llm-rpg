# タイルマップの旧イベント受け手の削除確認

Issue #1862 の変更範囲3。スポットのグラフの実行経路を保ったまま、旧イベント受け手と6種類の登録、まとめて登録する窓口を消す。

- [x] 廃坑の山村と避難訓練を各シード0〜2・40tickで前後実行し、観測種別ごとの件数と行動件数を比較する。
- [x] 消した受け手だけの試験を削除し、残すサービスの試験は実行する。

- [x] 消したモジュール名がsrc/testsに残っていないことを確認する。

## 確認条件

実LLMは呼ばない。作業ツリーに.envを置かず、一時的なsitecustomizeでdotenv.load_dotenvを無効化する。実験は比較型、profileはsmoke_stub、シナリオとtick数は既定値。でたらめな行動の検査はmine_village_v1とstation_drill、シード0〜2、40tick。通常の検査に加え、同じrun_random_agentsのNullTraceRecorder.recordを一時スクリプトで収集する。

## 参照と試験の扱い

削除前にsrc/testsをrgで検索し、ASTで削除対象のクラスを使う名前・属性と構築箇所を走査した。本番側では定義・削除する登録・再公開の中だけにあり、外側には構築箇所が無かった。srcに残っていた品を落とす受け手の名前は2か所とも説明文で、古い固有名を外した。

対象はapplication/world/handlersのうちconsumable_effect_handlerとgateway_handler以外の14本、application/conversation/handlers、infrastructure/eventsのcombat・monster・map_interaction・intentional_drop・inventory_overflow・conversationの登録、一括登録とその設定。消した受け手・設定専用の試験を削除した。

残す旧サービスを検証する試験は以下のように維持した。

- 移動2ファイル: ゲートウェイの受け手を直接同期登録。ゲートウェイを跨ぐ移動の期待値は維持。
- 宝箱: 収納・取得後の宝箱の状態と、その品のイベントの発行を確認。消した受け手が行う所持品の変更は期待しない。入力不正や例外の試験は維持。
- シミュレーション: 移動先・スキルのスロットを含む意思決定イベントと、1体の失敗後も別の個体が意思決定できることを確認。受け手による座標更新・当たり判定生成の確認は外した。移動統合の重複1例だけを削除し、追跡・天候・時刻・復活などの試験は維持。
- 旧確定経路と所持品付与経路の構造検査: 消したファイルを一覧から除去。

## 前後比較と判断

| 場面 | 削除前 | 削除後 |
|---|---|---|
| スポットで移動・戦闘・品の受け渡しを行う | 本番のサービスが処理する | 同じサービスが処理する |
| 消耗品を使う | 本番で直接受け手を呼ぶ | 維持する |
| 旧タイルのイベントを登録する | 未使用の登録が残る | 今回の6種類の登録と対応する受け手が無くなる |
| 旧移動を試験する | 一括登録を通す | ゲートウェイの受け手を直接登録する |

目的は本番の行動・観測を変えずに不要な経路を消すこと。登録だけを外す案は削除範囲が小さい一方、取り違えられる受け手を残す。今回は本体も削除するため旧統合の復元はできなくなるが、復元が必要なら新しいシナリオの設計で判断する。コード上は、消す受け手の効果を試験用に再実装する案も採らない。残すサービスの出口に試験を寄せる方が、消した処理を複製せずに済む。いずれも実装前の判断で、選択肢が一つだけだった判断は無い。

## 実行結果

削除前の比較基準はmainの `3ba6dd975f17484c0acd1beea1bc77c828f6d072`。作業記録は `/tmp/llm-rpg-1862-event-handlers/` に保存した。

- 関連試験は削除前298件成功。削除後は対象を会話本体とスポットの品の受け渡しまで含めて311件成功。
- 変更したPythonファイルへの `uv run --extra dev ruff check` が成功。`uv run --extra dev mypy` は1478ファイルで成功。
- 削除した完全モジュール名・ファイル名と一括登録のクラス名をsrc/testsで検索し、残存0件。宝箱のクエスト進捗用の変数は別の型であり、その登録は担当外なので維持。
- `make experiment EXPERIMENT_PROFILE=smoke_stub` の前後の解決済み設定は、survival_island_v3_coop・2tick・stub。観測と行動はともに0件で、全trace種別の件数が一致。これだけでは同等と判断せず、以下の40tickの検査を併用。
- `make fuzz-scenario SCENARIO=data/scenarios/mine_village_v1.json SEEDS=0-2 FUZZ_TICKS=40` とstation_drillの各前後で、例外と内部番号漏れの検出0件。
