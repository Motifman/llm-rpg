## D2232. ターンを回す決まりを巡り (TurnRounds) に置き、誰が動けるかは世界に問う

**何を**: D2225 の決まりを、遊びの進行のドメインの集約 `TurnRounds` と、世界に誰が動けるかを問う入口 `CheckReadinessToAct` で作った (#2232、親 #2212)。

### 1. 誰が動けるかは世界が答え、ターンを回すかは遊びの進行が決める

世界は、人ごとに 3 つのどれかで答える (`ReadinessToAct`)。

| 世界の答え | 根拠 | 遊びの進行が回すか |
|---|---|---|
| `FreeToAct` | 生きていて、結末が決まっておらず、行為の最中でない | 回す。ただし「待つ」を選んで待っている人には回さない |
| `InTheMiddleOfAction` | 生きていて結末が決まっていないが、行為の最中 (移動中など、`is_busy`) | 前の巡りで自分に向けた行為を知覚したときだけ回す (D2268-19) |
| `UnableToAct` | 気を失っている・死んだ・結末が決まって世界から外れた | 回さない |

- 根拠は、世界が行為を受け付けるかの判定 (`_acting_occupant`) の生者の側と同じにした。ずれると、ターンを回したのに行為が全部断られる人が出る
- 世界には死者が動ける設定 (`departed_persons_act`) があるが、死者にはターンを回さない (D2225)。幽霊を動かすときに改めて決める

例: ハルが北の坑道へ移動中なら `InTheMiddleOfAction`、サヨが気を失っていれば `UnableToAct`。

### 2. 「話しかけられた」は wants_wake の立った観測で代える

**D2268-19 で置き換えた。** 行為の最中の人は、自分に向けた行為 (`addressed_to_self`) を知覚したときだけ起こす。下は置き換える前の決まり。

D2225 は、行っているあいだの人には「話しかけられたときにだけ」回すと決めた。しかし、世界の観測の出口 (`ObservationExit`) は `addressed_to_self` を `UNKNOWN` で渡していて、話しかけられたかを見分けられない。

代わりに、`wants_wake` の立った観測を呼びかけ (`TurnRounds.hear_call`) として数える。`wants_wake` は、その人が関わっている (話しかけられた、自分に向けて何かされた) か、目立つ知らせ (`Notable`) のときに立つ。

- 待っている人も、同じ呼びかけで起こす
- 呼びかけは次の巡りでターンを回すためのもので、その巡りでターンにならなかった人 (気を失っていた人) の呼びかけは捨てる。持ち越すと、気がついてから移動を始めた人に、古い呼びかけでターンが回る
- ターンを終えたら呼びかけを消す。行為の確定のあとで消すので、自分の行為が呼んだ観測でもう一度ターンが回ることはない

### 3. 「待つ」を選んだ人は、決めた巡りの数のあいだ飛ばす

巡り r で待つを選んだ人は、巡り r+1 から r+N を飛ばし、r+N+1 でまたターンが回る。N は `TurnRounds` が受け取る値 (`wake_waiting_after`) で、遊びの進行のドメインは値を決めない。値は実験の条件として profile で渡し、既定は 3 にする (ユーザーと決めた)。

例: N = 3 のとき、巡り 1 で待つを選んだゲンは、巡り 2〜4 は飛ばされ、巡り 5 でターンが戻る。途中で呼びかけを受ければ、次の巡りで戻る。

### 4. 1 巡りの中の順番と、巡りを閉じる条件

- ターンを終えた順を `TurnFinishedEvent.order` (1 から) に残す。LLM の返事が返った順に終えるので、記録 (#2233) はこれで同じ tick の中の順番を書き出せる
- その巡りにターンのある人が全員終えるまで、巡りを閉じない (`RoundStillHasTurnsException`)。閉じたら時間を 1 進める
- 誰にもターンが無い巡りは、開いてすぐ閉じる。全員が移動中でも時間は進む
- 巡りを開いた (`RoundOpenedEvent`、ターンのある人の一覧と、飛ばした人と理由つき (D2268-19))・閉じた (`RoundClosedEvent`) をイベントで残し、時間を進めた時点を記録に渡す
- 決めた巡りの数 (`round_limit`、run の `MAX_WORLD_TICKS`) を閉じ終えたら、上限に届いたと答える

### 5. 進め方を差し替えられる形

D2225 で、決まった実時間ごとに進める案を今後の選択肢に残した。巡りで進める決まりは `TurnRounds` に閉じ込め、誰が動けるかの問い合わせ (`CheckReadinessToAct`) と、ターンを頼む先は巡りを知らない形にする。実時間で進めるときは、`TurnRounds` の代わりの集約を足して、同じ問い合わせと頼む先を使う。

### 6. 巡りを回すユースケースと、ターンを頼む先

`PlayRounds` が、世界の終わりと巡りの上限を確かめてから 1 巡りを回し、閉じたら時間を 1 進める。これを止まるまで繰り返し、止まった理由 (`WorldEnded` / `RoundLimitReached`) を返す。

- ターンを頼む先 (`TurnTakers`) は、その巡りでターンのある人の一覧を受け取り、ターンを終えた人を、終えた順に 1 人ずつ返す (`FinishedTurn`)。LLM の返事が返った順に世界へ送るのは、頼む先の仕事にする。頼む先が 1 人ずつ返すので、遊びの進行は並行して呼ぶかどうかを知らない
- 1 人終えるたびに世界の終わりを問い、終わっていたら残りの人には頼まない。頼む先を途中で手放すと、残りの人の分は呼ばれない
  - 例: ミオが籠に乗って世界が終わったら、同じ巡りのゲンにはもう頼まない
- 時間を進める要求の返事は見ない。断られるのは世界が終わっていたときだけで、次の巡りの前に終わりを問うため
- 呼びかけは、観測の受け口 (`HandObservationToBeing`) が Being に観測を渡したあとで巡りに伝える (`notice_observation`)。観測はターンの最中 (世界が行為を確定させるとき) に届くので、`PlayRounds` は 1 人終えるたびに巡りを取り出し直す。取り出した巡りを持ち続けると、そのあいだの呼びかけが保存で消える
- 頼む先が途中で例外を投げると、巡りは開いたまま残り、同じ `PlayRounds` を呼び直すと `RoundAlreadyOpenException` になる。異常終了からの再開は扱わない。頼む先を途中で手放したときの後片付け (並行して走っている呼び出しを止める) は、並行して呼ぶ頼む先を作るときに決める
- 巡りは、遊びを始めるとき (`StartPlaySession`) に、世界を開く前に作る。世界を開くと、入る人への観測が届き始めるため。巡りの上限と、待つ人を起こすまでの長さは、遊びを始めるコマンドで受け取る

### 7. ユーザーと決めた残りの細部

調整役を通して、ユーザーと例つきで決めた。例は廃坑の山村 v2 の 4 人。

| | 決まり | 例 |
|---|---|---|
| LLM の呼び出しが続けて失敗した人 | 同じ人が 3 回続けて失敗したら、その人を「待つ」を選んだ人と同じ扱いにする (目立つ知らせか、起こすまでの長さが経てば戻る)。成功を挟むと数え直す | ミオの呼び出しが巡り 4・5・6 と続けて失敗したら、巡り 7 からはミオを待っている人として飛ばす |
| run 全体を止める失敗 | 人を問わず、失敗が 8 件続き、その連続が 2 つ以上の巡りにまたがったら止める。数え方は遊びの進行に置く | provider が落ちて 4 人とも 2 巡り続けて失敗したら止める |
| 同じ行動の繰り返し | 今回は入れない。trace で見て、新しい流れで実際に起きるかを確かめてから決める | ゲンが金庫を「0000」で 8 巡り続けて開けようとしても止めない |
| 断られた理由が、結果と体の観測で 2 回並ぶ | 理由は行動の結果 (`OwnActionResult`) に書き、本人の体の観測としては届けない | ゲンの【直近の出来事】に「金庫を開けようとした → 番号が違った」が 1 回だけ並ぶ |
| 死んだ人 | 死者が動ける設定の世界でも、ターンを回さない (1 節) | |

- 失敗の扱いを D1595 からこう変えた理由: D1595 は「失敗した人を次の tick にもう一度回す」決まりだったが、D2225 では動ける人には毎巡り回すので、それは何もしなくても起きる。D1595 の「3 回続いたら戻さず、観測か待ち時間のタイマーに任せる」は、「待つ」と同じ扱いにあたる
- run 全体を止める数え方は、古い run の `LlmFailureStreakMonitor` (design_decisions 214) と同じ閾値にした。健全な run の最長連続が 4、壊れた run の最短が 35 だった
- 同じ人の失敗だけで止めないのは、provider が 1 人のモデルだけ落ち続けるとき、他の 3 人が成功して全員分の連続が切れるため。その人を待つ扱いにして、毎巡り最大 90 秒ずつ run を止め続けるのを防ぐ
- 失敗の数え方は `TurnRounds` に置く。ターンを頼む先は、`ChooseAction` が例外で落ちたら、そのターンを呼び出しが落ちたターン (`ChoiceFailed`、理由に例外の型と文) として返す。LLM の失敗は provider ごとに型が違うので型で絞らない。世界の確定や結果の受け渡しで出た例外は囲まず、そのまま上に出す。世界の側の例外まで落ちたターンにすると、壊れた世界で run が続くため
  - 囲んでいるのは `ChooseAction` ごとで、LLM の呼び出しだけではない。作業記憶の組み立てや短期記憶の保存で出た例外も、落ちたターンとして数える。LLM の呼び出しだけを囲むには `ChooseAction` の中に手を入れることになり、#2240 で並行して触っているので、今回は入れていない
- LLM は答えたが世界に渡す行動が無いとき (`ActionNotChosen`、思い出すだけ) は、呼び出しの失敗ではないので失敗の続きを切る (古い run の `LlmFailureStreakMonitor` と同じ)
- 一度止めると決めたら、後から選べたターンが届いても止めたままにする。止めたときの続きの理由 (8 件) を残し、`PlayRounds` は `ChoosingKeptFailing` にその理由を持たせて止まる。止まった側が、なぜ止まったかを記録に書ける
- `PlayRounds` は、巡りの頭と 1 人終えるたびに、止めると決めたかを問う
- 断られた理由の届け方は、別の PR で入れる

### 8. ターンを頼む先を、Being と世界につなぐ

`BeingsTakingTurnsOneByOne` が、ターンを頼む先 (`TurnTakers`) を 1 人ずつ順に頼む形で作る。1 人のターンは次の順に進む。

1. 案内と目的は配役 (`Cast`) から、場面は `DescribeScene`、行動の選択肢は `OfferActionChoices`、いまの時刻は `TellCurrentTime` から取る
2. Being の `ChooseAction` に行動を選ばせる。Being の道具 (`OfferedBeingTools`) と締めの一文 (`Closing`) は実験の条件なので、遊びの進行は受け取ったものをそのまま渡す
3. 選んだ行動を `TakeChosenAction` で確定させ、返事を `DescribeActionResult` で本人の行動の結果の観測にし、Being の `ReceiveActionResult` で試みに結び付ける
4. 返事が待つことだったら (`was_waiting`) 待つ人にし、そうでなければ行ったものとして巡りに返す

- `ChooseAction` が行動を返さなかったとき (ツールを呼ばなかった、無いツールを呼んだ、思い出すだけのように世界に渡す行為が無い) は、世界に何も送らず、ターンを使ったものとして次の巡りでまた頼む。待つとは別の扱い。古い run でも、思い出すことに 1 回のターンを使っていた (D1623)。`ChooseAction` の返事の型が増えても落ちないよう、`ActionChosen` 以外はまとめてこの扱いにする
- 結果の本文の人の穴は、Being の `ReceiveActionResult` が、`PerceiveObservation` と同じく受け取ったときの呼び名で埋める (D2229-3)
- 作業記憶 (`CurrentWorkingMemory`) が Being を引く形を、保存先のインタフェースと同じ `get` (いなければ `BeingNotFoundException`) にそろえた。Being の側の保存先をそのまま渡せる。古い run の保存先 2 つには `get` を足した
- LLM を並行して呼ぶ形と、考えている最中に届いた観測の預かりは、別の頼む先として足す (D2225 の 3、6 節)

### 9. #2232 の完了条件の確かめ方

#2232 の完了条件「スタブのエージェントで、廃坑の山村 v2 が終わりまで進む」は、最後の 3 手を通すテスト (`test_lift_started_by_gen_ends_the_world_and_stops_the_play`) で満たしたことにする (ユーザーが決めた)。鍵・発電機の暖機・燃料・籠の位置は世界に直に整え、スタブの Being がカンテラを灯し、灯を手に持ち、操作盤で昇降機を動かす。昇降機が出て全員の結末が決まり、`WorldEnded` で止まる。

金庫を開けて鍵を取るところから始める長い道のりは、#2219 と #2235 が受け持つ。

**採らなかった案**:

- 遊びの進行が世界の人の状態 (`PersonVitals`、`PersonOutcomes`) を直接読んで決める: 世界の判定と別に同じ規則を書くことになり、ずれる
- 世界がターンを回す人を決める: 「待つ」・呼びかけ・巡りは遊びの進行の決まり (D2226 の地図)
- 待っている人の起こしを tick (世界の時刻) で数える: 遊びの進行は自分の巡りを数えていて、1 巡りで 1 tick 進むので同じになる。世界の時刻に頼ると、時刻の読み方が変わるたびに直すことになる
