基準: `0783daed9b0c9a3710c71ad659a41581b1aec4e1`。Issue #1862、担当A。

## テストリスト

- [x] 現在状態と部品DTOが旧タイル項目を持たない。
- [x] 専用DTO型と未登録の旧囁き判定器が残らない。
- [x] 現在状態の部品変換でギルド文脈・取引情報・時刻を保つ。
- [x] SNSと取引の入力正規化・ツール露出を保つ。
- [x] スポットの状態表示、残り時間、会議、作業の情報を保つ。

- [x] 変更前後のスタブ実験・山村と避難訓練の各3シード40tickで記録種別・観測種別・行動件数が一致する。
- [x] 独立レビューの指摘を確認し、必要な修正と再検証を終える。

## 利用調査

`src`・`tests`・`scripts`のimport、再公開、属性読み取り、文字列と構築引数を確認した。HTTPは`SessionStateResponse`と`SpotViewResponse`を独立に構築し、Being保存codecはこのDTOを参照しない。旧項目の本番の値の読み手は未登録の`WhisperAvailabilityResolver`だけで、ほかは部品DTOのコピーと空値による構築だった。ギルドの判定器が読む`current_spot_id`・`area_ids`、取引の所持品と要約、SNS・取引の入力正規化は残す。天候・地形・場所・周辺人物の表示は`spot_graph_snapshot`が担う。

## 前後の振る舞い

| 場面 | 変更前 | 変更後 |
| --- | --- | --- |
| スポットの現在状態を表示する | `spot_graph_snapshot`から場所・天候・周辺人物・移動中状態を表示 | 同じ経路を使用 |
| 内部の現在状態DTOを構築する | 旧タイル項目へ空値を渡す | 旧項目38個と専用型14種を削除 |
| SNS・取引・ギルドの候補を判定する | アプリ状態・所持品・要約・場所ID・エリアIDを読む | 同じ値を保持 |
| HTTP応答と保存データを作る | 現在状態DTOとは独立して構築 | 変更なし |

## 設計の選択と自己レビュー

- 目的: スポットのグラフの振る舞いを保持し、退役したタイル機能の契約を残さない。タイル用の動作を復活させる案はIssue #1862の範囲外。
- 実装: 空項目の維持と、読み手のない項目・型の一括削除を実装前に比較した。前者は内部構築を保てるが利用できる機能と誤認しやすく、後者は構築試験の追従が必要だが契約が実態に合う。外部利用・永続形式との結合が見つかった場合に再検討する。
- 比較可能な案が1つしかない判断は0件。事後に追加した代替案はない。詳しい判断は[D1862-18](../design_decisions/D1862-18.md)に記録した。
- 本番の値の読み手、残す機能の試験、説明と実装の一致、削除専用試験の範囲、400行以内の追加を確認した。
- 独立レビュー: CRITICAL・HIGH・MEDIUMの指摘なし。古い契約説明コメント1件（LOW）を修正し、再確認済み。

## 検証結果

- 追加した構造検査は変更前に4件失敗。変更後は旧囁き判定器の非公開検査を含む5件が成功。
- 構造・LLM・世界・スポット・残り時間・無効ツール露出・既存シナリオの関連試験3154件成功。部品変換の保証を追加した後、DTOと構造検査13件成功。
- 変更Pythonのruff、mypy（1287ファイル）、`git diff --check`成功。
- 削除した型・判定器の名前は、srcでは0件。testsでは非存在を保証する構造検査だけに残る。
- 実LLMと`.env`読取は実施していない。実験は一時`sitecustomize`で`dotenv.load_dotenv`を無効化した。

## 質感

今回の変更はLLMへ届く情報を増減させない内部契約の整理で、人物のふるまいや世界の質感を改善する主張はしない。実LLMによる質感の評価は未実施。
