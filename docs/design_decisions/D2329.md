## D2329. メモの決まりはメモ帳が理由ごとの例外で断り、application は JSON の形だけを見る

**何を**: 行動の引数 `memo` を書くときの決まりを、application とドメインで二重に持つのをやめた (#2329)。調整役と決めた。

| | 前 | 今 |
|---|---|---|
| 決まりの置き場 | 自分で確かめたことに from を書かない、エピソードの from は `ep_` で始まる、分類と出どころの組み合わせ、知らないエピソード、文の長さを、application (`memo_arguments.py`・`memo_writing.py`) がドメインと別に確かめていた | `MemoProvenance`・`Memo`・`MemoBook` だけが確かめる |
| 断り方 | ドメインは `MemoValidationException` 1 種類 | 理由ごとの例外 (下の表)。どれも `MemoValidationException` の子で、`error_code` を持つ |
| application がすること | 決まりの写しで理由を見分ける | JSON の形 (配列か、オブジェクトか、`do`・`kind` の値、`text` が空でない文字列か、`id`、`source`・`certainty` の値) だけを見る。断られたら `error_code` の表で理由に写す |
| 操作の振り分け | application が `isinstance` で足す・書き換える・消すを見分ける | 操作の値 (`MemoAddition`・`MemoRevision`・`MemoRemoval`) をドメインに置き、`MemoBook.write` に頼む |
| 入口 | Being の `ChooseAction` と古い経路の `memo_turn.py` が別々に当てていた | どちらもユースケース `WriteMemos` を呼ぶ。本人に返す文は、それぞれの経路が今までの表で作る |

| 例外 | `error_code` | 理由 (trace の `reason`) |
|---|---|---|
| `MemoTextTooLongException` | `BEING.MEMO_TEXT_TOO_LONG` | `text_too_long` |
| `MemoProvenanceMissingException` | `BEING.MEMO_PROVENANCE_MISSING` | `missing_provenance` |
| `MemoProvenanceOutsideFactException` | `BEING.MEMO_PROVENANCE_OUTSIDE_FACT` | `provenance_outside_fact` |
| `MemoHeardSourceFromMissingException` | `BEING.MEMO_HEARD_SOURCE_FROM_MISSING` | `missing_from` |
| `MemoEpisodeSourceFromMissingException` | `BEING.MEMO_EPISODE_SOURCE_FROM_MISSING` | `missing_episode_from` |
| `MemoSourceFromNotNeededException` | `BEING.MEMO_SOURCE_FROM_NOT_NEEDED` | `from_not_needed` |
| `MemoSourceNotEpisodeHandleException` | `BEING.MEMO_SOURCE_NOT_EPISODE_HANDLE` | `unknown_episode` (呼び名を添えない) |
| `MemoSourceEpisodeUnknownException` | `BEING.MEMO_SOURCE_EPISODE_UNKNOWN` | `unknown_episode` (呼び名を添える) |
| `MemoLimitReachedException` (分類を持つ) | `BEING.MEMO_LIMIT_REACHED` | `limit_reached` |
| `MemoNotFoundException` (呼び名を持つ) | `BEING.MEMO_NOT_FOUND` | `no_such_memo` |
| 上のどれでもない `MemoValidationException` | `BEING.MEMO_VALIDATION` | `invalid` |

### 決めたこと

- **エピソードから分かったことに from が無いときは、人から聞いたときと別の理由にする**。前は同じ `missing_from` で「人から聞いたことには from に誰から聞いたかが要る」と返し、実 LLM の run で、エピソードから書こうとした本人に人から聞いた場合の直し方を返していた。Being には「エピソードから分かったことには from にエピソードの呼び名が要る」、古い経路には「エピソードから分かったこと (episode) には、from にエピソードの呼び名 (ep_ で始まる) を書いてください。」を返す。古い経路の文もこの場合だけ変わる
- **1 つの操作に不備が 2 つ以上あるときは、形の不備を先に、メモ帳の決まりを後に理由にする**。文の長さは形ではなくメモ帳の決まりになったので、ほかの不備と重なると後に回る。どちらも本当の理由なので、この変化は受け入れた。不備が 1 つの操作は、前と同じ文を返す
  - 61 字の文 + kind が `note`: 前「text は 60 字まで」→ 今「kind は todo / fact / person のどれか」
  - 61 字の文 + 自分で確かめたことに from: 前「text は 60 字まで」→ 今「自分で確かめたことには from を書かない」
  - 61 字の文で、無いメモを書き換える: 前「text は 60 字まで」→ 今「そのメモはない」
- **メモ帳の中の確かめる順は、前の application の順に合わせた**。足すときはメモを組んで (文の長さ、分類と出どころ) から、知らないエピソード、件数の上限の順。書き換えるときは、知らないエピソードを、無いメモより先に確かめる
- **当てたメモは、`WriteMemos` が保存の前に、メモ帳がためたイベントから取る**。状態を変える操作は値を返さない決まりのため。当てた操作 1 件につきイベントが 1 件ためられることに頼り、数が合わなければ保存せずに止める (`MemoBook.write` のテストと `WriteMemos` のテストで見張る)
- **書けなかった操作の言い方 (D2240) は、書かれていた値から作る**。読めた操作の値から言っていた `attempted_operation` は、読めなかった操作の言い方と同じ文になるので消した

**古い経路の trace で変わること**: 理由を分けた不備の `detail` に、断った例外の文が入る (前は None)。本人が行動を選べないときは、読めなかった操作を `rejected` に残さない (前は残していた。返す文は前と同じ「メモ帳に書けませんでした」)

**関連**: Issue #2329、D1628、D2240。
