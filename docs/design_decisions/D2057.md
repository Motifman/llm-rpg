## D2057. 新しい形式 (YAML) のシナリオの読み込み

**何を**: YAML のシナリオを読み、`includes:` の共通の部品を鍵ごとに重ね、名詞の宣言 → 動詞の宣言 → `WorldDesign.compose` の順に組み立てる読み込みを `game_world/infrastructure/scenario/` に作った (#2057、#1978 のステージ 6)。文書から決まらなかったことは、ユーザーと次のように決めた。

| 何を | 決めたこと | 採らなかった案 |
|---|---|---|
| 自分や互いを指す出来事・集団の決定 | `HappeningHasFiredCondition` と `TicksSinceHappeningAtLeastCondition` は `HappeningId` を持ち、`ScenarioProgress.last_fired_at` も ID で引く。ID が宣言にあるかは compose が `Requirements.reads_happenings` で確かめる。`StartGroupDecisionEffect` は決定と `voters` / `choices` を持ち、`DeclaredGroupDecisionRules` を外す | 読み込む側が依存の順に並べ、循環を `DesignFlaw` にする。「最後に襲ってから 5 tick 経ったらまた襲う」「決まらなければもう一度投票」が書けない |
| 書かなかった欄の既定 | 共通の部品の `defaults:` に、宣言の種類ごとに欄の既定を書く。シナリオでも上書きできる。「無い」を表す型は `null` | 空の一覧と「無い」型だけ読み込む側が埋める。埋める決まりがコードとデータに分かれる |
| `PassageDeclaration.states` の既定 | 型から外し、`defaults.passage` で埋める。「開いている」はドメインの決まった文だった | 型に残す |
| 体力と荷の上限の上書き (#2055) | `CharacterDeclaration` が `max_hp` と `pack_capacity` を「値 \| `UsesWorldDefault`」で持ち、`initial_world()` が `WorldRules` の値で解いて `StartingPerson` に入れる | 読み込む側が `WorldRules` の値を写して埋める。`WorldRules` の欄が読み込みでしか使われない |
| 登場人物の `being:` | 検査せず、`PersonId` → YAML の地図のまま `LoadedScenario.beings` に返す。地図でないときだけ `DesignFlaw` | ステージ 8 の前に人柄の型を決める |

**実装で決めたこと**:

- `ItemSpecDeclaration.hands_needed` の既定も、`states` と同じ理由で外し、`defaults.item_spec` で埋める
- `defaults:` で埋めるのは欄の 1 段だけ。地図の中まで重ねると、`states` を書いた通路にも既定の `open` が混ざるため。入れ子の欄 (`atmosphere`、`appearance`) は自分の種類を持つ
- 書かなかった知覚の文 (目撃、音、人への操作のされた人) は `perception_defaults:` で埋め、`DesignWarning` を残す。読み込みの警告と compose の警告は `LoadedScenario.warnings()` でまとめて引く
- 最初の体力は `HitPoints` (いまの値 = 上限) で持つ。`PersonVitals.start` がそのまま受け取れるため
- 宣言に無い欄は `DesignFlaw` にする。綴り違い (`failure_txt`) を黙って捨てないため
- 読めなかった名詞を指す名詞は、`DeclaredNouns` に渡さず読めなかったものとして扱う。`DeclaredNouns` が返した誤りの宣言も外して作り直し、動詞の誤りまで集めてから 1 つの `WorldDesignFlawsException` で投げる。読めなかった名詞を指す動詞は誤りにせず飛ばす (同じ誤りを二重に出さない)
- 誤りは宣言 1 つごとに集める。1 つの宣言の中では最初の誤りで止め、ほかの宣言は読み続ける。読めなかった名詞を指す宣言は、残りの欄を読まずに飛ばす。同じ誤りは 1 件にまとめる
- 相手のいない操作 (物・品物の操作、区画の出入り) に、された人の文 `target` を書くと `DesignFlaw`。誰にも届かない文になるため
- 鍵は文字だけ。数の鍵は `1` と `'1'` が黙って重なるので `DesignFlaw`。自分を含むアンカーと、展開すると 20 万節を超える YAML も `DesignFlaw`
- 共通の部品のファイルが読めない (文字コードが UTF-8 でないなど) ときは includes の位置の `DesignFlaw`。シナリオのファイルそのものが無いときは、呼び出し側の誤りなので素の例外のまま
- 誤りの場所は YAML の道筋から写す。名前で指す宣言は地図の鍵を名前にし (`spots.<場所>.objects.<物>` は `object`)、世界に 1 つの欄は `world` の欄に道筋をそのまま書く
- YAML の鍵の重複は、PyYAML の組み立て (compose) の木をたどって見つける。`yaml.safe_load` は後の値で黙って上書きするため
- 型の検査のため `types-PyYAML` を dev の依存に足した
- 最初の段階はトップの `initial_stage:` に書く。`world_stages` を書いたら必須
- 天候の移り変わりは、`transitions: default` でドメインの既定の表 (`WeatherTransitions.default()`) を使える
