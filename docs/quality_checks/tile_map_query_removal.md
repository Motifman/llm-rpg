## 判断の材料

変更前はタイル用の読み取りと本番のスポット用の読み取りが共存していた。変更後は本番の現在地、周囲、行動候補と観測の文面を維持し、タイル専用の読み取りを削除する。共有DTOと問い合わせ、NPC会話、クエスト・ショップ・ギルドの本体は今回の境界外として保持する。

実装前に、共有契約まで一括削除する案と、専用実装だけを削除する案を比較した。前者は整理が一度で済むが、現用のDTOと本番の取得契約まで巻き込む。後者は不要項目を後続へ残すが、独立して本番の同等性を確認できるため採用した。全利用側がなくなったことを確認した段階で共有契約を別途整理する。

## 参照解析と検証

- 不在検査は削除前15件失敗、削除後15件成功。
- `uv run pytest tests/application/world tests/application/llm tests/application/world_runtime tests/architecture tests/demos/test_disabled_tools_vanish_from_the_prompt.py -n 4 -q`: 2,450件成功。
- 独立側の契約・構造・プロンプトと、本番取得アダプタ・スポット整形の関連77件も成功。
- 変更したPython 5ファイルに `uv run --extra dev ruff check` を実行して成功。`uv run --extra dev mypy`: 1,365ファイル成功。
- 前後に `make experiment EXPERIMENT_PROFILE=smoke_stub` を実行。解決済み設定は `survival_island_v3_coop.json`・2tick・stubで一致し、全記録種別の件数も一致。

- 実LLM・手動のquality/live_api試験は実行していない。作業ツリーと変更前の一時展開には `.env` を置かず、一時 `sitecustomize` で `dotenv.load_dotenv` を無効化した。
