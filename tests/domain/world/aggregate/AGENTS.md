# 物理地図の試験で守る所有境界

以下は `PhysicalMapAggregate` を対象にする試験へ適用する。他の集約や世界サービスの所有規則を置き換えない。

- 同座標の配置・除去は `add_object`、`get_objects_at`、`get_object` などの公開操作と結果で検査する。内部のID辞書や座標辞書だけを正解にしない
- 公開配置へ準備を移すときも、元のID・座標・型・能力・時刻・忙しさを保つ。準備通知だけを分離し、検査対象の操作後の通知を消さない
- 拒否試験は別の条件だけでも拒否されないか確認する。群れ検索の型選別なら、元の群れなし入力を残し、同群れの通常型も使って区別する
- 一括照会は単体照会自身から正解を作らず、入力ごとの独立した固定期待値を持つ。順序を守る試験には、区別できる結果を複数用意する
- 集合比較だけでは多重度を失う。必要ならID一覧を並べ替えて比較し、元の件数・型付きID・物体実体の所属も残す
- 真偽値の型を守る断言は `is True` / `is False` を維持する。整数1や0を許す等値比較へ弱めない
- 表へ統合するときは元入力を先に移す。可視の逆方向、同座標の単数入力、空入力、重複入力はそれぞれ独立した違いがある
- 同じ実体の失敗→状態変更→成功は、別実体の失敗試験と成功試験だけで代替しない
- 集約から政策・幾何・天候・トリガーへの接続と通知蓄積は、協力先の単体試験とは別の契約である。単純な構築・既定値・拒否も短いというだけで削らない
- 製品呼出が見つからなくても、履歴が公開APIとして導入した機能を試験都合で廃止しない
- 未確定の追加仕様は元の有効な断言と分ける。物体のドア開閉フラグ、タイル上書き、実移動可否を同一の契約と決めつけない

判断と対照の詳細は `docs/test_audits/physical_map_contracts.md` を参照する。
