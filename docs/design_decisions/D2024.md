## D2024. 効果の木を、集約に頼む葉とつなぎで作る

**何を**: 作者が書いた効果 (扉を開ける、品物を渡す、痛手を与える) が、集約の操作として世界を書き換えるようにした (#1978 のステージ 4)。効果は `facts` で読み、`world` の集約に頼む。断るのは集約で、効果は集約の例外をそのまま外へ出す。文書から決まらなかったことは、ユーザーと次のように決めた。

| 型・振る舞い | 決めたこと |
|---|---|
| `ItemByArgument` の `place` (`InHands` / `InPack` / `Anywhere`) | `PersonInventory.give_up` は手と荷を区別しないので、`give_up_held` / `give_up_packed` を足し、場所の型が自分に合う操作を呼ぶ。手から奪う効果が荷の物を奪わないよう、集約が断る |
| `RandomItemOf` が荷から選ぶ | `PersonInventoryReading` に `random_packed_item` を足し、効果は `facts.inventory(owner)` から読む |
| `MoveItemEffect` の手放す人 | `from_who` だけに持たせ、`ItemByArgument` と `RandomItemOf` から `owner` を外した。両方にあると、手放す人を 2 か所に書けて食い違う |
| 去った人として動いている人 | `PersonVitals.occupant_in_world(departed_persons_act)` が答える。去った人が動く世界で体が死んでいれば `DepartedPerson`、それ以外は `PersonBody`。条件 (#2023) は結末が `Died` かで、効果は体の生死で見分けていて、死んだ直後 (結末を決めるハンドラが動く前) に食い違ったので、ユーザーと調整役で体の生死にそろえた。体の状態が先に決まる事実で、結末はそこから導かれるため。条件と効果の `_occupant_of`、共通の前提 (`ActionPrerequisiteCheck`) の 3 か所がこれを呼ぶ |

**実装で決めたこと**:

- `ForEveryoneEffect` と `ForSomeoneEffect` は、選ばれた人を世界の並び (`facts.people()` の順) でたどる。条件 (#2023) の `ForSomeone` / `ForEveryone` と同じ並び。`frozenset` の並びは実行ごとに変わり、`ForSomeoneEffect` が同じ偶然で別の人を選ぶため
- `ForSomeoneEffect` は、選ばれた人がいなければ偶然を引かない
- `RandomBranchEffect` は、引いた値に重みの合計を掛け、前から重みを足して超えた枝を選ぶ。枝が無ければ作るときに断る。重みは `effect/` の `Weight` (1 以上の整数)
- 引数の種類が違う (品物を指すはずの引数に文、文を指すはずの引数に品物) ときは、効果がドメイン例外を投げる。compose と行為の型が先に弾くので、ここに来るのは作り手の誤り
- `WriteTextEffect` の書いた人は `trigger.acting_person()`。行う人のいないきっかけは引数も答えないので先に断られるが、型の上では `TextHasNoAuthorException` で断る
- `SetOutcomeEffect` は結末を決めたあと体を `Whereabouts.remove` で外す。持ち物は外さない (Issue の表のとおり)。体が居場所に無ければ、結末だけ決まったあとで `Whereabouts` が断る
- 集約が途中で断ると、それまでの書き換えは残る (`SequenceEffect` の前の段、`GiveItemEffect` で荷が満杯のときに生まれた品物、`SetOutcomeEffect` の結末など)。巻き戻しはステージ 7 の `CommandScope` が受け持つ
- 新しい例外は `exception/effect_exception.py` (効果) と `exception/person_inventory_exception.py` (手・荷の区別) に置いた
