## D2229. 入るときの案内は世界が組み、見出しは共通の部品に書く

**何を**: Being を新しい世界に入れるとき (#2229、親 #2212)、案内 (`Orientation`)・課す目的・最初から知っている人を、世界の問い合わせ `BriefEnteringPerson` が返すようにした。案内の 3 つの見出しは、シナリオの `briefing_headings` に書き、共通の部品 `ja_default.yaml` に既定を置いた。

### 1. 案内を組むのは世界の問い合わせ

導入 (`introduction.text`・`premises`) と最初から知っている人 (`knows_at_start`) は、世界の宣言 (`WorldDesign`) の中にある。遊びの進行 (`play_session`) は世界を入口だけで呼ぶので、`WorldDesign` を直接読まない。

| | 決まり |
|---|---|
| 問い合わせ | `BriefEnteringPerson(BriefEnteringPersonCommand(person, known_facts, objective)) -> EntryBriefing` |
| 返すもの | 案内 (`Orientation`、導入・前提・立場の順)、課す目的の文、最初から知っている人の `PersonId` |
| 立場と目的の渡し方 | 呼ぶ側が `CharacterBriefing` の 2 つの文を渡す。`CharacterBriefing` はシナリオの読み込み (infrastructure) の型で、世界の application からは import できないため |
| 紹介の名前 | 世界は返さない。Being は自分の名前で入り (D1928-3)、世界は誰が何という名前で入るかを知らない。呼ぶ側が `PersonId` を Being の名前に変えて `EnvironmentEntry.introductions` にする |

例: 廃坑の山村 v2 のゲンには、「この世界について」(冬が近い山あいの廃村……)、「この世界の前提」(昇降機は一度しか動かない……)、「あなたが知っていること」(金庫の番号は 1907……) の案内と、目的「サヨと二人そろって、坑道の奥の昇降機で外へ出る。」と、最初から知っている人 `sayo` が返る。

**採らなかった案**:

- 遊びの進行が `WorldDesign` から導入と `knows_at_start` を読む: 世界の入口を越えて、世界の宣言の形に寄りかかる
- 世界が `EnvironmentEntry` まで組む: 紹介に Being の名前が要り、世界が Being の名前を知ることになる

### 2. 見出しはシナリオに書き、既定は共通の部品に置く

見出しは Being に見せる世界の言葉なので、断りの文や場面の文 (`surroundings_texts`) と同じく、コードではなくシナリオに書く。

| | 決まり |
|---|---|
| 欄 | トップレベルの `briefing_headings: { introduction, premises, known_facts }`。型は `BriefingHeadings` |
| 既定 (`ja_default.yaml`) | 「この世界について」「この世界の前提」「あなたが知っていること」 |
| 確かめること | どれも空白だけでない 1 行で、【】を書けない。3 つは違う見出しにする。`Orientation` は見出しの重なりを許さないので、run の途中ではなく読み込みで断る |

導入の見出しは「この世界のはじまり」ではなく「この世界について」にした。導入の中身は出来事の始まりではなく、状況の説明なので。

**採らなかった案**:

- 見出しを `BriefEnteringPerson` に書き込む: 日本語の文がコードに入り、世界ごとに変えられない
- 見出しを `introduction:` の中に書く: 導入はシナリオごとの文で、見出しは世界をまたいで同じものなので、共通の部品から取り込みにくい
