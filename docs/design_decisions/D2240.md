## D2240. Being が行動と一緒にメモを書き、思い出すツールで 1 手を使う

> 自分の行動の行の形 (`[結果]`・`[失敗] |`) と、結果を観測の経路で受け取る作りは、D2345 で改めた。

**何を**: Being が LLM で行動を選ぶとき (#2240)、古い run の Being の道具のうち、メモ帳への書き込みとエピソードを思い出すツールを付けた。どちらも世界の行為ではないので、Being の中で済ませる。調整役と決めた。

- メモの引数 `memo` は、環境が `OfferedBeingTools.memo` を出しているとき、どの行動のツールにも付ける。必須にはしない。毎回書かせると、書くことが無いターンにも何かを書かせてしまう
- メモは、`ChooseAction` が行動を選んだその場でメモ帳に書く。行動が世界に断られても、書いたことは本人がしたことなので残す (古い run と同じ)。世界に渡す `AgentMove` からは外す
- メモは試みより先に書く。試みを残してから書けずに止まると、世界に渡らない試みが結果を待ち続ける。書けなかったら何も変えずに例外を上げる。古い run は書き込みの失敗を握りつぶして行動を通していたが、保存の失敗を静かに捨てない
- 出どころに `episode` を選ばせるのは、呼び名の載る【思い出せる出来事】を出しているとき (`episode_index_shown`) だけ。知らない呼び名を書かせて外すだけになるため (D1616)
- 思い出すツールは、環境が `OfferedBeingTools.episode_recall` を出しているとき、行動のツールの後ろに並べる。選ばれたら世界には何も渡さず、思い出した本文を記憶の道具の結果 (`MemoryOperationOutcome`) として試みに結び付け、`TurnSpentRecalling` を返す。古い run と同じく 1 手を使う (D1623-3)
- 遊びの進行 (#2232) は、`TurnSpentRecalling` を「ターンを終えた。世界には行為が無い」として扱う。待つとは別にし、次の巡りではまたターンが回る
- 一度に思い出せる件数は、環境ではなく Being の設定なので、`ChooseAction` が受け取る

**採らなかった案**:

- 思い出したあと同じターンでもう一度 LLM を呼び、行動まで選ばせる: 古い run の 1 手の使い方とずれ、1 ターンの LLM の呼び出しの回数も変わる
- メモの結果を、世界の結果が届く `ReceiveActionResult` まで持ち越す: 世界の結果が来るまで、Being がメモの結果を持っておく状態が要る

**部品の置き場所**: メモの引数のスキーマ (`being/application/memo_argument.py`)、操作の読み取りと理由の文 (`being/application/memo_arguments.py`)、思い出すツールのスキーマと結果の文 (`being/application/episode_recall_tool.py`) を、古い `application/llm` から移した。`ToolDefinitionDto` を組む部品と、trace を書く部品は古い run の側に残し、移した先を使う。メモと思い出すことの trace は、実験 (#2233) で扱う。

### 書けなかったメモの操作は、しようとしたことと理由を、心の声の下に 1 行ずつ出す

**何を**: 行動と一緒に書こうとして書けなかったメモの操作は、【直近の出来事】の自分の 1 手の行の下に、心の声と同じ字下げで、心の声のあとに 1 つずつ出す。ユーザーと決めた。

```
- [1 日目 00:00] カンテラに油を足して火を入れた。灯を手に持てば足もとが明るくなる。
  心の声: まず灯りだ
  メモ: 「m_3f2a7b を消す」は書けなかった（理由: そのメモはない）
```

- 行は `メモ: 「{しようとしたこと}」は書けなかった（理由: {理由}）`。理由の括弧は全角
- しようとしたことは、番号 (「2 件目」) ではなく操作の中身で言う。番号では、どの操作のことかを本人が読み取れない
  - 足す: `やることに「金庫を確かめる」を書く` (分かったことに / 人についてのメモに)
  - 書き換える: `m_3f2a7b を「金庫は開いた」に書き換える`
  - 消す: `m_3f2a7b を消す`
  - 読めなかった操作は、書かれていた do・kind・text・id のうち読めたものから言い (`メモを消す` など)、do が分からなければ書かれたものを JSON のまま示す。引数ごと崩れていたら `メモの書き込み`
- 理由は、古い run の `rejection_text` から、操作と重なる部分を除いた短い文にする (例: 「m_3f2a7b というメモはありません。」は「そのメモはない」)。文は `being/application/unwritten_memo_text.py` の表にある
- 書けたメモは、この行に出さない。【メモ】の欄に出る (古い run と同じ)
- 古い run は、結果の文の末尾に「[メモ] 次の操作は書けませんでした。」の段落を足していた。この形は、「次の操作」「2 件目」が何を指すのか分からず、心の声がメモの段落の下に付いて、行動とメモのどちらにかかるのかも分からなかったので採らない。古い run のプロンプト (`rejection_text`・`feedback_text`・`memo_turn.py`) は変えない
- メモは行動を選んだときに書き、世界の結果はあとで `ReceiveActionResult` で届く。そのため、書けなかった操作の行は試み (`Attempt.memo_rejections`) が持ち、結果が届いたら行の下に並べる。世界の結果の文 (`Observation` の本文) は書き換えない
- 行は Being の snapshot で読み書きする。結果のある試みと、結果を待っている 1 手の両方が持つ。足す前に保存した snapshot の試みは、行無しとして読む。試みの中の欄なので、snapshot のいちばん上のキーの表 (`ADDED_PAYLOAD_KEYS`) には足さない
- 世界の結果が届かないまま次の 1 手を選んだ試みは、結果の分からない試みとして残り、【直近の出来事】に出ない (D1824-22)。そのとき、書けなかった操作も本人には出ない

**古い run と違うところ** (ドメインの都合):

- 書き込み自体に失敗したとき、古い run は「メモ帳に書けませんでした。もう一度書いてください。」を足して行動を通していた。新しい流れでは、上で決めたとおり例外を上げて何も変えないので、この文は出ない。保存の失敗を静かに捨てないため
- 試みが持つのは整形した行で、理由の種類 (上限・無い呼び名など) の値ではない。理由のコード (`REJECTED_*`) は application の `memo_arguments.py` と `memo_writing.py` にあり、ドメインの型に持たせるには、それをドメインに移す必要がある。本人に読ませる文を出すことだけが目的なので、文で持たせた。理由の種類で何かを判断したくなったら、理由のコードをドメインの型に移す

**採らなかった案**:

- 結果の文の末尾に、古い run の「[メモ] 次の操作は書けませんでした。」の段落を足す: 上のとおり、何を指すのか、心の声がどこにかかるのかが分からない
- 書けなかった理由を、メモ帳 (`MemoBook`) に持たせて【メモ】の欄に出す: どの 1 手で書いたメモの結果かが離れる
- 理由を `ReceiveActionResult` まで Being の外 (遊びの進行) に持っておいてもらう: Being の記憶の一部を、Being の外が持つことになる

### 自分の 1 手を、古い run の「[行動] 要約 → [結果] 文」の行で読む

**何を**: 【直近の出来事】の自分の 1 手を、古い run (`application/llm/contracts/chunk_encoding.py` の `format_action_result_body`) と同じ形の行にする。古い run に合わせた。

```
- [1 日目 00:00] [行動] 「カンテラ」に働きかけた → [結果] カンテラに油を足して火を入れた。
  呼び出し: interact(target="カンテラ", how="油を足して灯す")
  心の声: まず灯りだ
  メモ: 「m_3f2a7b を消す」は書けなかった（理由: そのメモはない）
- [1 日目 03:00] [行動] pickup({"item": "鍵"}) を実行しました。 → [失敗] | 'pickup' というツールは無い。…
```

- 成功は `[行動] {要約} → [結果] {結果の文}`、失敗は `[行動] {要約} → [失敗] | {理由}`。成功か失敗かは、世界の結果なら `OwnActionResult.succeeded`、記憶の道具なら `MemoryOperationOutcome.succeeded`
- 行動の要約は、行為の種類を知っている世界が `OwnActionResult.action_summary` で渡す (#2232)。Being 自身の道具 (思い出すツール、出していないツールの名前) は、古い run の `action_summary_format.py` と同じく、Being が `ツール名(引数の JSON) を実行しました。` の要約を作る
- 成功した 1 手の下に `  呼び出し: ツール名(引数)` の行を付ける。並びは 呼び出し → 心の声 → メモ。
- 呼び出しの行の引数は、古い run と同じく、LLM が書いた順によらない並びにし、候補から選んだ値を引用して先に、自由に書いた値を伏せてあとに置く。古い run は分類表の順、新しい世界は世界が渡す見取り図 (`outline`) の順
- 自由に書いた値は、古い run と同じく引数ごとの言葉 (say_inline は発言など) で伏せる。言葉は世界が見取り図の欄 (`ArgumentOutline.hidden_as`) で渡す (#2268)。Being が引数の名前ごとの表を持つと、ゲームの引数を知ることになるため。欄が無ければ「本文」
- 呼び出しの行は、行動を選んだ時点の呼び方で作り、試み (`Attempt.call_text`) が持つ。世界に渡す `AgentMove` の引数は人を人の印に戻してあり、そのまま出すと内部の番号が漏れるため
- 思い出すツールは、古い run と同じく、呼び名の書き方が崩れたときと上限を超えたときに失敗、知らない呼び名は「思い出せない」と答える成功にする
- 要約の無い試み (古い run、足す前の snapshot) は、結果の文だけの行で出す。古い run の観測の本文は、すでに古い run の行の形になっている
- あとから届く自分の行動の結果 (移動先に着いた、道がふさがって着けなかった) は、観測の経路 `OwnActionCompleted` (要約・ツールの名前・成否。呼び出しの ID は持たない) で届く。古い run と同じく、心の声を付けず、成功なら引数の無い呼び出しの行 (`呼び出し: travel_to()`) を付けて、自分の行動の行として書く。世界が渡すのは #2268

**古い run と違うところ** (どれもドメインの都合。ユーザーと決めた):

- 失敗の行に `error_code=… | tool=… | 次tick再試行の可能性あり` を付けない。新しい世界は断りを理由の文で返し、古い run の error_code のような分類の値を持たない。値を作ると、世界に無い分類を Being がでっち上げることになる
- 話すときにも呼び出しの行を付ける。古い run はツールの名前で話すことを見分けて省いていたが、Being はどのツールが話すことかを知らない。新しい話すは届け方と相手を選ぶので、伏せた中身のほかに写せる値がある
- 結果を省く (`omit_result_in_prompt`) ことと、話すときに要約と結果をつなげることは、Being に持たせない。どちらも古い世界がツールごとに決めていた。省きたい結果や文のつなぎ方は、世界が要約と結果の文で表す
