# イベントハンドラの試験

- 主な保証は公開 `handle` と、実リポジトリから読み戻した状態に置く。配送の接続は統合試験に任せ、同じ保証を全層で繰り返さない。
- 消失・重複イベントの「例外を出さない」は有効な契約。`assert True` では補強せず、その経路の状態や副作用を確認する。
- 否定ケースは検査対象以外の前提を満たす。討伐者が未登録のまま「場所情報は不要」を試験しない。
- `TransactionalScope` は終了時に確定イベントを消す。発行しなかったことは接続された発行器の公開履歴で確認する。
- 怪しい試験の削除・統合前に、残す主所有者と固有の保証を確認する。修復した検査は意図的な退行で失敗することも確かめる。
