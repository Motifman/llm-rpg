## 通知の対を確実に検査する

主担当は `TestMoveMonsterSuccess.test_triggers_left_appeared_event`。

`SpotGraphAggregate.move_monster` は退出通知と出現通知をこの順で対として発行する。現場の受信者解決は、退出元と到着先それぞれのプレイヤーへ通知を届ける。重複すると同じ移動が余分に観測される。

元試験は型名文字列の包含と最初の位置比較だけだった。`[退出, 退出, 出現]` や `[退出, 出現, 出現]` でも通り、対の件数を守れていなかった。

修復後は次を検査する。

- 通知は2件
- 先頭は `MonsterLeftSpotEvent`、次は `MonsterAppearedAtSpotEvent`
- 元の場所1、先の場所2、両通知のモンスター101

グラフ1、接続10、モンスター101、場所1→2、空の所持品・世界フラグ、配置後の通知クリアは元と同じ。4つのID/場所判定も残す。UUIDや生成時刻、無関係な全フィールド一覧は固定しない。

## 保持した契約と比較層

### グラフ・プレイヤー

ノード重複、未登録終点、逆ID必須、正逆辺、所在と在席の更新、二重配置拒否、初回入場通知、移動の退出→入場、未配置・始点違い・鍵不足の拒否、鍵あり成功、未知接続の専用例外を保持する。

接続列挙の独立期待値 `[(1, 2), (3, None), (4, 5)]` は並行辺・片方向辺・明示ペアを守る。SQLite往復の主要比較は同じ変換関数から期待値を作るため、これを代替する理由にはしない。読み込み側の不正レコード拒否と、集約の壊れた逆辺を列挙する際の拒否も別入口である。

### モンスター

配置・撤去・移動の公開状態と通知、複数体の共存、専用例外、所在辞書の防御的コピーを保持する。`EntityId`と異なる識別子・寿命を持つため、プレイヤーの配置試験では置換しない。

通行queryは徘徊・反応・群れ処理が候補選択に使う。実移動も別に条件を再評価するので、queryとmoveの通行試験は双方必要。下位のnavigation試験だけでは、それぞれの入口が評価を呼び出すことを保証しない。

`TestEmptyPresenceCleanup.test_other_monster_remains` の既存判定は残件数1であり、残った個体がID102であることまでは検査しない。今回その判定を拡張したとは主張しない。

### 保存向けAPIと復元入力

`monster_presences_mapping()` は現在の製品からの直接呼出がないが、[導入時の修正](https://github.com/Motifman/llm-rpg/commit/e5fd3152cabcb853d2b4f2221b230bc4fa35ee1e) は将来の保存・復元の対称API、防御的コピー、空レコード除去を明示した。所有者の説明にも残っている公開契約を、呼出数だけで廃止しない。

所在だけ・在席だけ・場所不一致を拒否し、一致する二重索引を受け入れる復元試験も保持する。この4試験を、現SQLiteがモンスター状態を保存している証拠とはしない。

### 値と識別子

`SpotPresence` の空状態・追加/除去・重複追加/不在除去の拒否を保持する。集約には先に独自のガードがあるため、この値の拒否契約を集約試験が代替するわけではない。

5種類のIDは別々の実装であり、正値・0または負数・EntityIdの文字列変換と固有例外を保持する。単純な作成試験という理由で削除しない。

## 故障を入れた旧新対照

元試験と候補を別作業木に置き、次の8種類を1つずつ製品所有者へ入れて計16回実行した。各回の直後に製品を元のバイト列へ戻した。

| 故障 | 元試験 | 候補 |
| --- | --- | --- |
| 退出通知をもう1件発行 | 成功して見逃す | 件数判定が失敗 |
| 出現通知をもう1件発行 | 成功して見逃す | 件数判定が失敗 |
| 退出と出現を逆順で発行 | 順序判定が失敗 | 先頭の型判定が失敗 |
| 退出通知の場所を到着先へ変更 | 場所判定が失敗 | 同じ場所判定が失敗 |
| 出現通知の場所を出発元へ変更 | 場所判定が失敗 | 同じ場所判定が失敗 |
| 退出通知のモンスターIDを102へ変更 | ID判定が失敗 | 同じID判定が失敗 |
| 出現通知のモンスターIDを102へ変更 | ID判定が失敗 | 同じID判定が失敗 |
| 未指定行為者を42へ誤変換 | 元の既定値試験が失敗、元の保持先は成功 | 統合後の保持先が失敗 |

型や数値を複数同時に壊して、個別の判定を証明したとは数えていない。変異は検証だけに使い、製品差分には残さない。

## 限界と別の所見

- monster tick関連試験はautouse準備で `tick` を `_tick_loaded_monsters` に差し替える。公開の確定境界やSQLite保存を証明していない
- player移動結合試験の `_DirectScopeFactory` は `collect_all` を捨てる。移動・nav状態の証明であり、通知の最終配送を保証しない
- 通常runtimeはメモリ上のグラフへシナリオ初期のモンスターを配置する。[設計判断23](../design_decisions.md) は世界状態スナップショットのモンスター・クエスト非保存と初期状態への復帰を既知制限としている。新発見の欠陥とは扱わない
- SQLite aggregate codecがモンスター索引を含めないことは静的に確認したが、保存→読込の実証や製品修正は今回行っていない。world snapshotとは別の保存経路として扱う
- 逆ID検査前に正方向の辺を登録する `add_connection` の状態更新順序を確認した。既存例外試験に全面状態不変を勝手に付け足さず、製品修正は混ぜない
- 全リポジトリ試験・実LLM・有償API・性能比較は未実行。公開後は正確な先端のCIを別途確認する。マージしない

## 今後の所有規則
