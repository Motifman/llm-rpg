# エージェントが、世界に無い行為を試みた記録

実 run で、**エージェントが機構の外側へ手を伸ばした**場面を残す。どれも「バグ」では
なく、**我々が世界を設計したときに想定していなかったこと**である。

直すかどうかは別の判断なので、ここには**起きたこと・なぜ起きたか・直す場合の
選択肢**だけを書く。**直した時点でこの記録は消さない** — 直さない判断をした理由も、
後から読む人に要るため。

---

## 1. 提案の相互デッドロック (v3.2 run, t16–t20)

### 起きたこと

双方が同時に逆向きの提案を出し、**互いの品を凍結し合って両方とも承諾できなくなった**。

```
t16 カイ → トム: 16G ⇄ パン   (カイの 16G が凍結)
t16 トム → カイ: パン ⇄ 16G   (トムのパンが凍結)
t17 両者が承諾を試みる → 両方 TRADE_ASK_NOT_MET
t19 カイが降りる (trade_decline) → トムのパンが戻る
t20 トムが承諾 → 成立
```

### なぜ起きたか

**差し出すものを返事まで凍結する**設計 (経済統合 Phase 2) の副作用。凍結は
「受けたときに確実に渡すため」に入れたもので、**同じ品が別の提案の対価にもなって
いる**状況を想定していなかった。

### エージェントが自力で解いた

カイの独白:

> 俺のオファーとトムのオファーが行き違って両方凍ってる。トムのオファーを断って
> やれば…

**3 手番のロスで解けている。** engine で防ぐと、**この解決そのものが観測できなく
なる**。

### 直す場合の選択肢

- **そのまま**: 自力で解ける。解く過程が観測として面白い
- **逆向きの提案を断る**: 相手からの提案が生きているときは、こちらから逆向きの
  提案を出せなくする。デッドロックは消えるが、**解く場面も消える**

いまは**そのまま**。「エージェントが自力で解けない」実例が出たら、そのとき考える。

## 2. 教わることができない (v3.2 run, t27–t29)

### 起きたこと

トムがレナに**窯の使い方を教える取引**を持ちかけ、レナはそれを受けて待った。

t27 トム:
> 窯の扱いを教える代わりにパン1つ——悪い話じゃないはずだ

t29 レナ:
> トムが「入れてみろ」と言ったけど、窯にはまだ操作が出てこない——教わるって
> 言っても、実際に触らせてもらえるまで待つしかないのか

**レナは永久に焼けない。** 職能は `PLAYER_STATE_IS` で固定されていて、世界に
「教える」という行為が無い。

### なぜ起きたか

職能を**道具ではなく本人の性質**として持たせた判断 (道具ゲートを却下した経緯は
`docs/design_decisions.md` を参照)。道具は取引に出せてしまい、手放されると世界から
職能が消えるため、この判断自体は正しかった。

**想定していなかったのは、エージェントが「教える / 学ぶ」を言語で提案すること。**
世界に無い行為を彼らは自然に思いつき、成立を待ち続ける。

### これは静かな失敗の形をしている

**拒否されるのではなく、待っても何も起きない。** 「できません」という応答すら
返らないので、レナは自分の理解が足りないのだと考え続ける。

### 直す場合の選択肢

1. **そのまま**: 職能は変えられない。ただし「教える」提案が空振りし続ける
2. **教えられるようにする**: `initial_state` を書き換える手段を作る。**世界観が
   変わる** (職能が交換可能になる)
3. **教えられないことを世界が示す**: 窯の行に「焼けるのは焼き手だけ」と出す

3 が有力。**行為を増やさずに、空振りだけを止められる。**

ただし **#1197 で「注記は理由を断定しない」と決めた**判断とぶつかる。当時の理由は
「落ちた理由は職能とは限らず、世界の状態のこともあるので、断定すると別の嘘になる」
だった。

**逃げ道はある。** シナリオはこの条件に `failure_message` を書いている。

> 窯の火加減も捏ね方も分からない。パンを焼けるのはあの人だけだ。

これは**engine の推測ではなく作者の言葉**なので、そのまま出せば嘘にならない。
「理由を断定しない」は engine が理由を**推測しない**という規律であって、**作者が
書いた理由を伝えない**という意味ではない。

## 3. 受け取ることができない (v3.7 run market_town_v37_division, t53–t65)

### 起きたこと

ミナが run で唯一の麦束をトムへ手渡した (t53、`give_item` 成功)。トムは直後に
**ミナに対して `take_item` を試みて失敗**し (t54、そんな操作は無い)、代わりに
選んだ `give_item` で**受け取ったばかりの麦束をミナへ送り返した** (t55)。

t57 のトムのメモ:

> ミナが麦束をくれた（観測では渡された）。しかし俺の持ち物に麦束は無い…？

自分が返したことに気づかないまま、t64 に床を探し (`pickup_item` 失敗)、t65 に
「ミナ、もう一度渡してもらえるか」と頼んだ。麦束は run 終了まで窯に戻らなかった。

なお、**麦束が届いていてもこの run でパンは焼けていない**。窯は麦束 1 + 薬草 1 を
要求し、薬草も焼き手には一度も渡っていない (摘み手が 5 束抱えたまま run が
終わった)。トム自身が t55 に「薬草がねえと焼けねえんだ」と言っている。
パン 0 の原因は逆流だけではなく、**両方の材料の流れが揃って止まっていた**。

### なぜ起きたか

段階が 2 つあり、性質が違う。

**t54: 受け取りは自動なのに、「受け取る」という操作が要ると思った。**
`give_item` の成功は渡した側の行動としてしか世界に現れず、受け取った側には
観測が届くだけ。トムは観測と自分の所持品を結びつける前に「受け取る行為」を
探し、`take_item` (人に使える操作は無い) で断られた。

**t55: 結びついた後も、行動が思考に追随しなかった。** 送り返した当の
`give_item` 呼び出しの独白にこうある。

> …いや、よく見りゃ俺の持ち物に麦束がある。ミナが「渡した」って観測にあるから、
> もう受け取ってるんだな。

**気づくことには成功している。** それでもツール引数は独白前半の放棄済みの計画
(「give_item で受け取る」) のまま発火し、say_inline は「ああ、受け取ったよミナ。
ありがとう」— 返す意図はどこにも無いのに、唯一の麦束がミナへ戻った。

give_item を対称な向きに使える (誰でも誰にでも渡せる) こと自体は正しい設計で、
**渡す行為だけがあり受け取る行為が無い**という非対称と、**独白の中の訂正が
ツール引数に反映されない**ことの合わせ技を想定していなかった。

### 直す場合の選択肢

- **そのまま**: 珍しい混乱で、観測としては面白い。ただし今回は run の経済を
  止めた一因になった
- **受領を本人の観測に明示する**: 「ミナから麦束を受け取った (所持品に入っている)」
  のように、**自分の所持品が増えた事実**を受け取り側の観測文に書く。行為は
  足さず、観測の解像度だけ上げる (静かな失敗の構造的対処と同型)。ただし効くのは
  t54 (結びつく前) までで、**t55 の思考と行動の不一致までは防げた保証が無い**
- **`take_item` を足す**: 世界に「受け取る」行為を作る。同意の設計が要る
  (勝手に取れてはいけない) ので重い

観測文の強化 (2 番目) が筋が良さそうだが、まだ直していない。1 例しか無いので、
次の run でも同じ滑り方が出るかを見てから決める。

## 4. 相手に対して何ができるかが分からない (供物競争 v2 run, t60–t80)

### 起きたこと

交渉が価格の水準まで進んだのに、**合意を品物の移動に変える手が見つからなかった**。

```
t60 ユノ  interact(ガレン, 'talk')       → 人を対象にした 'talk' という操作はありません
                                           人に対して使える操作: (なし)
t65 ユノ  use_item(麦束)                 → このアイテムは消費できません
t78 ガレン interact(ユノ, 'offer_herb')  → 人を対象にした 'offer_herb' という操作はありません
t80 ユノ  give_item(麦束 → ドナ)         → 指定された相手の名前は現在の候補にありません
                                           有効な相手の名前: ありません
```

`give_item` は t51 に一度だけ成功している (ドナ → ユノ、麦束 1)。t80 の失敗は
**同席していない相手を指した**もので、別の型である。

交渉の中身は前進していた。t61 にユノが「麦束 1 本につき薬草 2 本でどうだ？」と
値を付け、t78 にセラが「麦束 1 本につき薬草 1 本＋10G でどうだ？ お前たちは薬草が
4 本と 45G 必要だ。こっちは麦束 3 本と 60G だ。計算が合うだろ」と対案を返している。
**非対称な供物を読み切って 1:1 を拒んだ発話で、v1 では出なかった。** それでも
納品は 0 で終わった。

さらに t64 のドナの独白:

> ユノの提案は悪くないが、**麦束を先に全部預けるのはリスクが高い**

`trade_offer` (差し出したものを返事まで凍結する = 先渡しのリスクを消す道具) が
まさに要る状況を言語化しているのに、**この run で `trade_offer` は一度も呼ばれて
いない**。

### なぜ起きたか

3 つの手伸ばしは向きが違う。

**`interact` に人を指した 2 件は、「相手にする操作」の一覧が空だと分かるのが
呼んだ後だった。** `available_interactions` はオブジェクト向けだけを並べる。人を
対象にできる操作が 0 件でも、プロンプトは「人に対しては何も無い」と**書いていない**。
失敗文だけが (なし) を教える。

**`use_item(麦束)` は、「納める」を手持ちの品に対する操作だと読んだ形。** 納入は
祭壇オブジェクトへの `interact` なので、品ではなく場所を指す必要がある。

**`trade_offer` が呼ばれない理由は分からない。** 露出はしていて、リスクの言語化も
できている。ここは独白からも読み取れなかった。

### 直す場合の選択肢

- **人に対してできることをプロンプトに書く**: `speak` / `give_item` / `trade_offer`
  が「相手に対して使える手」だと明示する。3 件のうち少なくとも 2 件はこれで消える。
  行為は足さず、露出の解像度だけ上げる (#3 の 2 番目と同型)
- **`trade_offer` を交渉の文脈で近づける**: 相手の提案を観測したときに、その手が
  あることを添える。ただし**呼ばれない理由が不明なまま近づけても効かない**恐れがある
- **そのまま**: 交渉が価格まで到達したのは今回が初めてで、時間切れ (t78 に対案) も
  重なっている。run 長を伸ばして、時間の問題と道具の問題を切り分けてから決める

**run 長を 140 tick に伸ばすところまでしか手を付けていない。** 先に切り分ける。

## この 4 つに共通すること

**どれも、エージェントが機構の外側を試みた記録である。**

1 つ目は成功として解決し、2 つ目は**何も起きない**。どちらも失敗として trace に
残らず、行動の統計を見ても出てこない。3 つ目は手伸ばし自体は失敗として残る
(`take_item` / `pickup_item`) が、**核心の 1 手が正常な成功として残る**ため、
成功の統計をむしろ汚す。**どの型でも、独白を読んで初めて全体が分かる。**

4 つ目は毛色が違い、**失敗としてきちんと残る**。それでも統計だけでは足りない。
「人に対する操作は無い」という失敗が 2 件あることは数えられるが、その 2 件が
**成立寸前の交渉を落としている**ことは、前後の発話を読むまで分からない。

0 だった軸について「その行動を検討した独白を探す」を分析の手順に入れたのは
このためで、**同じ理由で、この文書は独白から作られている**。

4 つ目にはもうひとつ型がある。**露出されていて、リスクも言語化できているのに、
呼ばれない道具** (`trade_offer`)。これは手伸ばしですらなく、trace にも独白にも
痕跡が無い。**「無い行為を試みた」ではなく「在る行為に手が伸びなかった」**で、
今のところ検出の手立てが無い。

0 だった軸について「その行動を検討した独白を探す」を分析の手順に入れたのは
このためで、**同じ理由で、この文書は独白から作られている**。
