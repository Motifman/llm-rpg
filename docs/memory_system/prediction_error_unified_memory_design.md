> — 原理は実走に耐え、境界 (効用勾配の不在) が 1 つ見つかった。

## 1. 統一原理: 記憶システムは「世界モデルの圧縮学習器」である

情報理論の基本事実から始める。**予測できるものは圧縮できる**。逆に、
記憶に残す価値があるのは「モデルが予測できなかった分」だけである。
驚きの大きさ (サプライザル、予測できなさの情報量) = そのまま
「記憶すべき情報量」になる。

この視点に立つと、記憶システムの全操作が 1 つの原理の別の顔になる。

| 操作 | 圧縮学習器としての意味 |
|---|---|
| **意味記憶 (belief)** | モデル本体。「世界はこう応答する」の圧縮辞書 |
| **エピソード記憶** | 残差。モデルで説明できなかった具体的な出来事 |
| **想起** | 次の予測を組み立てるために、モデルと残差を復号すること |
| **符号化 (チャンク圧縮)** | 予測できた部分を捨て、誤差だけを高解像度で残すこと |
| **固着 (学習)** | 残差に繰り返し現れるパターンをモデル側へ移すこと |
| **再解釈** | モデルが更新された後、古い残差を新モデルで再符号化すること |
| **忘却** | モデルが完全に予測できるようになった残差の破棄 |
| **ソース健忘** | 固着の帰結。命題がモデルに移れば元の episode は不要になる |

「エベレストと即答できるが、どこで覚えたかは忘れた」は、この原理では
バグではなく**圧縮が完了した状態**である。belief journal (原本 evidence を
traceability として残しつつ想起は belief だけ) はまさにこの形をしている。

もう 1 つ重要な帰結: **誤差ゼロも学習信号である**。「予測が当たった」は
「そのモデルが正しい」という支持証拠であり、確信度を上げ、対応する
エピソードの圧縮を許可する。誤差だけを拾ってきた現行設計に欠けている
半身がこれ (後述の部品 3)。

## 2. 現状評価 — 3 つの問いへの答え (コード確認済み)

### 問い 1: 予測精度を高める想起ができているか

**半分できている。想起は「状況駆動」であって「予測駆動」ではない。**

- 予測の器は完成している: `expected_result` は全 world-action で required
  (`tool_catalog/subjective_action.py:48-56`)、`ActionResultStore` に保存され
  (`action_result_store.py:37`)、episode の `expected` に永続化される
  (`chunk_episode_draft_builder.py:189-191`)。
- 照合も 3 層ある: 【前回の予測と実際】(`prompt_builder.py:109-165`、最新
  1 件)、【直近の出来事】の行内 `[予測: …]`
  (`chunk_encoding.py:44-65`)、chunk 補完 LLM の `prediction_error`
  (`episodic_chunk_subjective_fields.py:52-56`)。
- しかし想起クエリ (situation_cues) は
  `build_situation_episodic_cues` (`episodic_cue_rules.py:108-172`) で
  「現在地・視界・同席者・直近観測・直近ツール名と成否」だけから作られる。
  直近 action からの cue は tool 名と success/error_code しか見ず
  (`episodic_cue_rules.py:246-257`)、**予測テキストが検索クエリに混ざる箇所は
  コード上どこにもない**。

ただし「状況駆動の想起」は間違いではない。予測は「今の状況で何が起きるか」
の関数なので、状況 cue は予測の前提を揃える働きを既にしている。足りないのは
次の 3 つ (部品 4・5・6 で扱う):

1. **これからやろうとしている行動に条件づけた知識** (「この場所で explore
   したら過去どうだったか」) を確実に引く経路
2. **想起の信用割り当て**: 「この記憶をプロンプトに載せたのに予測が外れた /
   載せたから当たった」を測る配線 (想起自体が誤差で学習できていない)
3. **保留中の予測** (約束・数 tick 後に結果が出る見込み) を時間・場所・人物で
   再浮上させる経路

補足: 意味想起 (`semantic_passive_recall_service.py:163-218`) の relevance は
cue と tags/text の字面一致で、`SEMANTIC_PASSIVE_TOP_K` の既定は 0 (= off)。
能動想起ツールは実験 (memory_full_003) で 4 人 × 140 tick 中
`memory_search_semantic` / `memory_explore_related` 使用 0 回。**学びが
プロンプトに戻る経路そのものが細い** (20/287 prompt)。

### 問い 2: 記憶の生成に予測誤差が絡んでいるか

**符号化の解像度・境界は予測誤差と無関係に決まっている。**

- チャンク境界は固定ルール: 行動 3〜7 件 / 観測 5 件 / 場面境界 / tick 差 8
  (`chunk_boundary/rules.py:46-49, 155-278`)。「チャンクが長いほど圧縮率が
  高い」という直観は正確には「境界の閾値定数が密度を決めている」で、
  時間でもトークン数でもなくイベント数で切っている。
- 圧縮の本体は chunk 補完 LLM (`episodic_chunk_subjective_fields.py:24-59`) で、
  `recall_text` は**内容の重要度に関係なく一律 250〜450 字**。予測どおりの
  平凡な 5 行動も、罠で大ダメージを受けた 5 行動も、同じ解像度で残る。
- 意味記憶の生成はクラスタ昇格 (`episodic_semantic_cluster_promotion.py:43-45`
  の recall_count>=3 + クラスタ>=3 ゲート) で、予測誤差と無関係な統計に
  依存し「運任せ」(実験で 4 人中 2 人しか学びが生まれなかった)。
  これは [semantic_learning_consolidation_design.md](./semantic_learning_consolidation_design.md)
  が既に解決策 (証拠台帳 + 固着パス) を持つ。**ただし未実装** (grep で
  `BeliefEvidence` / `BeliefConsolidation` は src・tests ともヒット 0 件)。

### 問い 3: 修正 (誤差でモデルを直す) はできているか

**エピソード側は形ができている。意味記憶側は設計済み・未実装。**

- エピソードの再解釈は journal 方式で動く
  (`episodic_reinterpretation_coordinator.py:159`、10 ターン周期 batch、
  原本不変・active recall text 差し替え)。ただし誤差を名指しせず generic。
  誤差専用入口は 3 段のはしご PR-D で計画済み。
- 「想起した意味記憶の再解釈」に相当するのは **belief journal の
  revise / contradict** である。エピソード再解釈 journal と対称の形で、
  「信じていた命題が反証されたら、原本を superseded にして改訂版を書く」。
  これが新設計の中核で、追記専用の現行 store には存在しない。

## 3. 統一設計: 6 つの汎用部品

シナリオを個別機構にしない。以下の 6 部品の合成で全シナリオを賄う。
1・4 は既定路線 (新設計) そのもの、3 は小さな対称拡張、2・5・6 が本メモの
新規提案。

### 部品 1: PredictionOutcome (予測の一生を 1 本の線にする) — 既定路線

3 段のはしご PR-B の `prediction_context_id` / `PredictionOutcome`。
「どのプロンプト (何が想起されていたか) で立てた予測が、どう外れたか」を
1 つの id で貫く。すべての信用割り当ての土台。

### 部品 2: 誤差ゲート付き符号化 (残差だけを高解像度で残す) — 新規

「密度を時間やイベント数ではなく、情報量 (予測誤差) で決める」。

- **(2a) 誤差が境界を切る**: 認知科学のイベント分割理論では、人は予測誤差が
  跳ねた所で場面を切る。現行の境界ルール (`rules.py`) に 1 条項足す:
  chunk 内 action に構造的予測ミス (成功予測 → success=False、または
  error_code 付き) が現れたら境界候補にする。ルールで安価に判定でき、
  「事件」が平凡な行動と同じチャンクに薄められるのを防ぐ。
- **(2b) 誤差が解像度を決める**: chunk 補完 LLM に `salience: low | high`
  (新設計で既定) を書かせ、**recall_text の長さ指示を salience 連動にする**。
  high (予測が大きく外れた / 初めての事態) は現行どおり 250〜450 字、
  low (すべて予測どおり) は 80〜150 字の定型に近い形で済ませる。
  プロンプト指示の変更だけで実装でき、想起時のトークン消費も
  「驚いた記憶ほど詳しく思い出す」という人間の質感に揃う。
- **(2c) 予測どおりの反復は忘却候補**: salience=low かつ belief の支持
  evidence として消費済みの episode は、リンク減衰
  (`memory_link.py:95-101`) より積極的に想起順位を下げてよい (将来拡張。
  ソース健忘の実装だが、原本削除はしない)。

### 部品 3: 的中も証拠にする (CONFIRMATION evidence) — 対称拡張

新設計の `BeliefEvidence.source_kind` に **CONFIRMATION** (予測的中) を足す。

- 転記条件 (ルール): そのターンの in-context belief (attribution ledger) が
  あり、かつ chunk 補完の `prediction_error` が None (= 予測どおり) だった
  とき、当該 belief への支持 evidence を積む。
- これで confidence = f(支持, 反証, 時間) の「支持」が実際の的中から供給され、
  「何度も助けてくれた人だから今回も頼れる」「一度通った道は地図なしで
  歩ける」が、**反復的中 → 高確信 belief** として自然に生まれる。
- 対称性が生む質感: 高確信 belief が破れたときの誤差は「重い」
  (「Bは変わってしまった」)。confidence を誤差の重みとして固着パスの
  LLM に見せれば、精度重み付き誤差 (確信していた予測ほど破れが目立つ) に
  なる。

### 部品 4: belief の cue_signature を多軸にする (entity / place / procedure / self) — 既定路線の明確化

新設計の cue_signature (`tool:explore|spot:浜辺`) の軸を明示的に 4 種に
広げる。**新しい機構ではなく、索引の語彙を増やすだけ**。

| 軸 | 例 | 賄うシナリオ |
|---|---|---|
| `tool:` (手続き) | 「gather は使えず interact で拾う」 | 手続き学習 (S5) |
| `spot:` (場所) | 「この道は前にモンスターが出た」 | ルート回避 |
| `player:` (人物) | 「ノアは機嫌が悪いと無視する」「Bは頼れる」 | 再会・信頼・裏切り |
| `self:` (自己) | 「自分は探索の見積もりを過信しがちだ」 | 自己認識 |

`player:` 軸の belief は**人物モデル**そのものになる。想起側は既存の
同席者 cue (`episodic_cue_rules.py` の runtime_targets) で決定論的に引ける
ので、「B に会った瞬間に B についての belief と代表エピソードが浮かぶ」は
索引を揃えるだけで成立する。`self:` 軸は自分の行動への予測 (「自分なら
できるはず」) の誤差から更新され、「自己認識は積み重ねた経験の記憶から
成立する」を同じ機構に乗せる。実験 003 で実際に生まれた学び
「探索の見積もりは過信しがちだ」は、既に self 軸の belief である。

### 部品 5: 想起の信用割り当て (想起自体が誤差で学習する) — 新規

「予測精度を高める想起」を直接最適化する配線。attribution ledger
(belief 用、新設計 PR-3) を episodic recall にも対称に広げる。

- prompt build 時に【関連する記憶】に載せた episode_id 群を
  `PredictionOutcome` に記録する (recall_buffer は既に「何を想起したか」を
  持っている。`prompt_builder.py:1256-1296`。足りないのは outcome との紐付け
  だけで、部品 1 の `prediction_context_id` がそのまま使える)。
- **外れたとき**: その episode 群を誤差つきで再解釈キューへ (3 段のはしご
  段 1 の誤差専用入口 PR-D と同一。「これらから X を予測したが Y だった」)。
- **当たったとき**: その episode の想起価値の確認として recall ランキングを
  boost ([recall_ranking_failure_boost_design.md](./recall_ranking_failure_boost_design.md)
  の路線と接続)。
- これで「どの記憶を思い出すべきだったか」がループの中で自己修正される。
  想起は状況駆動のままでよい — ランキングが誤差で較正されるから。

### 部品 6: 保留中の予測 (pending prediction / 約束) — 新規

現行の予測は「次の行動の結果」だけを見る即時型で、`build_prediction_feedback_text`
は最新 1 件のみ。しかし予測には**遅延して解決するもの**がある: 「木の下で
アイテムを交換する約束」「数 tick 後に嵐が来るはず」。約束とは
**二者で共有された予測**である。

- 段 0 台帳の N 件化 (3 段のはしご PR-A) の仕様に既に「結果がまだ出ていない
  予測の保持」が含まれている
  ([memory_full_loop_run_2026-07-05.md](./memory_full_loop_run_2026-07-05.md) 改善 #6)。
  そこに **解決条件の cue (いつ / どこ / 誰)** を持たせる。
- 保持: `PendingPrediction` = {予測文, 解決 cue (spot / player / tick 範囲),
  発生元 episode_id}。生成はルールで拾えない (「夕方に木の下で」は意味判断)
  ので、chunk 補完 LLM に「この chunk に将来の約束・見込みが含まれるか」を
  1 フィールド追加で書かせる (書き込み時に一度だけ、の分担原則どおり)。
- 再浮上: 想起と同じ cue 機構。その場所に来た / その人物に会った / tick が
  範囲に入ったら、プロンプトに【保留中の予測】として出す。
- 解決: 果たされたら CONFIRMATION (相手の人物 belief への支持 =「約束を守る
  人だ」)、破られたら PREDICTION_ERROR (反証 =「あの人は約束を破った」)
  として部品 3・4 の同じ道に流す。**約束専用の機構はここで消え、
  「解決が遅い予測」という一般概念だけが残る**。
- memo との関係: 実験で memo が既に明示的な約束の置き場になっている
  (「岩礁海岸は山方面に通じず×」)。MEMO_DISTILL (新設計 S6) と同じ思想で、
  memo は pending prediction の明示的入口として合流させる (二重化しない)。

## 4. 無意識コンテキスト — 行動以外の LLM 呼び出しに何を渡すか

行動ターンが「意識」だとすれば、符号化・固着・再解釈の LLM 呼び出しは
**同じキャラクターの脳内で走る無意識過程**である。記憶の作成はキャラクター
から切り離された別の工場で行われるのではない。この視点は統一原理から
直接導ける: **予測誤差は絶対量ではなく「その人のモデルからの乖離」**なので、
モデル (ペルソナ・自己像・信念) を渡さずに誤差や重要度を判定させると、
「誰にとっても同じ驚き」を記録する工場製の記憶になる。チェストの罠は
初心者には大事件だが、「チェストはよく罠だ」と確信している者には
想定内 — salience はモデルなしには決められない。

### 現状の実態 (コード確認済み)

ペルソナは全呼び出しに渡っている。一方、モデルの残り (belief / L5 / 目的)
はどの記憶処理にも渡っていない。

| 呼び出し | ペルソナ | L5 自己像・世界観 | 関連 belief | 現在の目的 | 感情 | 想起 snapshot |
|---|---|---|---|---|---|---|
| chunk 主観補完 (`episodic_chunk_subjective_fields.py:255-268`) | ✓ 断片 | × | × | △ (draft の why = intention) | △ (draft の felt) | × |
| semantic gist (`semantic_gist_service.py:110-129`) | ✓ 「あなたの性格」 | × | × (`existing_related_semantic=None` ハードコード) | × | × | × |
| 再解釈 (`episodic_reinterpretation_coordinator.py:278-281`) | ✓ snapshot | × | × | △ (current_state に間接) | × | ✓ (最も厚い) |
| L4/L5 要約 (`short_term_memory_long_summary_service.py:117-125`) | ✓ 不変指定 | ✓ (L5 のみ previous を参照) | × | × | × | × |

### 標準バンドル「無意識コンテキスト」

各層を変化速度で整理し、すべての無意識呼び出しに共通の縮約バンドルとして
渡す。個別呼び出しごとに文脈を発明しない (見落としの温床になる)。

| 層 | 内容 | 変化速度 | 何に効くか |
|---|---|---|---|
| 安定核 | ペルソナ断片 | 不変 | 口調・気質。悲観的な者と楽観的な者は同じ出来事を違う色で符号化する |
| 自己モデル | L5 `self_image` / `world_view` | 遅い | 解釈の枠。「世界はこういうもの」が誤差の背景になる |
| 信念 | cue 一致の active belief top-K (**confidence 付き**) | 中 | **誤差の基準線**。確信度がそのまま誤差の重みになる (精度重み付き誤差 = 部品 3 の補2 シナリオが機構を得る) |
| 現在の志向 | 現在の目的 + chunk 内 intention | 速い | salience は目的相対 (目的に関わる誤差ほど重要) |
| 感情 | chunk 内 felt / emotion_hint | 速い | 気分一致符号化 (怯えているときの出来事は怖く残る) |

呼び出し別の適用:

- **chunk 主観補完** (最優先): belief top-K と L5 を追加する。`prediction_error`
  と `salience` の判定が「このキャラにとっての驚きか」になる。効果が最も
  直接的
- **固着パス**: 新設計の shortlist (関連既存 belief) が既にこの思想。L5 を
  足すと「世界観に照らして一般化する価値があるか」を判定できる
- **再解釈**: 想起 snapshot は既に厚い。belief top-K を足すと「当時の解釈は
  今の信念とずれている」型の再解釈が可能になる
- **L4/L5 要約**: L5 は自己参照が既にある。belief の要約 1 行を足すか否かは
  L5 と belief の役割分担 (narrative vs 命題) を崩さない範囲で要検討

### 確証バイアスは仕様、ただし構造ガードの内側で

belief を見せて符号化すれば、信念に沿う解釈が強化される (確証バイアス)。
これは人間の質感そのものなので排除しない。ガードは既に構造にある:
ルールフィールド (observed / cues / what / outcome) の改変禁止
(`episodic_chunk_subjective_fields.py` の `_assert_rule_fields_unchanged`) に
より、**バイアスが染みるのは主観フィールドだけ**。原本の事実は不変なので、
belief が contradict で倒れた後の再解釈で「思い込みで歪んだ記憶」を
読み直せる。「事実は変えられないが、意味づけは信念に染まる」— 人間と同じ
構造になる。

コスト: belief top-K 5 件 × 50 字 + L5 480 字 ≈ 呼び出しあたり +数百
トークン。無意識呼び出しは行動ターンと別系統なのでプレフィックス
キャッシュへの影響はない。

## 5. LLM 呼び出しの会計 — 現状と計画後の差分

基準: memory_full_003 (140 tick / 4 人 / 行動ターン 287 回 / 約 8.5 分)。

| 呼び出し | 頻度 (現状) | 003 実測 | 計画後の変化 | 差分 |
|---|---|---|---|---|
| 行動ターン | 1 / ターン | 287 | 変化なし | 0 |
| chunk 主観補完 | 1 / チャンク (行動 3〜7 件) ≈ 0.28 / ターン | ~81 | **同じ呼び出しに同乗**: salience (新設計) + pending prediction 抽出 (部品 6) はフィールド追加のみ。誤差境界 (部品 2a) でチャンクがやや細かくなる | +10〜20% (誤差の多い局面のみ。平時 0) |
| 再解釈 | 1 / 10 ターン / 人 (batch ≤8) | ~28 | 誤差専用入口 (PR-D) は同じ周期に相乗り | 0 |
| semantic gist | 昇格ごと (運任せ) | 4 | 固着パスに吸収され**廃止** | −4 |
| 固着パス (新設計) | なし | 0 | 1 / 10 ターン / 人 (batch ≤8 evidence) | +~28 |
| L4/L5 要約 | RollingSummary 使用時のみ (L4: 溢れ 15 件ごと / L5: evict 時) | 0 (003 未使用) | 変化なし | 0 |

**合計: 1 run あたり ~400 → ~435 回、+8% 前後。行動ターン 1 回あたりの
総呼び出しは ≈1.4 → ≈1.5 回。**

差分の内訳を見ると、本設計 (部品 1〜6) のうち LLM を新規に呼ぶのは
**固着パス 1 本だけ**で、それも gist の置き換え + 周期 batch。部品 3
(CONFIRMATION 転記)・部品 4 (索引)・部品 5 (信用割り当て・ranking boost)・
部品 6 の保持と再浮上は**すべてルールベースで LLM 呼び出しゼロ**。これは
新設計の分担原則「LLM は意味判断を書き込み時に一度だけ、ルールが溜めて
絞って発火させる」が呼び出し回数の上限をそのまま保証していることの現れ。

- **レイテンシ**: 追加・変更分はすべて非同期 batch (chunk 補完は既に
  scheduler 経由)。行動ターンのクリティカルパスは不変
- **トークン**: 無意識コンテキスト (§4) は回数に影響せず 1 呼び出し
  +数百トークン。一方、部品 2b が低 salience の recall_text を
  250〜450 字 → 80〜150 字に縮めるので、想起が載る行動ターン側の
  トークンはむしろ減る方向

## 6. シナリオ検証 — 全部が部品の合成で書けるか

ユーザー提示の 11 シナリオ + 本メモで補足する 4 シナリオ。**個別ハード
コードはゼロ**で、部品番号の合成だけで書けることを確認する。

| # | シナリオ | 予測誤差の語彙での分解 | 部品 |
|---|---|---|---|
| 1 | Bと再会「久しぶり！変わらないなぁ」 | B を見る → `player:B` cue で belief + 代表 episode が浮かぶ。「変わらない」= 人物モデルの予測と現在の観測の**誤差が小さい**ことの言語化。「久しぶり」= episode の occurred_at と今の差の自覚 (素材は既存) | 4 + 3 |
| 2 | 伝聞で「Bは変わってしまった」と嘆く | 伝聞 (観測) が高確信の B モデルと矛盾 = 重い誤差 → belief revise + 感情。嘆きは確信度が高いほど強い | 4 + 3 + 新設計 S3 |
| 3 | チェストが罠 → 開けるのが怖い | 一撃学習: salience=high で件数閾値なしに固着 (新設計 S2)。次にチェストを見た時 belief が想起され、予測が悲観側に倒れる | 新設計 S2 + 4 |
| 4 | 木の下でアイテム交換の約束 | 共有された pending prediction。場所 + 時刻 cue で再浮上 → 履行 | 6 |
| 5 | 「前は違うこと言ってなかった?」 | 相手の発話 = 観測。`player:` cue で過去の発言 episode が浮かび、突き合わせで矛盾 = 知覚的予測誤差。想起は既存機構で足り、照合はプロンプトの構え (既に「相手の発話は未検証の主張。自分の記憶と照合してから返事」がある) | 4 + 既存 |
| 6 | 何度も助けてくれた人 → 今回も頼れる | 反復的中 → `player:` belief の confidence 上昇 | 3 + 4 |
| 7 | この道はモンスターが出た → 別ルート | `spot:` 軸の誤差固着 (新設計 S1/S4 と同型) | 新設計 + 4 |
| 8 | 「自分はこういう人間だ」という自己認識 | `self:` 軸 belief。自分への予測の誤差・的中から更新 | 3 + 4 |
| 9 | 一度通った道は地図なしで歩ける | 誤差ゼロの反復 → 高確信の spot/route belief + 個別 episode は低 salience で圧縮 | 3 + 2 |
| 10 | 「エベレスト」と即答 (出典は忘れた) | 固着完了 = ソース健忘。belief は残り、episode は忘却候補 | 新設計 journal + 2c |
| 11 | 「パリ」は知っているがいつ習ったか不明 | 同上 (意味記憶の定義そのもの) | 同上 |
| 補1 | 「やっぱりね」(的中の質感) | 誤差ゼロの明示。CONFIRMATION がプロンプトに出れば言語化できる | 3 |
| 補2 | 慣れた場所の小さな異変に敏感 (「あれ、いつもと違う」) | 高確信予測ほど同じ大きさの破れが目立つ = 精度重み付き誤差。符号化 LLM が confidence 付き belief を見ること (§4) で機構を得る | 3 + §4 |
| 補3 | 約束を破られて信頼が下がる | pending prediction の誤差が `player:` belief の反証に流れる | 6 → 3 → 4 |
| 補4 | 「怖かったチェストが実は宝だった」(過剰般化の訂正) | 恐怖 belief への反証 → contradict/revise。**間違った学びも経験で棄却される** | 新設計 S3 |

シナリオ 1 の「元気にしてたか！」に含まれるもう 1 つの質感 —
「B の現在について自分は何も知らない」という**不確実性の自覚** — は、
belief の confidence と最終接触からの経過時間をプロンプトに出せば LLM が
文脈内で導ける (「30 日会っていない相手のモデルは古い」)。専用機構は不要。

## 7. 既存設計との関係と実装順

本メモは [semantic_learning_consolidation_design.md](./semantic_learning_consolidation_design.md)
(PR-1〜5) と [prediction_error_correction_design.md](./prediction_error_correction_design.md)
(段 0/1) を**置き換えない**。両者は統一原理の「モデル側 (belief)」の実装で
あり、本メモが足すのは「残差側 (符号化)」と「復号側 (想起)」の残り半分。

推奨順序 (既定路線に割り込ませる形):

1. **既定路線をそのまま進める**: 3 段のはしご PR-A/B + 新設計 PR-1〜2
   (証拠台帳・belief journal・固着パス)。統一原理の背骨はここ
2. **PR-2 の時点で部品 3 (CONFIRMATION) を同梱する**: source_kind を 1 つ
   足すだけで、attribution ledger (PR-3) が入れば転記条件も揃う。
   「的中も学習」は後付けするより最初から evidence の語彙に入れておく方が
   安い
3. **部品 4 (cue_signature 4 軸)** も PR-2 の索引設計に含める (実装は同じ、
   軸の語彙を決めるだけ)
4. **部品 2 (誤差ゲート付き符号化)**: salience は新設計 PR-5 に既にある。
   そこに 2a (境界 1 条項) と 2b (recall_text 長の salience 連動) を足す。
   どちらも小粒
5. **部品 5 (想起の信用割り当て)**: PR-B の `prediction_context_id` が
   入った後、recall_buffer との紐付け + 的中時の ranking boost。段 1 の
   誤差専用入口 (PR-D) と同じ土台
6. **部品 6 (pending prediction)**: PR-A の台帳 N 件化に「未解決予測の保持」
   が入った後、解決 cue と再浮上を足す。約束シナリオが閉じるのはここ

横断規約として、**無意識コンテキスト (§4) は部品ではなく各 PR の DoD に
入れる**: バックグラウンドの LLM 呼び出しを新設・変更する PR は、標準
バンドルのうちその呼び出しに必要な層を渡すところまでを 1 PR に含める
(per-Being store の snapshot 追従 checklist #27 と同じ「あとで足す、を
禁止する」型の規約)。最初の適用先は chunk 主観補完への belief top-K + L5
追加 — salience 判定 (新設計 PR-5) がモデル相対になるかどうかが
一撃学習 (S2) の質を直接決めるため。

将来 (非スコープ): 知覚的予測 (行動を介さない「この部屋は明るいはず」) の
入口、忘却 (2c) の実運用、embedding による索引強化。いずれも evidence の
source / cue の軸を足すだけで同じ道に乗る設計になっている。

## 8. 失敗モードと逃げ道

- **salience 連動の解像度で「実は重要だった平凡な出来事」が痩せる**:
  再解釈 journal が後から recall_text を書き直せるので、固着後に重要性が
  判明した episode は復元可能 (原本 observed は不変)
- **CONFIRMATION の水増し** (in-context belief と無関係な的中を支持に数える):
  転記条件を「belief が in-context だったターン」に限定する (attribution
  ledger が根拠)。それでも過剰なら固着パスの LLM が strengthen を棄却できる
- **pending prediction の溜まりすぎ**: 件数上限 + 期限切れの自動失効
  (失効自体を「果たされなかった」誤差として流すかは要検討 — 忘れられた
  約束はしばしば人間でも静かに消える)
- **プロンプト肥大**: 部品 2b が低 salience 記憶を短くする分で相殺する
  方向。セクション追加 (【保留中の予測】) は件数 cap 必須
