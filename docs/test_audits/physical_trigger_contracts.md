## 本人除外へ到達する入力

`TestComputeObjectTriggerEvents.test_actor_self_does_not_trigger` は、部品のない物体だけを渡していた。
本人IDを除外する処理を削っても、部品なしの判定が先へ進ませないため、空イベントの断言は通っていた。

元の `PLAYER`・部品なし・同一IDと座標・位置索引・空イベント断言を残す。
追加行は、実際の `PlaceableComponent` と `DamageTrigger(10)` を持つ `SWITCH` を移動物体自身として渡す。
模倣部品で発動結果を作らず、本人IDによる除外が働いたかを区別する。
他物体の罠が発動する既存の単一・複数罠の正常例も残す。

この入力は公開 `PhysicalMapAggregate.move_object` が受け付ける範囲にある。
同メソッドは `get_object` で対象を取得し、通常歩行へ補完して移動した後、自身を含む位置索引を判定サービスへ渡す。
`ActorComponent` の必須判定はない。通常プレイヤーやモンスターが罠部品を持つという新しいゲーム仕様は主張しない。

## 最初に一致した効果を区別する断言

`TestComputeTriggerActivationAtCoordinate.test_returns_first_matching_trigger_when_overlapping` は、
同じ座標の `DamageTrigger(10)` と `WarpTrigger` を渡しても、戻り値が空でないことと発動1件しか確認していなかった。
後方の効果を誤って選んでも、この2つの断言は通る。

元の2範囲、ID、辞書順、呼出引数、非None・件数1の断言を残す。
戻り値がダメージ10、発動イベントが範囲ID1・`DAMAGE`であることを加え、効果と対象の選択を検査する。
期待値は固定した入力の契約から決め、戻り値自身から導出しない。

順序の保証は、計算入口へ現在渡された辞書の列挙順に限定する。
SQLiteからの復元は `ORDER BY trigger_id ASC` であり、保存前の追加順や設置時刻を保持する契約は新設しない。
他のイベント配列全体の順序も固定しない。

## 保持する境界

- 地図の公開照会・配置検証は、空座標、複数物体のID、正常受容、範囲外と衝突の専用例外を守る。返り値のない検証入口の正常受容を、断言なしという見た目だけで削除しない
- 地面アイテム3個の同時配置と通行可能性を残す。2個のID照会だけではこの通行判定を代替できない
- 実移動から踏み発動を蓄積する試験を残す。純粋な判定サービスでは、集約の呼び忘れ・通知蓄積漏れを検出できない
- 範囲の進入・退出・滞在・初回配置・無効状態・重複範囲、場所の説明とプレイヤーID、出口の移動先・着地点・発生時刻を保持する
- 踏み発動の空索引・他座標・部品なし・効果なし・複数物体、手動照会の対象あり/なし・範囲外・空集合・無効範囲を残す
- `AreaTrigger` の名前・範囲・効果・既定有効と構築後の無効化を残す。SQLite往復例が確認する範囲内判定とダメージ値だけでは、これらを一括して代替できない
- `AreaTriggerId` の整数/文字列入力、整数/文字列出力、不正文字列・負数・0の専用例外、別インスタンスの同値性を残す。単純な構築・取得や現在の直接呼出数だけを削除理由にしない

配置検証は `PlaceObjectApplicationService` の配置処理、座標照会は同サービスの破壊処理と
`PlayerSupplementalContextBuilder.can_destroy_placeable` が利用する。
物体移動は `MovementStepExecutor` と `MonsterDecidedToMoveHandler` が利用し、集約が判定サービスへ委譲する。
集約の範囲・場所・出口への接続は `test_physical_map_aggregate.py` と
`test_physical_map_aggregate_location_gateway.py` に残す。
型別イベント件数を、`WorldObjectMovedEvent` も含む全通知件数と混同しない。

## 設計と履歴

`docs/refactoring/phase2-3-refactoring-plan.md` は、集約が空間整合性を、`MapTriggerEngine` が判定を所有する分担を定める。
`40f8ba1` は範囲トリガーと、最初に一致した有効範囲を返す手動照会を導入した。
`9e0c66c` は公開配置・照会・踏み発動を導入し、この時点から本人IDを除外している。
`b4907de` は判定をサービスへ移し、今回の2宣言を追加した。`f1d2989` は重複範囲の不足例を加えている。
手動照会とIDの生成メソッドは基準時点で直接のアプリ呼出が見つからないが、公開契約として導入されており、今回廃止しない。
