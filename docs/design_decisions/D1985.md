## D1985. 疲れと空腹の段階の形と、限界との関係

**何を**: 世界の決まりの値 (#1978 の段階 1) として、`ActionKind`、`TendRule` / `NoTending`、`FatigueRule`、`HungerRule` / `NoStarvationDamage`、`DeathRule` を `game_world/domain/rules/` に作った。段階 (`FatigueLevel` / `HungerLevel`) の形は文書に無かったので、調整役と次のように決め、`docs/environment_model/design/world_design.md` を直した。

| 決まり | 破ったとき |
|---|---|
| 段階は境目 (`starts_at`) と、空でない呼び名 (`FatigueLevelName` / `HungerLevelName`) を持つ | `LevelNameBlankException` |
| 段階は 1 つ以上 | `NoLevelsDeclaredException` |
| 最初の境目は 0 | `LevelsNotStartingAtZeroException` |
| 境目は狭義の昇順 (同じ境目は重なりとして断る) | `LevelsNotAscendingException` |
| 呼び名は重ならない | `LevelNameDuplicatedException` |
| 境目は `limit` 以下 | `LevelBeyondLimitException` |
| `limit` は 1 以上 | `RuleLimitBelowOneException` |

**なぜ最初の境目を 0 にしたか**: どの量にも段階があれば `level_of` は必ず段階を返し、「段階なし」の型が要らない。

**なぜ呼び名の重なりを断るか**: 段階が変わったときだけイベント (`FatigueLevelChangedEvent` / `HungerLevelChangedEvent`) を出す。同じ呼び名の段階が 2 つあると、受け取った側は段階が変わったことを見分けられない。

**なぜ境目を limit 以下にしたか**: 疲れも空腹も `limit` で止まる。`limit` を超える境目の段階には決して届かないので、書き間違いとして止める。量を `limit` で止める処理は、使う集約 (`PersonVitals`) を作る段階 3 で入れる。

**`per_exertion` と `per_tick` は 0 を許す**: 疲れない世界、腹が減らない世界を書けるようにするため。

**`WorldRules` は作らない**: 聞こえ方 (`HearingValues`、#1982) と `StealthRule` (見え方に頼る、#1983) が別の Issue なので、それらが揃ってから作る。

**関連**: Issue #1985、#1978、#1975 の 8.。
