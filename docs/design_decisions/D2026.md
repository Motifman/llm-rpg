## D2026. 動詞の宣言と知覚の宣言を作る

**何を**: world_design.md の動詞の宣言 (名詞に付く動詞 7 つ、操作、出来事と知らせ、反応、二人で合わせる操作、見つかる物、終わり) と知覚の宣言 (`PerceptionDeclaration`、`SoundDeclaration`、`SightTextsDeclaration`、`BuiltInActionPerceptions`) を `game_world/domain/declaration/verb/` に、知覚の型 (`Salience`、`NotSeenInDim` など) を `perception/` に作った (#1978 のステージ 4)。

| 型・振る舞い | 決めたこと |
|---|---|
| `BuiltInActionPerceptions.by_kind` に書ける行為 | 操作 (`INTERACT_WITH_OBJECT` / `INTERACT_WITH_CARRIED_ITEM` / `INTERACT_WITH_PERSON`) と区画の出入り (`ENTER_SECTION` / `LEAVE_SECTION`) は作者の宣言の `perceived_as` で知覚され、`ATTACK_MONSTER` はこの世界に無い。表に書いても読まれないので、宣言 1 つで分かる誤りとして作るときに断る (ユーザーと決めた)。品物を使うこと (`USE_ITEM`) は `ItemUseDeclaration` に知覚の欄が無いので表に書く。表に足りない行為は compose が照らし合わせる |

**実装で決めたこと**:

- 宣言の型は既定値も `kw_only` も持たない (D2029 の E)。`SightTextsDeclaration` の `dim`・`unseen_actor`・`noticed_later` も、書かなかったときの値は読み込む側が埋める
- `AnnouncementTo` は `HappeningNotice` の 1 つとして `happening_notice.py` に置き、`PerceptionDeclaration.announcement` もこれを使う
- 操作の宣言の `arguments` に同じ名前が 2 回あれば、作るときに断る。引数の種類が違っても、効果と条件は名前で引くので区別できない
- 宣言が `DeclaredInteraction`・`FiredHappening` などの約束を import せずに満たすことは、mypy の検査対象の `tests/game_world/support/verb_declarations_for_tests.py` で、宣言を約束の型として返す関数を通して確かめる
